## 1. 出品前必须做的 5 项静态检查

| # | 检查 | 判据 / 命令 |
|---|---|---|
| 1 | 图件 ↔ 图号是否一一对应 | 按 `figures/` 路径分组，**同一路径出现 ≥2 个图号 = 硬伤** |
| 2 | 图号连续性 | 每章 `图 X.1..X.n` 无重号、无断号（改稿删图后最易残留） |
| 3 | 图引用形态 | 全稿 `[图 X.Y]` / `[表 X.Y]` 夹注计数应为 0（改为「如图 X.Y 所示」） |
| 4 | 文献表 ↔ 正文被引 | 双向 0 孤立、0 超范围、0 缺号（区间/逗号引用先展开） |
| 5 | 待填项 | 封面/扉页/作者简介/成果/致谢 + 正文自标的"数据待补"，全部列清单交用户 |

## 2. 图题位置的 DOCX 取证（本项只能查 DOCX，md 里看不出来）

```python
from docx import Document
NS = "{http://schemas.openxmlformats.org/drawingml/2006/main}"
def has_img(p): return len(p._element.findall(f".//{NS}blip")) > 0
for i, p in enumerate(doc.paragraphs):
    if has_img(p) or p.text.strip().startswith("**图") or "图注" in p.text:
        print(i, "IMG" if has_img(p) else "   ", p.text.strip()[:60])
```
**实测结论**：md 源里图题行在图片行之前 → DOCX 中 `图题段 → 含图段 → 图注段`，即**图题在图片上方**，与规范"图题在图下"相悖（全稿 10 张图同此版式）。修法是改生成器的段落顺序，**不是**改 md 行序（改 md 行序会连带影响图注归属，先确认生成器怎么处理再动）。

## 3. 同一张图件挂两个图号：根因与修法

**根因（实测）**：撰写时为让某节的结论有配图，直接**复用素材包里的现成附图**填空，同时给它另起了一个图题 —— 一张图同时承担两个角色（如"三支柱框架"与"逐级收缩漏斗"），且图件数（9）少于需要的图号数（10）。**诱因**：素材附图本身画了多个元素，看上去"两个位置都能用"。

**修法（优先级从高到低）**：
1. **删掉重复图号，让该处改引原图号**（零成本、图序自洽）：删图号 → 正文改「…如图 2.1 所示」→ 后续图号顺次重编 → 同步目录/插图清单/正文交叉引用。
2. 保留但**新绘一张独立图**（仅当两处确实需要不同图时）。
3. 只调位置（不推荐：编号仍重）。

**重编号的传播清单（实测 28 处，漏一处就前功尽弃）**：全部 `part*.md` 正文引用 + 插图清单行 + 目录条目 + 图注内部互引 + 附录交叉引用 + 第 1 章创新点里的引用。做法：一个脚本按"从后往前替换"避免链式覆盖（`图 3.8→3.7` 必须在 `图 3.7→3.6` 之前做），改完 grep 确认旧编号 0 残留。

## 4. 图序是否乱序：按「首次提及」判，不按版面位置

实测案例：图 2.2（§2.2.2）在版面上出现在图 2.1（§2.3）之前，初看像乱序；但图 2.1 的**首次引用**在第 1 章 §1.5，早于图 2.2 —— 按首次提及顺序编号，**正确，无需互换**。
判据：`grep -n "图 X.Y" part*.md` 取每个图号的**最小行号（注意跨文件按 part 顺序比）**，排序后与编号顺序比对。

## 5. 引文审计：三个实测要点

1. **区间/逗号引用要展开**：`[28-31]`、`[9,16,17]` 合法。只匹配 `\[\d+\]` 会把它们误报成孤立文献（实测初判"15 条孤立" → 规范核查后为 **10 条真孤立**）。
2. **数值区间的假阳性 `[30, 500]`**：阈值区间被当引用。特征 = **逗号后有空格 + 数值远大于文献总数** → 按此排除。
3. **孤立文献逐条按内容处置，不硬凑引用**：
   - 正文有对应内容但**缺编号** → 在正文补挂（实测：对比专利 D1–D5 在表里只有 D 标号，首列补成 `D1 [35]`）；
   - 与本文确实无关的残留条目 → **删除并顺延编号**，删后**重跑审计**确认无断号（实测删 1 条 CellBender，后序全部 -1）。

## 6. 待填项清单化（不代填）

| 组 | 项 |
|---|---|
| 封面 | 分类号 / 学号 / 学位类别 / 作者姓名 / 专业名称 / 研究方向 / 指导教师（姓名与职称间空一格）/ 培养单位 / 完成时间 |
| 扉页 | 作者、专业、指导教师、学位类别、答辩日期（`年【】月【】日`） |
| 作者简介 | 姓名·性别·出生年月日·民族·出生地·学位·职称·学历·工作经历·著作与成就·联系方式（**整页本人填**） |
| 科研成果 | 学术论文行（补作者位次 + 卷期页）；专利行（补申请人 + 申请号/公开号 + 年份） |
| 后记致谢 | 导师姓名、数据来源团队名、同门协助、日期 |

另有一类**正文自标的"数据待补"**（非【待填】标记），例如"原论文队列 23 只 vs 本文用 20 例的口径差"——同样要收进清单，别只在正文里挂着。

## 7. 批量改稿 + 双端复测（收尾一次做完，别连环核验）

- 改动集中到**一个脚本**：每处 `assert text.count(old) == 1` 再替换；`count==0 且 new 已在文中` 视为已应用（幂等续跑）。
- 复测**一次给全数字**：重跑生成器拿 `size / paragraphs / tables`；一个脚本同时打印「旧句式计数→0」+「新句子计数→命中」的 **MD 与 DOCX 双端**结果（DOCX 端把 `paragraphs + tables` 拼全文再 `count()`）。
- **表格里的内容不在 `doc.paragraphs`**：插图清单/附表清单是 DOCX 表格，查清单行要遍历 `doc.tables`（实测在段落里搜 `| 图 2.2` 永远查不到，误以为没登记）。
- ⛔ 收尾**不要**再回头"再确认一次"（同形态核验铺开多轮会触发循环检测强制干预，处置见 `platform-execution-pitfalls` 的 2026-09-16 行）。
