# 基因组注释文件核实与反义基因座判读（实测：2026-10-01，GRCh38 / GENCODE v32）

## 0. 第一判据：注释类事实必须「打开源文件核对」，不接受 API 摘要转述

**用户原话**：「GRCh38 这个 gtf 文件，**你下载下来，真实查看一下**，它在这里到底代表什么」——
此前我已用 Ensembl REST / NCBI Gene / UniProt 三处 API 给出过完整答复（坐标、biotype、链向），
用户仍要求看**文件本身**。⇒ 涉及「注释里怎么写 / 某基因在注释里代表什么」的问题，**源文件是唯一
权威**；API 返回的是数据库视图，不回答「你手上这份 GTF 里它长什么样」。

**优先路径（按序）**：

1. **先查本机是否已有该参考文件**（别重复下 1 GB）：`ls -la <参考目录>` + `gzip -t <file>.gz`
   （`gzip -t` 通过 = CRC 完整，可直接复用；失败才重下）。实测本机 `E:/Human_gene_reference/`
   已存 GENCODE v32 GTF（43,107,903 B），**可直接 zcat 统计，无需重新下载**。
2. 未命中再按官方 FTP 下载（GENCODE/Ensembl 的 EBI ftp 路径常年稳定）。
3. **真实打开统计**（不是 grep 一两条就下结论）：

```bash
GTF=gencode.v32.primary_assembly.annotation.gtf.gz
zcat $GTF | awk -F'\t' '$0 !~ /^#/ {print $3}' | sort | uniq -c        # 行类型分布
zcat $GTF | awk -F'\t' '$0 !~ /^#/ && ($9 ~ /gene_name "MEF2C-AS1"/ || $9 ~ /gene_id "ENSG00000248309/)' | head
zcat $GTF | awk -F'\t' '$0 !~ /^#/ && $9 ~ /gene_name "MEF2C"/ {print $3}' | sort | uniq -c
```

实测（v32）：`MEF2C-AS1` = **1 gene + 15 transcript + 62 exon，+ 链，lncRNA**；
`MEF2C` = **1 gene + 56 transcript，− 链，protein_coding**。⇒ 与 API 一致，**用户手上这份 GTF 没问题**
（这条结论只能由文件本身给出，API 答不了）。

4. **外显子级重叠要实算**，不能只看「区间有交叠」：把两基因的 exon 区间取出来做区间交集，
   才知道它们是否**共享序列**（同一基因座的正义/反义配对判读的关键一步）。

## 1. GTF vs FASTA：用户问「我需要哪个」怎么答

| 文件 | 内容 | 什么时候真的需要 |
|---|---|---|
| **GTF / GFF3**（v32 ≈ 43 MB gz，解压 1.3 GB） | 基因 / 转录本 / 外显子的**坐标表**（chr、起止、正负链、biotype） | ✅ 注释核查、read 归属、基因座关系、定量区间 —— **绝大多数问题只需 GTF** |
| **FASTA**（`GRCh38.primary_assembly.genome.fa.gz`，≈ 1 GB gz） | 基因组**碱基序列本体** | ⚠️ 只有要取**真实碱基序列**时才需要：切出某 lncRNA 的转录序列、设计引物、做 motif/序列比对 |

判据一句话：**要位置 → GTF；要碱基 → 加 FASTA**。两者不是「二选一才好」，而是按用途叠加；
用户只做注释核查时说清「GTF 够了、FASTA 暂时不需要」即可，别默认让他下 1 GB。

## 2. 反义基因座判读：`-AS1` 家族（可直接复用的领域知识）

命名规律：`XXX-AS1` = **XXX 的反义链转录本**（HGNC 统一命名，antisense RNA 1）。同族例子：
ZEB1-AS1、DSCAM-AS1。**看到 `-AS1` 先按「宿主基因的反义 lncRNA」假设，再去核对坐标。**

实测 `MEF2C` vs `MEF2C-AS1`（GRCh38）：

| 维度 | MEF2C | MEF2C-AS1 |
|---|---|---|
| biotype | protein_coding | **lncRNA**（无蛋白产物） |
| 位置 | chr5:88,717,117–88,904,257 | chr5:88,883,328–89,466,398 ⚠️ |
| 链 | **−** | **+** |
| ID | ENSG00000081189 / HGNC:6996 | ENSG00000248309 / HGNC:48908 |

> ⚠️ **坐标必须随文件重新 grep，不要复用旧值**：上表 MEF2C-AS1 是 **GENCODE v32 文件实测**（gene 行
> `grep -P '\tgene\t.*gene_name "MEF2C-AS1"'`）；旧版记的 `88,883,276–89,467,616` 来自 API 视图
> （版本不同，起止各差 52 / 1,218 bp）。换版本 / 换注释文件 / 隔了一段时间后复述坐标前，**重新 grep 一次**。

两者重叠 = **20,930 bp**（88,883,328–88,904,257）。**末端最近的一对是 5′-5′**（20.9 kb；其余三对端间距
166 kb / 562 kb / 749 kb）⇒ 属 **5′-5′ 相邻的反义配对**：两个 TSS 分别落在重叠区的两端，
并且**各自朝重叠区内部转录**（MEF2C-AS1 自左界向右、MEF2C 自右界向左，互读穿越）。

### 🔴 术语表述纪律（2026-10-02 实测自我纠正）

⛔ 别写「5′ 端**相向**（**divergent / head-to-head**）」这种自相矛盾的混称 ——
「5′ 端相向」描述的是**转录方向指向对方**，而「divergent / head-to-head」描述的是**转录方向背离**，
二者相反。安全写法 = **直接用坐标把两端点出来**（「重叠区左界 = MEF2C-AS1 的 TSS，右界 = MEF2C 的 TSS，
两基因均向区内转录」），比贴术语标签可靠，也更容易被合作方核对。

文献：PMID **36198203**（MEF2C-AS1 调控其邻近基因 MEF2C）；PMID 36064442（结直肠癌启动子高甲基化沉默）；
PMID 37711390（天然反义转录本调控正义编码基因的机制综述）；
PMID **40623475**（de Smalen 2025, Mol Metab, DOI 10.1016/j.molmet.2025.102206, PMC12309500 —
人骨骼肌耐力训练 ATAC：训练后染色质趋向**闭合**、抑制运动后即刻早期应激反应；⚠️ 仅核实到
标题/期刊/年/DOI，引用具体倍数前须取全文）。

### 🔴 对 DEG 结果的含义（报告/图注口径）

1. **同一基因座的正义+反义配对，不构成两条独立证据** —— 两者同时出现在上调列表里，更可能是
   **同一调控区被共同激活**，不要写成「MEF2C 及其反义 RNA 双双上调」当作两个发现。
2. **定量歧义**：两者区间物理重叠，重叠区（88.883–88.904 Mb）内 read/UMI 归属存在歧义。
   自查 = 算两者在 pseudobulk 矩阵中的表达相关性；**相关系数很高（如 > 0.9）⇒ 同一信号**，
   报告/图注宜合并表述为「**MEF2C 基因座（含反义 lncRNA MEF2C-AS1）**」。
3. 注释来源要写清：v32 里它是 **havana 人工注释**的正式条目（不是预测、不是拼接假象）——
   用户问「是不是注释错误」时，用 biotype + source 字段直接回答。

## 2.5 重叠区的可及性归属（ATAC 侧）——「能不能用 ATAC 证明运动也影响了宿主基因」

**问法先纠偏**（用户/合作方常这么问，直接照做会翻车）：

| 对方要的说法 | 能不能做 | 正确译法 |
|---|---|---|
| 「统计 MEF2C-AS1 与 MEF2C 的重合区运动前后变多变少」 | ❌ 字面做不到 | 同一段 DNA、ATAC 片段**无链信息**，一个片段只有一个数；不存在「两个基因各自的重合区」 |
| 「整段 20.9 kb 计数、前后比较」 | ⚠️ 能算但没意义 | 区间内含两基因的多个内含子，峰与非峰平均成一个数，说不清是什么变了 |
| 「**重叠区两端各自的 TSS 近端可及性**前后比较」 | ✅ 能，且能回答原问题 | 左界 = 反义 lncRNA 启动子；**右界 = 宿主基因启动子 → 这才是能回答「运动是否影响 MEF2C」的那一段** |

⇒ 判据一句话：**整段不能拆（物理同一段 DNA），两端能拆（两个 TSS 相距 20,930 bp，是物理上分开的两个位点）。**

**R1–R4 区间设计与统计**（可直接复用）：

| 区间 | 定义（本例坐标） | 回答什么 |
|---|---|---|
| R1 | 反义 lncRNA TSS ±2 kb（88,881,328–88,885,328） | 只含 AS1 启动子 ⇒ 变化 = AS1 侧调控活动变化 |
| R2 | **宿主基因 TSS ±2 kb**（88,902,257–88,906,257） | 只含 MEF2C 启动子 ⇒ **支持「运动影响 MEF2C」的关键区间** |
| R3 | 整段共享区（88,883,328–88,904,257） | 只作全景参考，别用它下结论 |
| R4 | 外显子重叠段（137 bp + 266 bp，共 422 bp） | 占比仅 2%，看它不如看两端 TSS |

统计口径：每样本每区间取片段计数（CPM / FRiP 归一）→ **按供体配对**统计 Post−Pre
（Wilcoxon 符号秩 / 配对 t）→ 比 R1 与 R2 的方向：

- 只有 R2 变 → 运动作用于宿主基因启动子 ⇒ 支持「运动也影响 MEF2C」
- 只有 R1 变 → 运动只作用 AS1 侧 ⇒ **不支持**「影响 MEF2C」
- 两端同向变 → 共有调控 / 双向联动
- 都不变 → 该位点非运动响应；换区间，或考虑转录后调控

**⛔ 三条不可越界的推论**：
1. **可及性 ≠ 转录**：染色质开放是转录的**必要不充分**条件（还有 Pol II 起始/暂停释放、延伸、RNA 稳定性）
   ⇒ 只能说「该位点可及性被重塑」，不能说「该基因表达变了」。
2. **变化方向不可先验假定**：人骨骼肌耐力训练 ATAC 证据是往**闭合**走（PMID 40623475）⇒
   ⛔ 别预设「运动后应该变高」。
3. **基因边界 ≠ 在用的启动子**：上岗前先确认哪个 TSS 在目标组织里真用 —— 数转录本起点分布：

```bash
# 转录本起点分布（按链取 5′ 端；− 链取 end，+ 链取 start）——本例 MEF2C 56 个转录本成两簇
grep -P '\ttranscript\t.*gene_name "MEF2C";' $GTF \
  | awk -F'\t' '{if($7=="-") print $5; else print $4}' | sort -n | uniq -c
```

本例实测：MEF2C 的 TSS 成簇在 88,904,052–88,904,257（最靠外、紧贴重叠区右界）与
88,888,964–88,889,324 两处 ⇒ **「gene 行的端点」只是某条转录本的 5′ 端，不代表组织里在用的启动子**。
再叠加一步佐证：查区间内是否有运动响应 TF motif（MEF2 / MyoD / NFAT）。

## 3. 提交答案的形状（用户偏好）

- 先给**一句话结论**（「它是 MEF2C 的反义 lncRNA，同一基因座、反向重叠 ≈ 21 kb」），再上对照表。
- 表格用**实测字段**（biotype / 坐标 / 链 / ID / 注释来源），标清物种与版本（GRCh38 / GENCODE v32）。
- 参考来源逐条列出（Ensembl REST 查询式、NCBI Gene ID、UniProt、PMID），并**区分**「文件实测」
  与「API/文献」两类证据 —— 用户会分别追问这两层。
