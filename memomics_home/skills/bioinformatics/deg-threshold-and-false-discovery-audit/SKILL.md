# DEG 阈值与假发现审计

> 配套详证（源码 formals 原文、文献原句、PMID/DOI、Europe PMC 全文抽取配方）见
> `references/parameter-provenance-and-mast-thresholds.md`；
> 阈值敏感性网格（FDR × 效应量）完整配方与措辞红线见 `references/threshold-sensitivity-grid-recipe.md`。

## 触发场景

- 「阈值取 0.2 还是 0.25？」
- 「别人做 DEG 的时候要筛选阈值吗？他们怎么做？」
- 「为什么我的显著基因有 5–6 万个？」「新方法比老方法多几十倍，是不是更好？」
- 写 DEG 的 methods 段，需要给阈值找依据。
- 任何 `fdr<0.05` 命中率异常高 / 上下调方向比失衡的情况。
- 「做阈值敏感性」/「换个阈值结论还稳吗」/「不要重跑模型，基于上游全量表重计数」。
- 接手一张来历不明的「已过滤 / formatted / CLEAN」结果表，要确认其真实过滤口径时。

## 🔴 铁律 1：阈值必须能追到具体出处，否则明说「无出处」

写 methods 或汇报时，`|logFC|` 阈值只能有三种写法：

| 写法 | 何时可用 | 例子 |
|---|---|---|
| ✅ 上游工具默认值 | **首选**，最可追溯 | 「沿用 Seurat v4 `FindMarkers` 默认 `logfc.threshold = 0.25`」 |
| ✅ 明标自定的最小生物学意义效应 | 无先例时 | 「自定最小效应标准 \|log2FC\| > 0.25（≈1.19 倍变化），非引用文献值」 |
| ⛔ 「参考某某文献」 | **禁止** —— 除非真的逐字查到那篇写了这个数 | — |

**实测教训**：曾把 `0.25` 挂到某篇猴脑图谱论文名下，逐段核对全文后确认**那是该文 ATAC sDARE 的判据（`P<0.05` 且 `log2FC>0.25`）**，而该文 RNA DEG 段用的是 MAST + 样本随机效应、**代码里没有任何效应量阈值** —— 属张冠李戴，审稿人一查即破。**参数溯源必须逐段核原文，不能凭印象或摘要。** 完整更正记录见 `references/parameter-provenance-and-mast-thresholds.md`。

**已交付表的「情况反查」——集合等式法（2026-10-23 实测新增）**：接手来历不明的「已过滤」表（formatted / CLEAN / 筛选版）时，**不要凭文件名或注释推断口径**：

1. 粗定位：对 `fdr/fdr_D` × `coef/coef_D` × 阈值网格做组合扫描，找行数最接近的判据组合；
2. **铁证 = 双向集合等式**：交付表键集合 F 与候选判据集合 C 比对，要求 **C−F=0 且 F−C=0**（跨全部 sheet/对比逐一验证）——单看行数接近不算证据；
3. 实测案例（五对比示例组织）：文件名 `..._coef025` 的表实际口径是 `|coef|≥0.25`（"coef025"= 0.25，**不是** 0.025）；5 对比全部双向差集=0、数值 join max diff=0 才落槌；
4. **笔误修复必须全量重导出**：口径注释常散落在图内注、工作簿说明 sheet、结论文档、脚本 docstring 多处——逐处排查修正并重出全部产物，只改文档不算修完。

## 🔴 铁律 1.5：自造「质控阈值 / 可疑标记列」比自造效应量阈值更危险（2026-11-03 用户当场否决）

铁律 1 管的是「`|logFC|` 取多少」；本节管**另一类更容易翻车的东西**：分析脚本里自作主张加的
**判定阈值**与**标记列**。用户原话：

> 「你加这个的意义在哪里呢？**官方怎么没有呢**？你让我怎么跟合作方解释呢？」
> 「**全都去掉，你标记上可疑，说的结果是错的一样。**」

**三类东西，进代码前必须先过出处门（任一不满足 = 删）**：

| 类型 | 例子（本轮被删的四个） | 改结果吗 | 危险在哪 |
|---|---|---|---|
| ① **分析期筛除型** | `COR_CUT <- 0.70`：丢掉 `\|r(W,stim)\|≥0.7` 的 RUV 因子 | ✅ **会**（少几个协变量，模型变了） | 等于悄悄改了模型，methods 里一个字都没写 |
| ② **事后标记型** | `SIG_CUT <- 0.30` / `ONEDIR_CUT <- 0.95` → 新增 `qc_flag = SUSPECT` 列 | ❌ 不改数值 | **在交付表里宣判「这条我怀疑是错的」却不给处置** ⇒ 合作方必然追问，而你答不上 |
| ③ **隔离/搬运型** | `QUARANTINE <- TRUE` → 可疑表移入 `quarantine/` | ❌ 不改数值 | 用户找不到文件；而「移到另一个目录」本身就是一种结论 |

**出处门三问（缺一即删）**：
1. **参考实现里有吗？** 用户给的原始脚本逐行 grep —— 本轮猴脑 `Figure7 MBA PFC DEG Recalculation`
   四个全无（没有任何相关性筛选、显著率阈值、`qc_flag`、隔离目录，直接 `write.csv`）。
2. **官方文档/源码里有这个参数吗？** `Rscript -e 'args(RUVSeq::RUVr); args(MAST::zlm)'` 自己跑一眼。
3. **没有出处 → 要么删，要么明标「自定」并配敏感性分析**（有/无该规则两版结果的重叠率）。

⛔ **禁止**把自定阈值说成「标准做法 / 官方推荐」—— 那是铁律 1 的死罪，只是换了个对象。
⛔ **禁止**用「这是工程质控、不改数值」当免责理由：②③ 类确实不改任何 logFC/p，
但**改的是交付语义**；用户的判据是「标记可疑 = 说结果错了」。

**为什么官方没有**：RUV 的 k 与因子取舍，官方范式是**看图**（RLE boxplot、PCA、再加一个因子图变差就停），
落到代码里是**一个固定常数**（如猴脑 `nruv=10` 估、`uruv=5` 入模），**不是自动阈值**；
`zlm()` 只负责按给定设计拟合，显著基因再多也照样 exit 0，它不做结果可信度判断。
无人值守批跑时想自动化这个判断可以，但**必须标成自定工程规则**，不能混进方法学叙述。

**副产品纪律**：删阈值时必须连带删掉它产生的列/目录/变量（`qc_flag`、`sig_rate`、`up_frac`、
`w_dropped`、`qdir`、`Wdiag_*.csv`…），否则残留未定义变量。删除按「变换 + 唯一命中断言」做，
见 reference 里的手术式配方。

## 🔴 铁律 1.6：细胞级协变量 vs 样本级技术因子 = 层级重复，先查再放（2026-11-03 CDR 案例）

用户问「**CDR 真的有必要吗？它会不会跟 RUV 共线？**」——这是问到了真问题。**CDR 与 RUVr 的 W 因子不在同一层级**
（cdr 是逐细胞的，W 是逐样本的），所以**不能直接算相关系数**说共线；但它们在**同一个技术变异方向**上重复：

| 证据 | 内容 | 结论 |
|---|---|---|
| MAST vignette 原话（本机 4.4.2 包内 `.Rmd` 实查） | 「**cdr（每细胞检出基因数）经常是第一主成分**」 | cdr 载的正是技术主变异 |
| RUVr 的 W 因子 | 由 TMM+GLM 后的 deviance 残差估计，抓的是**样本级**技术主结构 | 同一方向的样本级版本 |
| 已发表参考实现（猴脑 `Figure7`） | 公式 `~ Age + subtype_new + W_1..W_5`，**逐行 grep 无 cdr** | 有 W 时不再加 cdr |
| Finak 2015 原文推荐 cdr 的场景 | 前提是模型里**没有其他技术协变量** | 已有 W ⇒ 前提不成立 |

**判据（按序执行）**：
1. 模型里是否已有估计型技术因子（W/PC/其他 data-driven 技术轴）？有 → **默认不加细胞级检测率类协变量**；
2. 用户/数据确需加 → 先跑诊断证明二者捕捉的技术变异不重叠（W 与每样本 cdr 均值的 |r|、加入前后 stim 系数变化）；
3. 任何情况下都**不要**为了「更严谨」在已有 W 的模型上叠 cdr——局部 SE 膨胀会让单基因结论不稳，且与参考实现不可比。

**同类可推广对象**：`nCount`/`nFeature`（细胞级）、percent.mt、细胞周期打分（细胞级）——凡「细胞级 + 反映测序深度/质量」
的协变量，在已有样本级技术因子的模型里都要先过这道门。

→ 完整实录（MAST vignette 原句、猴脑公式逐行核对、去 cdr 的手术式补丁、删完后的优缺点与三条必报局限）：
`references/celllevel-covariate-vs-ruv-factors.md`

## 🔴 铁律 1.8：两版脚本「结果会不会变」——用「参数未变的那批结果逐位相同」来归因（2026-11-03 实测）

用户问「我按 v2 跑过了，换 v8 结果会不会变」/「你跑个 v8 看看两者区别」时，**不要逐条解释代码 diff 了事**
——要把「我猜是 k」变成「我证明了是 k」。方法四步：

1. **两版都真跑**，产出落**不同目录 + 不同文件名后缀**（`Immune/`+`_sDEG.csv` vs `Immune_v8/`+`_v8.csv`）。
   ⛔ 后缀不换 = 断点续跑读旧表，以为跑了新版其实没跑。
2. **按 `(亚群 × 比较组)` 配对**，逐对算五个量：显著数、显著基因 **Jaccard**、共有显著基因**方向一致率**、
   全基因 **coef Spearman**、全基因 **−log10(p) Spearman**。
3. **决定性一步 —— 按「可疑参数是否变化」分组**：
   ```
   若 参数未变 子集 的 Jaccard=1.000 且 Spearman=1.000（逐位相同）
     ⇒ 该参数被证明是唯一驱动因素，其余改动对统计量零影响
   ```
   本轮：k 未变的 5/50 组合**结果完全一致** ⇒ 证明新增的混杂标记列/元数据列零影响，差异全归 k。
4. **再按第二个因素分层**，量化它的额外贡献（本轮 batch 入模与否：Jaccard 0.517 → 0.236，差异翻倍）。

**必须同时报告「表数量差」**：本轮 v8=50、v2=55。少掉的组合要逐个查日志给跳过原因
（本轮 5 个全是 v8 新增的 `df_resid ≤ 2` 守卫，v2 无此门用 k=1 硬拟合）。**不能默认当噪声**，
否则对比基数就是错的，读者会以为两版覆盖同一批组合。

**实测读数（Immune 19,934 细胞 / 17 亚群 / 5 对比，50 对可比）**：

| 指标 | 值 | 读法 |
|---|---|---|
| 显著基因合计 | v2 17,051 / v8 18,387 / 共有 14,934 | — |
| Jaccard 中位 | **0.4216** | 名单重排约一半 |
| 方向一致率中位 | **1.0000**（最低 0.9817） | **方向可靠、名单不稳** |
| coef Spearman 中位 | 0.6402 | 效应量相关但不等价 |
| k 变化的组合 | **45 / 50** | 几乎全变 |
| v2 k 实测范围 | **2–10**（`min(10, df-1)`） | 大亚群 8–10 → 易过校正 |
| v8 k 实测范围 | **2–5**（`min(10, max(2, ⌊df/3⌋))`） | **39/50 被压到 2** → 易欠校正 |

归因分层（本轮）：

| 分组 | n | Jaccard 中位 | coef Spearman |
|---|---|---|---|
| k 未变 | 5 | **1.000（逐位相同）** | 1.000 |
| k 变 + batch 未入模 | 22 | 0.5168 | 0.8656 |
| k 变 + batch 入模 | 23 | 0.2357 | 0.5238 |

压缩幅度与差异单调相关（v8 k/v2 k ≤0.3 → Jaccard 0.345；0.3–0.5 → 0.422；0.5–0.8 → 0.737）。

**结论措辞**：写成「方向几乎没变，名单换了一半」，并明确告知**旧版结论不能直接沿用**、
**两版都不是文献口径**（文献如猴脑是固定 `uruv=5`，v2 的 k=10 与 v8 的 k=2 都不是它）。

→ 完整实录与可复用脚本：`references/version-diff-attribution.md`、`scripts/compare_deg_version_dirs.py`

## 🔴 铁律 2：Seurat `FindMarkers` 默认值随版本变 —— 必须显式写死

| Seurat 版本 | 默认 `logfc.threshold` | 默认 `min.pct` | 证据 |
|---|---|---|---|
| v3 / v4 | **0.25** | 0.1 | **官方源码逐字** `raw.githubusercontent.com/satijalab/seurat/v4.3.0/R/differential_expression.R` 的 `FindMarkers.default` 形参（2026-10-27 复核）；另有论文 methods 实证 |
| v5 | **0.1** | 0.01 | **官方参考页 5.6.0** `satijalab.org/seurat/reference/findmarkers` + `main` 分支源码（2026-10-27 复核）；本机 5.5.0 `FindMarkers.default` formals 同值 |

- ⚠️ 脚本里不显式写 → **v4 得 0.25、v5 得 0.1，同一份数据换版本结论就变**（隐蔽的可复现性坑）。
- ⚠️ 「用 MAST 的论文」绝大多数不是直接调 MAST，而是 `FindMarkers(test.use="MAST")` —— 阈值实际来自 **Seurat 默认值**，不是 MAST。
- 单细胞领域流传的 `0.25` 的真实血统 = **Seurat v3/v4 出厂默认值**，这是它站得住的正确理由。

## 🔴 铁律 2.5：DESeq2 自己既不默认 0.05、也不筛效应量 —— 组间阈值全是惯例叠加

被问「|log2FC|≥0.5 有出处吗 / DESeq2 默认 padj 是多少」时，直接给这张官方源码表（`thelovelab/DESeq2` `R/results.R`，2026-10-27 复核）：

| 参数 | 官方默认 | 含义 |
|---|---|---|
| `alpha` | **0.1** | DESeq2 出厂 FDR 门槛是 **0.1，不是 0.05**；写 0.05 属**主动收紧**，methods 里必须写明 |
| `lfcThreshold` | **0** | 默认**不做任何效应量过滤**，`padj` 只答「是否非零差异」，不答「差异够不够大」 |
| `altHypothesis` | `greaterAbs` | 与 `lfcThreshold=0` 配套；要检验 `|log2FC|>θ`（而非事后筛表）须显式设 `lfcThreshold=θ` |

⇒ 结论口径：**0.5 不是任何软件的默认值**，是 pseudobulk 组间比较的领域惯例切点（KB 记为 `domain_convention`）；`0.25` 才是 Seurat v3/v4 出厂默认。两者都不是「方法学标准」，写 methods 时按铁律 1 的三档写法落地。

## 🔴 铁律 2.6：引用知识库参数前先读它的 `source:` / `confidence:`（2026-10-27 实测）

用户说「**查知识库**：XX 方向 DEG 常用阈值是什么，给结论和依据」时，**只抄数值 = 把种子默认值包装成文献实证**。参数条目（如 `knowledge_base/<species>/<tissue>/<direction>/03_测序方法/RNA/deg.yaml`）每个值都自带两列溯源，必须一起读：

| 层级 | 取值 | 该怎么用 |
|---|---|---|
| 文件级 `source:` | `default_seed` / `literature` / `data_driven` | `default_seed` ⇒ 只能说「惯例 / 种子默认」，⛔ 不能说「文献推荐 / 已实证」 |
| 字段级 `source:` | `default_value` / `domain_convention` / `data_driven` | 只有 `data_driven` 可当实测依据 |
| `confidence:` | `low` / `medium` / `high` | low/medium **必须连溯源类型一起报给用户**，不许单独抛数字 |

**实测样例**（`Homo_sapiens/skeletal_muscle/aging/03_测序方法/RNA/deg.yaml`）：`padj 0.05` 与 `logFC 0.5` 都是 `domain_convention` + `medium`、文件级 `default_seed`；**唯一** `data_driven` + `high` 的是 `min_detection_rate=0.1`。
⇒ 交付必须分层写：**哪些是实测、哪些只是惯例**，并补一句「该方向知识库当前无 DOI 级阈值实证条目」。另：想确认「某套口径有没有进库」时用 `search_files` 在该组织目录下 grep 参数名（本轮 `coef|0.25|logFC` 命中 0 文件 ⇒ 用户项目里的 `|coef|≥0.25` 并未入库，不能当作 KB 依据）。

## 🔴 铁律 4：论文写法是「事实惯例」不是「方法学共识」

Europe PMC 全文检索（`logfc.threshold` + `FindMarkers`）命中 1263 篇，抽样规律：

- `0` / `0.1` / `0.25` **三档并存**；
- **同一篇论文里经常两个并用**：marker 鉴定用 `0.25`（要漂亮），条件间 DEG 用 `0`（原文 "allowing all genes to be evaluated"，要全）；

⇒ 汇报时如实说「这是事实惯例」，不要包装成「方法学标准」。

## 🔬 假发现审计流程（显著基因数异常多时走这套）

**症状判据（先量化，别先调阈值）**：

| 指标 | 警戒线 | 含义 |
|---|---|---|
| `fdr<0.05` 占全部检验行比例 | **> 50%** 强警戒；**25–50% 已可疑** | 显著性由分母（SE）决定，不是由信号决定 |
| 反例校准：细胞级 `glmer` + RUV5（`n_cells` 中位 8,956，2026-10-23 实测） | **35.4%** 命中 | 低于 50% 线也不能放过：该表叠 `\|coef\|>0.25` 后只剩 **0.37%（246 / 66,806 行）** ⇒ 引用其计数必须带效应量阈值 |
| 上下调方向比 | **> 10 : 1** | 极端不对称本身是膨胀指纹，正常生物学不会这样 |
| 边界带（如 `0.20<\|coef\|≤0.25`）的 `fdr` 中位数 | 仍在 1e-16 ~ 1e-45 量级 | ⇒ **p 值区分不了阈值带与保留组**，卡在哪纯属人为划线 |
| θ 等价 z 值 | `θ / se中位` 达 **10–21** | 常规 p<0.05 只要 1.96 倍 SE ⇒ 阈值比统计门槛严 5–10 倍 |

**根因优先级（按顺序排查）**：

1. **没有建模 biological replicate** ← **最常见、最致命**
   细胞级测试（MAST hurdle / Wilcoxon / 各种单细胞专用方法）把每个细胞当独立观测 ⇒ SE 被严重低估、假阳性膨胀。
   **权威依据（该引这三篇，不是引阈值）**：
   - Squair et al. 2021 *Nat Commun* [PMID 34584091](https://pubmed.ncbi.nlm.nih.gov/34584091/) · DOI 10.1038/s41467-021-25960-2 —— 14 种方法对比，**pseudobulk 显著优于全部细胞级方法（含 MAST）**，细胞级方法偏向高表达基因；**把聚合步骤关掉、让 pseudobulk 方法跑单细胞 → 优势立即消失**（这就是机制证明）。
   - Crowell et al. 2020 *Nat Commun*（muscat）[PMID 33257685](https://pubmed.ncbi.nlm.nih.gov/33257685/) —— 原文直写 **"Since relying on thresholds alone is prone to bias"**。
   - Murphy & Skene 2022 *Nat Commun* [PMID 36550119](https://pubmed.ncbi.nlm.nih.gov/36550119/) —— pseudobulk 优于混合模型与伪重复做法。
   **处置**：加供体随机效应（`(1|individual)`）或改 pseudobulk；不是在阈值上加码。
2. **批次/混杂未校正** → 检查 design formula 是否含 batch。
3. **分组不平衡 >3:1** → 报告限制或配对设计。
4. 以上都排除后，才谈阈值。

**正对照校准法（决定阈值该切在哪）**：
取领域公认的真信号基因集（如示例组织衰老/运动：CDKN1A、GADD45G、FBXO32、MYOG、NR4A3、MYBPH、HSPB1、PPARGC1A、ULK1、TFEB、FOXO3 等），测每个候选 θ 下**已知真信号的召回率**。
实测教训：`θ=0.25` 在衰老组砍掉 **2/3 已知真信号** ⇒ 阈值定得越高不等于越严谨，可能是在砍真信号。
**推荐交付**：θ 敏感性曲线（x = 剩余基因数，y = 已知真信号召回率）比直接拍一个数可信得多。

## 🔬 阈值敏感性网格（FDR × 效应量两维）——「不要重跑模型」类请求的标准交付

触发：「做阈值敏感性」「换个阈值结论还稳吗」「这些数字换门槛会不会变」。**只重计数、不重跑模型**——上游全量表（如 `ALL_merged`）已含全部检验行的 `fdr/coef`。

**网格**：FDR {0.1, 0.05, 0.01, 0.001} × |coef| {0.05, 0.1, 0.15, 0.25, 0.4, 0.6, 1.0}（现行档必含）。四类输出：① 主表（各对比每格 rows / unique genes / up% / retention / top 亚群）② 亚群级明细 ③ **交集/共享结构稳定性表** ④ |coef| ECDF。图：4 面板（计数曲线 symlog / 方向比 / 共享结构 / ECDF），现行门槛画竖虚线。

**读数四模式（每次必报）**：
1. **FDR 维度常惰性**：细胞级 p 饱和时 FDR 0.001–0.1 变幅可 ≤1%（实测 340,971 行数据 ≤1.1%）→ 筛选力全在效应量门槛；**惰性 ≠「多重检验没问题」**（p 分布诊断仍待补）；
2. **断崖**：相邻档计数可跌 2–9×（实测 0.15→0.25）→ 一切计数数字引用必须带门槛；
3. **标签漂移**：Top 亚群与阈值强相关（实测 Aging：0.05→LRP1B+(I)、0.25→IIA、0.4→RSS）→「XX 亚群主导」须注明阈值命中区间；
4. **交集是阈值产物**：共享基因数可塌缩至 0（实测五对比共同基因 4,073→45→1→0）→ **写「核心基因」前必须先给 4–7 档阈值轨迹**，否则不写。

**措辞红线（L2 辩论裁定 · stats_design 场景）**：宽松阈值计数 = cell-level 探索性结果，不得写「存在大量小效应差异」（受 SE 低估/伪重复膨胀影响）；共享集合写「主阈值下未检出」不写「不存在」；方向比/排序跨阈值稳定 = 仅描述性一致性，不证明效应真实。完整配方见 `references/threshold-sensitivity-grid-recipe.md`。

## 产出规范

1. **同时给未过滤与过滤后两套计数**（reviewer 必问口径）；有第三档时一并给。
   实测交付形态（2026-10-23，细胞级 glmer 单对比表）：**三档并排** —— 主口径 `fdr<0.05 & |coef|>0.25` +
   仅 `fdr<0.05`（不加效应量门槛）+ 严格 `fdr<0.001 & |coef|>0.5`。三列同表，读者自己看到差距
   （本例：246 vs 23,640 vs 11），比单写一句「我们加了阈值」有说服力得多。
2. **跨 sheet 的累加关系必须脚本核验，禁止口算**：`ALL_merged` 型汇总 sheet 通常是各分组 sheet 的
   **行累加**（实测 10 亚群 `up=109 / down=137` 与 `ALL_merged` 完全同值；行数 66,806 亦精确相加相等）。
   把两条路径都写进脚本、用 pandas 各算一遍对照输出；**手算列序错位会得出「ALL ≠ 累加（137 vs 127）」的假结论**
   （本项目 2026-10-23 踩过并在交付中更正）。两个数一致 → 累加口径确认，可放心引用；不一致 → 先查聚合口径再引用。
2. 阈值表注明**计算口径**：过滤分母是「全部检验行」还是「FDR<0.05 集合」；是「基因 × 亚群」行数还是「去重基因数」——两者差异可达数倍。
3. 报告里写清：**阈值只减少假阳性、不消除假阳性**；若根因是 SE 低估，调阈值只是掩盖。
4. 判上下调**用 `coef` 符号派生新列**，不要用表里现成的常量说明列（那种列每张表只有一个值，逐行用会全错）。
5. 计数表落 CSV 用 `utf-8-sig`（Windows Excel 双击不乱码）；若要给图，图内文字一律**英文**
   （matplotlib 默认字体无 CJK 字形），中文进图注/表注/正文。

## Pitfalls

| 坑 | 规避 |
|---|---|
| 把某论文的 ATAC 阈值当 RNA DEG 阈值引用 | 逐段核原文模态（RNA/ATAC/Bulk）与段落位置 |
| 以为「用 MAST 的论文」的阈值来自 MAST | 它们走 Seurat `FindMarkers`，阈值来自 **Seurat 默认值** |
| 脚本不写 `logfc.threshold` | 显式写死并注明版本来源 |
| 只报过滤后计数 | 必须给两套（有余力给三档：主口径 / 仅 FDR / 严格） |
| 手算「ALL_merged vs 各分组累加」是否一致 | 写脚本双路径对照（行数与计数各算一遍）；手算列序错位会造出「两者不一致」的假结论，并据此误报口径差异 |
| `direction` 类常量列用来判逐行上下调 | 用 `coef` 符号派生 `regulation` 列 |
| `fdr` 列出现 0 | 是 float64 下溢（<1e-308），不是缺失；根源常是 SE 低估 |
| 凭文件名/注释推断已交付表的阈值（如 "coef025" 误读成 0.025） | 集合等式双向实证（C−F=0 且 F−C=0），跨全部 sheet 逐一验证 |
| 口径注释笔误只改一处 | 图内注/工作簿/docstring/结论文档全量排查 + 全部产物重导出 |
| 报告共享/核心基因不附阈值轨迹 | 先给 4–7 档阈值下的计数曲线；塌缩到 0 的不得称「核心」 |
| FDR 维度不敏感 → 断言多重检验没问题 | 惰性只说明筛选力在效应量；p 分布诊断才能判多重检验 |
| 把知识库里 `source: default_seed` 的数值当「文献推荐阈值」交付 | 先读文件级 `source` + 字段级 `source`/`confidence`，按铁律 2.6 分层报；默认种子 ≠ 实证 |
| 以为「DESeq2 默认就是 padj<0.05」 | 官方 `results()` 默认 `alpha=0.1`；写 0.05 要自报为主动收紧 |
| 以为「|log2FC|≥0.5 是 DESeq2 默认」 | `lfcThreshold` 默认 0，不做效应量过滤；0.5 是惯例切点（铁律 2.5） |
| 用户项目里跑过的口径（如 `\|coef\|≥0.25`）当成本专业 KB 记录 | 在该组织 KB 目录 grep 参数名确认是否入库；未入库就明说「非 KB 依据」 |
| **自己**往脚本里加判定阈值/标记列（`COR_CUT`/`qc_flag=SUSPECT`/`quarantine/`） | 先过铁律 1.5 出处门：参考实现与官方文档都没有 → 删。标记列等于替合作方宣判结果有误 |
| 复现他人流程时只对齐「能跑通」，不对齐「参数与判据」 | 逐项 diff：k 怎么定（估 10 用 5 还是残差预算）、p 值来源（Hurdle LRT vs Wald）、协变量集合；差异列给用户拍板 |
| 删阈值后只删常量、忘了连带产出的列/目录 | 连带清理 `qc_flag`/`sig_rate`/`up_frac`/`w_dropped`/`qdir`/`Wdiag_*`，并做禁用词残留扫描 |
| 已有 RUV/技术因子还叠 CDR（或 nCount/nFeature/percent.mt 等细胞级深度类协变量） | 层级重复：cdr 载第一主成分、W 载样本级技术主结构。默认不加；要加先出诊断（铁律 1.6） |
| 搜 `library/<pkg>/R/` 找函数默认值或无命中就断言「官方没提」 | R 包 `R/` 是 lazy-load 二进制库，文本 grep 必然失败；搜 `doc/`、`vignettes/`（`.Rmd`/`.html`）或跑 `args()`/`formals()` |
| 长脚本（>500 行）在对话里贴第二次时手抄出错 | 以磁盘文件为唯一交付源；贴完声明「以文件为准，勿从对话复制投集群」。`parse()` 只抓语法错，抓不到 `sig - dn_col` 这类语义笔误 |
| 输出后缀不跟着版本换（`_v6` 保持不变） | 断点续跑（文件存在即跳过）会复用旧结果 ⇒ 以为跑了新版其实读旧表。删/改模型必换后缀 |
| 命名向量查表做标签映射：`md$type <- unname(type_map[as.character(md$type)])` | 未登记的取值**直接变 NA**，报错只剩一个 `NA` 看不出原值 ⇒ 四个分片同时崩。改 `ifelse(raw %in% names(type_map), unname(type_map[raw]), raw)`（等价 `dplyr::recode` 语义），并**先 `cat` 打印 raw 唯一值再映射** |
| 用「严格校验」当兜底却不打印中间量 | v2 用 `recode`（保留原值）能跑、v8 用查表（变 NA）崩，同一个对象两种结果 ⇒ 报错信息必须带原始取值，否则无法诊断 |
| 只对比结果、不对比两版产出的表数量 | 本轮 55 vs 50；少掉的 5 个是 `df_resid ≤ 2` 守卫跳过。不交代就以为两版覆盖相同组合，对比基数错 |
| 声称「两版差异来自某参数」却拿不出隔离证据 | 找「该参数未变」的子集：若其 Jaccard=1.000/Spearman=1.000（逐位相同），才算证明（铁律 1.8） |
