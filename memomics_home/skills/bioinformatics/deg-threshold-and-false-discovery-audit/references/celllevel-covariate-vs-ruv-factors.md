# 细胞级协变量 vs 样本级技术因子：CDR 与 RUV W 因子的层级重复（2026-11-03 实录）

> 场景：细胞级 snRNA-seq DEG，模型 `~ stim + W_1..W_k [+ batch] [+ (1|individual)]` 已含 RUVr 技术因子，
> 是否还要加 MAST 推荐的 cdr（cellular detection rate）？
> 用户最终裁决：**去掉 cdr**。本文记录证据链、判据、删除手术与删完后的诚实代价。

---

## 1. 用户的原话与判据

> 「CDR 真的有必要吗？它会不会跟 ruv 的共线吧，所以不应该添加 CDR 才对。」
> 「去掉 CDR，然后给我最新版的代码。然后解释这个代码最终定格在哪里，有哪些缺点，有哪些优点。」

用户的推理是「共线 ⇒ 不该加」。**注意：用户的结论正确，但机制描述需要修正**——不是共线（两者不在同一层级，
无法直接算相关），而是**同一技术变异方向上的层级重复**。回答时应先肯定结论、再修正机制，
不要顺着错误机制解释（会被后续追问拆穿）。

## 3. 判据（可复用）

```
模型里是否已有 data-driven 技术因子（RUV W / surrogate variable / 技术 PC）？
├─ 是 → 默认不加细胞级检测率类协变量（cdr / nCount / nFeature / percent.mt / 细胞周期打分）
│       └─ 若数据方坚持要加 → 先出诊断：W 与「每样本 cdr 均值」的相关、加/不加两版 stim 系数对比
└─ 否 → 按 MAST 官方建议加 cdr（此时它是唯一的技术协变量）
```

理由：cdr 与 W 都在解释「测序深度/文库复杂度」，叠加后
① 方差被两个高度相关的量分摊 → 单个系数的 SE 膨胀 → 单基因结论不稳；
② 与已发表参考实现不可比（人家没有）；
③ 过度校正风险：活化的 T 细胞 RNA 含量本就高于 naive，cdr 会把这部分真实生物学差异当技术噪声扣掉。

## 4. 删除手术（v7 → v8，8 处断言式补丁）

用 Python 脚本做「唯一命中断言 + 禁用词残留扫描」的批量替换，比逐次 patch 更不容易漏：

| # | 位置 | 改动 |
|---|---|---|
| 1 | 文件头标题 | `v6` → `v8` |
| 2 | 文件头设计口径 | 删 `cdr` 行，改为「✗ cdr 已彻底移除（v8）」+ 三条理由 |
| 3 | 文件头 | 新增「模型（三种形态）」与「已知局限」两段 |
| 4 | 用法注释 | `v6` → `v8` |
| 5 | `outdir` | `Immune_v6` → `Immune_v8` |
| 6 | 配置区 | 删 `USE_CDR <- TRUE` |
| 7 | 文件名 | `_v6.csv` → `_v8.csv` |
| 8 | 7.9 节 | 删 `cdr <- log10(colSums(mat>0)+1)`、公式里的 `+ cdr`、`covmat$cdr <- ...` |
| 9 | 7.11 节 | 删溯源列 `main$cdr_used` |

**必做的两步校验**（都要做，缺一不可）：
1. **禁用词残留扫描**：`USE_CDR / cdr 计算 / cdr_used / _v6` 逐行扫描，0 残留才算过
   （文件头解释性文字里的 `cdr` 允许，但计算与列名不允许）；
2. **R 静态解析**：`Rscript -e "e <- parse('xxx.R'); cat('PARSE_OK', length(e))"`
   —— 删变量最典型的翻车是留下悬空引用，`parse()` 能抓到语法级问题
   （语义级悬空引用如 `sig - up` 被误改成 `sig - dn_col` 抓不到，见 §6 教训）。

**输出后缀必须换**（`_v6` → `_v8`）：本脚本用「文件存在即跳过」做断点续跑，后缀不变会直接复用旧结果，
导致「以为跑了新版其实读的是旧表」。

## 5. 删掉 cdr 之后的诚实代价（必须主动声明，不要藏）

| 代价 | 说明 |
|---|---|
| 细胞级测序深度不再显式校正 | 仅靠 TMM（样本级）+ W（样本级）间接吸收；深度差异大的亚群可能有残留 |
| 与「加了 cdr 的版本」结果必然不同 | 同一基因的 coef/p 会变，尤其低检出基因 |
| 若审稿人问「为什么不用 MAST 推荐的 cdr」 | 答：已有 RUVr 技术因子，cdr 会与之重叠；且与所复现的参考实现口径一致 |

**推荐话术（可直接转发合作方）**：
> 「本研究采用 RUVr 估计样本级技术因子（W）作为技术变异校正。MAST 建议的 cdr 反映每细胞检出基因数、
> 主要作用于测序深度这一方向，与本模型中的 W 存在层级重复，故未纳入；这与所复现的参考实现
> （`Age + subtype_new + W_1..W_5`）口径一致，便于横向比较。」

## 6. 本次会话的额外教训（交付层面）

1. **在对话里贴超长代码会被输出上限截断**：609 行脚本贴到一半被切，第二轮续贴时**手抄出错了一行**
   （`sig - up` 被写成 `sig - dn_col <- NULL`）。
   → 正确做法：**长脚本以磁盘文件为准交付**（给绝对路径 + 关键段落），或在贴完后立刻声明
   「以磁盘文件为准，请勿从对话复制后直投集群」；续贴时只贴「从某节之后」，不要重头再来。
2. **删除类改动一律先 grep 定位再动手**：`search_files(pattern, path=<文件路径>, target='content')`
   传文件路径曾返回 0 命中，改用 `grep -n` 直查才定位到 17 处；先确认文件存在（大小/时间戳）再排查检索方式。
3. **用户要「优缺点」时按「定稿口径表 + 优点清单 + 缺点严重度表」三段给**：
   缺点表必须有「严重度 / 现状（已接受·无法解决·可缓解）/ 处置」三列，
   不要用「但是我们需要谨慎解读」这类模糊措辞代替具体后果。
4. **参考实现的差异要主动列全**，不要只说「我们对齐了」：
   本次仍存三项差异（k 定法 / Hurdle LRT vs Wald / 协变量集合），其中
   **p 值来源差异对基因列表的影响远大于删 cdr**，必须让用户自己拍板。
