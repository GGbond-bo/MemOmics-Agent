# matplotlib 改图验收：标注几何 + 墨迹级证据（2026-09-30 实测）

场景：改一版已存在的图（加标注 / 挪箭头 / 换配色），必须证明「该改的改了、不该改的没动」。
本文对应一次真修 bug：DEG 8 亚群柱图 Σ 计数行的箭头消失 + 左右编码不一致。

---

## 1. ⛔ 小箭头别用字体字形，用矢量 `FancyArrowPatch`

实测 Arial 同字号墨宽：`←`(U+2190) / `→`(U+2192) = **31 px**，`↑`/`↓` = **13 px**（宽 2.4 倍）。
水平箭头在「数字与中心线之间 ~11 px」的窄间隙里塞不下；更糟的是**光栅层可能完全不出墨**：
SVG 里字符与坐标都对、`arial.ttf` 里 glyph 312/314 确实存在、独立探针渲染 `←→` 也正常，
但整图 PNG 里那一格是**空白** → 用户打开图看到「箭头消失」。

**判定陷阱**：`fc-list` 有字体 / `FT2Font.get_char_index` 有字形 / SVG 里有字符 **≠ 渲染出墨**。
唯一可信判据是**像素墨迹**（§3）。⛔ 别用「字形存在」当渲染证据。

```python
from matplotlib.patches import FancyArrowPatch
fig.add_artist(FancyArrowPatch((x, y0), (x, y1), transform=fig.transFigure,
                               arrowstyle="-|>", mutation_scale=3.8, lw=0.85,
                               color=c, shrinkA=0, shrinkB=0, zorder=6))
```

- 方向 = 起点 → 终点（`↑`: y0<y1；`↓`: y0>y1；横竖同一套，不换字形）
- `mutation_scale` 控头部尺寸（3.5–4 适合 6–7 pt 正文旁的小箭头），**尺寸按 pt 走**，与画布缩放解耦

## 2. 贴到「某文字的下一个位置」→ 先量 bbox（renderer 实测，不估算）

```python
t = fig.text(x, y, s, ha="right", va="center", fontsize=6.6, ...)
fig.canvas.draw()                                    # Agg 后端：先 draw 才有 renderer
bb = (t.get_window_extent(renderer=fig.canvas.get_renderer())
        .transformed(fig.transFigure.inverted()))
x_next = bb.x1 + gap        # 文字右缘 + 间隙（fig 比例坐标）
```

- 同一 figure 内：**先建好全部文字 → 统一 `fig.canvas.draw()` 一次 → 批量放箭头**
  （省一次渲染；也避免 draw 期间量到半成品）。保存用 `fig.savefig` 会重新渲染全部元素。
- 文字 bbox 与字号 / 字体 / **matplotlib 版本**相关 → 换解释器量出来的值就变了（见 §3）。

## 3. ⛔ 同解释器重渲染：否则逐像素差分骗你

本机并存 `.venv` 持久内核（matplotlib **3.10.9**）与系统 Python312（**3.11.0**）。
同脚本、同字体（都解析到 arial.ttf），仅换解释器：

| 渲染器 | 与上一版逐像素差分 |
|---|---|
| `.venv` 持久内核（原图就是它渲染的） | **13,320 px，全部落在被改的那一行带** ✅ |
| 系统 Python312 | **111,449 px 散布全画布**（柱区 33,277、底部 41,022）❌ |

后果：第二种会被误读成「版式也变了」，把「只改一行」的结论带反。
**规则：改图重渲染一律走会话持久内核**（`execute_python` 里 `exec(open(脚本).read())`），
禁止 `terminal python xx.py` 冷启动；做前后差分时两边**必须是同一解释器**。
（同族：本 skill 坑表「内核解释器 ≠ environment.json 声明」「python-docx 只在共享库」诸行 —— 选错解释器是本机头号系统性坑。）

## 4. 墨迹级判据（"看着像"不算）

| 要验的事 | 判据 |
|---|---|
| 元素是否真的画出来 | 该窗口内有对应颜色墨迹；**矢量箭头用竖向 run 长度**区分：箭头 run≈33 px vs 同字号数字字高≈26 px（6.6 pt @400 dpi） |
| 颜色/元素是否越界 | 颜色掩码 x 极值 vs 中心线：如「蓝墨 max < 中心线 < 红墨 min」 |
| 箭头朝向 | 箭头列窗口内逐行墨宽 profile，**最宽行**（三角底边）在上半→`↑`，下半→`↓` |
| 改动是否只影响目标行 | 与上一版逐像素差分，报**差分像素的行分布**（应全部落在目标行带内） |

颜色掩码示例（避开深色 ink `#2B2B2B`、品牌色 `#3D3B4F`/`#0F5F6E`）：

```python
red  = (R > 120) & (G < 90) & (B < 90)      # #B2182B
blue = (B > 120) & (R < 90)                 # #2166AC
```

现成探针：`scripts/figure_ink_probe.py`（判据 1–3 一次打印 + PASS/FAIL + 退出码）。

## 5. 诊断预算：一轮搞定，不要连打微探针

为了查「箭头该有墨却没有」，我连跑了字形度量 → SVG 解析 → ASCII 墨迹点阵 → Arial 墨宽实测
等多轮微诊断，**两度触发系统循环检测强干预**（「判定为循环失控…若产物已生成直接视为完成」）。

- ✅ **渲染 + 全部判据写进同一个 `execute_python` 调用**，一次打印表格化结果
- ✅ 多个假设**并联验**（同一调用内依次算），不是一个假设一次调用
- ✅ 只保留「能改变下一步动作」的探针；已知结论不重复验
- ⛔ 一轮里不要既渲染又反复 micro-check 同一件事；被干预后照它说的收尾（给结论 + 产物路径），
  若**下一步交付件还没生成**，直接去生成（生成 ≠ 重复验证）

## 6. 编码一致性自检（本会话被用户抓到的真 bug）

图元有**空间编码**（柱子向中心线左/右伸），文字有**阅读顺序**（先 Up 后 Down）——
两套必须同序，否则用户一眼看出「红色数值怎么在左边」（原话）。

- 定稿前一句话自检：**「左→右读出来的字符串」与「柱子左→右伸出的语义」是否同序**
- 顺带查**文字与箭头的左右不能交叉越界**（上一版 `↓`/`↑` 都跨过了中心线，正是原始缺陷）
- 本项目口径：`蓝(Down) 在左 | 红(Up) 在右`，箭头竖直 `↑/↓` 且**紧跟各自数字右侧** → `380 ↓ | 16,535 ↑`

## 7. 口径歧义 → 一次渲染两个变体，不要猜一次赌一轮

用户对版式的自然语言可能二义（如「箭头在右侧」= 数字右侧 还是 中心线右侧）。
脚本留**注入式开关**，内核里 exec 两次出两个 stem，两个都渲染好再交给用户挑：

```python
STEM_OVERRIDE = globals().get("STEM_OVERRIDE")
MF_VARIANT    = globals().get("MF_VARIANT", "right")     # right | center
# 内核里：
for v, s in [("right", "fig_v7a_arrows_right_of_number"), ("center", "fig_v7b_arrows_at_center")]:
    MF_VARIANT, STEM_OVERRIDE = v, s
    exec(open(SCRIPT, encoding="utf-8").read())
```
