# ask_user 意图门禁（硬阻断）——实测记录与规避

## 一、机制

调用 `ask_user` 后，系统为该会话置「意图未确认」标记。此后**所有执行 / 产物类工具**一律被拦：

```
⛔ 意图还没确认，先别执行：你已经用 ask_user 问了用户「<问题摘要>」，但用户还没回答（或还没提交勾选）。
现在必须做的：结束本回合等用户答复。不要再尝试调用 terminal 或任何执行/产物工具。
解除方式：① 用户在确认弹窗里勾选并提交；② 用户直接在输入框回复（也算答复）；③ 30 分钟内无人答复则门禁自动失效。
```

受影响工具（实测）：`terminal`、`write_file`、`execute_r`、`execute_python`、`rail_review`、`skill_evolution`
（即任何写盘 / 跑代码 / 留档的动作）。

**仍可用的只读工具**：`read_file`、`search_files`、`skill_view`、`session_memory`、`todo`。

## 二、真实代价（为什么要当"重武器"用）

- 门禁期间若撞上**系统唤醒轮**（`[系统唤醒]`、LoopX 自动续跑、"检查主线任务进度"），该轮**同样跑不动**：
  只能做只读核对，**产出为零**。一次多余弹窗 = 一整个工作轮停摆。
- 实测事故：用户明确说「**你自己分类好**，做第二版图」——已把分类决定权授予 Agent。
  Agent 仍回弹一个 Q1（分到哪个轴）/ Q2（要不要连 IIa 一起加）的确认弹窗 →
  门禁生效 → 后续 `terminal`（读数据列名）被拦、`head -1 *.csv` 被拦 →
  该轮只产出"待确认"汇报，图一张没出。用户视角：说了"你自己定"却被反问。
- 门禁生效时**不要换工具试探绕过**（`execute_code` 之类的替代路径同样被拦，且记一次违规）。

## 三、规避铁律（按优先级）

1. **用户已把决定权交给你时，禁止再回弹窗确认。**
   触发语：「你自己分类好 / 你自己定 / 你看着办 / 随便 / 按你的来 / 你觉得呢 / 不用问我」。
   → 视为**明确授权**：直接决定并执行；在回复里用一行说明"我这样分类，若不同意可推翻"，
   **不要拿它换一轮等待**。把已授权的决定回弹回去，既违反指令又白扔一轮。
2. `ask_user` 只留给**真正无法自行判断且有代价**的歧义：
   - 不可逆操作（覆盖 / 删除既有产物）
   - 要花钱或占集群 / GPU 资源
   - 方案分支会显著返工（改错方向要重跑几小时）
   - 缺少必需输入（数据路径 / 物种 / 组织 / 分组 / 输出形式）
3. 确实要问 → **只问一个**可一键勾选的问题，选项收敛到 2-4 个。
   禁止 Q1/Q2/Q3 连环问——每多一问多一轮停摆。
4. 已经被问过、门禁还没解除 → 不重复追问。正确动作是**结束本回合**，回复里给出
   三段式：① 当前状态（未开工 / 卡在等你确认）② 本轮已核实的事实（只读所得）
   ③ 待你确认的那**一项**（用户一次点击即可解除）。
5. 高代价任务开工前的意图确认（SOUL 铁律 27/28）应**合并成一次**提问完成，
   不要在执行中途再补问——中途补问 = 中途停摆。

## 四、与"只读探查要批量"的关系

门禁带来的空转轮往往源于**跨轮重复同类扫描**。正确姿势：
- 同一主题的只读探查集中在**同一轮**并行发完（`read_file` / `search_files` 可同轮并行）；
- 跨轮重发相似扫描会被系统循环检测判为「循环失控·强制干预」，注入打断消息并强制结束本轮。
- 因此：先把该读的读完（脚本头部 + 数据列名 + 产物清单 = 一轮搞定），再决定是否开口问。
