# Sankey / Alluvial 节点布局与标签几何（实测：2026-10-01，三组共同 DEG 桑基图 UP/DOWN）

适用：matplotlib 手绘桑基图 / 冲积图（两轴节点 + 连线带），以及任何「节点高度按权重、标签放节点中心」
的自定义布局。用户对版式的判据非常直接——**标签必须落在自己那条色块的中心；列标题不许压住最顶端
节点的文字**——所以这两项要做成**可测量的硬指标**，不能靠肉眼。

## 1. 最贵的坑：间隙按「权重数值」缩放 ⇒ 节点高度为负 ⇒ 色块互相重叠

**错误写法**（把总权重当成比例系数）：

```python
GAP  = 0.022
gap  = GAP * tot / (n - 1)      # tot = 该列权重总和（如 102），n = 节点数（如 10）
usable = 1.0 - gap * (n - 1)    # = 1.0 - 0.022*102 = -1.244  ← 负数！
```

`tot` 是**权重之和**（几十到几百），不是比例。实测 UP 图 `tot=102, n=10` ⇒ 间隙总和 2.244 ≫ 可用高度
1.0 ⇒ `usable = -1.244` ⇒ **每个节点高度为负** ⇒ 相邻节点区间互相重叠：

| 节点 | 区间（display 坐标） | 与下一个重叠 |
|---|---|---|
| ITIH4 (22) | [1.00, 1.27] | 与 MEF2C-AS1 叠 0.14 |
| MEF2C-AS1 (20) | [0.89, 1.14] | 与 PALLD 叠 |
| PALLD (17) | [0.78, 1.01] | … |

后画的色块盖住前一个的下半截，**而标签仍画在真实中心**（`(y0+y1)/2`）⇒ 顶部 3 个基因的标签
「掉」到自己色块下面 ⇒ 用户看到的就是「**标签没有跟自己的色块对齐**」。

实测像素偏差（UP 图）：ITIH4 **72 px**、MEF2C-AS1 **53 px**、PALLD **27 px**；下面 4 个基因因未重叠
而完全对齐 —— 这正是「越靠顶越明显、只在 up 图被发现」的原因。**DOWN 图 `tot=24` 侥幸没算出负值
（usable=0.472），所以完全正常**。

**正确写法**（间隙是整列的固定比例，与权重解耦）：

```python
GAP_RATIO = 0.10                       # 整列留 10% 给间隙
gap    = GAP_RATIO / (n - 1)           # 与 tot 完全无关
usable = 1.0 - GAP_RATIO               # = 0.90，永远为正
# 节点高度 = usable * 该节点权重 / tot，按顺序累加 gap
```

> 🔑 判据：**只要表达式里出现「总权重 × 某比例」再与 1.0 相减，就先心算量级**（`GAP*tot` 是否 > 1）。
> 纯算术自查，不依赖画图经验。

## 2. 列标题压住顶端节点（用户第一次纠正）

现象：右轴权重最大的基因节点伸得最高，列标题 `Shared up genes (Up, n=7)` 与 `ITIH4 (22)` 文字框
交叠 11–23 px（OCR 实测：标题中心 y=289、顶端标签中心 y=399，仅 110 px；左轴因首个节点小反而有 189 px）。

修法（两处联动，保持左右标题同行对齐）：

```python
ax.text(x, 1.32, "Subcluster")            # 列标题 y：1.21 → 1.32
ax.text(x, 1.32, "Shared up genes (Up, n=7)")
ax.set_ylim(0, 1.44)                      # 画布上沿：1.34 → 1.44
```

实测：标题 ↔ 顶端基因间距 **110 px → 177 px（+61%）**，标题 ↔ 主标题仍留 193 px；Down 图同类间距 453 px。

> ⚠️ **只有权重最大的那一列会挤** —— 别因左轴正常就判定「没问题」。修完两轴都要测。

## 3. 把两项做成脚本内置的几何自检（下次不靠肉眼）

出图末尾直接量 renderer 坐标并打印，**出图即出证据**：

```python
fig.canvas.draw()
r = fig.canvas.get_renderer()

def bbox_px(txt):
    bb = txt.get_window_extent(renderer=r)
    return bb.y0, bb.y1                       # display 坐标自下而上

# ① 标签必须落在自己色块中心（偏差单位 px）
for i, (lbl, (y0, y1)) in enumerate(zip(ax.texts, node_spans)):
    cy = (y0 + y1) / 2.0 * ax.bbox.height + ax.bbox.y0     # 节点中心 → display
    t0, t1 = bbox_px(lbl)
    print(f"label {i}: dev={abs((t0 + t1) / 2.0 - cy):.2f}px")

# ② 相邻节点不得重叠（用真实区间，不是显示区间）
print("node overlaps:", sum(1 for a, b in zip(node_spans, node_spans[1:]) if a[1] > b[0]))

# ③ 列标题与顶端节点标签的间距
print("title↔top-node:", bbox_px(title_txt)[0] - bbox_px(top_label_txt)[1], "px")
```

目标值：**标签↔色块中心偏差 0.00 px、相邻节点重叠 0 对、标题↔顶端节点 177/453 px**。

⚠️ `Text.get_window_extent()` 返回的 `Bbox` **没有 `get_center()` 方法**（会 `AttributeError`）——
用 `(bb.y0 + bb.y1)/2` 或 `bb.get_points().mean(axis=0)`。
⚠️ display 坐标**自下而上**：标题在上方时 `b0 - t1` 为负，别把符号写反（把「无重叠」打印成负数，
会让人误判「还要再挪一次」）。

## 4. 同一次任务里一并修掉的其它版式项

| 项 | 做法 |
|---|---|
| 脚注被图例挤同一行（OCR 混读成一串乱码 @2035） | 脚注改用 **figure 坐标锚底**（`fig.text(0.5, 0.044/0.016, ...)`），别用 axes 坐标跟着图例走 |
| 链路宽度语义 | 写进图注：「宽度 = 被几个对比共同支持（1/2/3，图例标注）」，**不是效应量** |
| 交付前健康检查 | PNG 非空白判据用**颜色数**（`len(im.getcolors(maxcolors=2_000_000)) <= 1` ⇒ blank），文件大小只作辅助 |

## 5. 复用清单（下次画桑基图直接照做）

1. 间隙固定比例（`GAP_RATIO/(n-1)`），**绝不与权重相乘**；写完先心算 `tot` 量级。
2. 标签 y = 节点真实中心 `(y0+y1)/2`；**节点区间不重叠是前提**（先修布局，再怀疑标签）。
3. 列标题与 ylim 上沿**联动抬高**，左右两轴都测间距。
4. 脚本内置三项几何自检，跑完把三个数写进汇报。
5. 🔑 用户说「标签没对齐」时 —— **先量几何、再查布局公式，不要直接去挪标签位置**
   （本次根因 100% 在 `layout()`）。改图只 patch 对应常量，别重写整个脚本。
