# session_memory 锚点与「系统注入警告」的实测坑（2026-10-08）

## 坑 A：锚点必须存**完整路径**，否则每轮误报「路径不存在」

**现象**：会话每轮被注入一条
`⚠️ 以下要求中的路径不存在，请向用户核实是否已更新/作废："E:\文献\AI\Closed-loop transfer enables a(E:\文献\AI\Closed-loop 不存在)`
——注意那串被截断的字符串（结尾带省略号/半个括号）。

**根因**：不是文件没了，而是**锚点当初被截断存进去**——
`session_memory(add, kind="path", content="E:/文献/AI/Closed-loop")` 只存了路径前缀。
系统把它当"已知资产"注入并与磁盘比对，必然失败 ⇒ **每轮一条噪声**，
更糟的是**未来会话会真的以为该 PDF 不存在**，进而重新下载或误报给用户。

**实测对照**（同一会话）：

| 动作 | 结果 |
|---|---|
| `ls "E:/文献/AI/"` | PDF **存在**，24,214,769 B，10月2日 01:10；同目录另有 `agent/` 子目录 |
| 系统注入的警告 | 声称该路径「不存在」——**警告字符串自己就是被截断的** |

### 规避三条

1. **add 一律存完整绝对路径 + 文件名**。⛔ 不要存显示用的短名/省略形式；
   同一文件既已有路径锚点，就不要再单独存一个截断版本。
2. **见到「资产/要求路径不存在」先实测再表态**：`ls "<完整路径>"` 或 `os.path.exists(...)`。
   实测存在 ⇒ 正确动作是**修锚点**（`remove` 旧条目 + `add` 完整路径条目），
   ⛔ 不是改数据、也不是拿一条假警告去追问用户。
   判据：**系统注入的资产警告是"声明"，不是"事实"**（与「回执是声明、磁盘是事实」同族）。
3. 🔴 **`session_memory(action="remove")` 的 `content` 要给完整原文字符串**——给片段会**静默失败**：

```
remove(content="📌🔬 竞品定位交付定稿(2026-10-07 20:36 终版)")   → {"ok": true, "removed": 0}
remove(content="<该条完整正文，含尾部被截断的 'L'>")             → {"ok": true, "removed": 1}
```

⇒ 先 `session_memory(action="list")` 取回完整 `content` 再删；
**看到 `removed: 0` 就是没删掉**，不要当成成功。

## 坑 B：锚点会过期，且没有 replace

`session_memory` 只有 `add` / `list` / `remove`，**没有 replace**。
阶段结论被新一轮推翻时（本次实测：旧锚点仍写「16 张首轮 10-02 + 15 张 10-07 深读升级」，
而 store 里 31 张已全部升级为深读卡、其中 16 张是 round2）——
**留着旧锚点 = 下一轮的你按过期口径干活**。

处置：`remove`（完整原文）+ `add`（新结论）两步；新结论里带上**可核对的数字**
（卡数 / 文件字节数 / 校验通过率），便于下一轮直接比对是否又过期。

## 坑 C：锚点数量会缓慢膨胀

本次一个会话累计 48 条锚点，其中大量是**同一文件的重复登记**（`figures/*.png` 逐个条目）。
新增锚点前先 `list` 看一眼有没有同义条目；文件类锚点**一条目录 + 少数点名文件**比逐文件登记更耐用。
