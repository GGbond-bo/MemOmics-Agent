# ☁️ DCS Cloud / GenPilot 云平台操作手册

> 一句话：用户的数据或算力在**华大 DCS Cloud（www.dcs.cloud，含 GenPilot）**上时，用 `dcs_cloud` 工具
> 去看/取/传云上的东西，或者把活交给云平台跑。**MemOmics 只是中介 —— 真正干活的是云平台**（GenPilot 智能分析
> 与离线任务都跑在云上同一套 OpenSandbox 容器里），所以**动手前必须把项目、数据、参数、输出、费用问清楚**。

**阅读顺序**：`🔒 铁律` → `🚦 触发场景` → `✅ 开工前确认协议（重点）` → `🧭 项目定位` → `🛠 配方` → `⚠️ 坑表`。

---

## 🔒 铁律（不许违背）

1. **不问清不动手**：项目 / 数据位置 / 任务或流程与参数 / 输出位置 / 费用，五项确认完才执行（对齐铁律 27、28、35）。
2. **绝不替用户默认项目**：用户有**很多**项目（实测某账号 12 个、其中 3 个欠费）。当前项目只是**候选**。
   只有两种情况可以直接用当前项目：① 用户明说「就用当前项目」；② `config.yaml` 的 `dcs_cloud.default_project` 已配置且用户同意。
   其余一律列出候选让他选。
3. **不索要密码、不索要 PAT 文本**：PAT 由用户自己在 DCS 个人中心 → 访问令牌 创建，再在 MemOmics「☁️ DCS 云」面板粘贴绑定。
   工具报未绑定 → 引导去面板，别让他贴给你。
4. **写操作先确认**：`upload` / `container_open` / 投递任务（analysis run、workflow submit）/ 切项目，都改云端数据或产生费用 → 先说清再动。
5. **欠费先充值**：`projects[].is_arrears = true` 的项目，投递会被平台拦；先告诉用户充值，别硬试。
6. **三套文件系统不互通**：云上 Files = `/Files/...`；云容器内 = `/work/...`；本机 = `E:/...`。路径写错必失败 —— **先 `ls` 确认再动**。
7. **证据口径**：报结果时给「工具动作 + 关键字段 + 云上路径/任务 ID」，不要口头断言。

## 🚦 触发场景（精准）

**该触发**（用户话里出现这些 → 先 `skill_view("dcs-cloud")`，再按确认协议走）：

| 用户怎么说 | 实际要做的事 |
|---|---|
| 「云平台 / DCS / DCS 云 / genpilot / 华大云」 | 认云平台上下文，问清要干什么 |
| 「在云上跑分析」「云上跑一下」「投递任务」「提交流程」 | 投递/执行 → 必须走确认协议 |
| 「云上那份数据」「云上的文件」「把结果传到云上」「从云上下载」 | 浏览/传输 → 先 ls 定位 |
| 「云容器」「开个容器」「在容器里跑」 | container_open → exec → close |
| 「云上任务」「任务日志」「跑完没有」 | tasks / task_logs |

**不该触发**（别把活往云上推）：本机能跑的小分析、只在本机数据上做的常规分析 —— 除非用户明确说「上云 / 用云平台算」。
用户只是问「DCS 是什么」→ 直接回答，不用动手。

## ✅ 开工前确认协议（重点 · 用户要的 grill 流程）

**第 0 步：取上下文（只读）**
```
dcs_cloud(action="context")     # 一次拿到：当前用户/当前项目/候选项目(含欠费旗标)/数据根/默认下载目录/写开关
```

**第 1 步：一次问清（不要挤牙膏）** 用 `ask_user`，`kind="intent"`，把候选做成选项：

```json
{
  "kind": "intent",
  "header": "云平台开工确认",
  "question": "这次在云平台上跑，用哪个项目？（当前项目是 P25Z10200N1075，只是候选）",
  "options": [
    {"label": "P25Z10200N1075 · FSHD 骨骼肌时空图谱", "desc": "当前项目 · BGI-时空 · 有失败任务", "recommended": true},
    {"label": "P24Z10200N1046 · 唐氏综合症/老年痴呆", "desc": "BGI-时空"},
    {"label": "P25Z10200N1110 · 运动干预骨骼肌衰老", "desc": "⚠️ 欠费：投递会被拦，需先充值"}
  ]
}
```

**五个必问项**（缺一不可，能合并就合并成 1–2 个弹窗）：

1. **项目**：候选来自 `context.projects`（标出当前项与欠费项）。
2. **数据在哪**：本机路径 / 云上 `/Files/...` / 容器内 `/work/...`。用户说不出路径 → 用 `dcs_cloud(action="find", name="*.csv")` 或 `ls` 给候选让他挑。
3. **跑什么**：分析类型或流程名 + 关键参数（分组、物种、参考基因组…）。用户没说清 → 按铁律 28 继续问，不要自己填。
4. **结果回哪**：云上输出目录（默认 `/Files/...`）或下载到本机哪个目录（`context.download_dir` 是默认值）。
5. **费用**：是否有欠费项目参与；开容器/投递会产生费用 → 让用户勾「确认计费」。

**第 2 步：用户确认后才执行**。执行顺序照 `🛠 配方`；执行中被平台拦（业务码）→ 翻译成人话再反馈。

## 🧭 项目定位（回答「是不是用当前项目？」）

- 「帮我在云平台跑分析」= 信息不足 → **先问三件事**：哪个项目、数据在哪、跑什么。别默认当前项目。
- 「用户有很多项目」是常态 → 把 `context.projects` 全部当候选列出（超过 5 个按当前/最近使用优先，其余加「其他（填 ID）」）。
- 切项目有后果：**切换后云容器会话失效**（要 `container_close` → 重开），所以切之前说清是给谁切的。
- 只有用户说「当前项目就行」时直接 `use_project`（或什么都不做，CLI 当前项目即目标）。

## 🛠 配方

**A. 把云上数据拿到本机**
```
dcs_cloud(action="context")                                # 看默认下载目录
dcs_cloud(action="ls", path="/Files/Muscle", long=True)    # 定位文件（点/选出来）
dcs_cloud(action="download", path="/Files/Muscle/x.csv", target="E:/MemOmics-Agent/results/dcs", type="web")
```
> 小文件 `web`（下载 ≤200MB，且不支持文件夹/FastQ/BAM）；大文件用 `raw` 换 `oss`/`raysync`。

**B. 云上算（容器）**
```
dcs_cloud(action="container_open")                         # 等 3–5 秒（否则报 83007）
dcs_cloud(action="container_exec", command="ls -lh /work") # 容器内命令
dcs_cloud(action="container_close")                        # 用完必关，别占资源
```

**C. 看离线任务 / 日志**
```
dcs_cloud(action="tasks", page_size=20)                    # 列表（含创建人/时间/统计）
dcs_cloud(action="task_logs", task_id="2105195089460039681")
```

**D. 投递任务（高代价 · 必须先确认）**
```
# 1) 先确认协议五问 → 用户勾确认
# 2) 走白名单逃生舱（参数确认后才用）：
dcs_cloud(action="raw", command="analysis ls -p 1 --page-size 20")   # 看可用分析
dcs_cloud(action="raw", command="workflow ls -p 1")                   # 看流程
# 3) 投递：把用户确认过的参数原样拼进命令；跑完用 tasks/task_logs 盯
```
> 投递前再确认一次：**项目 / 输入数据路径 / 参数 / 输出目录 / 费用**。含糊就去问，不要猜。

## ⚠️ 坑表

| 现象 | 原因 | 处置 |
|---|---|---|
| 业务码 83003 | 没选项目 | 先 `projects` → `use_project` |
| 业务码 83006 / 83007 | 容器没开 / 刚开还没就绪 | 先 `container_open`；83007 等 3–5 秒重试 |
| 业务码 41201 / 60003 | PAT 失效/未登录/被删 | 让用户去面板重新绑定（不要索取 PAT 文本） |
| 切项目后容器命令失败 | 容器会话绑定项目 | `container_close` → 重开 |
| upload 大文件失败 | web 通道上限（≤100MB） | 用 `raw` 换 `oss` |
| 找不到文件 | 路径口径混了（/Files vs /work vs 本机） | 先 `ls` 各根目录确认 |

## 🔗 与既有铁律的关系

- 铁律 27（方案前 grill-me 拷问）+ 28（需求含糊先问）→ 本技能的第 0/1 步就是它在云平台场景的落地。
- 铁律 35（高代价任务弹意图确认表单）→ 投递任务 / 开容器 / 上传时**必须**弹 `ask_user(kind="intent")`。
- 用户在弹窗里勾选确认过之后 = 需求已确认，不必再问一遍（但参数变了要重问）。
