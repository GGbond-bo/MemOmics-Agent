## Part A　补绘独立图件（素材包缺图 / 一图两号需拆开时）

触发：图号有图件无（题注自注「不另附图／以文字描述」）；或一张素材图被两个图号共用，需要拆。

### A1 先决定：去号 还是 补绘

| 判据 | 选择 |
|---|---|
| 内容 3 句话 + 一张表就能说清，读者不需要视觉骨架 | **去号**（删图号与题注，流程写成编号步骤）—— 零成本 |
| 流程类：≥4 步、有分支/循环、带参数或阈值，且正文已有对应数字来源 | **补绘** |

实测（2026-09-16）：图 2.2「统一同源元件网格的构建流程」5 步、图 2.3「物种内年龄效应量的计算与聚合流程」4 步
→ 都选补绘，因为两节正文本身就是分步叙述，配图能直接印证数字链。

### A2 风格必须与既有图件一致，否则一眼看出是后补的

动手前**先读素材包既有图件脚本或上一张自绘图件脚本**，抄参数，不要另起一套审美：

- 本项目素材包附图全部为**灰度**：浅灰底框 `#EBEBEB`、黑边 `linewidth=1.3`、黑字、
  圆形步骤徽标（`#404040` 底 + 白字）、`font.sans-serif = ["SimHei"]`
- `figsize` 宽 7.2 in、300 dpi、入稿宽 14.5 cm（渲染脚本里 `add_picture(..., width=Cm(14.5))`）
- 图内**标题**措辞与文档**图题**适度区分（图内是短语，图题是完整题名），沿用既有图件版式

### A3 公式与希腊字母一律走 mathtext，不要塞进中文字符串

- ❌ `"Z = sign(r) × Φ⁻¹(1 − p/2)"` —— SimHei 没有 `Φ⁻¹` `z̄` `√` 这些字形，会渲染成**缺字方框**，
  matplotlib 会在 stderr 报 `Glyph ... missing from font(s) SimHei`
- ✅ 数学段用 mathtext，中英混排同串即可：
  ```python
  plt.rcParams["mathtext.fontset"] = "dejavusans"     # matplotlib 自带数学字体，必有字形
  r"$Z=\mathrm{sign}(r)\times\Phi^{-1}(1-p/2)$"
  r"$Z_{\mathrm{agg}}=\sum Z_i/\sqrt{n}$"      r"$\bar{z}=Z/\sqrt{n}$"
  r"式中 $\Phi^{-1}$ 为标准正态分布的逆累积分布函数"      # 中英混排
  ```
- 出图后**必须搜一次 stderr**：`missing from font` 出现即缺字，回去改 mathtext。
  （`font weight bold` 回落是另一回事：SimHei 无粗体，matplotlib 回落 regular，与既有图件一致，可忽略）

### A4 裁切/溢出必须**测量**，不要采信读图工具 —— 本手册最重要的一条

`vision_describe` 的 OCR 会把相邻文本块**合并成一个检测框**再截断显示，从而报「文字被裁掉」。
实测两张新图都报底栏截断，**都是假象**。

正解：用 matplotlib 量文本实际渲染宽度，与框内可用宽度比：

```python
t = ax.text(0, 50, 文本, fontsize=fs)
bb = t.get_window_extent(renderer=fig.canvas.get_renderer()); t.remove()
# x 单位 → px：x/100 * fig_w_px ；框内可用宽 = (X1-X0)/100*fig_w_px - 2*内边距
```

实测：最长一行 **1088 px** vs 框内可用 **1710 px** → FIT。全部文本逐条量过再下结论。

⚠️ 读图工具仍要用，但只用它的**内容清单**（文字/数字是否都在、有无错字），
**不要用它的「截断/缺失」结论**去改图。

### A5 导出与登记（漏任一步＝白干）

1. 导出**三格式**：`png`（入稿，dpi=300）+ `pdf` / `svg`（矢量，便于排版复核）
2. 母本入稿三行，顺序不能错（行序即版式）：
   ```
   ![图X.Y　完整图题](figures/xxx.png)
   **图X.Y　完整图题**
   图注：…（可含图内呈现的阈值/分位数，便于正文呼应）
   ```
3. **插图清单新增一行**（图号 | 图题 | 页码）
4. **正文补叙述式引用**（「…如图X.Y 所示」）—— 有图件但正文从不引，同样是不一致（铁律 9f）
5. 重跑渲染脚本出 DOCX，断言 `word/media/` 张数 == 图号数

### A6 出图后自检断言（一次跑完）

```python
print("size:", im.size, "→ 入稿宽 14.5cm 时高 %.2f cm" % (14.5*im.size[1]/im.size[0]))
print("非白像素占比: %.1f%%" % (100.0*(np.asarray(im.convert("L"))<250).mean()))
```

- 文本宽度**全部 FIT**（逐条量，见 A4）
- stderr **无** `missing from font`
- 非白像素占比与既有图件同量级（本项目 ~60%，过低＝几乎空白）
- 入稿后：**图号数 == 图件文件数 == 插图清单行数**（三方 1:1）

## Part B　页码实排，与「本机没有渲染器」时的诚实协议

### B1 先查渲染器，别默认有 Word

```python
import win32com.client as w
try:
    app = w.Dispatch("Word.Application"); print("Word COM OK:", app.Name, app.Version); app.Quit()
except Exception as e:
    print("Word COM 不可用:", e)
```

同时查 `soffice` / `pandoc` / `docx2pdf`。三者皆无 → **拿不到 Word 真实分页**。
🔴 此时**禁止声称「已按实排复核」**。用户要的是「页码准」，拿不到就得如实说拿不到。

### B2 版心实算模型（可复跑 → `scripts/estimate_thesis_pagination.py`）

- 版心 = A4 21×29.7 cm − 页边距（本项目上 2.7 / 下 2.5 / 左 3.0 / 右 2.5）→ **15.5 × 24.5 cm**（439.4 × 694.5 pt）
- **行高基准从 docx 自己读，不要猜**：`w:sectPr/w:docGrid@w:linePitch`（twip，/20 = pt；本项目 `360` → **18.0 pt/行**），
  再乘段落 `line_spacing`（本项目生成器默认 1.5）
- 逐段折算行数：CJK 字符宽 = 字号；ASCII = 0.5 × 字号；其他 = 0.75 × 字号；行数 = `ceil(文本宽 / 版心宽)`
- 图片段：按实际像素高宽比 × 入稿宽（14.5 cm）计高；`wp:extent@cy`（EMU /12700 = pt）可直接读
- 表格：逐行取各单元格折算行数的**最大值** × 行高 + 少量行内边距
- 必须计入：分节符（每章另起页）、显式分页符（`w:br w:type="page"`）、`keep_with_next`（图与图题同页）
- ⚠️ `document.body` 的直接子节点里，**末尾的 `w:sectPr` 不是段落**——按 `w:p` / `w:tbl` 分类遍历，
  否则 `'CT_SectPr' object has no attribute 'r_lst'`

**分量拆解必须报出来**（否则无法判断模型是否合理）。本项目实测：

| 分量 | 实算 |
|---|---|
| 纯文字 | 53 264 字 → 1 433 行 → 48.3 页 |
| 图片 11 张 | 4.6 页 |
| 表格 42 个 / 305 行 | 20.0 页 |
| **含分页浪费合计** | **≈ 92 页** |

### B3 不确定度必须显式声明（否则等于造一个假数字）

行距口径不同，结果差很多：`line_spacing=1.5` × 单倍行高（15.6 pt 经验值）↔ docGrid 18 pt，
本项目给出 **75–105 页**区间、单点 92 页。因此交付话术固定为：

> 「按版心实算的**估算值**（±N 页），**不是** Word 实测；终稿请在 Word 里 Ctrl+A → F9 后据实校对。」

- 文档内「页码为版面示意，Word 生成后须更新域并据实校对」的提示句**保留，不要删**
- 用户要精确值 → 请他把 Word 里的实际页数发回，按实排重排；或先把清单页码改成「待定」，
  **避免估算值被当成实测值**（这一条比给错数字重要）

### B4 页码坏值的廉价探针（不需要渲染器）

| 探针 | 判据 | 实测 |
|---|---|---|
| **单调性** | 目录/清单页码必须按出现顺序**单调不减** | 旧静态页码 `表2.2 = 23` 早于 `表2.4 = 17` → 一眼判坏 |
| **表序倒置** | 与「图序倒置」同源，表号须按正文出现顺序 | `表3.3`（p38）出现在 `表3.2`（p42）之前 |
| **跨度异常** | 某章页码跨度远超其内容页数 = 数字串位 | 目录里第 2 章从 17 页跳到 33 页 |

⚠️ 这三条是**在任何渲染器下都能跑**的探针，出稿前跑一遍成本极低、收益极高。

## 实测案例（2026-09-16，吉大硕士论文）

1. **补绘两张图**：图 2.2（5 步流程，配表 3.1 收敛数字 26 501→16 160→16 029）、
   图 2.3（4 步 + 判定阈值 |Z_human| ≥ 12 + 实测背景分布分位 3.37 / 6.69 / 11.32 / 24.69）。
   两图 OCR 均报底栏「截断」，用 A4 方法实测均 **FIT** → 判定为识别框合并假象，未做无谓改动。
2. **页码**：旧静态页码合计 61 页（且内部非单调，判坏）→ 实算分量 48.3 + 4.6 + 20.0 页、
   含分页浪费 ≈ 92 页，区间 75–105 页。明确标注为估算值并请用户在 Word 中 F9 校准。
3. **顺带查出**：图 3.4 / 3.6 / 3.7 有图件、进了插图清单，但**正文从未引用**（只出现在附录表格与图注里）
   → 属于铁律 9f 的不一致，需补叙述式引用。
