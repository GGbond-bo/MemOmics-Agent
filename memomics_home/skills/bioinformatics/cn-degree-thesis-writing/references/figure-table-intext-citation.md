# 图表正文引用写法与「假夹注」排查手册

> 配套 `cn-degree-thesis-writing` 铁律 8。触发场景：用户说"正文图引用格式不对""按学校要求改"，
> 或交付后用户质疑"稿里怎么有 `[图 3.2 三柱分布]` 这种东西"。来源：2026-09-16 吉大硕士论文实修。

## 1. 写法对照（中文学校规范惯例）

| 位置 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 正文引图 | `技术路线分为五个步骤，如图 1.1 所示：` / `……，如图 2.1、表 2.3 所示。` | `……（图 1.1）：` |
| 正文引表 | `扫描结果概况如表 3.4 所示` / `结果均不显著（如表 4.2 所示）。` | `（表 4.2）` |
| 多图表同引 | `（如图 3.3、图 3.4 所示）` | `（图 3.3、图 3.4）` |
| 图题 / 表题 | `**图 3.2　完整图题**`（图**下方**、表**上方**，黑体居中，序号与题名**空一个汉字**） | 简称、缺空格 |
| 图片 alt（母本） | `![图 3.2　L1 序列保守评分与 L3 年龄效应量的实测分布](figures/x.png)` | `![图 3.2 三柱分布](figures/x.png)` |
| 图注内互引 | `本图与图 3.7 采用完全相同的统计量…`（图注允许） | — |

**为什么**：方括号夹注 / 括注是英文期刊排版习惯；中文校内规范要求把引用写进句型。
表格清单（插图和附表清单）、图注、表格单元格内的"计算输入见图 X.Y"这类**说明性**提及可保留，不必强行改。

## 2. `[图 3.2 三柱分布]` 到底是怎么冒出来的

Markdown 图片语法是 `![alt](src)`。当**图片渲染失败**时（路径失效、看的是 `.md` 母本、或在结果面板里预览），
渲染器会把 `alt` 原样显示，形如 `[alt]` —— 于是母本里的

```markdown
![图 3.2 三柱分布](figures/v21_fig4_distributions_bw.png)
```

在用户屏幕上就变成了正文里的一句 **`[图 3.2 三柱分布]`**。用户看到方括号夹注来质问，是**对的**。

⚠️ 关键认知：**这类质疑往往不是 DOCX 的问题**。DOCX 里图件是嵌入对象，正文只有"图 3.2　完整图题"这行题注。
先自证 DOCX，再动母本 alt —— 否则会去改一个不存在的问题。

## 3. 排查顺序（先自证，再改）

1. **证明 DOCX 里究竟有没有** → 解 zip 取 `word/*.xml`，**剥标签后**正则（见 §4）。
2. DOCX 命中 0 处 → 问题在母本 alt 文本 → 把 alt 改成**完整图题**（§5）。
3. 两处都改完 → **重新跑渲染脚本出 DOCX**（只改 md 不重渲染 = 改了没生效，用户会再问一次）。

## 4. DOCX 正文文本核查（去标签是必须的）

```python
import re, zipfile, glob
zp = r"<论文.docx>"
z = zipfile.ZipFile(zp)
raw = z.read("word/document.xml").decode("utf-8")
t = re.sub(r"<[^>]+>", "", re.sub(r"</w:p>", "\n", raw))   # 先按段落断行，再剥标签
print("方括号夹注:", len(re.findall(r"\[图[^]]*\]", t)), "| CellBender:", t.count("CellBender"))

# 查"某词是否出现在全稿"要扫 word/ 下全部 xml（页眉/页脚/脚注/图片替换文字都不在 document.xml）
for n in z.namelist():
    if n.startswith("word/") and n.endswith(".xml"):
        s = z.read(n).decode("utf-8", "ignore")
        if "关键词" in s: print(n, "命中")
```

⚠️ **不要直接 `grep` DOCX 内部 XML 里的连续字符串**：Word 会把一句话拆进多个 `<w:r>/<w:t>`，
`grep -o "CellBender" word/document.xml` 可能报 0 处，而正文其实有。**必须先剥标签**再匹配。
⚠️ 只读 `document.xml` 会漏页眉/页脚/脚注/文本框（分别在 `header*.xml` / `footer*.xml` / `footnotes.xml`）。

## 5. 母本批量修复

**alt 文本（机械改写，图题就近配对）**：在同一分片内建 `图号 → **图 X.Y　完整图题**` 映射，再改写 `![…](src)` 的 alt。

**正文括注式（逐句判断，走原子落盘脚本）**：用 `(file, old, new)` 三元组 + `count(old)==0 → sys.exit(1)` 断言
一次落盘，禁止逐条手改（见 `citation-reference-table-audit.md` §5）。实测 6 处：
`（图 1.1）：`→`，如图 1.1 所示：`、`（图 2.1、表 2.3）`→`，如图 2.1、表 2.3 所示`、
`（图 3.3、图 3.4）`→`（如图 3.3、图 3.4 所示）`、`（表 3.6）看`→`看（如表 3.6 所示）`、
`（表 4.2）`→`（如表 4.2 所示）`、`（图 3.3 中格内数字…）`→`（如图 3.3 所示，格内数字…）`。

改完复跑探针：`python check_intext_citations.py <论文目录> --docx <论文.docx>` 应报 0 问题。

## 6. 用户质疑"稿里有 X"时的处置协议（陈旧版本 / 读错文件）

用户读的可能是**上一版**（尤其在我方刚重生成之后），或看的是 `.md` 母本 / 结果面板预览而非 DOCX。

1. **先在当前产物上实查**（§4 脚本），**不要盲改** —— 盲改会删掉本已正确的内容或制造重复。
2. 结果 0 处 → 回："该问题在 <上一版> 已修，全稿复查 0 处；你打开的可能是我改前的稿"，
   并给出**最新文件绝对路径 + 修改时间 + 大小**（用户能据此确认自己打开的是哪一个）。
3. 结果有 → 按规则改，改完**重渲染**并复验，再汇报。

**实测（2026-09-16）**：用户同轮提出两处——① "ATAC 哪来的 CellBender?没有的事情"：该条目（旧 `[54]`）上一轮已替换为
猴侧 ATAC 真实用到的建库试剂盒条目（MGI DNBelab C 系列，货号 1000021878），当前 DOCX 为 **0 处**；
② "图引用是 `[图 3.2 三柱分布]` 方括号夹注（13 处）"：DOCX 内 **0 处**，真身是母本的 **10 处**图片 alt 文本。
两处都属"用户看到的是旧稿/母本预览"，正确的回应是**自证 + 定位 + 修母本 alt**，而不是去 DOCX 里找不存在的夹注。

## 7. 顺带核查项（同一轮一起做掉，避免用户再提）

- **表格引用**同样按`如表 X.Y 所示`叙述式扫一遍（`（表 X.Y）` 是最常被漏的一半）。
- **工具/试剂的文献表条目**是否与本研究 assay 匹配（如 ATAC 研究里不该出现 RNA 去污染工具）——见铁律 7d。
- **图号连续性**：插图清单 / 附表清单 / 正文 / 题注四处编号必须一致，无跳号。
