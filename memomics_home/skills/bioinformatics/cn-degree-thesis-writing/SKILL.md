# 中文学位论文撰写与格式合规

服务对象：在校研究生。核心矛盾不是"写得好不好"，而是**写出来的东西必须逐条对上学校规范**——
规范里全是硬指标（字体字号、页码分段、页眉内容、图表题位置、著录格式、页边距、装订），错一条就是形式审查不过。

## 0. 铁律（用户明确要求，2026-09-16）

1. 🔴 **不擅自开写**。用户说"先读资料、等我让你撰写再撰写"时，只做「读规范 + 整理标注 + 报备」，
   绝不动笔写正文章节。撰写权在用户手里，一句"开始撰写"才开工。
2. 🔴 **只改指定清单项**。修订轮次里用户说"已经没问题的就不要动了"= 零润色零重构；
   顺手发现的问题单列出来问用户，不直接改。
3. 🔴 **规范原文优先于记忆**。学校规范按年份改版（吉大现行 2023 年 3 月版），
   每轮先读原件确认版本，别凭上次的印象写。
4. 交付物放 `results/<sid>/results/`，抽取的原文放 `data/`，脚本放 `scripts/`（项目目录铁律）。
5. 🔴 **不臆造，【待填】显式标注**。凡属"只有作者本人/培养单位才知道"的信息（学号、分类号、导师姓名与职称、
   专业名称、答辩日期、致谢里的人名、成果表的作者位次与卷期页、专利号/申请号），一律写成 **【待填】** 并附一句
   填写要求，**绝不代填、绝不编造**；交付时**附一份「待填项清单」**（分组 / 项 / 填写要求 / 来源提示）。
   ——用户原话："要求按照真实内容填写…不要有幻觉"。
6. 🔴 **交付后必跑自洽性自审**。稿子写完必须对**已成稿章节**跑一遍「数字与引文自洽性审计」
   （数字重算 / 计数对账 / 引文-论断对齐 / 原文核对）。原因：**数字自相矛盾与引文张冠李戴是审稿人最先抓、
   杀伤力最大的一类错**，且它们在"自己写的稿子"里几乎必然出现（2026-09-16 实测：一次审计击破 2 处硬伤，
   属"论文自己的数据推翻了论文自己的结论"级别）。执行手册 →
   `references/manuscript-consistency-audit.md`
7. 🔴 **文献表必须与正文双向对齐，著录信息必须双源核验**（2026-09-16）。
   (a) **抽样或简易正则都不算数**——必须跑一次全量核查：抽文献表全部 `[n]` 定义行，扫正文全部引用
   （含区间 `[28-31]`／逗号 `[9,16,17]`／连排 `[35][36]`），双向报出「孤立文献」「超范围引用」「缺号」。
   脚本 → `scripts/audit_citations.py`；方法 → `references/citation-reference-table-audit.md`。
   ⚠️ 核查必须带**数值区间假阳性过滤**：方括号内任一分量 > 文献表最大编号 → 判为数值区间（如目标区间
   `[30, 500]`），不是引用。不加此过滤会数出幻影命中并凭空报"超范围引用"。
   (b) **卷、期、页一律不得采信用户粘贴或记忆**：用 **Crossref + Europe PMC 双源**核验后再著录；
   与用户所给不一致 → **以实证为准，并主动回报这处出入**（实测：用户给 `38(18)`，双源均为 `38(19)`）。
   (c) 处置孤立文献**不得为凑对齐硬塞引用**：正文有该事物→首次出现处补号；全文+**原始素材包**零提及→
   删条目并顺延编号；对比文件 D1–D5 与文献号两套并存→表首列并列 `D1 [35]`。零提及判定前必须实查素材包，
   若真实流程做过该步骤（只是正文没写），应**补写步骤并保留引用**，吃不准就问用户。
   (d) **孤立文献还要查「主题相关性」，不只看「有没有被引」。** 每条孤立条目都必须能回答"本文哪一步用到它"，
   答不上来 = 模板残留 → 删条目并顺延其后编号。实测（2026-09-16）：ATAC-only 论文的文献表里躺着 `CellBender`
   ——它是**来源论文 snRNA 分支**用的去环境 RNA 工具，与本文 assay 毫无关系。用户原话：
   "ATAC哪来的 cellbender? 没有的事情"。审稿人同样会抓这种"工具与研究类型不匹配"的残留。
   ⚠️ 替换这类条目时优先补**真实用到的东西**（如猴侧 ATAC 建库试剂盒 + 货号），而不是直接留空。
   (e) **取不到出处的声明不要编，去它该在的地方取**。实测（2026-09-16）：新颖性声明的「检索式 + 检索日期」
   需要落进正文，用户告知\"CNIPA 那 5 件的检索是你另一个会话做的\" → 检索式原文就在那一会话的交付件里
   （`检索记录与对比文件_vN.docx` 的「（二）检索式」节），日期用产物**文件 mtime** 作证据
   （公开文本落盘 2026-09-13 22:37–22:39、逐件权利要求比对 2026-09-14），**不是**问用户重述、也不是凭印象写。
   通用做法：凡\"某步骤是别处/别的会话做的\"这类归因，先去对应产物取证（文件时间戳 + 文内注记），
   取不到就如实说取不到；同时**标注该原文是否为「建议式」**（实测 v17 里那份检索式标注为\"（建议）\"，
   即交给代理师用的建议稿）——口径不符要问用户，别默认它就是实际执行的那版。

8. 🔴 **图表一律用叙述式引用：「如图 X.Y 所示」/「如表 X.Y 所示」**（2026-09-16 用户要求）。
   正文**不得**用 `（图 3.2、图 3.4）` 这类括注式，更不得出现 `[图 3.2 三柱分布]` 这种方括号夹注
   —— 括注是英文期刊习惯，中文校内规范/惯例要写进句型（`……，如图 1.1 所示：`、`结果如表 3.4 所示`、
   多图同引 `（如图 3.3、图 3.4 所示）`）。
   ⚠️ **方括号夹注的真正来源是 Markdown 图片 alt 文本**：母本写 `![图 3.2 三柱分布](figures/x.png)`，
   图片渲染失败（路径失效，或用户看的是 `.md` 母本／结果面板预览而非 DOCX）时会显示成 `[图 3.2 三柱分布]`，
   用户会当成正文夹注来质问。规则：**alt 文本写成完整图题**（`![图 3.2　L1 序列保守评分与 L3 年龄效应量的实测分布](…)`），
   正文引用另用叙述式。诊断／批量修复 → `references/figure-table-intext-citation.md`；
   只诊断不改的探针 → `scripts/check_intext_citations.py`。

9. 🔴 **图号与图件文件必须一一对应，且图号必须按正文出现顺序**（2026-09-16 用户追问「为什么图2.1和3.1会是一张图？」）。
   (a) **一个图号 = 一个图件文件**。当「需要真图的图号数 > 实际图件数」时，**绝不允许拿同一张 PNG 顶两个图号**
   ——要么删掉冗余图号（正文改引已有的那个图号），要么为缺口重绘一张独立图件；**改图题掩盖不算修复**。
   实测：母本 10 个需真图的图号（图 1.1、2.1、3.1–3.8；图 2.2/2.3 是文字+表格标「不另附图」）只有 9 张素材图，
   `v21_fig2_pillar_funnel_bw.png` 被同时挂成「图 2.1 三层证据框架」与「图 3.1 三层证据的逐级收缩」。
   诱因：素材图本身含两个视觉元素（该专利附图同时画了「三支柱」与「漏斗」），最容易被两边同时引用。
   (b) **图号按出现顺序连续编号**。同一次实测里还出现图序倒置：图 3.1 落在图 3.2/3.3/3.4 **之后**。
   (c) 出稿前跑 `scripts/check_figure_numbering.py`（重复图件／图序倒置／图号空洞三类探针）；
   修完必须**同步五处**：插图清单、目录页码、正文全部交叉引用、图注、图片 alt —— 缺一处即不一致。
   手册 → `references/figure-numbering-and-inventory.md`（含**路线 A 执行配方**：原子脚本 + 断言 + 三项自检 + 替换顺序两坑）。
   (d) **有图号必须有图件**。题注自注「不另附图／以文字描述」而正文又写「如图 X.Y 所示」= 读者找不到图，
   审稿人必问。两条路：**去号**（删图号与题注，流程写成步骤，零成本）或**补绘**（真实数字的独立图件）。
   插图清单**只列有图件的图号**；清点后若「正文图号数 > 图件数」即为缺口。
   (e) **插图清单/附表清单的页码列是静态数字**，图表一增删就会偏。
   🔴 **先查渲染器，再决定怎么说**：`win32com` 起 `Word.Application`、再查 `soffice`/`pandoc`。
   三者皆无 → **拿不到 Word 真实分页，禁止声称\"已按实排复核\"**（宁可说做不了）。
   此时按**版心实算**给估算值（脚本 `scripts/estimate_thesis_pagination.py`；行高基准读 docx 自身的
   `w:sectPr/w:docGrid@w:linePitch`，不要猜），**必须报分量拆解与不确定度区间**，交付话术固定为
   「按版心实算的**估算值**，不是 Word 实测；终稿请在 Word 中 Ctrl+A → F9 后据实校对」。
   用户要精确值 → 请他回传 Word 实际页数、或先把清单页码改成「待定」，**别让估算值冒充实测值**。
   执行手册 → `references/thesis-figure-authoring-and-pagination.md` Part B。
   (f) **每个图号必须在正文被引用**（叙述式，见铁律 8）。\"有图件 + 进了插图清单\"还不够——
   实测（2026-09-16）：图 3.4 / 3.6 / 3.7 有图件、有清单行，但**正文从未引用**，只出现在附录表格与图注里，
   同样是不一致（清点时\"正文被引图号\"应等于图号全集）。补引用只需在对应段落挂一句\"……如图X.Y 所示\"。
   (g) **表序同样须按出现顺序**（与图序倒置同源），且**页码坏值有不依赖渲染器的廉价探针**：
   ① 目录/清单页码必须按出现顺序**单调不减**（实测旧静态页码 `表2.2=23` 早于 `表2.4=17` → 一眼判坏）；
   ② 表号出现顺序（实测 `表3.3` 落在 `表3.2` 之前）；③ 某章页码跨度远超其内容页数 = 数字串位。
   出稿前跑一遍，成本极低。

11. 🔴 **增删列表条目后，正文里的「自指计数」必须同步**（2026-09-16）。论文里到处是
   「三条待补充事项」「六条使用边界」「五个步骤」这类**指向自身结构的计数**；只要增删一条（哪怕是修缺陷顺手加的），
   全文所有引用该计数的地方都要跟着改。实测：把「三层非独立」写进局限性后，表 4.3 从 6 条变 7 条 →
   须同步 4.4 开头「六条边界」→「七条」、§1.5「七条使用边界」。**只改表不改正文声明 = 新的自相矛盾**。
   自查：对每个「N 条/N 项/N 个」定位其被指的清单，数一遍实际条数。

10. 🔴 **自审/查重结果一律「现跑现取」，不得沿用上一轮的口头描述或记忆**（2026-09-16 实测翻车：
   我照上一轮说法汇报「88 字最长重合片段 = 图 3.8 图注」，现跑后发现真正的 88 字片段是第 2 章方法描述）。
   原因：母本每轮重新生成，**字符偏移会变**；片段必须用本次脚本输出的 `pos/len` 在当前母本上重新切片。
   判读要区分两类：**「有意同源」**（方法/参数描述与专利交底书逐句一致 → **不改**，两文档配套，改了反而口径冲突）
   与**「该重述」**（图注、论述性重复、同一句式逐字重复）。改完未复跑就如实说"新数字未复跑"。
   去 AI 味 + 查重两道自检（脚本、口径、已知坑、自检基线）走 `human-skill`。

## 1. 第一步：读规范原件

规范通常是一套附件（正文 + 封面/扉页 + 声明页 + 参考文献国标 + 专业学位名称表），格式还经常是旧版 `.doc` 或扫描 PDF：

| 原件格式 | 用什么读 | 要点 |
|---|---|---|
| `.docx` | `read_file` | 自动抽取正文 |
| `.doc`（Word 97-2003 二进制）| `antiword` | `antiword -w 0 -m UTF-8.txt "x.doc" > x.txt`；`-w 0` 关自动换行 |
| 扫描版 PDF | `pymupdf` 渲染 + `RapidOCR` | 先判文字层是否为空 |
| 旧版 `.doc` / 扫描件的完整实操（命令、批量循环、表格错位坑） | → `image-ocr-fallback` skill（含 `scripts/ocr_scanned_pdf.py`）| |
| 产出符合规范的 `.docx` | → `docx-generation` skill | python-docx 不继承 Normal 样式，每个 run 要显式设字体；中文字体需同时设 `w:eastAsia` |

⚠️ `read_file` 打开 `.doc` 会报 "Cannot read binary file" —— 这是**预期行为**，不是文件损坏，别重试，直接换 antiword。

## 2. 第二步：整理成「标注版」速查（本 skill 的标准交付物）

用户说"整理出来，并做好标记"时，产出一份 Markdown，**必须带三类标记**：

- **适用范围**：`【硕】` / `【博】` / `【通】`
- **约束强度**：`🔴 硬性要求` / `⚪「可根据需要」的选做项`
- **来源定位**：条款号（如 2.1.4 / 3.8 / 4（2）），便于回查原件

并附带：章节骨架（可直接照抄的树状结构）、写作前自查清单（硬性项逐条 checkbox）、参考文献常用著录条目。

为什么必须标注硕/博：规范正文把两者写在一起，**硕士前置部分只有 7 项**（无评阅意见、无答辩决议书），
装帧上硕士单双面均可、博士必须双面。照抄博士版 = 形式不合格。

## 3. 第三步：按骨架撰写

吉大硕士骨架（其他学校结构类似，按各自规范替换）：

```
封面（学术学位版 / 专业学位版）→ 原创性声明 → 使用授权声明
[序或前言] → 中文摘要+关键词 → 英文摘要+Keywords → 目次页
[插图和附表清单] → [符号/缩略词/术语注释表]
── 主体从另页右页开始，每章另起页，加页眉 ──
第1章 绪论 → … → 第N章 结论 → 参考文献 → [注释] → [附录]
作者简介及在学期间所取得的科研成果 → 后记和致谢 → 封底（无页码）
```

撰写要点（易被形式审查挑出的地方）：

- **摘要**：硕士中文约 1000 字；英文摘要**据中文摘要翻译**；关键词 3–8 个，紧随中英文摘要之后。
  非汉语撰写的论文另有加长要求（硕士中文摘要≥3000 字）。
- **图表题注**：图号图题在**图下方**、表号表题在**表上方**，均居中、**黑体、字号同正文**，
  题号与题名之间空一个汉字；编号按章连续（图1.1、表2.2），跨页续表需注"续表"并重复表头。
- **公式**：另起一行居中，编号右端对齐，公式与编号之间用"…………"连接。
- **引文标注**：顺序编码制（引文末字右上角方括号、小 5 号宋体上标）或著者-出版年制，**全文统一**；
  🔴 **不得把文献标示放在各级标题处**。
- **页码**：前置部分（序/前言起）罗马数字，主体+结尾（引言起）阿拉伯数字，封底不编码；
  单页印刷页码右下角，双面印刷单页右下、双页左下。
- **页眉**：仅主体部分；楷体小 5 号居中、普通单划线；双面版双页页眉为「吉林大学博士（或硕士）学位论文」。
- **装帧**：A4 横开本左侧装订，天头/订口 ≥25mm、地脚/切口 ≥20mm，裁切后 29.1×20.7cm。

## 4. 第四步：产出 .docx

格式实现（宋体/黑体字体落 run、Normal 样式不继承、页码分节、页眉单划线、题注居中）走 `docx-generation` skill。
关键：python-docx **不会**自动继承 Normal 样式字体，每个 run 必须显式 `font.name`；
中文字体需同时设 `w:eastAsia`，否则 Word 里回退成默认字体。

### 母本分片 + 脚本合并（长论文的唯一安全布局）

长论文**不要**维护单一巨型 Markdown，也**不要手改合并稿**：按「前置／各章／文末」拆成多个 part 文件，
用一个生成脚本 `merge_md() → build() → save()` 合并出 `.md` 与 `.docx`。

- 改稿只改 **part 文件**；合并稿与 DOCX 一律**重新生成**——手改会被下次重跑覆盖，且两个版本从此不一致。
- 单次修订涉及多处／多文件时，用**一个脚本原子落盘**（断言命中 + 按文件缓存只写一次），
  做法见 `references/citation-reference-table-audit.md` §5。
- 出 DOCX 后**逐节核验**：分节数、页眉是否**逐章**写入、页码格式（前置罗马／主体阿拉伯重新起算）。
  实测曾漏写章标题页眉（规范硬性要求）→ 必须查 `header` XML 确认，不能只看正文渲染效果。

## 5. 第五步：交付前自查清单

照 `references/jilin-university-master-thesis-spec.md`「写作前自查清单」节逐条打勾（结构/格式/封面/摘要/声明/装帧六类）。
每一项都要能指回规范条款号；指不回去的项，回原件核对后再定。

| 照抄博士版前置部分 | 多出评阅意见/决议书，结构不符 | 硕士 7 项，按规范逐项核对 |

| 导师姓名与职称连排 | 封面不合规 | 姓名与职称之间**空一个汉字** |
| 专业名称用简称 | 不合规 | 严格按「研究生教育管理信息系统」名称 |
| OCR 出来的国标表格直接引用 | 表格多栏错位 → 著录格式抄错 | 表格类内容标注"待核原件"，以原件/权威来源为准 |
| 参考文献序号/类型标识混用 | 著录不合格 | 全文统一一套（`[J]/[M]/[D]/[P]/[EB/OL]`…），3 位以上作者列前 3 位加"等" |
| 🔴 **同一文献被复用来支撑互不相干的论断** | 引文张冠李戴，审稿人一眼看穿 | 全稿统计每个 `[n]` 的被引次数，**≥2 次的逐处读上下文**核对是否同类论断。实测：`[9]`（猴脑图谱）被同时挂到「人脑取样受限」与「liftOver 坐标迁移」上 = 明显错引 |
| 🔴 **自报数字链不自洽**（"区间外 N 组"与"区间内 M 组"不闭合） | 硬伤，审稿人会反算 | 交付前对**每句带比较级/占比/组数的论断**独立重算一次；分母−分子必须闭合（实测 175−19=156 却写成 18，且 18 不是"大多数"） |
| 🔴 **把"高于/低于独立期望"写反** | 论断方向错，且常被自己的机制解释二次打脸 | 任何"显著高于/低于 X"的 X 都用**文中自己的边缘总数重算**；再检查所给机制解释能否推出所报方向（实测声称"正相关"但数据实为负相关） |
| 对比文件用 D1–D5、文献表用 [35]–[39] | 读者无法对应 | 正文首次出现处给对应关系，或表首列并列两种编号 |
| 背景综述两节内容重复（同一组文献出现两次） | 结构冗余、标题口径不符 | 每节标题必须覆盖其全部小节；发现重复即归并到一节 |
| 🔴 **数值区间被误判成引用**（如目标区间 `[30, 500]`） | 引用计数虚增、凭空多出「`[500]` 超范围引用」、真孤立文献被掩盖 | 核查加过滤：方括号内**任一分量 > 文献表最大编号 → 判为数值区间，非引用**。实测 13 处幻影命中 |
| 文献表里有从未被引用的条目 | 正文 ↔ 文献表双向不对齐，审稿人会数 | 三分类处置：①正文有该事物但缺号→首次出现处补号；②全文+**素材包**零提及→删条目+顺延其后编号；③DB 编号并存→表首列并列 `D1 [35]` |
| 🔴 **卷/期/页直接采信用户粘贴或记忆** | 著录信息错，等于文献不存在 | Crossref + Europe PMC **双源核验**后再著录；与用户所给不一致以实证为准并**回报出入**（实测 38(18) 实为 38(19)） |
| 批量改稿逐条手改 / 同文件多处并发编辑 | 漏改、互相覆盖（"以为改了其实没改"） | 一个脚本一次落盘：`(file, old, new)` 三元组 + `count(old)==0 → sys.exit(1)` 断言 + 按文件缓存**只写一次**；改完复跑核查 |
| 电子资源条目只写机构名不写 URL | `[DB/OL]` 著录不合格 | 补 URL 或改著录类型；删条目后检查正文有无引用已删编号 |
| 🔴 **文献表里躺着与本研究 assay 无关的工具条目**（实测：纯 ATAC 论文里出现 `CellBender`＝来源论文 snRNA 分支用的去环境 RNA 工具） | 模板残留，用户/审稿人一眼看出"哪来的这个" | 孤立条目必须能回答"本文哪一步用到它"（铁律 7d）；答不上来→删并顺延编号，优先替换为**真实用到**的条目（含货号/型号） |
| 🔴 **正文图表用括注式 `（图 3.2）` 或方括号夹注 `[图 3.2 …]`** | 不符中文学校惯例（应写"如图 X.Y 所示"），用户会直接要求整改 | 正文改叙述式；**夹注真身多为 Markdown 图片 alt**，alt 必须写完整图题（铁律 8）；诊断脚本 `scripts/check_intext_citations.py` |
| 🔴 **用户质疑"稿里有 X"但当前稿实查为 0 处**（用户读的是上一版／看的是 `.md` 母本／结果面板预览） | 盲改会删掉本已正确的内容或制造重复，且"改了但用户仍看到旧的" | 先**在当前 DOCX 上实查**（解 zip → 剥标签 → 正则）再决定改不改；确为 0 处就回"该问题在 vN 已修，你打开的是改前版本"，并给**最新文件绝对路径 + 修改时间 + 大小**。实测两处质疑：CellBender 上一轮已替换、方括号夹注在母本 alt |
| 直接 `grep` DOCX 内部 XML 找词 | Word 把一句话拆进多个 `<w:r>/<w:t>`，跨 run 的连续字符串 grep 会**漏检**（报 0 处而正文其实有） | 必须先剥标签再匹配；查"是否出现在全稿"要扫 `word/*.xml` 全部（页眉/页脚/脚注不在 `document.xml`，图片 alt 不在正文 XML） |
| 🔴 **同一图件被两个图号引用**（需真图的图号数 > 图件数时就地复用素材图） | 一图两号两图题，查重与审稿都会抓；用户会直接追问\"为什么这两张图是一张\" | 出稿前跑 `scripts/check_figure_numbering.py`；修法只有两条：删冗余图号让正文改引现有图号，或重绘独立图件（**改图题不算修复**）。同步五处：插图清单/目录/交叉引用/图注/alt（铁律 9） |
| 🔴 **图号不按出现序**（图 3.1 落在图 3.2–3.4 之后） | 违反\"按章连续编号\"，读者先看到 3.2 再看到 3.1 | 探针报「图序倒置」→ 重排图号；重排后插图清单、目录页码、正文引用全要跟着改 |
| 长文档改稿时反复勘察同一批文件（一轮挨一轮 read/grep 同一批 md） | 触发系统循环干预，浪费上下文，用户看不到推进 | **一轮批量取证**（同轮并行 read + grep 目标文件，一次拿全）→ 直接改 → 重生成 → 汇报。产物已成功生成即视为完成，**不要对同一件事反复验证**；确需再确认也只做一次 |
| 生成 DOCX 时当前解释器缺 `python-docx` | 生成中断，或误判成\"装不了/要装\" | 按候选解释器列表逐个探测 `"$py" -c "import docx"`，用第一个可用的（本项目实测：系统 Python312 可用、项目 `.venv` 无）——**先探测，不重复安装** |
| 🔴 **用字符类窄匹配 grep 清点文件**（如 `grep -o "figures/[a-z0-9_]*\.png"`） | 含**大写字母**的文件名（`v23_fig3a_sweep_**L3**_bw.png`）被静默漏掉 → 统计出\"8 张图件\"、进而得出\"图 3.3 无图件\"的**假结论**，差一步就向用户汇报了一个不存在的缺陷 | 清点一律用**宽匹配**（`figures/[^)]*\.png` 或 `re.findall(r"figures/([^)\"]+)")`），别把文件名关进小写字符类；**任何\"文件缺失／不存在\"的结论必须换第二种写法复核一次再报**（实测案例见 `references/figure-numbering-and-inventory.md` §4.3） |
| 🔴 **有图号却没有图件**（题注自注\"不另附图/以文字描述\"，正文又写\"如图 X.Y 所示\"） | 读者照图号找不到图，审稿人必问；\"正文图号数 > 图件数\"即缺口 | 二选一：**去号**（删图号与题注，流程写成步骤，零成本）或**补绘**（真实数字的独立图件）。插图清单只列有图件的图号（铁律 9d） |
