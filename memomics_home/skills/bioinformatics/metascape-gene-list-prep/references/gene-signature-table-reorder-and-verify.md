# 基因集（signature）表重排 + 独立校验（2026-10-21 实战）

场景：用户给一张"基因集补充表"（宽表 xlsx，一行一个 signature），说"内容随便排的，
按分类所属排列、去掉那几个、重命名成 X"。产出一张**行序重组过**的新表，源表只读不动。

## 一、输入形态：宽表 xlsx（Gene signature 补充表）的列位真相

实测样本：单 sheet `Gene_signatures_CLEAN`，**24 行 × 203 列**

| 行/列 | 内容 |
|-------|------|
| R1 | 标题（如 `Supplementary Table 3. Gene signatures. [CLEAN v3 - …]`） |
| R2 | 表头 `Class \| Signature \| Annotation \| Genes` |
| R3+ | 每行一个基因集 |

⛔ **关键（差一列就错）**：基因**从第 4 列（就是 `Genes` 表头那一列）起**横向铺开 ——
第 1 个基因写在 `Genes` 表头**底下**，右侧都是无名空表头列。
所以 **基因列 = 4..max_column**，不是 5..max_column。写成 `r[4:]` 会让 200 基因的集少读 1 个。

**每行基因数 = 从第 4 列起非空计数。** 本次实读与分类表 `n_genes` 逐集完全相等
（98 / 58 / 200 / 158 / 137 / 200 / 16 / 27 / 38 / 15 / 11 / 200 / 200 / 49 / 44 / 95）
→ 反证**表未被截断**。
⚠️ 反之：若某集实读数 < 分类表 `n_genes`，说明原表被 Excel 列上限截断 —— **必须报告，不许静默接受**。

## 二、重排口径：先确认"分类"是哪一套，再动手

用户原话通常是"内容随便排的，按分类所属排列" —— **"分类"必须先确认**。本次弹窗给两组选项：
(a) 本会话建立的生物功能轴（6 轴，来自分类文件） vs (b) 原表 `Class` 列（Muscle/Metabolism/…）。
**用户选了 (a)**。确认后把口径写成脚本顶部常量，不要散在代码里：

```python
AXES = [(轴中文名, 轴英文名, 归类依据, [成员 signature 名, ...]), ...]
ordered = [(a[0], s) for a in AXES for s in a[3]]
kept = [s for _, s in ordered]
assert not set(kept) & set(DROP)                 # 要删的集不能还在轴定义里
assert not set(recs) - set(kept) - set(DROP)     # 不能有集没归轴
assert len(kept) == len(set(kept)) == EXPECT_N   # 行数 == 弹窗里承诺的行数
```

轴内保持分类文件给出的成员顺序（稳定），不重排；被删的集从轴定义里也一并去掉。

## 三、⛔ 关键陷阱：给表**前置新增一列**后，验收脚本忘了同步列位

新增 `Axis` 列插在最前面 → 派生表所有列位右移 1。验收脚本仍按源表列位解析 → 取到的
"Signature" 其实是 `Class` 值 → 只剩 5 个"唯一集" → 报：

```
KeyError: 'Muscle'
② 删除 2 集/剩 20: FAIL | 剩余 5
```

**教训：验收脚本必须显式声明"源表 / 派生表"的列位偏移，不要写死一份索引。**

```python
def load(p, new=False):
    o = 1 if new else 0                     # 派生表前面多一列 Axis
    ... recs[r[o+1]] = dict(cls=r[o], anno=r[o+2],
                            genes=[g for g in r[o+3:] if g not in (None, '')])
```

**排查特征**：报错里的键是**分类名**（Muscle/Metabolism/Diabete/Aging/Inflammation）而不是签名名
⇒ 一定是列位偏移，**别去怀疑数据**。
**另一个关键分辨**：同一次输出里 `①轴序与20行: PASS` 已经证明**产物本身是好的** ——
先分清"产物错"还是"验收件错"，改验收件而不是重跑产物。

## 四、独立校验 6 项（读回磁盘，不信内存对象）

| # | 校验 | 为什么 |
|---|------|--------|
| ① | 轴序序列 == 期望序列，且行数 == 承诺行数 | 用户按"剩 20 行"验收 |
| ② | 被删集确实不在（剩余数 == 承诺数） | 防漏删/多删 |
| ③ | 每个保留集基因**集合**与源表相等 | 不丢不增 |
| ④ | 基因**顺序**逐位相等 | 集合相等 ≠ 顺序相等，**两条都要** |
| ⑤ | `Class` / `Annotation` 未改一字 | 用户没让改元数据 |
| ⑥ | 基因数与分类表 `n_genes` 对齐 | 交叉源验证，防截断 |
| + | 源表 mtime 未变 | 证明只读 |

可直接复用：`scripts/verify_gene_score_table.py`（参数化，改顶部常量/传 CLI 参数即可）。

## 五、交付表结构（用户认可的形态）

- 主 sheet：`Axis | Class | Signature | Annotation | Genes…`
  （**原列全保留**，`Axis` 插最前；`freeze_panes='D3'` 让横拉看基因时行名不丢）
- 附 sheet `Axis_legend`：轴名 / 轴 EN 名 / n_members / 成员清单 / 归类依据 / 参考文献
  —— 写图注或回审稿人时直接可用，且不污染主表宽度
- 源表**只读**不动，新表另存到用户指定路径
- 脚本落 `results/<sid>/task2/scripts/`（build + verify 两个）

## 六、两个必须主动说明的判断（用户认这个）

1. **不在功能轴体系内的集要另立轴，不要硬塞进最像的轴。**
   本次 4 个肌纤维型打分（Type I / II / IIA / IIX）按**会话既定口径**另立"肌纤维身份轴"置顶 ——
   依据是 fibertype 脚本头部原文：*"scoreI/II/IIx 是肌纤维身份打分（MyHC 亚型），与现有 5 个
   「功能程序轴」语义层级不同 → 另立一轴，不并入 Contractile（收缩机制 ≠ 纤维身份）"*。
   → **同类决策先翻本会话既有脚本的注释/常量，会话自己定过的口径优先于现场直觉。**

2. **轴名用哪一套要避开"悬空改名"。**
   图上 EN 轴名可能正处于"用户已定但尚未落到脚本"的状态（本次 `Sarcopenia / Inflammaging`）。
   交付表改用**分类文件里的中文轴名**（①技术伪影轴 … ⑥终末失代偿重塑轴）可避免表↔图不一致；
   同时在回复里给一句"要不要我一次把图脚本两个 name 字段改掉、重出 4 格式"的选项。
