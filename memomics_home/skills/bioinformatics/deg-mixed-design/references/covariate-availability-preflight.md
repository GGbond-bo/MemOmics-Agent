## 为什么必须先预检（三门，缺一不可）

用户给一张外部表 ≠ 该表能进模型。三道门按顺序过，任何一道不过都要先回报用户而不是硬跑：

1. **命名能否对上**（最容易翻车，也最隐蔽）
2. **覆盖率是否够**（不是总命中率，是**每个比较组两侧分别**的命中数）
3. **与设计结构是否共线**（嵌套关系决定它是协变量还是不可识别项）

---

## 门 1：命名对不上 —— 编号在不同组之间复用

对象里的三层嵌套是干净的：

```
24 individual  →  47 samplename（Pre/Post）  →  94 library（每 samplename 恰好 2 个）
```

用户表是 **library 级**、连字符写法（`Y16-1-1`），对象是下划线（`Y16_1_1`）——这一层只需
`gsub("-", "_", x)`。**真正的问题不是分隔符，是编号在不同组之间复用**：

| 对象里的个体 | 实际所属分组 |
|---|---|
| `Old_2` `Old_4` `Old_5` `Old_10` `Old_13` `Old_17` `Old_23` | **OD 组**（`Old_diabete`，老年糖尿病） |
| `Old_1C` `Old_2C` `Old_4C` `Old_5C` `Old_8C` `Old_9C` `Old_10C` | **O 组**（`Old_normal`，老年正常，**带 C 后缀**） |

用户表写的是 `O5 / O23 / O1 / O10 / O2 / O4` —— 探针显示它们全部落在 **OD 组**上，
而真正的 O 组（带 `C` 后缀的 7 个）**一个批次都没给**。另有一个 `O1` 在对象里无对应
（只有 `Old_1C` 与 `Old_13`），所以 64 行只命中 **60 个 library**。

**覆盖率实测（samplename 级）**：

| 分组 | 总 samplename | 有批次 | 可用 |
|---|---:|---:|---|
| Y_Pre / Y_Post | 10 / 10 | 10 / 10 | ✅ |
| OD_Pre / OD_Post | 7 / 7 | 5 / 7（缺 Old_13、Old_17） | ⚠️ 部分 |
| **O_Pre / O_Post** | 7 / 6 | **0** | ❌ 完全没有 |

**后果**：`Aging（Y_Pre vs O_Pre）` 与 `Diabetes（O_Pre vs OD_Pre）` 这两个最需要批次校正的
**正交比较，拿不到任何批次**；而本来就没问题的 `Y_Pre_vs_Y_Post` 批次齐全。

### 硬规则

- 预检第一步：**打印对象里每个分组下的完整个体名单**，再和用户的表逐个比。
- ⛔ 不要相信「编号前缀相同就是同一组」——同一套数字常被不同组复用，
  而「正常/疾病」对照往往只差一个后缀（本例 `C`）。
- 未命中不要只报「60/64 命中」，要**列出未命中的具体 ID + 对象里最接近的候选**
  （`agrep`/`grep -i` 模糊找），否则用户无法判断是"少给了"还是"名字写错了"。

## 门 2：`aggregate()` 默认 `na.action = na.omit` 会静默吃掉整行

```r
# ❌ 错：batch 为 NA 的 17 个 samplename 全部消失，日志只打 30/47
smpsum <- aggregate(batch ~ samplename + individual + type, data = smp,
                    FUN = function(x) unique(na.omit(x)))

# ✅ 对：显式保留含 NA 的组合
smpsum <- aggregate(batch ~ samplename + individual + type, data = smp,
                    FUN = function(x) if (all(is.na(x))) NA else unique(na.omit(x)),
                    na.action = na.pass)
```

**症状**：汇总表的行数少于 `length(unique(samplename))`，而且**少掉的恰是没有协变量那批**——
于是覆盖率被低报，看起来像"数据更全/更缺"的假象。

⇒ 任何「按分组汇总一个可能缺失的协变量」都要显式传 `na.action = na.pass`；
写完顺手断言 `nrow(smpsum) == length(unique(smp$samplename))`。

⚠️ 补救成本很低：探针若已把**原始明细**（本例 `library_level_full.csv`，94 行未过滤）
落盘，直接读它重算即可，**不必重读 794 MB 的 rds**。

## 门 3：batch 与设计结构的嵌套 —— 决定"能不能加"而不是"要不要加"

实测（本例）：

- batch 在 samplename 内**一致**（47/47 个 samplename 内 batch 唯一）⇒ 可作为**样本级**协变量
- batch **完全嵌套于 individual**（每人一个 batch）⇒ 在**配对比较**里 `(1|individual)`
  已经把 batch 整份吸收，再加 `+ batch` 是**争抢方差 / 秩亏**

⇒ 推理链：
```
配对比较  → batch 与 RE 共线 → 不加（加了也不收敛）
独立比较  → batch 可估       → 加
但独立比较恰好是 O 组缺批次的那些
```

**全局交叉表的 Cramer's V 会骗人**：本例 `V = 0.305 / p = 0.47`，看着"不共线"，
但分组一拆就露馅 —— Young 的 10 人里 4 人在 batch3，**Old 组 0 人在 batch3**
⇒ Aging 比较里 batch3 的系数与 Young 效应**不可分离**。

⇒ **必须看「每个比较组内部」的 `batch × type` 表，不是全局 V。**

## 用药 / 治疗类协变量（用户常问："独立比较是不是有点问题？"）

**这个判断用户往往是对的**，要正面肯定再补机制：

| 设计 | 用药能不能进模型 | 原因 |
|---|---|---|
| **配对**（同一人 Pre/Post） | 通常不需要 | 用药在个体内是常量，被 `(1\|individual)` 完全吸收。**例外**：Pre 与 Post 之间换过药 ⇒ 变成随时间变化的真混杂，必须建模 |
| **独立**（Y vs O、O vs OD） | 需要，但常常加不进去 | 若 OD 组人人用降糖药、Y 组无人用 ⇒ 用药与分组**完全共线**，设计矩阵奇异。此时它不是"协变量"，而是**统计上不可分离的混杂** |

**先做交叉表再开口**：`table(用药, 分组)` 看有没有空单元格。

- 每格 ≥1 人（有空格的补集）⇒ 可作协变量，报每格 n
- 完全共线 ⇒ 三条出路：① 结论里显式声明局限；② 做「仅未用药老年 vs 青年」敏感性分析；
  ③ 匹配子样本（propensity/精确匹配）
- ⛔ 不要悄悄塞一个与分组共线的协变量 —— 模型报错，或者给出不可估的系数而下游照常出表。

## 评审"已发表论文的代码"（≠ 评审用户自己写的脚本）

用户会问「**难道人家这个代码就没问题吗？它比我好在哪里？**」
固定四段骨架：

1. **先纠正前提：发表 ≠ 统计正确**。逐项实测量化，不凭印象。
   本例实测：论文版 `RUVr(counts, rownames, k = nruv, res1)` 在本机 RUVSeq
   直接报 `formal argument "k" matched by multiple actual arguments`
   （签名是 `RUVr(x, cIdx, k, residuals, ...)`，第 3 位就是 `k`）。
2. **拆两栏**：「该学的设计纪律」 vs 「仍然存在的统计缺陷」——不要一边倒。
3. **解释它为什么没出事**：通常不是它"更正确"，而是它**答的科学问题更简单**
   （本例：论文用 Age 连续回归取斜率，我方是 5 个两组比较）。换了问题一样爆。
4. **明确它在原理上做不出你要的东西**，防止用户拿别人的代码硬套自己的设计。

实测对照（猴脑 Figure7 vs 本项目免疫）：

| 项 | 论文版（猴脑 PFC） | 我方 v2 |
|---|---|---|
| 推断单位 | 细胞级 | 细胞级（**同病**） |
| 随机效应 | **无** | 配对时 `(1\|individual)` |
| RUV k | `nruv=10` 估、`uruv=5` **固定用** | `min(nruv, df_resid-1)` → **饱和到 10** |
| 分层 | 按 `Region`（脑区）分层跑 | 无（本侧是肌肉，**没有 Region**） |
| 分组处理 | Age 连续回归（11/22/29 三档） | 5 组两两比较 |
| 死代码 | `meta_age_1..4` / `outtsv` / `outrda` 建了不用 | — |

- **该学**：k 固定不饱和、批次/分层进模型、亚结构协变量进模型。
- **不该学**：连续年龄回归（答不了五组比较）、那行 `RUVr` 位置参数写法。
- ⚠️ **`Region` 是脑/多部位数据的维度**，单组织（肌肉）没有这一列 ⇒
  「照抄分层变量名」会产出「我的肌肉哪来的脑区」这种必然翻车的问题。

## v3 的三件校正（脚本 → `scripts/immune_RUV_MAST_v3.R` 思路）

1. **k 的残差预算**：`k_actual <- min(nruv, max(2, floor(df_resid / 3)))`
   —— 给 `stim` 留 ≥2/3 自由度。v2 的 `min(nruv, df_resid - 1)` 在 16 样本时顶到 10、
   残差 df 只剩 2 ⇒ SE 被系统性压低（显著率从 0.1% 跳到 88%）。
2. **W–stim 共线性闸门**：`abs(cor(W_j, stim)) > 0.7` 的因子剔除；剩 <2 个则跳过该对比
   （说明组间差异已被 RUV 当噪声吸走）。
3. **batch 的进入条件**：`!anyNA(sample_batch) && n_levels >= 2 && !use_re_here`；
   design 秩亏时自动去掉 batch **并留日志**（静默回退 = 以后没人知道设计被降级过）。

输出增列供审计：`batch_used` / `n_batch_lv` / `k_pre_v3`（v2 口径的 k）/ `w_dropped` / `df_resid`。
有了 `k_pre_v3` 与 `nRUV_used` 两列并列，就能直接量化「k 约束救回了多少」。

⚠️ **统计口径一改就必须整批重跑、另开 outdir**（本例 `Immune_v3`）；
⛔ 不要局部替换几个 csv —— k 随样本数变化，混版结果无法比较。
