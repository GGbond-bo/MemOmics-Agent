# 「优化这张图」请求：改视觉参数 + 产物级验证（2026-10-15 实测）

> 配套 SKILL.md 章节：「优化这张图」类请求（点名一张图 + 保持口径 + 调一个视觉参数）

## 一、请求形态识别（这是 cosmetic fix，不是重分析）

用户原话：`FigA2_program_5effects_drop2.png，这个图，帮我优化一下：① 继续保持 d_av ② 我希望把图中的星号变大一点`

特征 = **点名一个已存在的图 + 保持某个口径 + 调一个视觉参数**。
⇒ 数据源、统计口径（本例 `d_av`）、显著性判据、几何/版式**一字不动**，只动被点名的那一个参数。
⛔ 不要顺手"优化"用户没点名的东西（配色 / 别的字号 / 边距 / 标签角度）。

## 二、三个硬动作

1. **视觉参数提成具名常量**，放在已存在的几何常量旁边，让"调大一点"变成一处改动：

   ```r
   CELL <- 1.0; PANEL_GAP <- 1.8
   STAR_CEX <- 13 / 9        # 星号字号：原 7/9(=7pt) → 13/9(=13pt)；只改这里即可整体缩放
   ```

   唯一的绘制点改成引用常量（`text(..., cex = STAR_CEX, font = 2, col = if (abs(val) > 1.5) "white" else "black")`）。
   好处：用户下一轮说"再大一点"时，不必重新读整个 184 行脚本找魔数。

2. **改前先归档同名产物**（本例 4 格式 + 脚本 `.bak`，各带 `_star7pt` 后缀）：
   `archive_superseded/FigA2_program_5effects_drop2_star7pt.{png,pdf,svg,tiff}`
   ⚠️ 与「多版本并存时不要归档」（同名并存的 raw-p 变体那节）**相反**：**同名覆盖才归档** ——
   旧版一旦被覆盖就找不回来；而多版本并存时归档反而制造版本歧义。

3. **跑完用"改前后共同存在的统计量"自证零改动**：本例星号计数
   `Aging 77 / T2D 2 / ExYoung 10 / ExOld 27 / ExT2D 5` 改前改后**逐项相同** ⇒ 纯视觉改动。
   ⛔ 不要只说"重跑成功" —— 用户要的是"**你没动数据**"的可核查证据。

## 三、产物级验证：怎么证明"字号真的变大了"

改了字号而图看着"差不多"时，必须有像素/矢量级证据。三条路，实测只有一条真的管用：

| 方法 | 实测结果 | 判定 |
|---|---|---|
| 栅格墨迹掩膜（PIL：`sat>30 & max(RGB)<90`） | 黑墨 10,775 → 11,477（1.07×）；"星形"块均值 13.3 → 13.0 px | ❌ **无效**，掩膜被格子填色污染 |
| 在 SVG 里找 `font-size` 属性 | **0 命中** | ❌ 该设备不写 font-size |
| **SVG 里同一字形 `<use>` 的落点坐标比对** | 同一 glyph 的 `x/y`：`230.99, 92.59` → `229.82, 95.94` | ✅ **决定性** |

细节（下次直接用，不用重新摸索）：

- R 的 `svg()`（cairo）把文字**转成字形路径**：`<defs>` 里 `<g id="glyph-N-M"><path .../></g>`，
  正文用 `<use xlink:href="#glyph-N-M" x=".." y=".."/>` 引用。文件里**既没有 `font-size`，也没有
  `matrix(` 变换，也搜不到 `>*<` 字面星号** ⇒ 前两条路必然 0 命中（别浪费回合再试）。
- 字号只能从**同字形 use 的落点位移**间接读出：`text(adj = c(.5,.5))` 是**中心对齐** ⇒ 字形放大后
  左缘左移（Δx<0）、基线 y 下移（Δy>0）。实测 Δx = −1.17pt、Δy = +3.34pt，与 7pt→13pt（1.86×）
  中心对齐的位移吻合 ⇒ 字号确实生效。
- **字形身份**靠上下文定：文件里第一个被绘制的文本就是星号 ⇒ `glyph-0-0` 即星号；再用它前面那条
  格子填色 `<path fill="rgb(41.96%, 67.45%, 81.96%)">` 确认比对的是**同一个格子**。
- 栅格掩膜为什么会失败（记住别再踩）：浅色格（如 `#D1E5F0`，`sat = 0xF0−0xD1 = 31`）会通过任何
  `sat>30` 的"彩色区"过滤 ⇒ `white_ink` 数出 **681,320 px** 的荒谬值（真星号墨迹只有百来个像素级量级）。
  ⇒ **凡是想用颜色阈值框"图内的文字"，先假设它会被格子填色污染**；想数文字就换矢量源。

## 四、验证预算：只打一发，且要打最强的那发

本轮我连做 3 次验证（栅格墨迹 → SVG 找 font-size → SVG 找 matrix），触发平台
**「循环检测·强制干预」**（"连续执行相同/相似的监控命令 → 判定循环失控"），被迫中断，
只允许 2–3 句结论收尾。⇒ 纪律：

1. **一个改动只允许一发决定性探针**，且直接上**最强的那一发**（本例 = SVG 同字形坐标比对）；
   ⛔ 不要"先试个便宜的，不行再说"。
2. 弱探针**返回了无用数字**（掩膜被污染 / 属性 0 命中）= **探针设计错了**，直接换成最强探针**一次**；
   ⛔ 不在同一条弱路线上换写法反复试（那是"重复监控"的判定特征）。
3. 探针一旦给出可支撑结论的证据 ⇒ **立刻收尾汇报**，⛔ 不再"顺手再确认一下"。
4. 已被判循环后：按提示**立即停止所有验证动作**，用 2–3 句给出「已完成 / 失败 / 卡死 + 产物路径」。
