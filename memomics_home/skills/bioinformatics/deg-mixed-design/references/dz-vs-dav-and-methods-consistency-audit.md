# d_z vs d_av：换算恒等式的适用条件 + Methods 文档口径审计（2026-10-14 实测）

## 1. 换算式只在**等方差**时成立 —— 换算前先看 s_pre 与 s_post

| 量 | 定义 | 用到 r 吗 |
|---|---|---|
| Cohen's d_z | `mean(post−pre) / sd(post−pre)` | 隐含（sd_diff 含 r） |
| Cohen's d_av | `mean(post−pre) / √[(s_pre²+s_post²)/2]` | **不用** |
| Hedges' g（独立） | `(ȳ−x̄)/s_pooled × J`，`J = 1−3/(4df−1)` | 不用 |

精确关系（任意 s_pre / s_post）：

```
sd(post−pre)² = s_pre² + s_post² − 2·r·s_pre·s_post
d_z / d_av    = √[(s_pre²+s_post²)/2] / sd(post−pre)
```

只有 **s_pre ≈ s_post** 时才退化成教科书的 `d_z/d_av = 1/√(2(1−r))`。

🔴 **⛔ 不要用 `d_av = d_z × √(2(1−r))` 做换算或反算**。实测反例：本项目 660 个配对格，
逐格比较 `实测 d_z/d_av` 与 `1/√(2(1−r))`，**最大绝对偏差 = 2.09**（远非舍入级）。
⇒ 两个量**要么都实测、要么只报一个**；「一个实测 + 假设 r 换另一个」在**格级别**上是错的。
⚠️ 聚合到面板层（取中位 r）再比，偏差会小很多 —— 这正是早期用中位 r 做的体检"看起来对得上"的原因，
别因此以为换算式可用。

## 2. 偏差**方向由 r 决定** —— ⛔ 不要照抄「d_z 虚高 58%」

本 skill 主文那句「r=0.8 时 `d_z` 比 `d_av` 大 58%」的前提是 **r = 0.8**（高相关数据）。
运动/衰老类项目的实测 r **远低于此，方向甚至翻转**：

| 效应 | r 中位（660 格按效应分组） | `d_z/d_av` 中位 | 改用 d_z 后中位 \|d\| |
|---|---|---|---|
| ExYoung | +0.495 | 0.978 | ×0.95（几乎不变） |
| ExOld | +0.413 | 0.888 | ×0.88 |
| ExT2D | **−0.195** | **0.651** | **×0.71（缩 29%）** |
| 全配对池 | +0.322（**32% 的格 r<0**，范围 −0.894 ~ +0.970） | — | — |

⇒ 换 d_z 的影响**不是全局等比缩放**，而是**按面板不同程度缩**，r 越低缩得越狠。
⇒ 在共用色标的多面板图里，这等于让某个面板因**统计口径**而非生物学"变弱"。
⇒ **引用「d_z 虚高 58%」前先实测本项目的 r 分布**；r 低或为负时那句话要反着写。

## 3. 读效应量表：`aux1` / `aux2` 是多用途列

`build_effect5_v3.py` 产出的表（本例建表脚本）：

| 行类型 (`eff_type`) | `eff` | `aux1` | `aux2` |
|---|---|---|---|
| 配对（`"d_av"`） | d_av | **d_z** | **逐格实测 r** |
| 独立（`"g"`） | Hedges' g | **J（Hedges 校正因子）** | NaN |

⚠️ 直接把 `aux1` 当 d_z 用，会在独立行拿到 J（例：Aging 行 `aux1 ≈ 0.949`）。
判行类型**一律先看 `eff_type`** —— 与「任何列先算 `nunique()`」同族的自查。

✅ 好消息：`aux2` 里的**逐格 r 是现成的** ⇒ 算「改口径的代价」（§2 表）不必重跑上游。

## 4. 审计「三套代码统一口径」类文档的四步

用户会拿自己整理的 Methods 一致性文档来问「**你觉得我们是不是改成 X**」。
文档里的"推荐"**不等于**正确 —— 本例文档有两处概念错，要独立核验：

1. **逐条回源码验公式**：文档称"临床脚本实际算的是 d_z" → 去读那个脚本的效应量函数，
   ⛔ 不信描述。（同理：出图脚本普遍只读表不重算，公式藏在建表/验表脚本里。）
2. **核验换算关系有没有被当恒等式用**：本例文档写 `d_av = d_z × √(2(1−r))` 并据此要求
   "若坚持 d_av，上游必须用各变量**实测 r** 重算" —— **两处都错**：
   ① 该式仅在 s_pre≈s_post 时成立（§1）；
   ② **d_av 的分母 `√[(s_pre²+s_post²)/2]` 里没有 r，计算 d_av 根本不需要 r**
   （r 只在**换算到 d_z** 时才用到）。"必须用实测 r 重算 d_av" 是把换算误当计算。
3. **量化改动代价**：用现成表算「改口径后每个面板变多少」（§2 表），⛔ 不要只说"会不一样"。
4. **给分场景结论，但先量『旗翻转』再开口**（方法见 §5）：
   - 跨面板**共用色标/共轴**比较（独立 + 配对混排）→ 默认 **d_av**
   - 单变量、单独报告的图（火山图/箱线图）→ `d_z` 可用（它衡量该队列的干预敏感度）
   - 两条都要 → 主报一个 + 另一个进补充材料作敏感性分析，Methods 各写一句
   ⇒ 所谓"统一"应是**统一框架与报告语言**，不是把符号统一成同一个。
   ⛔ 也不要把 `d_z` 从表里删掉 —— 它作为审计列存在（`aux1`），随时可取。
   🔴 **但"共色标必须 d_av"不是否决 `d_z` 的理由**：若实测完整双旗翻转 = **0**，换口径就只是
   换注脚。本项目即如此，用户据此拍板**全项目统一 `d_z`**（2026-10-15）—— 见 §5。

## 5. 决定改不改：先量『旗翻转』，再给建议（2026-10-15 实测，**推翻了我的第一次建议**）

**教训**：第一轮我凭公式（`d_z/d_av` 随 r 漂移 → "会让 ExT2D 因口径而非生物学变弱"）建议**不要**改；
第二轮用用户自己的数据量出实际后果后，建议**反转为「建议改」**。
⇒ **口径建议必须带实测代价**，⛔ 不许只讲公式方向 —— 公式给方向，**数据给结论级影响**。

四个审计量（660 个配对格，`eff` = d_av vs `aux1` = d_z）：

| 审计量 | 实测 | 含义 |
|---|---|---|
| 跨格排序一致性（Spearman ρ） | **0.986** | 图的高低形态几乎不动 |
| **完整双旗翻转**（`p<.05` 且 `\|d\|>0.5`，逐栏） | ExYoung **18→18** / ExOld **43→43** / ExT2D **12→12** | **0 翻转 ⇒ 显著性结论零改变** |
| 单看 `\|d\|>0.5`（不看 p） | 净减 **65** 格（ExT2D −43 / ExOld −21） | **全被 p 旗拦住**，不进最终显著集 |
| 逐栏缩放（`d_z/d_av` 中位） | ExYoung ×0.978 / ExOld ×0.888 / **ExT2D ×0.651** | 只有 ExT2D 栏明显变淡 |

⛔ **最常见的误读**：把"单看 `|d|>0.5` 少了 65 格"当成结论级影响 —— **必须同时看 p 旗**，
只有**完整双旗**的翻转数才决定结论变不变（本例 0）。

**判据（照抄）**：
- **0 翻转 ⇒ 换口径只是换注脚，不是改结论** → 可以直接统一，风险极低；交付里仍要说明
  "某栏深浅会变，不可跨栏直接比深浅"。
- **有翻转 ⇒ 把翻转的格摆给用户拍板**，并说明是**变宽**还是**变窄**。
- 一键探针 → `scripts/caliber_switch_impact.py`（`--csv/--eff-col/--dz-col/--p-col/--paired-effects`
  四审计量一次出，含"独立行 `aux1`=J"的护栏）。

**本项目最终决定（2026-10-15 用户确认）：全项目统一 `d_z`**，三条理由值得照抄：
1. **0 翻转**（实测，非推断）—— 改的是报告口径，不是结论；
2. **三套代码一个语言**：临床脚本本就是 `mean/sd_diff`（= `d_z`），统一后 Methods 写一段话就够；
3. **`d_z` 更诚实**：它用 `sd(diff)` 做分母，会如实惩罚 **Pre/Post 负相关**的测量不稳格
   （ExT2D 有 **32%** 的格 r<0），而 `d_av` 的 `√[(s_pre²+s_post²)/2]` 与 r 无关、反而**掩盖**它们。
⇒ 代价只有一个：ExT2D 栏整体变淡约 1/3 ⇒ 交付**必须说明"该栏与另两栏不可直接比深浅"**。
⇒ 落到图上（3 处同步改）：图注 `d_av (r~.32)` → `Cohen's dz`；`d_av` 描述文字；Methods 口径表。
⇒ **`d_av` 版图原封保留、不覆盖**（用户明确要求）→ 出对照图时用**派生变体脚本 + 独立输出名**
（同族做法见 `references/exploratory-rawp-figure-delivery.md` 的"派生变体脚本"一节）。

### 5.1 落地配方：换列只换「配对面板」（2026-10-15 已执行，实测 6 处改动）

🔴 **最硬的一条：统一 `d_z` ≠ 把 `aux1` 整列当效应量**。独立比较（Aging / T2D）**没有配对、
`d_z` 无定义**，必须保持 Hedges' `g`。而该表独立行的 `aux1` 装的是 **J ≈ 0.94**（§3）——
**整列替换会把这两栏变成近似常数（每格都 ≈0.94）→ 整块塌平**；更阴的是它**不会报错**，
因为 0.94 落在 `|d|>0.5` 内、颜色看着"正常"。本次靠一条断言拦住：

```r
PAIRED_EFF <- c("ExYoung", "ExOld", "ExT2D")          # 只有这三个走 d_z
# 防误取：独立行的 aux1 是 Hedges 校正因子 J，与效应量必须不同
stopifnot(!isTRUE(all.equal(eff$aux1[eff$effect %in% c("Aging", "T2D")],
                            eff$eff [eff$effect %in% c("Aging", "T2D")])))
eff$eff_plot <- ifelse(eff$effect %in% PAIRED_EFF, eff$aux1, eff$eff)   # 只换配对行
stopifnot(all(is.finite(eff$eff_plot)))
```

**实测 6 处改动**（派生脚本；版式 / 几何 / 配色 / 字号 / 边距 **零改动**）：

| # | 位置 | 改动 |
|---|---|---|
| 1 | 数据段 | 矩阵输入列 `eff` → `eff_plot`（配对取 `aux1`，独立保持 `eff`） |
| 2 | 数据段 | 加上面两条 `stopifnot`（列存在 + 独立行 `aux1` ≠ `eff`） |
| 3 | 输出基名 | `BASE` → `<原名>_dz`（**独立文件名，⛔ 不覆盖交付件**） |
| 4 | 图内图注 | `g: indep, d_av: paired (r~.32)` → `g: indep, dz: paired`（顺手删掉误导的单一 `r~.32`） |
| 5 | 主标题 + 色标标签 | `Hedges' g / d_av` → `Hedges' g / Cohen's dz` |
| 6 | 清单名 | `*_manifest_QA.csv` → `*_dz_manifest_QA.csv`（防两份清单混用） |

⚠️ 顺手加一段**口径核对打印**（每栏 `d_av 中位 → dz 中位 + 比值 + r 中位`），让"换口径确实生效、
且只作用在配对栏"变成**运行时可见的输出**，而不是注释里的承诺。实测输出：

```
ExYoung  d_av 中位 -0.1677 → dz 中位 -0.1635 (比值 0.978) | r 中位 +0.4951
ExOld    d_av 中位 +0.2076 → dz 中位 +0.1942 (比值 0.888) | r 中位 +0.4125
ExT2D    d_av 中位 -0.1173 → dz 中位 -0.0782 (比值 0.651) | r 中位 -0.1945
```

**✅ 端到端确认（图级，非推断）**：dz 版出图后**星号计数与 d_av 版逐栏完全相同**
（Aging 77/150、T2D 2、ExYoung 10、ExOld 27、ExT2D 5；分母 = 15 程序 × 10 亚群 = **150**）——
这是"0 翻转"在**交付物层面**的复核，比只在统计表上算一遍更硬。
⇒ 报告时**必须同时给分母**（程序数 × 亚群数），否则与 18 程序 / 6 轴版（分母 **180**）没法比。

⚠️ **图注写单一 `r~.32` 覆盖多个配对栏是误导**：实测三栏 r 中位各异（ExYoung **+0.495** /
ExOld **+0.413** / ExT2D **−0.195**，后者为负）—— 用一个数概括三栏，读图人会以为三栏可同尺度比。
⇒ 要么**逐栏写 r**，要么只写效应量名、**不写 r**。

🔴 **对照组源码找不到时的诚实边界（别拿未核实的前提支撑建议）**：本例文档称"临床脚本实际算的是 d_z"，
但 `Clinic_ALL` 在 `results/` 与 `<数据目录>/` 下 **0 命中、无法独立核实** ⇒ 必须**显式声明**
"这一条引自你的文档、我未验证源码"，并把"请把该脚本给我"作为**前置条件**列出。
⛔ 不要把"文档说它用 d_z"写进 Methods 建议里当作已验证事实 —— 用户会拿它去投稿。
