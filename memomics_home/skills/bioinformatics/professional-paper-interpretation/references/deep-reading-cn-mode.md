# 中文精读解读模式（精读 ≠ 翻译）

> 2026-10-23 建立。本文件是「用户要精读/解读，不要翻译」时的落地配方。

## 1. 触发与反触发

**走本模式**：精读 / 精读这篇文献 / 解读这篇 / 告诉我这文献背景·实验对象·方法内容·结论 / 思路框架是什么 / 这篇文章讲了什么 / 帮我从编辑角度分析。
**不走本模式**（→ 双语 reader，且必须用户点名）：中英对照 / 原文对照 / 全文翻译 / 双语 / 翻译这篇 paper / bilingual。

### 事故记录（为什么要写这条铁律）
71 页 Cell 论文（Maier et al., *Cell* 2027, "Multi-omics atlas of chronic exercise", DOI 10.1016/j.cell.2026.09.044）。
用户：「帮我精读这篇文献，告诉我这文献背景，实验对象，实验方法和内容，结论是什么？怎么思路框架是什么？」
Agent：按 nature-reader 双语 pipeline 写了 part1/part2/part3（英文原文 + 中文对照），第 3 个分片写到一半被用户打断：
> 「双语精读器，谁要你中英文对照了？？？？我要精读，不是要翻译」

处理：双语分片全部移出交付路径（`data/paper_src/_discarded_bilingual/`），改为中文单语解读 `results/精读解读_<主题>_<一作><年>_<刊>.md`（33.7 KB / 265 行）。
**结论：精读 = 中文深度解读。双语不是"顺便多给一点"，而是跑偏。**

## 2. 交付物骨架（中文单语，一节一个主题）

```
0. 文献身份表 + 一句话结论
   标题/作者(通讯)/期刊卷页/DOI/文章类型/投稿时间线(Received→Revised→Accepted)/数据可得性号/代码仓库/在线资源
   一句话结论 = 用一句话把"做了什么 + 最硬的数字 + 为什么这算新"说完
1. 研究背景：已知 3 条 + 关键空白 3 条（把 gap 当骨架，不平铺综述）
2. 实验对象与设计（最该先抓住）：表格化
   品系/起始年龄/性别/光暗与取材时点(ZT)/分组/笼养方式(单笼 vs 群养！)/剔除标准/器官清单(全缩写)/各平台覆盖度(不是所有组织都做了所有组学)
3. 方法与内容：平台参数 + 数据规模表 + 分析链条（每步工具与阈值，例：DESeq2 / Fisher 合并 p / BH-FDR；共识聚类 Leiden 200 次；SVM min_AUROC>0.90；HOMER q<0.05；BooleanNet S>2.5 P<0.15）
4. 结论：按维度分层，每条带硬数字（组织维度 / 性别维度 / 时相维度 / 细胞类型维度 / 调控维度 / 泛化维度）
5. 思路框架：mermaid flowchart TD（gap → 模型选择 → 设计 → 数据层 → 各维度发现 → 建模 → 外部验证 → 交付）
   + "框架内核 2–3 条"文字总结（例：宽筛查→深度投入；两个正交组学互证；从描述走到可泛化模型 + 基线对照）
6. 关键数字速查表（可直接引用：规模/效应量/AUC/样本量/多重比较口径）
7. 局限与批判要点：作者自陈的局限 + 读者视角补充（混杂设计、关联 vs 因果、测序深度、样本量与效应量、分类器的"预测"≠预测训练效果）
8. 参考图索引（抽出的主图表格：图名/内容/文件路径）+ 补充图 S1–Sn 标题清单
9.(可选) 对我方工作可迁移的 2–3 点
```

## 3. 对话交付要求（硬约束）

- 解读成品**必须直接写在回复里**（背景/对象/方法/结论/框架齐全 + mermaid + 关键数字），再附交付物清单表；只回"已落盘，路径在 X" = 交付不完整。
- 图内文字用英文、正文解释用中文。
- 框架图用**独立 ```mermaid 围栏**（不进 dsh-ui JSON，避免长 JSON 被截断降级）。

## 4. 抽取步骤（Cell 单栏整页图版，本次实测可用）

```bash
# ① 逐页文本落盘（带页分隔标记，便于后续精确 grep 章节区间）
python - <<'PY'
import fitz
d = fitz.open(r'<数据目录>')
with open('data/paper_src/pages_text.txt','w',encoding='utf-8') as f:
    for i,pg in enumerate(d):
        f.write(f"\n===== PAGE {i+1} =====\n" + pg.get_text())
print('pages', d.page_count, 'meta', d.metadata)
PY
# ② 定位结构：meta 里的 title 直接告诉你是什么文章
grep -n '^===== PAGE' data/paper_src/pages_text.txt     # 主文/参考文献/STAR Methods/补充材料各自的页行区间
# ③ 主图裁取（整页图版）
python scripts/crop_fullpage_figures.py <pdf> results/<sid>/figures --pages 3,6,8,10,13,16,17 --dpi 200
# ④ 图非空白校验 + 抽查
python -c "from PIL import Image;import numpy as np;a=np.asarray(Image.open(p).convert('L'));print(a.mean(),a.std(),(a<240).mean()*100)"
#   非白像素 15–25% 属正常；再用 vision_describe 抽查一张，确认 OCR 出的是图内标签而非正文段落
```

Cell 论文的正文结构（以本次为例，套用其他 Cell 论文同理）：p.1 封面/Graphical abstract → p.2 起 Summary+Introduction → 主图各占一页（图版页夹在正文页之间）→ References → **STAR★METHODS**（实验 + 统计 + 计算细节，最该 grep 的部分）→ Supplemental information（Figure S1–Sn 图注，标题在每页顶部）。

## 5. 踩坑（本次实际踩过）

- **页索引 off-by-one（静默失败）**：PyMuPDF `d[i]` 是 0-based，而读者按 1-based 数页。本次主图在 1-based 的 3/6/8/10/13/16/17 页 → 索引应为 2/5/7/9/12/15/16；写成 3/6/8… 裁到的全是**正文页**，脚本"成功"、图非空（只有页眉条），不抽查根本发现不了。→ 脚本一律接受 **1-based** 页号，并打印 `非白像素%` 供判空。
- **别用 `get_drawings()` 的并集当图区**：矢量图内容常驻 XObject，`get_drawings()` 只返回页眉/装饰碎片 → 裁切矩形退化成一条页眉。整页图版用"**页脚文字块上沿**"作下界最稳。
- **页脚锚点不止一种**：`Cell 190, 1–27, ...` 与纯页码数字都会出现，两者都要判。
- **样本量口径不一致要照原文标注，别自行调和**：本次同一篇里图注写 `n = 12/组`、体成分写 `n = 10/组/性别`、方法学写"每组选 5 只取材"。解读里逐处注明引用口径（并在批判节点出不一致），比"统一成一个数"更专业。
- **图表说明的双记法**：正文提到 Figure Sn 时，若该图的标题不在正文页而在补充材料页，补充图标题清单要单独列（S1–S17 各一行），否则读者以为没有补充图。
- **长解读文档分片写**：`write_file` 分 3–4 次写不同主题段落再合并，避免单次超长；每块主题必须明确不同，形态相似的分块容易触发系统循环检测提示。
