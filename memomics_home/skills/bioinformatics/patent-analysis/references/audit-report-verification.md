# 第三方评审意见核实（Audit Verification）

> 触发：用户把**别人（另一个 session / 另一个 AI / 审稿人）写的审查意见**整段贴进来，说
> 「**这是自查找到的问题，你核实一下**」「这份评审意见对不对」「它说的这些问题是真的吗」。
>
> 2026-09-12 实测：用户贴入一份 9 节专利审查意见（含法条逐条判定 + P0 硬伤 + 4 处 P1），要求核实。
> 核实结果 **13 项为真 / 3 项评审自身写错 / 2 项评审漏掉** —— 所以「核实」不是点头，是三分类。

---

## §0 🔴 铁律：核实 ≠ 复述。三个必做动作

| # | 动作 | 不做会怎样 |
|---|------|-----------|
| 1 | **每个数字回源重算** | 评审的数字可能是它抄的、或它算错了。必须用源表独立跑一遍（`pandas` + `scipy`），逐项并排放「评审值 / 我实跑值 / ✅❌」 |
| 2 | **每句"原文引用"回交付件核位置** | 评审说「交底书 §三（七）原文：……」→ 必须真去 docx 提段落，确认**这句真的在**、在第几段。评审也可能编引文 |
| 3 | **报评审自己写错的 + 评审漏掉的** | 只说"评审都对"= 二次传声。用户要的是**独立判断** |

**输出必须三分类**：`✅ 为真（我复现）` / `⚠️ 评审自身有误（附实测值）` / `🟡 评审漏掉（我补查）`。

---

## §1 执行顺序（一次跑完，别拆成 N 个探针）

> ⚠️ 与 SKILL.md 的「一个产物只配一个探针脚本」同源：**一个核实任务 → 一个探针脚本 → 一次汇报**。
> 禁止「想到一项就再写一个小脚本」。

1. **定位源表 + 交付件清单**（一次 `ls -la` + `find`）
2. **源表实跑**：把评审里所有统计量一次算完（写成一个 `.py`，`exec(open(...).read())` 跑）
3. **交付件正文提取**：docx 提 `paragraphs` + `tables`，按关键词表扫（见 `scripts/scan_docx_text.py`）
4. **交叉比对**：评审的每个数字/引文 → 标注 ✅/⚠️/🟡
5. **落盘核实备忘**：`results/<sid>/results/评审意见核实_<日期>.md`（13 项表 + 订正 + 新查）
6. 出图（`rail_review(post)` 会要求至少 1 张）→ **核实图本身就是证据图**，三联面板足够
7. `debate_analysis(level='L1')` 辩「该不该按评审的救法改」

## §2 🔴 交付件「创新性」表述：先核后写，禁止从需求清单/记忆列举

**2026-09-12 事故（用户原话：「你这就是造假，误导我」「明明没有跑，为什么一会儿说跑了，一会儿说没跑呢」）**

用户问「当前专利的创新性在哪里」，我给了「四条别处没有的组合」，其中第 4 条是
**「二维经验贝叶斯五态判定 + local FDR」**。用户追问「你确定你用了这个方法了吗？」，实查结论：

- `claims.md` 独权 1 的动词链是 `S1 取数据 → S1.5 统一网格 → S2 算 Z₁/Z₂ → S3 S=Z₁×w(Z₂) → S4 置换定阈 → S5 二级分级`
- 全目录 grep `经验贝叶斯|local FDR|lfdr|五态` → **0 命中**
- 那条「四」来自**早期需求/规划清单**（`REQUIREMENTS.md` / `.memory/conclusions.md`），**不是交付件内容**

**铁律**：
1. 回答「这个专利/交付件的创新性在哪 / 有什么技术效果」时，**每一条都必须先在 `claims.md` / `disclosure.md` / docx 正文里 grep 到位**，grep 不到的条目**一律不得列入**。
2. **区分三种东西**：① 需求清单里写的（想做）② 探针里跑过的（试过）③ 交付件里真有的（已入册）。**只有 ③ 能对外陈述**。
3. 探针产物（如 `scripts/ebayes_lfdr_probe.py`、`results/lfdr_probe_summary.json`）**存在 ≠ 专利用了它**。要给用户看探针，必须明说「这是我替你跑的可行性探针，不在专利里」。
4. 自查信号：如果一条"创新点"你说不出它在 `claims.md` 的第几项权利要求、或第几段说明书 → **停，先去 grep**。

## §3 用户记忆中的数字与现文不符 → 先查互补数，再判"是不是退步了"

**2026-09-12 实测**：用户问「**之前不是已经到 50% 多了吗？怎么还是 46%？**」（怀疑倒退了）。

排查法（两条，成本极低）：
1. **互补数检查**：率类指标先看 `1 − 现值`。实测 `全流程溯源档案.md` 写着
   「方向一致 7,431（**46.4%**）/ 相反 8,598（**53.6%**）」→ **53.6% 就是反向率**，
   用户记的「50% 多」= 它的补数，两者是同一件事的正反面，**没有退步**。
2. **全库同量级扫描**：`grep -rno "5[0-9]\.[0-9]\+%" --include="*.md" .` → 实测全库 5x% 数字
   （54.3 / 55.6 / 58.7%）**全部是反向混入率或精度**，不存在任何 >50% 的同向率。

⇒ 结论要给「**它从来就是 <50%，不是退回去了**」，不要含糊地说"我再确认一下"。

## §3.5 🔴 形态二：审计**自带脚本**（统计重分析型）—— 2026-09-13 实测

> **形态一**（§4，2026-09-12）：评审只读交付件、只对账，问题清单停在「文字/数字不一致」。
> **形态二**（本节，2026-09-13）：评审**自己重跑了统计**——换零假设、换口径、算出新结果，据此说
> 「全篇唯一的正面证据是长度假象」「你的结论方向反了」。破坏力最大，核实必须升级。
>
> **识别信号**：审计里出现**它自己的脚本清单**（`audit9_*.py` / `verify_*.py` / `imgcheck.py`）+
> 「我把 v17 的置换重跑了四种零假设」这类第一人称实跑叙述。

### 固定四步（顺序不可换）

| # | 动作 | 为什么 |
|---|------|--------|
| 1 | **先读审计脚本源码**（`read_file` 全文），确认它的**统计量定义 / 置换对象 / 分层键**与它文字描述的是同一件事 | 它的叙述可能与它脚本里跑的并不一致；读源码才判断得出它的零假设换得对不对 |
| 2 | **一个 runner 跑完全部脚本**：`AUD=<审计目录>; for s in <脚本清单>; do echo "### $s"; $PY "$AUD/$s"; done` —— **一次工具调用**输出全部 | ⛔ **一个脚本一次 terminal = N 次调用 = 触发循环检测**。本次 6 个脚本天然想发 6 次调用，第 3 次就被系统拦。SKILL.md 的「一个产物只配一个探针」在形态二等价于「**一次调用跑完所有审计脚本**」 |
| 3 | **逐位对账**：它的每个数字（含 `±`、`z`、`p`）与我的实跑值并排放，标 ✅/⚠️ | `±` 与 `p` 是最容易露馅处；本次 12 项逐位吻合 = 它真跑了，**可信度可据此上调**，汇报时要明说 |
| 4 | **引文单独回 docx 核**（形态一动作 2 照做，不可省） | 🔴 **统计全对 ≠ 引文全对** —— 见判据 1，本次它编了一处引文 |

### 🔴 三条判据（形态二必带）

1. **统计全对 ≠ 引文全对，两者分开验。** 标本：审计称「§三（一）只写『猴侧约 530 万个 tile』」，
   实测 §三（一）= P18 原文**只写「猴侧为 20 例食蟹猴，覆盖四个年龄梯度…」，无任何 tile 计数**；
   全文 `5,296,656` **零命中** → 这句引文是它造的。**但它要指出的问题仍成立**（两套口径并存：
   置换检验用 6,085,841、主输入 `monkey_ageDA_all.csv` 是另一套）。⇒ 判据：**问题真 ≠ 引文真**；
   汇报格式写「**问题成立、引文不成立**」——不因引文假否掉问题，也不因问题真放过引文。

2. **审计的「救法 / 新发现」在过匹配零假设前是假设，不是结果。** 本次审计在第三层给出反转性新发现
   （长度中性化后出现剂量-反应，方向与旧口径相反），但它**自己只给观测率列、没给匹配零假设列**，
   把「改用 count_h×count_m 联合分层的匹配零假设」塞进「免责」一句。⇒ 按本项目自己的标准
   （率类指标必须报 **观测率 + 匹配零假设 + 配对 z** 三元组），**必须把它从 caveat 提升为 gate**：
   未过匹配零假设前不得进交付件、不得当结论上报，只能标为待验证线索。汇报用词：「**这是线索，不是结论**」。
   ⚠️ 审计**主动自曝的边界**（本次：「bin 级 0.57 不能直接用，2211 bins 只来自 1324 基因，
   基因级符号检验 p=0.64 不显著」）要**单独表扬并复现** —— 自曝边界的审计可信度显著高于只报有利结果的。

3. **审计建议「重定位」（改发明名称 / 换保护对象 / 换主口径）→ 一律交用户拍板，禁止自行采纳。**
   本次审计建议「改名（如『候选元件（带方向标注与判定等级）』）+ 独权落点挪到标定判定上」，
   而用户此前已点名锁定「**我们的专利不应该是筛选方法吗？**」。⇒ 见
   `references/screening-method-effect-argumentation.md` §1 定位锁定：
   **「结论层被否」≠「claim 定位要改」**。审计的重定位建议只作为**选项** + 附我的逐条判断列给用户。
   🔴 **核实轮一律不动交付件**（连"顺手改掉算错的那一格表格"也不做 —— 先问）。
