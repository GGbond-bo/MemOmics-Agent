# 方向门控类方法的前提审计（反向侧对照法）

> 2026-09-11 建立。触发场景：用户说「你从专业专利老师的角度评价 <交底书>」「从审查员/答辩老师角度评价」，
> 或任何 claim 里出现 **同向 / 方向一致 / direction conservation / w(Z₂) / sign gate / concordance**。
> 本文件给出**自证伪**审计法 —— 用申请人自己的数据检验其核心前提，而不是复述其结论。

## 0. 为什么需要它

以「参考侧方向可信」为核心特征的方法（`S = Z₁ × w(Z₂)`、符号门控、方向一致性筛选），
最常见的**逻辑跳跃**是：

```
参考侧效应量强度测不准（|Z₂| 大值 = 小样本噪声极值）
        ↓  ❌ 推不出
参考侧方向可信
```

强度与方向是两种**不同的统计性质**。前者被 shuffle 否定，不蕴含后者成立。必须独立检验方向。

## 1. 核心洞察：只查同向侧会被共享技术混杂骗过

朴素做法是「同向侧是否有富集」——不够。必须做**反向侧对照**：

> **若反向侧也富集（甚至更富集），则富集来自 |Z₁| 与 |Z₂| 的共享技术混杂
> （覆盖度 / 检验力），而不是方向保守。**

机制：人侧强效应元件同时参考侧覆盖高 → 参考侧 p 更容易 <0.05 → 与方向无关。
证据链：`corr(n_tiles₂, |Z₂|) > 0` 且 `corr(n_tiles₂, p₂) < 0`（覆盖高→p 小）。

## 2. 三检验 + 一对照 + 一分解

| # | 检验 | 算法 | 判据 |
|---|------|------|------|
| ① | 全局同向率 | `mean(sign(Z₁)==sign(Z₂))` | 二项检验 vs 0.5；显著 <0.5 = 方向**系统性反相关** |
| ② | 强效应池同向率 | 同上，限定 `\|Z₁\|≥τ` | 同上 |
| ③ | **最可信子集同向率**（最致命） | 限定 `p₂<0.05 且 \|Z₁\|≥τ` | 最该同向之处若仍 <0.5 → 前提**当场崩塌** |
| ④ | **反向侧对照**（核心） | 比较 `同向&p₂<0.05` 与 `反向&p₂<0.05` 各自相对池底的富集倍数 | 反向 ≥ 同向 → 富集是混杂，不是方向 |
| ⑤ | 共享混杂分解 | `corr(\|Z₁\|,\|Z₂\|)`、`corr(n_tiles₂,p₂)`、按覆盖度**分层**同向率 | 分层后各层仍 <0.5 → 排除单一层解释 |

可跑探针：`scripts/direction_premise_audit.py`（一次输出全部五组，不要拆成多次调用 —— 见 §5 陷阱）。

## 3. 本项目实测（跨物种衰老可替代性专利 · all 口径）

表：`P3_L1_data/M2_repro_gene_conservation_all.csv`（n=16,029，`Z_human`/`Z_monkey`/`p_monkey`）

| 检验 | 结果 | 判读 |
|------|------|------|
| ① 全局同向率 | **0.4636**，二项 p=3.2e-20 | 显著低于 50% |
| ② 强效应池 (\|Z₁\|≥12, n=1409) | **0.4131**，p=7.2e-11 | 显著低于 50% |
| ③ 最可信子集 (p₂<0.05, n=894) | **0.3993**（357 同向 vs **537 反向**），p=1.9e-9 | 🔴 前提崩塌 |
| ④ 反向侧富集 | 反向 **13.0×**（537/41.4） **>** 同向 **12.3×**（357/29.1） | 🔴 富集是混杂 |
| ⑤ 混杂 | `corr(\|Z₁\|,\|Z₂\|)=+0.2248`；`corr(n_tiles_m,\|Z₂\|)=+0.4003`；`corr(n_tiles_m,p_monkey)=−0.1548` | 覆盖度→p₂ 路径成立 |
| ⑤ 分层同向率 | 0.3647 / 0.4804 / 0.4678 / 0.3974（按 n_tiles_m 四分位） | 各层均 <0.5，非单层所致 |

## 4. 配套审计：数字层级错挂（A26.4）

交底书把某个效应量挂到错误的**数据层级/统计量**上时，审查员会判「数据与主张不对应」。

标本：v9 (三)(七)/从权3/图2/有益效果1 把 **24.3×** 说成「τ_A = \|Z₁\|≥12 的显著元件数达空分布均值 24.3 倍」，
而源头 RDS 实为**人侧 peak 级、\|r\|>0.5**：`obs=6285 / null_mean=258.4 / n_peaks=525,137`。

**方法**：任何被引用的效应量，回到源 RDS/表的**字段名**核对三件事 ——
① 数据层级（peak/tile/gene）② 统计量（\|r\|>0.5 vs \|Z\|≥12）③ 分母（`n_peaks` vs `n_tiles`）。

```r
s <- readRDS("P3_L1_data/v8_age_shuffle_stats.rds"); str(s, max.level=2); print(s$human)
# 字段 n_peaks=525137 / n_tiles=6085841 直接暴露层级
```

同批审计：**整体 ρ 未披露**（本项目 ρ=−0.0971，负）—— 审查员会问「整体反相关，凭什么说同向保守」。

## 5. 陷阱

| 陷阱 | 说明 |
|------|------|
| 🔴 **只查同向侧就下结论** | 必须同时算反向侧富集；反向 ≥ 同向即前提不成立 |
| 🔴 **从「强度不可信」推「方向可信」** | 两种统计性质，无蕴含关系 |
| 🔴 **把自家负面 shuffle 结果不写进交底书** | 数据已归档可查 → 选择性披露风险；专利可沉默，**论文必须披露** |
| 🔴 **把诊断拆成 N 次连续工具调用** | 实测触发系统循环检测干预。铁律：把全部检验写进**一个脚本**一次性跑完，再一次汇报 |
| 🟡 混用不同层级的阈值 | 「24.3×」属 τ（p<0.05 分位），「1409」属 τ_A（\|Z\|≥12）；两者不可互挂 |
| 🟡 只看 p 值富集不看方向 | p 富集可完全由共享覆盖度混杂产生（本项目已验证） |
