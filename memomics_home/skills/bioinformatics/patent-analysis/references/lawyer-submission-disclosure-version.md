## §0 🔴 先判收件人，再定形态（防震荡——最容易反复的一步）

同一份交底书，**收件人不同 → 形态不同**，两个结论都对，不可互相否：

| 收件人 | 形态 | 判据 |
|---|---|---|
| **代理人 / 代理机构**（给了原始 6 栏模板） | **瘦身 + 附件**：凡代理人自己能产出的（摘要 / 权利要求 / 检索报告）**不进正文**，降级为独立附件 | 见 `disclosure-delivery-structure-and-docx-split.md` §0 |
| **律师 / 导师审阅**（本会话） | **单文件完整版**：摘要 + 权项框架 + 检索记录**一并纳入正文**；🔴 **但「法条答辩」章节一律不纳入**（禁令与理由见 §1.1） | 律师要据此判断**保护范围与可专利性**，散件反而增加其工作量 |

🔴 铁律：**不要拿「送代理人瘦身」的结论去否「送律师完整」**，反之亦然。2026-09-12 曾因把交底书写得像申请文件草稿被追问「有些东西真的要加吗？」，2026-09-15 又因缺权项框架/检索记录被评为硬伤 —— **两次都对，差别只在收件人**。落笔前先一句确认收件人（用户通常已明说：「我要交给律师去审核查看」）。

## §1 送审版四项必查硬伤（v21 实测 → v22 修法）

| # | 硬伤 | 症状 | 修法 |
|---|---|---|---|
| 1 | 🔴 **摘要超 300 字 + 留字数标注** | `零、说明书摘要（302 字）` —— 既超限（细则上限 300），又把内部工作标注写进正式件 | 削到 ≤300（实测 **267 字**）；**删除字数标注**，节标题只留「零、说明书摘要」。削法：删冗余定语（如「不少于 30 例年龄连续梯度供体」→「（人）」），括号内只留必要限定 |

### §1.1 🔴 「法条答辩」章节禁令（2026-09-15 用户当场否掉）

用户原话：「**十一、实用性答辩要点（专利法第二十二条第四款）这些不要写上去吧？**」——**对，且必须整节删除**。三条理由按重要性排：

1. 🔴 **禁止反悔（prosecution history estoppel）风险 —— 最实质的一条。** 该类章节的核心句式是「本方法主张的技术效果是筛选与判定的性能及其误差控制……**而非某一具体生物学结论的成立**」。这是**主动对技术效果做限缩性陈述**，等于白纸黑字承认「本方法不保证生物学结论成立」。一旦进了申请文件或审查档案，将来若需主张「核心元件具有衰老生物学意义」（为 A22.3 创造性辅证、或答复审查意见），审查员或无效方可直接引这段作为**申请人自认** ⇒ **把软肋写进档案，得不偿失**。
2. **越界。** 交底书是**技术披露件**（发明人 → 代理人），法条判定与审查意见答复是**代理师/律师的职责**。发明人预设答辩口径 = 替代理师定调，还会限制其策略空间。
3. **靶子打错。** 该节挂 A22.4「实用性」，但**实用性不是「数据筛选方法」类专利的风险点**（A22.4 只要求「能被使用并产生积极效果」，输出确定、可复现即满足）。真风险是 **§25.1(2) 智力活动的规则和方法（客体）** 与 **§22.3 创造性**。写一节 A22.4 答辩会让代理师**误判焦点**、浪费篇幅，真正该防的两条反而不在。

🔴 **删前必做「零损失核验」**（否则会连技术内容一起删掉）：

```
① 待删节逐句拆两类：技术事实句 / 法条论述句
② 技术事实句回交付件别处 grep —— 命中即零损失
③ 法条论述句一律删（不留正文、也不搬去附件）
```

实测标本：该节 3 条技术事实（端到端可复现 `16,029→3,180→1,604→150` / 三层证据各自可复核 / 175 组扫描·19 组落区间·输出 150）**在第四节「有益效果」逐条已有原文**；余下只有法条论述（「若审查员以……质疑」+「符合第二十二条第四款」）⇒ 整节删除**技术内容零损失**。删后核验：全文（段落 + 表格）搜 `实用性答辩` / `第二十二条第四款` / `A22.4` / `若审查员以` **零命中**，且限缩句「而非某一具体生物学结论的成立」已消失。

### §1.2 章节标题不得含撰写过程后缀（`（补充）`）

实测残留：`三（补充）、三层证据框架与实测量`、`九（补充）、从属权利要求 6–8、11 的说明书支持说明` —— 这类后缀是**撰写过程标记**，不是正式件该有的（与用户「**不要有什么备注之类的**」同一类要求）。
**修法**：**不动章节号顺序**，把该节正文**并入其前一节末尾**（不单独成章）。清理范围同 §1.1 —— 四处（正文 / 表格 / 页眉 / 页脚）都要扫同类过程标记（`（补充）`、`（新增）`、`（待核）`、版本别名）。

🟡 **三项配套优化**（同批做掉，别留到下一轮）：
- **L1 类定义具体化**：把「从保守性轨迹逐碱基提取单元内保守分值」改成「**基因体 ±2 kb 窗口内可及元件单元的保守分值均值**」—— 窗口与聚合口径写在定义句里，避免 A26.4「取值出处不明」。
- **去比喻词**：`承重柱 → 证据层`、`黄金区间 → 目标输出区间`、`物理数据绑定 → 数据来源`。正式件里不出现口语化/自造术语。
- **表口径区分句**：同一层有两个数时必须显式区分。标本：L2 行同时有「两侧均检出（15,860 / 16,029，98.9%）」与「达下限 tile ≥ 30（10,401，64.9%）」→ 表下加一句「**「检出」指至少 1 个可及 tile，「达下限」指两侧均不低于 30；本实施例以达下限者参与逻辑与判定，检出率仅作覆盖情况说明**」。

**公开号一律取自已坐实档案，不得现编**：本项目五件对比专利（`创造性锚_五件对比专利逐件比对.md`）实测 = D1 `CN117542414A` / D2 `CN121075446A` / D3 `CN109528197A` / D4 `CN121617472A` / D5 `CN122619115A`。检索记录里每件给 公布号 + 名称 + 申请人 + 权利要求 1 核心 + 与本案区别。

## §3 🔴 交付前验收器设计（本会话踩到的真坑在这里）

一个送审版 docx 只配**一个一次跑完的探针**（防循环检测）。四段必查：

### A. 全文提取必须含表格 —— 否则制造假 ✘（**本会话实测**）

```python
paras   = [p.text.strip() for p in d.paragraphs if p.text.strip()]
tbl_txt = [" | ".join(c.text.strip() for c in row.cells)
           for t in d.tables for row in t.rows]
full = "\n".join(paras + tbl_txt)      # ← 少了 tbl_txt 就会误报
```

**标本**：只扫 `d.paragraphs` 的探针报出「✘ D1–D5 含公开号」「✘ 申请人信息空表」两个假告警 —— 公开号在**对比文件表**里、申请人 4 字段在**申请人表**里，文档本身完全正确。⇒ 判「缺」前先核**扫描范围**（正文段落 / 表格单元格 / 页眉 / 页脚**四处**），与「判『死』前先核它在不在」互为镜像。汇报时若确认是探针漏检，**明确说是探针问题、不是文档问题**，不要说成"文档缺陷已修复"。

### B. 内嵌图 sha256 逐张对账（强于字节数反查）

```python
import zipfile, hashlib
z = zipfile.ZipFile(DOCX)
src = {f: hashlib.sha256(open(os.path.join(FIG, f),"rb").read()).hexdigest()
       for f in os.listdir(FIG) if f.lower().endswith(".png")}
inv = {v: k for k, v in src.items()}
for m in sorted(n for n in z.namelist() if n.startswith("word/media/")):
    h = hashlib.sha256(z.read(m)).hexdigest()
    print(("✔ " + inv[h]) if h in inv else ("�’ 未匹配 " + m))
```

字节数相同可能巧合；**sha256 是精确等同**，一锤定音。实测 5/5 全等（290,612 / 221,812 / 449,782 / 252,936 / 621,366 B）。若 hash 不匹配但字节数相同 → 疑重压缩，单列说明。

🔴 **数量断言必须对源目录求集合相等，不能写死数字**（2026-09-15 v24 实测）：v23 起为解「印刷后图内字高仅 1–2 mm」，把**图 3 拆成 3A/3B、图 5 拆成 5A/5B/5C** ⇒ 源图 8 张、内嵌 8 张，而探针沿用旧断言 `len(media) == 5` → 报出一条**假 FAIL**（8 张本身全部 hash 命中）。改法：`assert len(media) == len(src)`，并以「**每张 sha256 都落在源目录集合内**」为真判据（数量相等只是附检）。同源纪律：**图被有意拆分/重出后，「图号说明」与「内嵌件」必须同步核**（附图说明里「图 3 由 3A/3B 组成」要能一一对上 `word/media/image*.png`）。

### C. 黑白纯度（用户说"黑白图片"时的硬验收）

`PIL` 打开 → `convert("RGB")` → 彩色像素 = `((a.max(2)-a.min(2)) > 12).sum()`，**必须为 0**；另报非白像素占比（线条图健康区间 ≈ 8–26%）。同批报尺寸。

### D. 结构要点清单（一次全查）

- [ ] 摘要节存在且**无字数标注**
- [ ] 权利要求 1…N 齐备（送审版含框架节）
- [ ] 🔴 **无「法条答辩」章节** —— BANNED 词 `实用性答辩` / `第二十二条第四款` / `A22.4` / `若审查员以` 必须**零命中**（检查方向是「**不得存在**」；旧版此处写的是「必须存在」，已于 2026-09-15 作废，见 §1.1）
- [ ] 检索记录节存在（含检索式 + `G16B 40/00` 等 IPC）
- [ ] 对比文件公开号全部在册
- [ ] 无 emoji / 方向标记（✅🔥⚠️🔴★）
- [ ] 无「待跑 / 占位 / 粗估 / TODO / 草案」
- [ ] 无版本变更备注（「vN 相对 vM」）
- [ ] 关键实测数字在册

## §4 汇报骨架

1. **文件名 + 字节数**（绝对路径全串）
2. **图片核验表**：逐张 `sha256 匹配源图名 | 彩色像素 | 尺寸` —— 用户明确要求"图片记得确认对不对"时这是首答项
3. **逐条修正表**（🔴硬伤 N 项全修 / 🟡优化 N 处），每条给"原 → 现"
4. **唯一需用户手填项**（申请人姓名/电话/身份证/地址 —— 只有用户能提供，主动点出）
5. 若探针报过假 ✘ → 一句话说明是**探针漏检**（附原因），避免用户以为文档有缺陷
6. 末尾问一句要不要再出一版（**不要自己改交付件**）
