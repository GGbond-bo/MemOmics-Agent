## 执行流程（S1→S6）

### S1 先定位"哪些交付件嵌了旧数字"——用**生成时间戳**做第一判据

**不要逐个打开文件读内容**，先比时间：
```bash
ls -la --time-style=long-iso <交付件目录>/*.docx    # 看生成时间
```
口径切换日期 > 交付件生成日期 → 该件**必为旧口径**，无需读内容。
标本实测：v8.docx 生成于 9-10，口径 9-11 切换 → 直接判定 v8 是旧口径（后续核验证实：装的正是 537/336/37/12.5×/16,031）。

⚠️ 交付件里**还有一类"隐藏的旧数字源"**：只 grep `.md` 会漏掉 binary 格式。
- `.docx` / `.xlsx` 是 zip 包，`grep` 搜不到内容 → 用 python-docx 提取后再搜
- 附图 `.png` 里的数字（轴标签、标题）也是旧口径 → 必须**重出图**，不能只改文字

### S2 数字台账先行，文档脚本只从台账取数

把新旧两套数字写成一份 JSON（本项目 `results/Phase4_numbers.json`），作为唯一真值来源。
文档生成脚本**不得内联手写数字**——数字全部来自台账，这样核验只需比一份 JSON。

台账里每个数字都必须能在**最终输入表上用一个表达式复算出来**（见 S5 数字溯源总表）。

### S3 版本化重出，绝不覆盖原交付件

- 输出 `_v9.docx` 而非覆盖 `_v8.docx`：①保留追溯链 ②旧文件可能被 Word 占用
- **Word 占用信号**：目录里出现 `~$xxx.docx` 锁文件 = 该文档正被打开 → `docx.save()` 到原路径会锁冲突，必须改新文件名
- 附图同理用新文件名（`fig_core_elements_357.png`，不覆盖 `_336`）

#### S3.1 Word 锁：不只写不进去，**改名覆盖也会失败**（2026-09-11 实测）

被 Word 打开的 docx，两种覆盖方式都拦：

```
docx.save(原路径)        → PermissionError: [Errno 13] Permission denied
mv -f 临时文件 原路径    → mv: cannot move ... : Device or resource busy
```

> 🔴 **先分清「有锁」与「无锁」两种情形，别把无锁当成死路**（2026-09-11 v9 实证）：
> - **锁是逐文件（per-document）的** —— 目录里可能同时躺着多个 `~$`（标本：`~$技术交底书.docx`、
>   `~$...v3.docx`、`~$...v8.docx` 都在，而本次目标 **v9 恰恰没有锁**）。**旧版留下的 `~$` 不会
>   自动消失**，看到目录里有 `~$` ≠ 目标文件被占用。**只查目标文件自己那一个**：
>   `ls -a | grep '^~\$技术交底书_已填写_附图版_v9'`
> - **目标文件无锁 → 直接换件，成功即止，不要交给用户**。标本：v9 无锁 →
>   `cp v9.docx 备份` + `mv -f _tmp_v9_fix.docx 技术交底书_已填写_附图版_v9.docx` **一次成功**
>   （646,248 → 658,425 B）。把无锁情况也当成"死路"上报 = 让用户白等一轮，是过度保守。
> - **仅当确认占用**（`open(path,'r+b').close()` 抛 `PermissionError`）才走下面的临时件 + 交付用户流程。

→ **确认被 Word 占用时，不要在打开状态下自动换件**。正确处置顺序：

1. **探锁**（先判，别等报错）：`ls -a | grep '^~\$'` → 有 `~$<名>.docx` 即被占用；
   更硬的判据：`open(path,'r+b').close()` 抛 `PermissionError` = 确认占用
2. **生成到临时路径**，且**不改动正本生成脚本的 `out` 常量** —— 写一个临时运行器，
   读入正本脚本源码、只替换 `out = r"..."` 那一行后 `exec`：
   ```python
   src = io.open(SRC, encoding="utf-8").read()
   assert 'out = r"E:/.../v9.docx"' in src
   src = src.replace('out = r"E:/.../v9.docx"', 'out = r"E:/.../_tmp_v9_fix.docx"')
   exec(compile(src, SRC, "exec"), {"__name__": "__main__"})
   ```
   好处：正本脚本仍是唯一真源（用户复现时路径不变），临时件可随时重生成
3. **临时件照常走完整核验**（S4 + S4b），核验通过才通知用户
4. **交付动作交给用户**：告知「关掉 Word 后执行 `mv -f <临时件> <正本>`」，并给出替补
   （用户自行改名 / 删 `~$` 锁文件）。**不要空等，也不要反复重试 mv** —— 连试必触发系统循环检测

⚠️ 覆盖成功后**必须重新识图复验最终文件**（换件用了新生成的内容，不是核验过的临时件）。

### S4 零残留核验（**必做，这是"改完了吗"的唯一硬证据**）

docx 是 binary，必须提文本 + 表格单元格一起核：

```python
from docx import Document
d = Document(path)
txt = '\n'.join(p.text for p in d.paragraphs)
for t in d.tables:                                  # ⚠️ 表格文本不在 paragraphs 里
    for r in t.rows:
        txt += '\n' + ' | '.join(c.text for c in r.cells)
print('新口径命中:', {k: txt.count(k) for k in new})   # 应全 >0
print('旧口径残留:', {k: txt.count(k) for k in old})   # 必须全 ==0
print('段落数', len(d.paragraphs), '表格数', len(d.tables), '图片数', len(d.inline_shapes))
```

⚠️ **千分位陷阱**：文档里写 `16,029`，用 `txt.count('16029')` 得 0 → 核验串要带逗号（`'16,029'`）或先 `txt.replace(',','')`。

**残留判据要覆盖"局部数字"**：核 `336` 会命中 `3360` 之类；优先核**带上下文的串**（`'336 个核心元件'`）或核完整旧值集合（旧值 9 个全为 0 才算通过）。

### S4b 内嵌图**逐张识图**核验（🔴 不可省 —— S4 通过 ≠ 图文一致）

> **2026-09-11 实测教训（用户当场追问「你再确定一遍，图标要用识图确定」）**：
> S4 文本核验报「旧数字零残留」并据此汇报，但交付件内嵌的**流程图末箱仍写着旧口径
> 「A级336/最高置信37」**（正文已改 357/16）→ 图文矛盾，审查员一比即中。
> 根因：图里的数字是**像素**，`grep` + `python-docx` 提段落/表格**都拿不到**。
> **结论：S4 绿了只证明"正文干净"，不证明"交付件干净"。**

四步固定流程（可跑探针：`scripts/verify_docx_embedded_figures.py`）：

1. **抠图**：docx/xlsx 是 zip 包 → 解 `word/media/*`（xlsx 为 `xl/media/*`）到临时目录
   ```python
   z = zipfile.ZipFile(docx)
   [open(os.path.join(out, os.path.basename(n)), 'wb').write(z.read(n))
    for n in z.namelist() if n.startswith('word/media/')]
   ```
2. **按字节数反查来源**：把每张内嵌图的字节数与候选源图目录比对 ——
   **字节数完全一致 = 该源图未重出 = 旧口径头号嫌疑**。
   标本：`image1.png 171779B` 与 `fig_main_reference_asymmetric_scoring.png 171779B`
   完全一致 → 一眼定位到"9-9 生成的流程图没跟着重出"；
   而 `image3/4` 字节数与 9-11 新出的 `fig_core_elements_357.png` / `fig_enrichment_12_3x.png`
   一致 → 确认是新的。
3. **逐张 `vision_describe`** 取 OCR 事实清单，**重点看带数字的注释串与轴标签**，
   与正文口径逐项比对。核验话术示例：
   `vision_describe(image_path=..., question="图中所有数字分别是多少？是 A 还是 B？")`
4. **改源图 → 重出交付件 → 再次识图复验**，直到每张图数字与正文一致。

⚠️ **源图没重出时，只改交付件是无效的**：docx 只是引用源 PNG，必须改源图
（或改生成脚本里的数字常量）再重跑文档生成脚本。标本中 `gen_figures_all_v3.py`
（9-11 重出）产出了图3/图4，而图1 的源图由 9-9 的另一次内联生成产生、**没留下脚本**
→ 只能按 OCR 复刻版式重出，写入 `scripts/regen_fig1_asymmetric_flow_all.py` 固化下来。

### S5 全流程溯源档案（用户说"能溯源"时的标准交付，7 个部件）

写到交付目录，文件名 `全流程溯源档案.md`：

| # | 部件 | 要点 |
|---|------|------|
| 0 | 一句话复现路径 | ASCII 管道图 + **口径唯一性声明**（哪几步是两物种对称的） |
| 1 | 模块总表 M0..Mn | 列：模块 / 脚本 / 输入 / 输出 / 关键数字。一个模块一行，n 通常 8–12 |
| 2 | 逐模块**复现四件套** | 脚本绝对路径 + 输入文件**列名** + 参数常量值 + 输出 + 正本数字 |
| 3 | **数字溯源总表** | 交付件里每个数字 → 出处 + **一行可执行判据**（如 `((df.Z_human.abs()>=12)&(df.p_monkey<0.05)&sd).sum()` → 357） |
| 4 | 口径警示表 | 命名陷阱、哪些版本已作废、哪些差异是"必然"不是 bug |
| 5 | 可执行复现命令 | 可直接粘贴的 bash/python，含解释器绝对路径 |
| 6 | Mermaid 管道图 | 含**互证支线**（两个独立实现对同一指标） |
| 7 | 诚实边界 | 不显著项、符号相反项、名单换血、小样本侧限制 |

**部件 2 的"列名"不可省**：用户会拿脚本独立复跑，缺列名 = 无法验证（铁律：交付数字必须带复现清单四件套）。

**部件 3 是灵魂**：每个数字配一条能在输入表上直接跑的判据 —— 审阅人不必信任你，自己跑一行就知道对不对。

### S6 重跑文档 + 出图，然后质检

- 出图后做**空白/黑底检测**（不可省，用户会查"你画的好多图都是空的"）：
  ```python
  a = np.asarray(Image.open(p).convert('RGB'))
  print((a.min(axis=2) < 240).mean(), len(np.unique(a.reshape(-1,3), axis=0)))
  # 非白像素占比 0.01~0.5 且唯一色 >100 → 正常；接近 0 或唯一色=1 → 空白/黑底，重画
  ```
- docx 内嵌图片数必须 == 附图说明条数（`len(d.inline_shapes)` 核对）

## 陷阱（本类任务实测踩过）

| 陷阱 | 事实 / 处置 |
|------|-------------|
| 用**生成时间戳**判交付件口径，而不是读内容 | 快且准。v8 时间 9-10 < 口径切换 9-11 → 一次 `ls` 判定 |
| **文件名/路径名当口径用** | `M2_repro_gene_conservation_continuous.csv` 名为 continuous，装的却是 all 输出。口径唯一判据 = **生成脚本里的输入常量 + 逐基因比对** |
| 只 grep `.md` 交付件就宣布"改完了" | binary 交付件（docx/xlsx/png）必须单独提取核验；png 里的数字要重出图 |
| 🔴 **文本「零残留」通过就汇报图文一致** | **像素里的数字文本核验永远查不到**。2026-09-11 标本：S4 通过、正文全对，但流程图末箱仍是旧口径 336/37。**S4 绿 ≠ 交付件干净** → 必须跑 S4b 逐张识图（探针 `scripts/verify_docx_embedded_figures.py`） |
| 🔴 **Word 打开时反复重试覆盖/改名** | `save()` 抛 PermissionError、`mv -f` 报 `Device or resource busy` = **那个文件确实被占用**；但 🔴 **锁是逐文件的**——目录里有别的 `~$` 不代表目标文件被锁（标本：`~$技术交底书/v3/v8` 都在、**v9 无锁**）。**无锁 → `mv -f` 一次成功，直接换件，不要交给用户**（过度保守地交回 = 让用户白等一轮）；确认占用才走「临时件 + 交付 mv 命令给用户，关 Word 后执行」。两种情形都**禁止反复重试**（触发系统循环检测） |
| 🔴 **改源图前先查它有没有生成脚本** | 源图若是某次**内联生成**的（无脚本留存），改不了常量 → 只能按 `vision_describe` 的 OCR + 颜色分布复刻版式重出，并把重出脚本固化进 `scripts/`（标本：图1 源图生成于 9-9 无脚本，图3/图4 有 `gen_figures_all_v3.py`） |
| 🔴 matplotlib 中文图里用下标/数学符号 → 豆腐块 | SimHei 缺 U+2082（₂）、U+2212（−）字形，`savefig` 只报 `UserWarning: Glyph ... missing`，图照样出但变成方框。**中文图标签一律用 ASCII**：`Z1`/`Z2`、`-1`（不用 `−`）。出图后扫一眼 stderr 有无 `Glyph` 警告 = 免费的豆腐块检测 |
| 内联 `python -c "..."` 写多行带引号的替换逻辑 | 单双引号嵌套极易 `SyntaxError: unterminated string literal`。**一律先 `write_file` 落脚本再运行**（临时运行器、探针脚本都走这条路） |
| 把"差异"当"bug"上报 | 有些差异是数学必然（标本：猴侧 20 样本 × 529 万 tile 全局 BH → q<0.1 命中必然为 0；`monkey_ageDA_down.csv` 仅 21 字节空表头属正常）。先算期望再判 bug |
| 全盘 `grep -r` 搜大文件目录 | 本项目有 400–456MB CSV，`grep -r` 必然 180s 超时（exit 124）→ 改用 `search_files`(ripgrep) 或 `find -maxdepth N` + `--include=` |
| 文档生成脚本依赖 python-docx 而持久内核没装 | **先探测用户环境**：`for P in python python3 <候选路径>; do $P -c "import docx" && echo $P; done`。用户环境已有 → 直接用它跑（符合"优先用用户环境"）；不要为一次文档生成去改项目 venv |
| 交付件里"某条 claim 失效"就先删章节 | **先核它到底有没有进正文**：全目录 grep 关键词，零命中 = 该阶段从未进入交付件，不是阻塞项。标本：v6 promoter 置换 p=0.261 不显著，但 grep 证实它不在任何交付件中 → 曾误报"章节不能再用"，后撤回 |

## 交付清单（本类任务收尾必核）

- [ ] 新交付件已生成（版本号 +1，未覆盖旧件）
- [ ] 旧口径数字**零残留**（含表格单元格、附图内数字）
- [ ] **内嵌图逐张识图核验**（S4b：抠图 → 字节数反查来源 → `vision_describe` OCR → 与正文逐项比对）—— 只在文本核验绿了就汇报图文一致 = 不合格
- [ ] 附图重出且通过空白检测
- [ ] 出图 stderr 无 `Glyph ... missing` 警告（中文图用 ASCII 替代下标/减号）
- [ ] Word 锁**已逐文件确认**（不是看到目录里有 `~$` 就判死）：有锁 → 临时件 + 交付 mv 命令；**无锁 → 已直接换件**。无论走哪条路，**换件后必须从磁盘正本重新抠图核验**（重新解 `word/media/*` 算 md5——与核验过的临时件一致 = 廉价铁证；再加一次 `vision_describe` 复验图内数字）
- [ ] 全流程溯源档案已写入交付目录（7 部件齐全，含数字溯源总表）
- [ ] 数字台账 JSON 存在且为唯一真值源
- [ ] task_plan 记录 Phase + 产出路径（非只口头汇报）
- [ ] 诚实边界单列一节（不显著项 / 符号相反项 / 名单换血）
