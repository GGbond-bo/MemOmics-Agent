# 口径切换影响归因 —— "能不能只换数字"判据

> **触发**：用户拿着旧版交付件问「难道换到新口径全都变了？如果没变，为什么不只是替换一些数值就可以了呢？」
> 或更早的「为什么一直在变呢？到底是什么问题，导致你一直在变？」
>
> 本文件回答两件事：**归因**（到底哪一层变了）与**交付判据**（能不能 find-replace）。
> 前提本身已被否掉时的收尾流程另见 `premise-falsified-disposition.md`。
>
> 首测 2026-09-12（专利 v8 continuous → v9 all）。

## 一、第一刀：按字段一致率定位"哪一侧变了"

**不要一上来比总量。** `537 → 582` 只能告诉你"变了"，不能告诉你"哪里变了"。
取两版**输出清单的共同实体**，逐字段算一致率：

```python
import pandas as pd
A = pd.read_csv(".../A级核心元件_357_all.csv").set_index("symbol")   # 新版
B = pd.read_csv(".../A级核心元件_336.csv").set_index("symbol")       # 旧版
common = A.index.intersection(B.index)
for col in ["Z_human", "n_tiles_h", "Z_monkey", "n_tiles_m"]:
    same = (A.loc[common, col].round(4) == B.loc[common, col].round(4)).sum()
    print(f"{col:10s} 逐位一致 {same}/{len(common)}  ({same/len(common):.1%})")
```

**实测（159 个共同基因）**：

| 字段 | 逐位一致 | 判读 |
|---|---|---|
| `Z_human` | **159/159 (100%)**，两版 r = 1.0000 | 人侧矩阵一个字没改 |
| `n_tiles_h` | **159/159 (100%)** | 人侧 tile 网格完全一致 |
| **`|Z_human|` 中位数** | **15.381 → 15.381（Δ = +0.000）** | **不只是"一致"，是量级完全相同** —— 最强的单侧不动证据 |
| `Z_monkey` | **0/159 (0%)**，两版 r = 0.8842 | 猴侧全变 |
| **`|Z_monkey|` 中位数** | **6.346 → 5.098（−19.7%）** | **缩水幅度 = 名单换血的机制**（见第四刀） |
| `n_tiles_m` | 74/159 (46.5%) | 猴侧 tile 网格重建过 |

**全表复验（16,010 个共同基因，非只 A 级子集）**：`|Z_human|` 中位 **3.360 → 3.360（Δ=0）**、`|Z_monkey|` **1.822 → 1.859**。
两个粒度（A 级 159 个 / 全表 16,010 个）都指向同一结论：**人侧零位移，猴侧整体移位**。

**结论**：continuous → all 的口径切换**只动了猴侧**。人侧铁证（24.3×/p=0.005/|Z₁|≥12、图1、图2）逐字不变；
**全部变动都压在"卡猴侧门槛"的数字上**（`p_m<0.05`、`|Z_m|≥12`）。

### 第四刀：缩水幅度 → 判定"阈值边界集合"

只报"哪一侧变了"不够，必须报**变多少**——幅度才是机制。

```
|Z_human| 中位  15.381 → 15.381   (Δ = +0.000)   ← 大样本侧零位移
|Z_monkey| 中位   6.346 →  5.098   (−19.7%)      ← 小样本侧整体缩水
                          ↑
        约 20% 的整体缩水，把元件从 |Z_m|≥12 / p_m<0.05 门槛的一侧挤到另一侧
        ⇒ 名单换血不是"结论变了"，是"阈值上的站位重排"
```

**判据（可推广到任何"共同实体 + 双侧门槛"的方法）**：

| 交集率 | 变化侧缩水幅度 | 判定 |
|---|---|---|
| ≥90% | <5% | 稳健集合，可 find-replace |
| 50–90% | 5–15% | 需附差异清单 |
| **<50%** | **≥15%** | **阈值边界集合（threshold-boundary set）——不是生物学本体** |

**"阈值边界集合"这个判定必须在汇报里显式写出来**：真实的生物学类别不会因为换一次小样本导出就换掉一半成员。
一旦判定成立 ⇒ 该名单只能作"实施例输出"，**禁止写进 claim 的技术效果断言**（"本发明筛出 N 个元件构成 XX 轴"这类句子随时会被自己的数据推翻）。

> **可推广的判别式**（人-参考双输入方法通用）：
> - 共同实体的**一侧字段 100% 一致 + 另一侧 0% 一致** ⇒ 换的是**该侧输入表**（不是方法/阈值/锚定实现）
> - **两侧都大面积不等** ⇒ 换的是**实现层**（见 `data-integrity-self-proof.md` 三层归因）
> - 只有总数差、实体值逐位相同 ⇒ **桥接/取舍残差**（<1% 可接受）

### ⚠️ 数字来源依赖（引用前先锁定文件）

同一结论在不同产出上有 **±5 个实体**的残差。循环论证检验从**锚定表** `P3_L1_data/M2_repro_gene_conservation_all.csv` 实算：

| 量 | 锚定表口径（本 SKILL 统一采用） | 管线 `b1_gate_null.py` 口径 |
|---|---|---|
| `\|Z_h\|≥12` 强效应 | **1409** | 1404 |
| 其中同向（富集分母） | **582** | 581 |
| 同向且 `p_m<0.05`（分子） | **357** | 357 |
| 猴侧显著不分方向 | **894** | 890 |
| 同向 : 反向 | **357 : 537** | 357 : 533 |
| 实测 ÷ 随机符号期望 | **0.80×** | 0.79× |
| 置换 null | — | 449.7 ± 14.8（z = −6.27） |

**结论完全一致**（两项独立检验均判定同向为**亏损**而非富集），**但引用具体数字时必须注明取自哪份文件**——
用户对"数字老是变"零容忍，同一结论报出两组数字会被当成新的漂移。**本 SKILL.md 与 `references/` 统一采用锚定表口径**；
`b1_gate_null.json` 的 1404 系列标注为管线口径。A22.3 交付件写的 582 与锚定表一致。

## 二、第二刀：把"变了的东西"分三类（决定要不要动图 / 动文案）

| 类别 | 本例内容 | 交付动作 |
|---|---|---|
| **⓿ 口径无关项（逐字不变）** | 发明名称、术语定义、四步骤框架、`S = Z₁×w(Z₂)`、`\|Z₁\|≥12`、人侧置换 **24.3× / p=0.005**、图1、图2 | **一个字都不动** —— 这是"没全变"的**正面证据**，汇报时必须**先列这一行**，再讲变了什么 |
| ① **机械连锁数字** | 16,031→16,029；537→582；26.9→29.1；13.4→14.6；12.5×→12.3×；25→24.5；37.4%→38.7%；89%→95.5%；299→341 | **成组替换**——同一公式链，改一处必改一串，**禁只改一半** |
| ② **名单换血 → 图须重画** | 图3 扇区构成 `37+299` → `16+341`；图4 `537/26.9/12.5` → `582/29.1/12.3` | **重画**，不是改数字 |
| ③ **正文点名实体 → 文案须重写** | 有益效果4 点名 GRIA1 / GRIA2 / SYT1 / EPHA5 / EPHA6——**全部掉出 16 子集**，其中 SYT1、EPHA6 连 357 都离开 | **重写实体清单**，不是替换 |

**判据（可直接复用）**——一次口径切换能否只靠 find-replace 交付，看三件事：
1. 有没有**结构性变化**（图的扇区 / 分组构成变）→ 有则必须重画；
2. 正文有没有**点名实体**（基因名 / 样本名 / 通路名）→ 有则必须逐个核对是否还在新名单里；
3. 输出清单的**新旧重合率**（见第三刀）。

## 三、第三刀：重合率阈值（< 50% 就不能只换数字）

**实测（本例）**：

| 集合 | 旧 | 新 | 交集 | 重合率 | 结论 |
|---|---|---|---|---|---|
| 最高置信子集 | 37 | 16 | **9** | **24%** | 名单大换血；6 个基因彻底离开 357 |
| A 级核心清单 | 336 | 357 | **159** | **47%** | 清单换了近一半 |

**经验阈值**：

| 重合率 | 交付方式 |
|---|---|
| ≥ 90% | find-replace 可行（改数字 + 附差异清单核对） |
| 50–90% | 必须随件交**差异清单**（掉了哪些 / 新增哪些） |
| **< 50%** | **禁止 find-replace** —— 清单文件本身必须一起换，否则"交出去的清单"与正文对不上 |

## 四、把"数字变了"翻译成"哪些实体进/出"

用户真正要问的是**后者**，不是前者。本例 37 → 16 的四分类：

| 类别 | 数量 | 明细 |
|---|---|---|
| 两版重合 | 9 | SLC1A2、NRXN1、GLIS3、TNIK、MSI2、SORL1、NRP2、CNKSR2、STXBP5L |
| 掉出 16、仍在 357 | 22 | 猴侧 \|Z\| 跌破 12：ADGRV1(−15.29→−6.74)、SLC4A4(−12.60→−7.49)、GRIA1(−14.68→−5.00)、NELL2(−17.73→−5.36)… |
| 掉出 16 **且离开 357** | 6 | **EPHA6、GRM7、KCND2、NRG3、SYT1、TENM2** |
| 新增进 16 | 7 | RBFOX3、CACNA1B、TMEM132D、KCNT1、LDB2、ADAM12、CRACR2A |

校验：9 + 28 = 37 ✓ / 9 + 7 = 16 ✓ —— 交付前用这类恒等式自检，别让名单表与计数脱节。

## 五、必须主动讲清的隐患（不要等用户发现）

两个名单都**卡在小样本侧门槛上**。大样本侧逐位不变的前提下，小样本侧输入一换，
重合率就掉到 **24% / 47%** ⇒ **这两个名单不具备口径稳健性，换一次小样本导出还会再变一次。**

这与「方向门控有效性前置检验」是同一件事的两面：**人侧证据稳、方法层稳；小样本那一半撑不起 claim 落点。**
归因结论必须连到 claim 分层（见 `premise-falsified-disposition.md` §claim 分层重定位）：
**claim 只压方法层（四步 + w 门控 + 置换定阈值），结论层（元件清单）降级为"实施例输出"。**

## 六、回答骨架（用户问"是不是全都变了"时照这个讲）

1. **一句话结论**：不是"全都变了"——变的全在小样本侧，大样本侧那一半逐位没动。
2. **硬证据表**（第一刀的字段一致率表，带 r 值）。
3. **逐项对照表**：不变项 / 数字（连锁）/ 名单换血 / 须重画 / 须重写 —— **五行分组**，别混着列。
4. **为什么不能只换数字**：① 图结构变 ② 点名实体掉出 ③ 清单重合率 < 50%。
5. **实体拆解表**（第四刀那种四分类），把数字翻译成基因名。
6. **隐患 + 编号建议选项**（claim 分层），让用户拍板。
