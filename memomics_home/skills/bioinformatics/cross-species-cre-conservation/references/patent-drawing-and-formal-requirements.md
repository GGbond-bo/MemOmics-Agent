## 一、附图形式：硬性法规要求（不是偏好，是条款）

**《专利审查指南》第一部分第一章 2.4 说明书附图**（原文已核）：

> 说明书附图应当**使用制图工具和黑色墨水绘制**，线条应当均匀清晰、足够深，**不得着色**和涂改。

**推论（三条，缺一条就会被形式审查发补正）**：

| # | 要求 | 实测判据 |
|---|------|---------|
| 1 | **纯黑白**，不得着色 | 逐图算「彩色像素占比」，须 **0.000%**（判据：`max(|R−G|,|G−B|,|R−B|) > 12` 即判彩色） |
| 2 | 线条均匀清晰、足够深 | 墨迹占比（`sum(RGB) < 600` 的像素比例）落在 **4%–20%** 属正常；< 1% 疑似空白/过淡 |
| 3 | 图面尺寸受格式限制 | 见下方「尺寸」条 |

**交底书正文里的配图不受此约束**——彩色版可保留作内部配图 / 答辩 PPT；但**送代理的附图必须是黑白线条版**。
实践口径：**同一套图出两版**（`figures/` 彩色 + `figures_bw/` 黑白），交底书内嵌黑白版。

**尺寸提示**：附图图面一般控制在 A4 竖版内、尽量竖向绘制。实测本套黑白图 2128×1129 ～ 4039×1823 px @300dpi（≈18×9.5 cm ～ 34×15 cm），横向宽图超过单页宽度时，需要代理机构缩排或在交底书里声明版面处理方式——**送代理前与代理人确认一次**，不要自己假设。

## 二、黑白化实现配方（把彩色图改造成线条图）

核心原则：**区分系列只能靠「图案 / 线型 / 标记形状 / 黑白色阶」，不能靠颜色。**

| 彩色图里的表达 | 黑白替代 |
|---|---|
| 同一柱状图多系列不同颜色 | `facecolor='white'` + `edgecolor='black'` + `hatch`（`'//'` `'xx'` `'..'` `'\\\\'`）+ 本方法用**纯黑填充** |
| 散点不同类别不同颜色 | **空心圆**（`facecolors='white', edgecolors='black'`）vs **实心方块**（`c='black', marker='D'`） |
| 双轴折线两条彩色线 | 黑**实线 + 空心标记** vs 黑**虚线 + 实心标记** |
| 直方图两组彩色叠加 | 白填充黑边 vs 灰填充 `0.55` + `hatch='///'` |
| 流程图彩色框 + 彩底标题条 | 白底黑框 + hatch；标题条改 **黑底白字**（专利附图常用反白标题） |
| 图例色块 | `Patch(facecolor=..., edgecolor='black', hatch=...)` |

**全局 rcParams（务必显式设，别只设 `facecolor`）**：

```python
plt.rcParams['figure.facecolor'] = 'white'
plt.rcParams['axes.edgecolor'] = 'black'
plt.rcParams['axes.labelcolor'] = 'black'
plt.rcParams['text.color'] = 'black'
plt.rcParams['xtick.color'] = 'black'
plt.rcParams['ytick.color'] = 'black'
plt.rcParams['hatch.linewidth'] = 0.7      # 影线过粗在小图上糊成一片
```

⚠️ **`matplotlib` 默认配色会在若干处偷偷带色**，改造时逐个排查：`barh(color=[...])`、
`grid(color=...)`、`annotate(color=...)`、`axvline(color=...)`、`style='italic'` 之外任何传色参数。
**跑完必须用彩色像素占比实测复验**，不要凭"我改了配色"就宣布黑白——见 `scripts/check_figure_bw.py`。

**中文/英文混排**：轴标签可保留英文数学符号（`$|Z_{human}|$`），但**优先中文**；专利附图不禁止外文，但中文化可读性更好。

## 三、送代理前形式要件清单（交底书完整度，逐项打勾）

| # | 要件 | 规则依据 / 实践 | 状态判据 |
|---|------|----------------|---------|
| 1 | **摘要 ≤ 300 字** | 实施细则形式要求 | 逐字计数（中文字符），实测 v13 压到 **300 字**＝卡上限，留余量更稳 |
| 2 | **摘要附图指定** | 「说明书有附图的，应当指定一幅最能说明技术方案主要技术特征的附图为摘要附图」 | 全文 grep「摘要附图」须**有命中**（零命中 = 未指定） |
| 3 | **附图标记说明** | 说明书应对附图标记作说明（图 1 各步骤 ①–⑤ 应可标引） | grep「标记」须有命中 |
| 4 | **检索记录** | 交底书不强制，但**送代理前附检索式 + 命中清单 + IPC 分类号 + 对比文件 D1–D3**，代理人写创造性论证会省一大截 | 无 = 待做 |
| 5 | **每条从权的实施例落点** | 从权写了 N 种方式，实施例须至少各有一种落点 | 逐条核对（实测：权 5 写了「年龄标签置换 + 同源对应关系置换」两方式，实施例只有前者 → 后者补写） |
| 6 | **下游用途从权要有实施例** | 权 10 仅并列 3 项用途、无实施例 → 支撑力薄 | 补一段可执行的下游用法 |
| 7 | **样本量偏小的从权要补 z 值** | 权 12 只有 n=8/24，n 过小易被质疑；若该门控有**配对 z=+3.27 / +3.09**（高于匹配零假设）应补进表/正文 | 数值可核 + n 的边界如实写 |
| 8 | **数字格式统一** | 同一数字两种写法（`1,409` vs `1409`）是形式瑕疵 | 全文统一（千分位） |

**本轮（2026-09-12）实际遗留项 = 上表 1/2/3/4/5/6/7/8 中 4–7 未做**：
检索记录 🟡、摘要附图 🟡、权 5 同源对应关系置换实施例 🟡、权 10 下游用途实施例 🟡、权 12 支撑力 🟡（已有 z=+3.27 可补强）。
**教训**：这些在 v9→v14 六轮内容修订里**从来没进过修订清单**——每轮都在改数字与论证，
形式要件属于"送代理前必做但内容迭代期不浮现"的一类。**做交付件收尾时，先把本表当 checklist 过一遍**，别等用户逐项点名。

## 四、中文法规/专利信息的在线查证路径（网络受限时的可用源）

**判据：不是"某搜索引擎不能用"，而是"一次写多源探测脚本，把可用源找出来"。**

可用性实测（2026-09-12，本机）：`www.baidu.com` 200 / `www.cnipa.gov.cn` 200 / `www.so.com` 可出结果页 /
`patents.google.com` 与 `duckduckgo` 与 `bing` 与 `google` 均不可达；百度网页搜索页会跳 `wappass` 验证码页；
搜狗跳 `antispider` 反爬页。

**工作模式（可复用）**：

1. **一次写多源探测脚本，不要逐源 curl**——后者触发系统循环检测（见 `platform-execution-pitfalls`）。
   脚本骨架：`urllib.request` + 桌面 UA + `Accept-Language: zh-CN` → 多编码 fallback（`utf-8` → `gb18030` → `gbk`）
   → 剥 `<script>/<style>/<tag>` → 压缩空白 → **按关键词打印前后 ±150 字上下文**。
2. **关键词带引号原文**（如「黑色墨水」「不得着色」「附图应当」）比长句命中率高。
3. **能拿到法规原文摘要即够用**（本次由结果页摘要拿到「附图应当用制图工具和黑色墨水绘制，线条应当均匀清晰，
   不得涂改」，与《审查指南》2.4 一致）；**引用时写条款号 + 注明"原文经检索页摘要核到，建议送代理前由代理人复核"**，
   不要断言"我读了官方 PDF 原文"。
4. **URL 里含中文必须 `urllib.parse.quote()`**，否则 `UnicodeEncodeError`（本次实测一次踩中）。
5. ⛔ **不要用内联 `python -c "<含中文的长命令>"`**——全角括号/引号会触发 `SyntaxError`，
   且重试会被记成"连续失败 N 次"锁住 terminal。**一律 `write_file` 落成 `.py` 再跑**。

## 五、交付句式（回答"要不要黑白图"这类问题时）

```
规范（条款）→ 现状实测值 → 结论（要不要出）→ 已出的产物路径
```

本次示范：**要**——《审查指南》2.4 要求黑色墨水、不得着色；实测 5 张图彩色像素 4.8%–37.4%；
故另出 `figures_bw/`（彩色像素 0.000%），彩色版保留作内部配图/答辩 PPT。
