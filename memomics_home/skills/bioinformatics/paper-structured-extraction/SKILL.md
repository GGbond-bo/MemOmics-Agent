# 论文结构化提取（源文本锚定 / 反编造）

把论文提炼成**固定节、可核查、每篇独立分节**的中文结构化摘要。适用对象：本项目 `results/<sid>/data/lit_text/*.txt` 里的论文纯文本 dump、粘贴近文、已导入文献库的 PDF，以及一次任务中的多篇论文。

## 一、核心纪律：禁止编造（最高优先级）

这是本类任务的唯一定死规则，用户常显式给出（"禁止编造：所有数字必须来自原文"）。执行时按以下四条落地：

1. **每个数字都能回溯原文**。准确率/成本/耗时/样本量/统计量/P 值/轮次/参数量——全部取自文本，不推算、不四舍五入到好记的数字、不用"约""左右"掩盖不确定。
2. **未报告项显式标注**「原文未报告」（而非留空或猜）。常见于：数据可用性链接、许可、代码规模、训练轮次、超参细节。
3. **图轴读出的数字必须降级标注**。当数字只能从图的坐标轴/柱高目测得到（正文没有明确写），写入时标注「读自 Fig.X，建议核对原图」，不要当作正文事实陈述。
4. **构建/来源元信息要带可核查锚点**：DOI、代码仓库 URL、HuggingFace/数据 Zenodo 链接、arXiv 号、许可、通信作者邮箱——照抄，不改写。
5. **源文本自相矛盾时，如实并列、不擅自统一**。原文内部可能不一致——例如图注/摘要说"实现了 18 个工具"，而 Methods 逐条列出 19 项；或页首 DOI 与参考文献里的 DOI 不同（常见于 "Article in Press" 未编辑版）。处理口径：**报原文口径的数字**，把逐条清单/另一口径一并列出，并在脚注显式标注差异（"已如实标注，未强行统一"），**不要**悄悄挑一个数、也不要自己加减对齐。矛盾在同一篇论文里往往不止一处，**逐条扫**；常见类型见 `references/deep-structured-extraction.md` §F「矛盾类型学」。
6. **每条数字后带原文行号出处**（最强可核查性）。源文本是 txt dump 时，交付里给每个数字/断言标 `（第 X–Y 行）`。这让用户（和自己复扫）能秒级回原文核对，把"禁止编造"从承诺变成可验证的机械事实。落盘文件与回复正文都带行号。
7. **核对用户给定标题 vs 原文实际标题**。用户给的标题常是简称/描述性标题（如《paper2Agent: Automatic generation of AI agents from research papers》《CASSIA: A multi-agent framework for interpretable and consensus-based cell type annotation》），与原文实际标题（"Reimagining research papers as interactive and reliable AI agents" / "CASSIA: a multi-agent large language model for automated and interpretable cell annotation"）**不一致**。元信息里两个都写清并标注差异，**不要**默认题名就是原文名。

> 反向检查：交付前对每一个出现的百分数/金额/倍数问一句"这句原文在哪？"。答不上就删或标注。

## 二、固定节模板（10 节，每篇独立分节）

对**每一篇**论文按以下 10 节输出，节标题统一、顺序固定，多篇各自成一级标题分节：

1. **元信息**（表格）：标题 / 作者 / 通讯+邮箱 / 机构 / 期刊或类型+年份 / DOI 或 arXiv 号 / 代码仓库 / 数据可用性 / 许可
2. **一句话定位**（≤40 字）
3. **研究思路**：核心设计哲学、系统/实验架构、关键策略、agentic 探索循环、与已有工作的差异
4. **解决什么问题**：痛点一句话说清
5. **工作量与内容**：团队/机构、构建产物清单、任务/数据规模、训练或演化轮次、模型清单、硬件
6. **怎么测试**：评测设计、对照基线、专家打分与一致性、统计方法、消融、对抗/鲁棒性测试
7. **Benchmark 与数据集**（表格）：名称/来源 / 规模 / 说明
8. **关键结果数字**（表格或分块）：逐条原文数字
9. **局限**：拆两小节——① **作者自述局限与免责边界**（原文明确承认的）；② **我发现的原文自相矛盾**（逐条列出，每条标两处出处行号）。二者分开，别混为一谈。
10. **可复用信息**：可复用组件、开源地址、许可、前瞻主张、**对做同类系统的借鉴点**（本节最有价值，写给下一班人用）

（可选）全部写完后追加一段**跨篇对比速览表**——本类任务多篇同题材时非常有用；但每篇的独立分节不可省略。

完整模板（含每节要点与变体：AI-agent 方法论文 vs 实验论文 vs 综述）见 `references/deep-structured-extraction.md`。

**变体：组学论文精读报告（scRNA-seq / 空间转录组，QC 参数为重点）** —— 当用户要求「精读 N 篇文献 / 逐篇产出中文
结构化精读报告」且对象是组学论文（scRNA-seq / snRNA-seq / Stereo-seq / Visium / 多组学），并带「含精确质控参数」
「务必带英文原文引用作为证据」这类要求时，改用 **7 节模板**（研究问题与结论 / 样本与数据规模 / 生信分析全流程 /
**质控参数（重点）** / 细胞类型注释与 marker / 下游分析 / 数据与代码可用性）+ 末尾「两篇对比表」与
「空间 QC vs scRNA QC 差异」专节。该文件含 scRNA 与空间各自的 **QC 参数抽取清单**、QC 关键词机械核验 grep、
空间/scRNA QC 差异知识库，以及 Stereo-seq / Visium 平台 QC 指纹。见 `references/omics-qc-reading-report.md`。

**变体：四段式方法学对比（多篇 · 无固定 10 节）** —— 当用户要的是「**按文章分别讲**背景 / 用了什么测序方法 /
用了什么质控标准 / 用了什么参考与分析标准」这类**横向对齐的方法学梳理**时，不要硬套 10 节或 7 节模板，
直接用**四段式**（背景 → 测序平台与文库 → **质控阈值标准** → 参考基因组与分析工具/统计标准），
每篇独立分节，末尾追加**跨篇对比表**（阶段 / 平台 / 质控后规模 / 关键阈值）与
**跨篇不一致清单**（同类阈值口径不同、参考基因组版本混用等），后者是本类交付最有价值的部分。
若用户在意图确认里勾选了「质控阈值标准」「分析工具与统计标准」两项，则这两栏要**逐句原文展开**
（阈值、参数名、工具版本号、检验方法、多重检验校正），其余两栏压缩。

## 三、执行流程

1. **定位源文本**：先 `search_files(target=files)` 或 `wc -c` 确认文件与体量；大文件（数万~十几万字符）**不要一次读完**。
   - **源文本还没落盘时（用户直接丢来 PDF）**：先做出版级版式恢复再谈提取——双栏期刊用
     `professional-paper-interpretation/scripts/pdf_2col_extract.py`（按 x-中心分栏，逐页 txt + 结构表），
     caption 锚点裁图用同目录 `scripts/crop_figures_by_caption.py`；配方与坑见该 skill 的
     `references/pdf-layout-recovery.md`。**别用 y 分桶排序**（会把左右栏静默交错），
     也别写只匹配 `^Figure\s+S?\d+\.` 的 caption 正则（Cell 补充图是 `Figure S1:` 冒号，会全漏）。
2. **分块精读**：用 `read_file` 带 `offset`/`limit`（每次 400–500 行）逐段读完全文，**含 Methods / Appendix / 参考文献后的附录**——关键的数字（容差、轮次、数据集 counts）常藏在 Methods 和 Appendix。
3. **验证关键串**：对要写进摘要的核心断言，用 `search_files(target=content)` 复核确实出现在原文。
4. **起草**：按第二节 10 节模板逐篇写。
5. **落盘 + 回复**：把完整结构化摘要写入文件（默认放 `results/<sid>/data/paper_structured_summaries.md` 或用户指定路径），**同时**在回复里给出结构化摘要本体（本类任务的交付物就是这份摘要本身），并在末尾附「交付物/执行说明」（新建文件路径、需复核项）。
   - **分支：用户明确要求「只对话里回答，不落盘文件」时**（常见于意图确认弹窗勾选该交付项），
     **不要落盘交付文件**——回复正文就是交付物，照旧给全（长不是问题）。
     同时必须**声明工作文件的非交付物地位**：PDF 纯文本 dump、检索命中日志、收敛抽取脚本等
     属**中间工作文件、不是交付物**，在回复末尾列出其所在目录并说明"可直接清理"。
     ⛔ 不要因为"没落盘"就削减正文内容，也不要把中间产物当成交付物递给用户。
6. **收尾自检**：逐条回扫所有数字；把只能从图标目测得到的段落加上「建议核对原图」。

### 多篇（N≥5）语料的收敛式抽取（省上下文的关键）

一次处理 ≥5 篇、每篇数万字符时，「逐篇 read_file 分块精读」会直接吃掉上下文预算
（7 篇 × ~2000 行 ≈ 15 万字符），而宽 grep 的输出更占地方（1476 行 ≈ 20 万字符）。
改用**两步收敛**，把「读全文」降级为「读命中句 + 定点回读上下文」：

1. **先落盘 + 解析健康检查**：批量 PDF → 纯文本，同时打印**页数 / 非空页数 / 字符数**；
   非空页数明显少于页数 = 有解析残页（换 `get_text("blocks")` 或 pdftotext 复核），
   字符数/页 < 500 = 扫描件（改走 OCR）。脚本 `scripts/pdf_corpus_extract.py`。
2. **一级宽检索定位，但不要读它的输出**：按 13 类检索式扫全语料，
   **输出重定向到日志文件**，只 `wc -l` + 看每篇 `###` 分节行号。
3. **二级收敛抽取**：只保留「**同一行里既有数字、又含质控/统计关键词**」的句子，
   每篇压成 ~50 行、按篇拆独立小文件（实测 4–6k 字符/篇），**每行前缀 `L<行号>|`** 锚回原 txt。
   脚本 `scripts/focus_extract.py`。之后才逐篇读这些小文件，需要上下文时
   `read_file(offset=行号, limit=40~55)` 定点回读原文。
4. **核对轮（不可省）**：收敛抽取必然丢上下文，每个要写进交付的阈值句都要回原文确认——
   重点防「**同类不同口径**」读混：线粒体 `<5% 保留` vs `>10% 剔除`、`min_gene/min_cells`、
   是否还有 `800–6000` 这类**区间**口径、`MAPQ`、bin 大小、read 级过滤（MID/CID/质量分）、
   参考基因组版本（hg19 与 hg38 可能**同篇混用**）。

> 何时**不要**用：只 1–2 篇（直接分块读完更省），或用户要的是叙事逻辑/写作策略解读
> （走 `professional-paper-interpretation`，收敛会把论证链切碎）。
> 完整配方、预算基线、判读表见 `references/multi-paper-qc-corpus-scan.md`。

## 四、Pitfalls

- **不要只读正文就读完**：PDF→txt dump 里 Methods/Appendix 常在文末、且被参考文献隔开，容易漏读；关键参数、tolerance、subset 准确率常在那里。
- **`search_files` 返回 0 不代表内容不存在**：含特殊字符的查询串（如带 `.`/`-` 的版本号 `Qwen3.5-4B`、或用 `|` 交替的多模式）可能漏匹配，即使该串你在正文里亲眼见过。**grep 意外为 0 时用 `read_file` 直接读该行区域复核，不要据此判定"原文未报告"**。
  - **三种已实测的 0 命中诱因，按顺序排查**：① **传目录 + `file_glob` 常静默失效**（同一 pattern 对目录返回 0、改成**传文件路径本身**立刻命中 2 条）；② **多词/含空格的交替式**（`spots were|spots retained|total of`）返回 0，**单个字面量 token**（`38,562`）正常命中——先降级成最短的字面量再逐步加长；③ pattern 里的数字用 `\d` 简写可能不识别，改写字面数字或 `[0-9]`。三条都试过仍为 0，才允许写"原文未报告"。
  - **④ 先跑对照词，再拿 0 命中当结论**：用**一个必然出现的字面**（如 `cell`）搜同一语料，命中数正常才证明检索通道可用；
    此后**单词字面量的 0 命中才可以当"证据性否定"**。实测（7 篇人类胚胎文献）：对照词 `cell` 命中 1,593 处 →
    同一通道下 `snRNA` 0 命中、`nucleus` 仅 3 处且全在抗体染色描述里 → 可下结论"7 篇无一为单核 RNA"。
    通道未验证就把 0 命中写成"原文未报告"＝**把工具缺陷当成论文事实**（本会话首轮 `nuclei|snRNA|...` 交替式返回 0，差点误判）。
  - **⑤ 否定性结论与正数阈值同等值钱，也要落盘**：如"这批文献里没有 snRNA""无人设 counts 下限"这类**排除性发现**，
    下次同类提问可一次答完、不必重跑检索——写进对应 references（本主题见 `references/human-embryo-gastrulation-qc-bank.md` §七）。
- **图轴数字是最容易造假的点**：作者把某几个数只放在图里（如各任务族 before/after），很容易"顺理成章"补一个数。凡是正文没明写、只能从图读的，必须标注「读自 Fig.X，建议核对原图」。
- **多篇必须各自独立分节**：不要合并成对比表湮没每篇；用户要的是「每篇独立分节」。可在全部之后再附一段跨篇对比（可选）。
- **别把论文自带的相关工作叙事当成已核实领域史**：这是论文的自我陈述，转述时要标明来源是"原文所述"。
- **回复过长不是问题、漏落盘才是**：本类任务的交付物是摘要本体，回复里应给出完整结构化摘要；但**同时**必须落盘成文件，且在回复末尾给出文件路径。**例外**：用户明确要求「只对话里回答，不落盘文件」时不落盘（见 §三 步骤 5 分支），但正文仍须给全。
- **"Article in Press" / 未编辑版要标版本状态**：正文含 "We are providing an unedited version…""Article in Press" 声明时，元信息里注明"Article in Press（含未编辑声明）"，DOI 以**页首**者为准并说明；不要把它当成终版 `Version of Record`。
- **源文本数字与清单不一致时不得自行对齐**：见 §一 规则 5。典型坑——图注计数 18、Methods 清单 19；或"表 X 列 N 项"但正文只列了 N−1 项。交付里两边都写、显式标注差异，做一个"风险点/说明"收尾段列出所有此类不一致，交由用户判断。
- **别默认题名就是原文名**：见 §一 规则 7。一次任务两篇论文的**用户给定标题都与原文实际标题不同**（简称/描述性 vs 正式题名）。元信息里两个都写并标差异。
- **回复给全文，别只给文件路径**：本类任务交付物 = 摘要本体。**同时**做两件——回复里给出完整结构化摘要、并落盘成文件且末尾给路径。只给路径 = 交付不完整。**例外**：用户要求只对话回答时，正文给全 + 声明中间产物为非交付物（见 §三 步骤 5 分支）。
- **交付里没写行号 = 可核查性降级**：能用行号就用（见 §一 规则 6）。行号是"禁止编造"从承诺变成机械事实的最便宜手段。

- **组学论文的关键 QC 阈值几乎只在 STAR Methods / Methods，且排在参考文献之后**：漏读文末 = 漏掉全部 QC 阈值，
  这是组学精读最常见的失败模式。必须 read_file 分块读到**文件末尾**再动笔（详见 references/omics-qc-reading-report.md）。
- **空间转录组的「原文未报告」是常态，不是你没找到**：空间 QC 阈值 / 过滤比例 / spot 总数经常整节缺失。
  先用 QC 关键词 grep（spot|percent.mt|min_gene|min_cells|MAPQ|bin50|retained|excluded）核验，
  再写「原文未报告」，并在交付里说明「grep 后确认原文未报告」——让「未报告」也是可核查结论。
  **不要**用平台默认值（如 Visium 55 µm spot、默认过滤）填空冒充原文报告值。
- **过滤比例多为自算**：原文常只给过滤前/后数量。自算的百分比必须标注「据原文数字计算，原文未直接给出百分比」，
  不要与原文字段混排。
- **组学精读的交付形态**：落盘 markdown 报告（results/<sid>/data/<数据集>/reports/<主题>_N篇_结构化精读报告.md），
  **同时**回复里给报告本体 + 一段「核心质控发现」浓缩段（含关键阈值数字）+ 文件路径。
  （用户要求只对话回答时改为：正文给全 + 末尾声明工作文件为非交付物，不写交付文件。）
- **QC 阈值口径知识库（细胞 vs 核）**：判「这批数据是单细胞还是单核」、counts 在单核里**只作上限**
  （约为细胞的一半）、下限交给 nFeature（200–600）——见 `references/snrna-vs-scrna-qc-conventions.md`。
  回答「这批文献有没有做 snRNA / 有没有设 counts 下限」类问题时同理（本主题见 §七）。

## 五、与相邻 skill 的分工

- `literature-full-summary`：文献库内论文的 9 项思路提炼，走 `summarize_paper` 工具（固定 9 项，落库标记 summary_done）。
- `paper-summary`：两级文献解读（Tier1 交互框 + Tier2 深度 HTML 报告）。
- `nature-paper-card`：单篇论文 16 节深度拆解卡片，带 `prepare_paper.py`/`audit_paper_card.py` 脚本管线。
- `professional-paper-interpretation`：专业编辑视角的叙事逻辑/写作策略解读（不侧重字段）。
- **本 skill**：自定义固定节、可多篇、源文本可任意（不限于文献库）、带反编造硬纪律、可交付到任意路径。当用户要的是"结构化摘要/关键信息提取/每篇独立分节"时用本 skill；当用户要的是"HTML 报告/卡片/叙事解读"时用对应 skill。
