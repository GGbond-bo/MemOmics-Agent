## 静默生效后单轮的实际成本（照抄即可）

1. `grep -n "deleg_" results/<sid>/notes.md` → 命中该批核销行，且行内含「后续同批重放**静默**处理」；
2. 交付物字节数比对（DOCX / HTML / MD 字节数 + CSV 行数）—— 与台账末条逐位一致 ⇒ 无真事件；
3. 回四块（判定 / 证据链层级 / 指纹 / 台账已有条目），**零写入**。

全程 **1 次 grep + 1 次探针**：不碰 store、不重跑 5 项 diff、不重派、不重读全文。

## 两条口径纠正

1. **台账条目数 ≠ 到达次数**。静默后不再 append ⇒ 行里的 `replay#N` **冻结**在首次记下的 N。
   正文第 ④ 块写「台账已有条目（末次 <日期> · 累计重放序号 ≤N）」或直接「静默中」，
   ⛔ **不要声称「这是第 M 次到达」**（M 取不到，编出来就是把一条未经证据支持的计数写进交付回复）。
2. **不要回填台账去维护计数器**。回填 = 恢复每轮写入 = 正是 4-b-ii 要止住的开销（该批实测已堆 8 条同结论条目）。

## 反面（本会话实测过的越界提议，已同时写进 SKILL.md §二 开头「不能说的话」）

- ❌「把去重写进 skill 的回执表，之后同类重放直接静默丢弃」—— 重放是**框架的投递行为**，
  `SKILL.md` / `notes.md` 都只是**读侧**；实测 10-07 写下之后，同一批仍持续到达。
  能给的止血只有「把单轮成本压到一次 grep 一跳定案」。
- ❌「静默丢弃」= 跳过台账 grep —— 台账行带**交付物字节数**，字节数一变（交付物被重建）旧结论即失效。
  允许的最省形态是「台账命中 + 字节一致 ⇒ 零写入」，**不是「不查」**。

## ✅ 可直接复用的汇报形态（dsh-ui 三件 + 围栏外一行）

```
判定：重放（静默中）· 不重派 · 主数据与交付物零字节改动
```
