```bash
# ② 判归属：从批次的 task-*.log 里抽会话号并计数

```

⇒ **命中他会话 ⇒ 铁律 -5 session 隔离**：不读产物、不合并、不接管、不重派。

## 3. 为什么三条「看起来像」的证据都不能用

| 假证据 | 本轮实测 | 为什么不算 |
|---|---|---|
| **主题同域** | 3 批是 AI-agent 文献结构化提取；本会话是 AI-agent 竞品定位 | 同一研究项目的相关子任务，主题必然重叠 |
| **SKU / 专名重叠** | 本会话 store 里 `CASSIA` 13 次、`ChemCrow` 8 次、`Biomni` 3 次 | store 里出现过该名字 ≠ 这批内容是我们合并的（可能是正文引用） |
| **时间上「比上轮新」** | 批次 10-11 17:5x；本会话 task_plan 10-13 更新 | 时间序只能**触发调查**，不能定归属 |

同理**台账零命中**也不是「未合并」的证据 —— 它只说明「本会话没记过这个 id」，
既可能是本会话的未记批次，也可能是他会话的批次；必须靠 ② 分流。

## 4. 缓存根位置：两个候选都要 `ls -d` 过再下结论

```
memomics_home/cache/delegation/   ← 本轮实测批次的真实位置（live/ 在其下）
hermes_home/cache/delegation/     ← 旧安装形态（目录改名前的根），部分回执页脚印的就是它
```
⛔ 一次 `ls`（或一条 `find`）的 MISSING 不是「批次不存在」的证据 —— 先 `ls -d` 两个候选根，
再决定（与 §二 ⓪-k ①「find 先行」同族）；回执页脚自己印的 `Full live transcript:` 路径**优先照抄**。

## 5. 收尾形状（这类轮次不是纯重放，正文与台账都要写）

| 动作 | 写什么 |
|---|---|
| `notes.md` | **一行**：`[replay#N] live/ 里 3 个 10-11 批次 = 外部会话（grep 命中 memomics-75ba0499 ×35，本会话 ×0），按铁律 -5 不接管`＋本会话自身的三源复核值（指纹 / 卡数 / 交付物字节） |
| `task_plan.md` | **一行 checklist + 一行 Decisions**：说明「外部会话批次 ✓ 已甄别，不接管」，`Status` 保持 completed |
| 正文 | 报「外部会话批次 · 不接管」+ 本会话终态结论；⛔ 不推进 Phase、不合并、不把甄别过程写成交付物 |

**为什么要落这一行**：不落，下一轮唤醒看到同 3 个目录会**再查一遍**（会话号 grep + 主题比对 + 台账复核），
每轮重复烧上下文。归属事实属于「跨轮锚点」——写一行即永久关闭这条调查线。
⚠️ 边界：**同一批次**的重放不再追加台账行（§二 4-b-ii 静默规则）；本条针对的是**首次甄别出的新事实**，
两者不冲突：一个是「同批再来」，一个是「新类别第一次出现」。
