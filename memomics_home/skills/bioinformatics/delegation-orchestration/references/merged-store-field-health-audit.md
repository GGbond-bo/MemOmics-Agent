# 已合并 store 的字段健康审计（重放轮顺手做）

> 场景：回执已判「迟到重放」→ 主数据一个字节都不动。**但这不等于什么都不看** ——
> 顺手对 store 做一次便宜的字段健康扫描，往往能抓出上一轮**真正漏掉的内容缺陷**。
> 实测（2026-10-07 第四次回执 `deleg_15d8b24b`）：判定重放的同时抓出 n=2 卡 `limitations` 被截成 8 字。
> 直接跑 `scripts/audit_store_field_health.py`。

## 一、逐字段长度分布（主力手法）

对 store 全部记录的每个核心字段，算 `min / p25 / median / max`：

```
architecture    min=  337(n=26)  p25=  456  median=  823  max= 1560(n=45)
inputs          min=   29(n=29)  p25=   56  median=   73  max=  191(n=7)
limitations     min=    8(n=2)   p25=  149  median=  184  max=  431(n=45)   ← 离群
evidence_quote  min=   91(n=4)   p25=  128  median=  157  max=  244(n=1)
```

判读：**同一字段内 min 与 p25 差一个数量级 → 那个 min 是缺陷，不是风格。**
`limitations` 的 p25=149 而 min=8 ⇒ n=2 那张卡内容丢了。

## 二、⛔ 尾部标点启发式：对中文卡片是垃圾，别用

第一直觉是「结尾无句号 = 被截断」。实测**不可用**：

```
尾部 14 字无任何标点的字段 = 54 处   ← 其中真缺陷 1 处
```

原因：这批卡片的既定文风是**不写句尾句号**，字段本来就以名词短语收尾
（`…与后续随访实验建议` / `…各 agent 贡献` / `…architectures`）。
把这 54 处当缺陷去「修」= 把好数据改坏 + 白烧一轮。

**可靠判据只有一个：字段长度 < 25 字。** 用长度，不用标点。

## 三、合法短值白名单（否则 5 个假阳性）

观点文 / 综述文**本来就该**是短字段，扫出来不许当缺陷：

| 值 | 出处 | 为什么合法 |
|---|---|---|
| `无量化评测` | n=26（SDL 综述） | 综述本身无基准 |
| `无量化评测（观点文，无实验基准）。` | n=11（MCP 生态观点文） | 同上 |
| `未披露（综述性质，未固定底层 LLM）` | n=26 models | 综述不指定模型 |
| `无（综述论文，未做真实数据或湿实验验证）` | n=26 validation | 同上 |

⇒ 脚本里配 `LEGIT_PATTERNS`（含 `无量化评测` / `未披露` / `无（` / `不适用`），命中即跳过。
**先跑再判**：全库 <25 字的字段共 5 处，剔掉白名单后剩 **1 处**真缺陷。

## 四、真缺陷长什么样 + 怎么补

实测样本：`n=2`（PMC13573717，*Closing the Empirical Loop*）`limitations = "作者自陈：物理能"`（8 字）。

- 特征：以「作者自陈：」这类**引子**结尾 ⇒ 引子后面的正文整段丢了。
- 补法：回**源全文**取原句，别自己编 ——
  在该文 `data/text/PMC<id>.txt` 里定位 `Limitations` 段（本例 `re.finditer(r"(?i)\bLimitations?\b")` 命中偏移
  70392/70601/70682/71113，取 §4.2），原文对应句为：
  > “currently its physical capabilities are domain-constrained to online experiments for which the necessary
  > tools and interfaces are available”
- ⛔ 改完 store ≠ 完事：DOCX / HTML / positioning md 里的该卡段落**同时过期**（见下节）。

## 五、🔴 冻结交付物：只报告，不擅自改

发现缺陷时**不要顺手把 store 打上补丁**。两个理由：

1. **会产生分裂状态**：只改 `cards.json` 而不重建 `positioning_full.md` / DOCX / HTML ⇒ 交付物内部自相矛盾，
   用户审阅时看到的是旧的那句。
2. **用户的既有偏好**：本项目/本用户明确要求「只改指定清单项，顺手发现的问题**单列出来问**」——
   发现即改 = 越过授权，改的又是**已冻结**的定稿（本例 20:36 定稿，用户可能正在审阅）。

**正确动作（三步）**：
1. 报告时把它**单列成一条**，附上从原文取回的**原句**（让用户一句话就能批）；
2. 明说影响面：「需重建定位文档受影响段落」/「可并入下一轮批量升级一起做」；
3. 写进 `notes.md`，防止下一轮又当新发现重新报一遍。

## 六、附带：系统注入的「路径不存在」警告要先核实再转述

同一轮里，会话要求块标注：

> ⚠️ 以下要求中的路径不存在，请向用户核实：`E:\文献\AI\Closed-loop transfer enables a(…`

实测 `os.path.exists()` **为真**（同目录 2 个文件）—— 警告是**字符串被截断显示**造成的误报
（注意警告里的路径本身在 `…enables a` 处被切断了）。

⇒ 规则：**系统注入的资产警告也是「声明」不是「事实」**，先 `os.path.exists` / `glob` 实查，
确认无误就在汇报里**就地更正**（「那条警告是显示截断的误报，无需处理」），
⛔ 不要原样转述给用户，否则会让他去查一个根本不存在的问题。
