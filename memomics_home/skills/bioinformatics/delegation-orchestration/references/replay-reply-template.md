## 二、新加的最便宜一条断言：mtime 时序

| 断言 | 取数 | 判读 |
|---|---|---|
| **store 合并件 mtime < 交付物 mtime** | `os.path.getmtime`（`cards.json` / DOCX / HTML） | 合并**之后**确实重出过交付物 ⇒ 交付物必然含该批 |

实测：`cards.json` 01:39:12 < DOCX 01:40:12 < HTML 01:41:06。
优点：一次调用、不依赖 store 字段名（不怕代次字段被覆盖重写）、**比字节指纹更抗「值抄错」**
（字节指纹可能照抄 SKILL.md 里的历史值 ⇒ 四项全报「正差异」⇒ 误判新工作，见 §二 第 5 项踩点）。
与 §二 ⓪-b「合并时间戳 < 交付物 mtime」互为印证。放进第 ③ 块。

## 三、非四块内容的路由表（本规则的核心）

| 内容 | 去处 |
|---|---|
| 判定 / 证据链层级 / 指纹 / 台账已记账 | **正文四块**（唯一允许出现在回复里的内容） |
| 待决项、挂起项（含「已 N 轮无答复」「想推再说一句」「要不要看某篇」） | 只进 `notes.md` |
| 已闭合缺陷的销账说明（上轮报过、已被后续轮次补上的窟窿） | 只进 `notes.md`（销账本就写在台账里，正文不得重报） |
| 系统注入警告的更正（`路径不存在` / 渲染伪影 / 单层 `ls` 报 MISSING） | 只进 `notes.md` 一行 `[已核] …` |
| 「本轮省了多少成本 / 止血手段在哪」的自我说明 | 只进 `notes.md` |

判据本质：**回放轮的证据已全部进四块与台账；正文再出现任何新句子，都只是某个挂起项在借尸还魂。**

## 四、发送前扫描清单（一次动作，零记忆量）

扫**整条回复**（含首行标题、dsh-ui 卡片、收尾句），命中任一 ⇒ **整段删掉**（不是改措辞）：

`挂起` · `已连续` · `无答复` · `再说一句` · `要不要` · `想推` · `第 N 次重放` · `replay#` ·
`路径不存在` · `伪影` · `仍等你` · 以及待决项的**名字本身**

⛔ 三个已实测踩过的「换皮」台阶，一律不认：
1. 措辞从追问换成汇报（「已连续 4 轮无答复，按协议降级为挂起」）；
2. 改成 `[挂起 · 非阻塞]` 标注；
3. 加一句「不再逐轮追问」的自我安慰 —— 它既是汇报、又把项名重新推回用户眼前。
