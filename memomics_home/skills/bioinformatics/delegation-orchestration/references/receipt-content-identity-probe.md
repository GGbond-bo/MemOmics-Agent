# 回执内容同一性探针（键存在 ≠ 本批贡献）

## 触发
重放判定走到「该批的 n 键在 store 里**全都在**」时 —— **⛔ 不要就此定案**，补一次本探针。

## 陷阱（本轮踩到的那一类）
`键存在` 只证明「这些 n 有卡」，**不证明「这些卡是本批写的」**：

- store 的 n 是**全库共享坐标**（本例 31 张卡 = 两批并集）⇒ **任何一批**的键都会「天然存在」。
- 升级轮 / 补派轮会**覆盖式重写**同一条卡（§二 ⓪ 第二类假阴性）⇒ 键在、内容却是别批的。
- ⇒ 拿键存在当「已合并」证据，会把一个**从没进过 store 的批次**判成重放 = **真缺口被吞掉**。
- 反向也成立：键集并集相等 + 闭环不变量都对，仍是**计数级**证据，不排除「A 批的卡被算进 B 批」。

## 配方（receipt-text ↔ store，一次 `execute_python` 搞定）

从**回执行文本身**取 2–8 条**高区分度逐字片段**，逐条断言 `fragment in stored_value`：

| 片段来源 | 取值 | 为何抗截断 |
|---|---|---|
| 字段**开头句** | `architecture[:~30]` | 回执截断发生在**中段**（§二 ⓪-c），首句必在 |
| **末尾字段** | `evidence_quote` 全文 | 卡的最后字段，短（<200 字符），整体可见 |
| 关键数字 | `Recall@1 57.18%` / `pLDDT 0.94` 等 | 数字最难被别批碰巧写同 |

```python
for k, (field, frag) in checks.items():
    it = store[k]
    txt = it.get("architecture", "") if field == "arch_head" else it.get(field, "")
    print(k, field, "MATCH" if frag in txt else "MISS")
```

- **全中** ⇒ 本批文本**就是**落盘那一份 ⇒ 判重放、零写入。
- **未命中但键存在** = 危险信号：先 `print` 两侧原值（可能只是口径：大小写 / 全半角 / 片段取在了截断点上），
  ⛔ 不许直接跳到「重做」——那正是本条要防的错。

## ⚠️ 三条纪律

1. **片段必须避开回执的截断点**：回执正文可能被削成 `head 1500 + tail 500`（§二 ⓪-c）。
   取 `architecture[:30]` 或末尾 `evidence_quote`；⛔ 不要取 `architecture[500:600]` 这类中段。
2. **片段必须是「只有该字段值里才会出现的专名 / 数字」**（同 §二 check 3 的口径卫生）；
   ⛔ 短通用词（`thin` / `缺口`）会假阳（实测 `thin` 命中 `thinking`）。
3. **证据链汇报写实**：本轮 diff 的是「**回执正文短片段 ↔ store 字段值**」，
   ⛔ 不要包装成「散件 ↔ store 的逐字段 diff」（后者本轮一次都没跑）。

## 便宜的旁证（可与上式同轮取）

- **派发时序自证**：`回执 dispatched 时间戳 < store mtime` ⇒ 内容**必然**已含入
  （本批 dispatched `10-07 19:14:45` < `cards.json` mtime `10-08 01:39:12`）。
  ⚠️ 用的是 dispatched **时间戳**（它虽不能判「这批新不新」，见 ⓪-g，但作为「早于 store 写盘」的**下界**是安全的）；
  ⛔ 不要用 `(Nm ago)`。
- **库指纹跨轮比对**：`md5(cards.json)` 与台账历轮值逐位一致 ⇒ 整库未动。
  本项目口径用 `md5`；换算法必须在台账注明（⓪-k ③）。
