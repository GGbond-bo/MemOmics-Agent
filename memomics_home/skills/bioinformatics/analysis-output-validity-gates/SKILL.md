# 分析产出有效性门（Analysis Output Validity Gates）

## 核心原则

> **退出码 0 ≠ 结果有效；文件非空 ≠ 内容有意义；日志有 ✓ ≠ 分析成立。**

生信工具（尤其 pySCENIC / 分布式 / 多步骤管线）会在**参数或数据口径错位**时**静默降级**：
照样打印 `✓ completed`、照样写盘、行数形状都正常，但数值已经是垃圾。
**唯一可靠的防线是「可量化的不变量断言」**——每条断言都必须能自己算出一个数字（命中率、非零占比、
交集数、维度匹配），断言失败就报错、拒绝产出、拒绝汇报"分析完成"。

**禁止**：产出异常时先说"分析完成"，等用户质疑才发现无效。
**必须**：先自证（算出数字）→ 通过才汇报。

## 一、产出有效性硬校验清单（通用四问）

对**任何**交给下游/写进结论的结果表，依次回答：

| # | 问题 | 怎么答（要算出数字，不是眼看） | 不合格的信号 |
|---|------|------------------------------|-------------|
| 1 | **标识符对得上吗？** 结果 ID 命名体系和输入是同一套吗（HGNC vs ENSEMBL、带不带版本号、大小写） | `len(set(结果ID) & set(输入ID)) / len(结果ID)` | 命中率 < 0.9 → 口径错位 |
| 2 | **数值分布合理吗？** 是不是全 0 / 全 NA / 全同一个值 | `(arr > 0).mean()`、`np.nanmean`、`pd.Series.nunique()` | 非零占比 < 0.5、唯一值 = 1 |
| 3 | **形状/维度对得上吗？** 行列、ID 顺序、分组水平数 | `shape`、`index.is_unique`、`value_counts()` 与预期水平数比对 | 维度对不上、ID 重复 |
| 4 | **生物学/统计方向说得通吗？** 效应量符号、量级、组间关系 | 与知识库/文献已知方向比对；关键 marker 是否出现在该出现的位置 | 方向相反、量级离谱 |

把四问写成脚本（**每步分析都做**，不是最后统一做），断言失败直接 `raise`，不要 try/except 吞掉。

## 二、静默失败的「症状特征」速查（一眼认出）

| 症状 | 典型根因 | 深入 |
|------|---------|------|
| 结果表里出现**单字符**条目（`[`、`(`、`'`、单个字母） | 一个 str 被当成「列表/集合」逐字符迭代 | [references/prune2df-targetgenes-stringification.md](references/prune2df-targetgenes-stringification.md) |
| 整张活性/打分矩阵**全 0**，summary 也全 0（不是"算得低"） | 输入基因集与表达矩阵零交集（上游 ID/类型错位） | 同上 |
| 行数正常但**每条都是同一个值/权重 1.0** | 解析失败走了 fallback 默认值 | 同上 |
| 工具刷屏打印 `Less than N% of the genes ... are present` | **不是无害 warning**，是 ID 错位告警，命中率接近 0 | 同上 |
| 中间表列名对不上（`KeyError`），且发生在**最贵的步骤之后** | 自写代码猜了上游 DataFrame 的列结构（MultiIndex / 列名被截断） | 同上「列结构先看清再写」 |
| `MemoryError: Unable to allocate 1.93 MiB` + `FutureCancelledError: finalize-... cancelled for reason: unknown` | **不是代码 bug**：worker 被 OOM 杀掉 → scattered 数据丢失 | [references/distributed-worker-oom-vs-code-bug.md](references/distributed-worker-oom-vs-code-bug.md) |
| 产出**数值齐全、分布像样**，但显著率高达 50–99.7%，或比对照方法多几十到几万倍 | **不是方法改进**：SE 被压小 → 假精度 → 假阳性膨胀（细胞级把细胞当独立 n） | [references/statistical-inflation-diagnostics.md](references/statistical-inflation-diagnostics.md) |
| 模型公式里写了随机效应 `(1\|donor)`，但加与不加 SE 几乎不变（如 0.050 vs 0.052） | 随机效应**没进 SE** → 方差结构未被吸收，等同没做校正 | 同上（第三节） |

## 三、失败归因决策树（先归因，再动手）

```
跑失败 / 产出可疑
  ├─ 进程崩了、有 traceback
  │    ├─ traceback 里有 MemoryError / ArrayMemoryError / "Unable to allocate" / worker removed
  │    │    → 归因【内存】。先量资源余量（Windows 看 commit 上限！），再定并发。禁止反复改代码重试。
  │    │    → 见 references/distributed-worker-oom-vs-code-bug.md
  │    └─ KeyError / TypeError / AttributeError 发生在"导出/汇总"步
  │         → 归因【自写代码猜了上游结构】。先 print 上游真实列/类型，再改代码。
  └─ 进程正常退出、产出可疑
       → 归因【口径/解析错位】。跑第一节四问；从最上游产出开始逐层验证（见第四节）
```

**⚠️ 铁律**：同一失败**换并发/换路径重试前**，先确认根因判对了。
本类事故的典型浪费模式是"崩了 → 直接重跑 → 又崩"，每次烧十几分钟。

## 四、最小重跑路径（别从最贵的一步重来）

1. 先列盘上已有中间产物（`adjacencies.csv` / `modules.pkl` / 导出矩阵…），**最贵的一步（GRN 推断、
   比对、训练）几乎总能复用**；
2. 只重跑被修的那一步，并**立刻把该步原始输出落盘**（`*_raw.csv`）——本类事故最亏的是
   "跑完 10 分钟才发现中间表没存，只能整步重来"；
3. 旧（无效）产出**移到 `_old_*/` 子目录留痕**，不要就地覆盖到无法追溯；
4. 重跑后用第一节四问自证，把断言输出的数字写进汇报。

## 五、与平台上其它门的关系

- `rail_review(pre/post)`：平台级质量门（图数量、文件存在性）→ 本 skill 补的是**内容有效性**（数值可信否）。
- `enrichment-conclusion-validation`：DEG→富集**结论**的定稿前验证 → 本 skill 面向**任意产出物**的中间自证。
- 汇报纪律：断言数字必须如实报（"非零占比 100%、基因命中率 0.998"），**不许**只报"分析完成"。

## 六、统计有效性门（数值合理 ≠ 统计可信）

第一~四节管的是「产出是不是空的/错位的」；本节管**第二类静默无效**：
**产出完全不空、数值分布也像样，但统计量在数学上不可能成立**。

> **显著率高得离谱不是"威力更强"，先假定是假阳性膨胀，再用数字证明或推翻。**
> 真实生物学数据里不可能有 50%+ 的基因在同一对比中差异表达。

**六问诊断协议**（逐项算出数字，对照同一批数据的已审查老方法，取单一亚群/对比）：

| # | 诊断 | 膨胀信号 |
|---|------|---------|
| D1 | p 值分布 | p 中位 <1e-10、p<0.001 >90%、p>0.5 <5%（健康：p 中位≈0.5、p>0.5≈50%） |
| D2 | FDR 口径复现 | 自己跑 BH 对不上给出的 fdr 列 → 家族范围不明 |
| D3 | **SE 对比**（新 `se` vs 老 `\|logFC/t\|`） | 中位比值 **>3 即低估**，>20 极严重 |
| D4 | **效应量脱钩** | 显著基因 \|效应\| 中位 ≈ 全部基因 \|效应\| 中位 → 显著性由分母驱动 |
| D5 | 方向指纹（up/down） | 严重单向（如 46:1；健康≈1:1） |
| D6 | 已知阴性对照 | 此前多方法一致的阴性对比被报出成千上万显著 |

**D3+D4 最致命**：D3 给根因（SE 被压小 k 倍 → 有效 n 被高估 k² 倍），D4 给后果。

**必做**：新方法声称含随机效应时，**实测 RE 是否真进了 SE**（同数据跑 RE / 无 RE 两版比 SE；
SE 没变 = RE 没生效）。**"公式里有随机效应" ≠ "SE 反映了随机效应"。**

**查出膨胀后禁止只报"方法不行"**：主分析退回已审查方法 + 给补救路径
（供体级一致性过滤 ≥70% 供体同向 / 换正确建模 SE 的工具）+ 六问数字写进汇报。

**⛔ 不要把"必须 pseudobulk"或"必须随机效应"说成硬规定**（过度绝对化）。
红线只有一条：**样本/供体层变异必须出现在模型里**——pseudobulk、随机效应、
或 RUV/SVA 因子当协变量，**三条途径都合法**。选前先查已发表先例，别凭直觉否定。

→ 完整协议、实测参照值、ICC/细胞深度与假阳性率曲线、四条合法途径对照表：
[references/statistical-inflation-diagnostics.md](references/statistical-inflation-diagnostics.md)

## 七、方法选型类问题的执行纪律（2026-09-29 用户当场纠正，硬约束）

用户问「**哪个 DEG 方法更适合我 / 这个方法合理吗 / 要不要换方法**」时，是**方法学选型**问题，
不是本地数据探查问题。执行顺序不能颠倒：

| 顺序 | 做什么 | 为什么 |
|---|---|---|
| 1️⃣ | **先检索文献**（`search_papers` 定向词 + 官方文档 + 已发表先例的公开代码） | 用户要的是"文献里怎么做"，答案在文献里。本会话先在本机反复探查数据/装包，被用户当场斥责「**我要你去网上找 DEG 的方法呀，文章**」 |
| 2️⃣ | 找**反例**：用户点名的论文/工具 → 拉它的 methods + 公开仓库，读**实际调用** | 用户说"别人怎么就能用 X"是在提供线索，不是抬杠。本会话据此发现 RUV 因子当协变量的合法途径 |
| 3️⃣ | 只在做完 1️⃣2️⃣ 之后，才用本地数据做**定量裁决** | 本地数据只能回答"在这个数据上表现如何"，回答不了"方法是否合法" |

**⛔ 禁止**：用本地探查（装包、试跑、翻历史产物）**代替**文献检索来回答方法选型问题。
那是把可回答的问题拖成了循环。

### 辩论纪律：不要什么都辩（用户原话「不要什么都辩，该做就直接做」）

触发辩论的唯一准绳是 **「辩完能不能改变下一步动作」**。以下情形**直接做，跳过辩论**：

- **呈现层 / 收尾操作**：配色、布局、格式转换、文件移动删除、空白图重绘
- **纯线性命令执行**（ls / cat / mv / 重跑同一脚本）
- **本会话已经辩过的同一议题**（重开一次辩论不产生新信息）
- **活选项 < 2**（没有真正的分歧可选）
- 用户已明确说过"不要辩/直接做"

本会话因在**出图任务**上触发完整辩论并被用户当场纠正过——系统门控提示不等于必须辩，
拿不准就在回复里写明"本轮跳过辩论及理由"并继续交付，**不要用一篇辩论代替交付**。

**⚠️ 第二个入口（2026-10-03 再次踩）：`rail_review(post)` 返回的 `debate_reminder` 也不是强制令。**
"代码包含参数选择或结论输出 — 必须调 debate_analysis 进行辩论"这句对**任何**含参数/出结论的脚本
都会打印，包括纯呈现层任务。呈现层（配色 / 布局 / 图注 / 文件导出）收到这条提示时**照旧跳过**，
在回复里写一句"本轮跳过辩论：呈现层操作"即可。实测代价：一次 30 秒的出图被裁决带出
`need_more_info` + 4 条 `next_actions` + `blocks`，而裁决内容仍是"保留原方案、低置信"。
**判据不变：辩完能不能改变下一步动作。**

### 推翻用户/用户方法之前，先找反例（顺序不可反）

不要在没找到反例的情况下把某个方法说成"不能用"。本会话曾据此把"细胞级 MAST 不能作主分析"
写进 skill，随后被一篇 *Cell* 2026 论文（细胞级 MAST 作主分析）直接推翻，只能全量撤回。
**先找反例 → 读它的代码 → 再决定是"方法非法"还是"我记错了"**。

## 八、效应量阈值门（阈值救不了坏掉的 p 值）

用户在看出膨胀后**下一步几乎必定问**：「那我加个 `|coef| > 0.2` 还是 `> 0.25` 过滤一下行不行？」
这是**第三个独立问题类**（继「产出无效」§一~四、「统计不可信」§六之后），不能当 §6 的尾巴随手答。

> **底线**：效应量阈值只能**减少**假阳性，**不能消除**。先修分母（§6），再谈阈值。
> 用阈值去"救"一个失校的 p 值集合，只会让它**看起来合理**，掩盖根本问题 —— 审稿人第一个问的是 SE 校准。

**回答「0.2 还是 0.25 / 有没有文献支持」的四步（顺序不可颠倒）**：

| 步 | 做什么 | 关键陷阱 |
|---|---|---|
| 1 | **审来源方法的官方代码**，确认阈值是否真写在那里 | 用户方法若源自某论文，别假设它继承了这个阈值。实测猴脑 NHPABC `RUV_MAST_pDEG_MBA.R` **只有 `p.adjust` + 剔 NA coef，无任何 `\|coef\|` 门** |
| 2 | **回原文核对文献阈值（模态 + 统计量）** | ⚠️ 曾把 **0.25 说成「猴脑 RNA DEG 阈值」——错的**：它是 **ATAC** sDARE 的 `P<0.05 & log2FC>0.25`（用的还是未校正 P）。**禁止凭记忆引用阈值**；对不上就是张冠李戴，审稿人一查就破 |
| 3 | **边界带诊断 + z 等效尺度** | 被砍掉那一带（0.20<\|coef\|≤0.25）fdr 仍 `1e-16` 级 → **p 值区分不了两档阈值**，这是生物学判断不是统计判断；θ=0.25 ≡ 要求 **10–21 倍 SE**（惯例 1.96） |
| 4 | **正对照召回率**（领域公认差异基因面板） | 把阈值成本翻译成生物学语言，比讲 p 值有效。实测 θ=0.25 砍掉 Aging 组 **2/3 已知真信号**（33.2%）；要保住 ~80% 需降到 θ≤0.10 |

**措辞纪律**：查不到就是查不到 —— 不要写 "threshold as in <某文献>"，写
"a self-imposed minimal biologically meaningful effect size (≈1.19×, log2FC = 0.25)"，
并**同时**报告显著率 / 边界带 / 正对照召回 / 分母限制声明。

**量纲**：`log2(1.2)=0.263` → θ=0.25 ≈ 1.19 倍。用户说"大于 1.2 倍算初步有变化"时，
**先认可他算得对**，再讲代价（θ=0.25 对失校 p 值更安全，但砍掉 2/3 已知信号）——
冲突时**如实并列，不要粉饰成"更正确"**。能修分母就优先修分母，或改**排名法**（每亚群 top-N / top 5%）。

→ 完整实测表（5 对比组的边界带 / z 尺度 / 正对照召回）、二选一裁决逻辑、methods 措辞对照：
[references/effect-size-threshold-justification.md](references/effect-size-threshold-justification.md)
→ 一条命令跑出上述全部判据：[scripts/coef_threshold_audit.py](scripts/coef_threshold_audit.py)

## 九、集合交并结果的期望值门（交集数 ≠ 发现）

第四个独立问题类（继「产出无效」§一~四、「统计不可信」§六、「效应量阈值」§八之后）。
用户拿着多对比 DEG 表问「三组交集有什么 / 衰老上调但运动后下调的有哪些」时：
**交集数字本身不是结果，只有"期望值 fold + P"才是结果。**

> **`A ∩ B = 785` 听起来像发现；期望 779（fold 1.01, P=0.30）说明什么都没发现。**
> 只报 785 就是误导。

**三步自证（一处都不能省）**：

| 步 | 做什么 | 陷阱 |
|---|---|---|
| 1 | **universe 取自未过滤全表**（各对比全表基因取交集） | 拿过滤后的显著表当分母 → 期望值被算小，结论整体反向 |
| 2 | **算期望与检验**：2 集合用**精确超几何**（`math.comb`，零依赖）；3 集合**没有精确检验** → 从 universe 抽同大小集合做**置换**（5000 次） | 不给期望就报交集；或对 3 集合硬套二元检验 |
| 3 | **覆盖率体检**：`\\|A\\| / N > 0.5` 时先警觉 | 见下 |

**🔴 覆盖率陷阱（本类最贵的假发现）**：实测 `Aging_up = 6,571`、universe `7,743`
⇒ **覆盖率 84.9%**，`Ex_Old_down = 918` ⇒ 期望 `6571×918/7743 = 779`，观测 **785**。
**785 不是生物学，是覆盖率的算术后果。** 判据：

- `观察/期望 ≈ 1`（fold 1.0–1.2）⇒ 该方向**零信息**，必须在汇报里**显式写出来**
- 真富集长这样：`27 vs 期望 1.0 (fold 27.5, P=3.2e-33)`、`13 vs 0.3 (fold 41.9)`

**通吃型集合是上游失校的症状**（显著率 98%、up:down = 59:1、SE 低估 ~26×）
⇒ **先回 §六 修分母，再谈交集/阈值/口径**；不要用"缩口径"或"加效应量阈值"去救它。

**共享组的结构性依赖**：两对比共享一组（`A_pre_vs_B_pre` 与 `A_pre_vs_A_post` 共享 `A_pre`）时，
两估计量天然负相关 ⇒ "反向显著"交集被人为抬高（实测符号一致率仅 **15.7%**，远低于独立假设 50%）。
报此类交集须声明共享组，不得当独立证据。

→ 完整实录（观测 vs 期望表、覆盖率算术、三组置换、逆转四方向数字、交付清单）：
`gene-set-overlap-analysis/references/overlap-vs-chance-and-venn-layout.md`

## 十、数值显示完整性门（数值对 ≠ 用户读得到）

第五个独立问题类（继 §一~四 产出无效、§六 统计不可信、§八 阈值、§九 交集期望之后）。
**交付表里的数值正确，不代表用户打开能读到** —— 用户拿 Excel 打开，看的是**单元格渲染结果**，
不是 pandas 里的 double。实测：一份 DEG 导出表的 fdr 列，**97.9% 的格在 Excel 里显示成 `0.0000`**，
用户当场质问「FDR 怎么全是 0？？？？？」。

**两层根因必须分开报（互相独立，别混成一句"值太小"）**：

| 层 | 机制 | 判据 | 实测 |
|---|---|---|---|
| **① 显示层**（大多数） | 导出时数值列 `number_format` 落成 `0.0000` ⇒ 凡小于 5e-5 一律渲染成 0 | 读单元格 `c.number_format`；「显示成 0 的格数」＝ `count(abs(v) < 0.5 * 10**-decimals)` | 22,692/23,178 ＝ **97.9%**（中位 1.02e-51、最小正值 1.63e-307 **仍显示成 0**） |
| **② 数值层** | 细胞级 glmer/bayesglm 大 n_cells ⇒ abs(z) 达几十上百，`2*pnorm(-abs(z))` 低于 double 最小正数（≈5e-324）⇒ **精确 = 0**，BH 后仍 0 | 精确 0 的行 abs(z) ≥ 37.5、非 0 行 abs(z) ≤ 37.5（5 个对比组边界一致） | 4,478 行真 0（占 19.3%），**上游未过滤全表里就已经是 0** |

**交付前必做（写进每次导出）**：
1. 小数值列（fdr / p / p_val_adj）导出时设科学计数法，或另给对数尺度列（`log10fdr`，可用 `z` 反算，
   不受双精度下限约束）；
2. 跑 `scripts/probe_excel_numeric_display.py <xlsx>` 把「显示成 0 的格数」报出来 ——
   **禁止只看 pandas 里的值就交付**（用户看的是 Excel）；
3. 汇报分两句写清：「真实精确 0 ＝ X 行（abs(z) ≥ 37.5 的 p 下溢）；显示成 0 ＝ Y 格（格式所致）」；
4. 影响面如实说：真 0 等价于"极端显著"，**不影响"哪些基因显著"**，但 `-log10(0)=Inf`
   会毁掉按显著性排序与火山图。

## 十一、派生表溯源门（用户问「这个表是不是来自那几个文件」）

用户拿着派生表点名几个源文件问来源时，**凭印象答"是/不是"＝把送分题做成送命题**。
三步给可证伪证据：

1. 读**导出脚本**（`search_files` 定位）确认真实输入与过滤规则；
2. 比对**列结构**（源 15 列 vs 导出 16 列 ⇒ 多出来的那列是脚本派生的，如 `regulation`）；
3. 在源文件上**复现过滤规则**（`fdr < 0.05 & abs(coef) >= 0.25`）→ 行数逐 sheet 相等，
   再排序后 `np.array_equal(fdr)` + `np.allclose(coef / p)` **逐值比对** → 报「逐值一致 = True/False」。

实测：5 个 `merged_*.xlsx`（340,971 行）→ 过滤后 25,696 行 ＝ 导出表 25,696 行，coef/fdr/p 数组全等。
⚠️ 顺带纠偏：源文件 `method` 列写着 `glmer` / `bayesglm` + `nRUV_used` ⇒ 它本身就是**新方法**的全量输出，
**不是**老方法 FindMarkers 的表 —— 不要按文件名或方法名前缀想当然归类。

## 十二、同数据两套结果冲突的门（效应量一致 + FDR 发散 ⇒ 差异全在分母）

用户问「**这个基因在你这套表里怎么没有**」「**两套结果怎么差这么多**」时，**分三栏各自算数再下结论**——
笼统回一句\"口径不同\"等于没答，用户还可能按错的那套下强结论。

| 栏 | 怎么量 | 本次实测（同一基因 × 同一对比） | 含义 |
|---|---|---|---|
| ① **效应量** | 逐行（基因×对比）比 `logFC`/`coef` 的符号与量级 | 两表同号同量级（全局逐行相关 0.61） | **点估计可信**，差异不在这里 |
| ② **FDR** | 同一条记录的两个 FDR | `0.712` vs `4.6e-235` ⇒ **差 100 个数量级** | 差异**全在分母**（SE / 自由度结构） |
| ③ **显著占比** | 各表「显著数 / 全表」 | `27.8%` vs **`99.7%`（7,289/7,309）** | 后者是**伪重复**症状（细胞当独立重复）→ 回 §六 |

**处置三步**：① 三层数字一起报（效应量一致性 / FDR 分位差 / 显著占比），别只抛结论；
② 说明**哪套有校验口径、哪些下游产物建在第二套上**（本次桑基图/共同 DEG 全基于高显著率那套）；
③ 下游重做与否**由用户拍板** —— 用户回「只查 X，到此为止」时**只留结论、不动产物、不重跑分析**，
把发现的上游问题如实报告即算交付完成。

**⚠️ 「某基因找不到」的默认答案不是\"漏了\"**：先算两道阈值各自的边界值 —— 本次该基因 50 个检验
FDR 全部 ≥0.333（**无一显著**）+ `|coef|` 最大 0.206 < 0.25 阈值 ⇒ **双重被筛**，与\"漏行/漏基因\"无关。
先算边界值再答，比\"我查查有没有漏\"快且可证伪。

## 十三、基因水平定量的归属门（表达量可信吗 —— 反义/重叠基因的链特异归属）

第六个独立问题类（继 §一~四 产出无效、§六 统计不可信、§八 阈值、§九 交集期望、§十 数值显示、
§十一 派生表溯源、§十二 两套结果冲突之后）。

**触发**：合作方/审稿人质疑某个基因的表达量（真实案例 `MEF2C` ↔ `MEF2C-AS1`，GRCh38 / Gencode v32）；
或用户问「他是不是想让我在真实数据上统计？这样只有 ATAC 能统计吧？RNA 不就是表达量吗？」。

> **质疑「表达量可不可信」＝ 质疑 read 归属；而归属只在 RNA 层存在 —— ATAC 没有「这条 read 算给哪个基因」这一步。**

| 层面 | 归属单位 | 感知基因模型与链 |
|---|---|---|
| RNA-seq | read → 比对 → **链特异归属到基因模型** → UMI 计数 → 归一化 → coef/FDR | ✅ |
| ATAC-seq | fragment → 基因组区间 / peak | ❌（无链感知的基因模型归属） |

- 「RNA 就是表达量」没错，但**表达量的上游正是归属** —— 所以验证必须在 RNA 层做，拿 ATAC 答 = 用尺子量温度。
- 在 GTF 上核对注释位置只证明「注释对不对」，证明不了「reads 落到了对的基因上」；两件事不可互相替代。
- 文献锚点：**Zhao et al. 2015 BMC Genomics, PMID 26334759** —— 无链信息时反向链重叠位点的表达量
  难以甚至无法准确定量（这正是链特异 RNA-seq 存在的理由）。引用落到 PMID，别只说\"有文献支持\"。
- 验证分级：**L1 = pseudobulk counts + GTF（不用 BAM、不用 ATAC）**；**L2 = featureCounts `-s 1/0/2`
  或 HTSeq `-s yes/no/reverse` 三态对比**（需比对产物，L1 存疑才做）。
- 沟通纪律：给合作方的技术说明**中文 + 英文两版**；**先一句话结论再 ≤3 点**，不要五层框架长文
  （本项目给过 5 层长文被要求「不要太复杂，简单点」，砍成三句才收货）；审计图内标签写**全注释版本号**
  （用户追问过「图里为什么写 GRC 而不是 `gencode.v32.primary_assembly.annotation`」——事前写全比事后解释便宜）。

### 十三续｜「如何区分 A 与 B 的 reads」的五层判据（逐层收窄竞争窗口）

被问「怎么区分」时要**正面给判据链**，不是只答「靠链」：

| 层 | 判据 | 把窗口缩到 |
|---|---|---|
| ① | **链方向 strand** | 类别上分开（决定性的一层）|
| ② | **外显子 vs 内含子** | 只剩外显子重叠（本例 20,930 bp → **422 bp / 3 段**，占 2.02%）|
| ③ | **UMI 锚点几何（3′ vs 5′）** | 3′ 建库下 ≈0（两 3′ 端相距 750 kb 且都不在共享区）；**5′ 建库此层失效** |
| ④ | **唯一外显子重定量** | 实证（剔共享 exon 重算，看结论变不变）|
| ⑤ | **参数自检 + 结果独立性** | 自证（RSeQC `infer_experiment.py`；两基因 counts 是否同向同幅）|

**三个必须纠正的说法（不改口会被反驳）**：① 在 ATAC 上「统计两个基因的重合区」——物理上只有一段 DNA，
ATAC 不带链信息 ⇒ 只有一个数；且会退化成**循环论证**（反义转录时 Pol II 占据该区、核小体被置换，
可及性本就升高）。② **可及性 ≠ 转录**（必要不充分；DUET-seq PMID 42801560 实证时间性解耦）。③ **方向不可预设**
——人骨骼肌耐力训练 ATAC 是往**闭合**走（PMID 40623475）。要真做 ATAC 侧，就把位点拆成
**两个 TSS 窗口（±2 kb）+ 中间共享区**分别做**同供体配对**检验，而不是整段平均。

## 十四、基因集合方向结论的特异性门（「这批基因全上调」≠ 有生物学意义）

第七个独立问题类（继产出无效 / 统计不可信 / 阈值 / 交集期望 / 数值显示 / 派生表溯源 / 两套结果冲突之后）。

**触发**：交付了「某基因集合在某对比里全 Up / 全 Down」的图或表之后，用户回问
「**你确定都上调吗？没有下调的吗？**」（本次真实对话），或你自己看到**整片同色**的矩阵热图。

**先答"是不是"，再答"算不算发现"——第二问几乎总会推翻第一问的解读。两问都要算出数字：**

| 步 | 算什么 | 本次实测（HSP 家族 × Aging，48 样本 10 亚群） |
|---|---|---|
| 1 | 集合内方向分布 + **全表 Down 行里有没有该集合成员** | 44 个显著格 **100% Up**、coef 全正（0.250–0.390）；全表 469 个 Down 行中 HSP 命中 **0** ⇒ 第一问答：是，一个都没有 |
| 2 | **对照全表的符号指纹与效应量分布（同一张表、同一口径）** | Aging 全表 23,178 行：**正号占比 98.0%**、中位 coef 0.301；HSP 44 行：100%、**中位 0.304**（四分位 0.288–0.320 vs 全表 0.273–0.342）⇒ **两套分布几乎重合** |

> **判据**：集合的符号占比 ≈ 全表符号占比，且 `\|集合中位效应量 − 全表中位效应量\|` 远小于全表四分位间距
> ⇒ 该"发现"是**全表偏移的算术后果**，不是集合特异信号。**必须把这一步报出来，只报第一步等于误导。**

```python
# 五行的对照（含缺格的表也安全）
d = pd.read_excel(SRC, sheet)                              # 全表（不是过滤后的显著表）
s = d[d.gene.str.upper().str.startswith("HSP")]            # 集合
print(d.coef.median(), round((d.coef > 0).mean(), 3),       # 全表指纹
      s.coef.median(), round((s.coef > 0).mean(), 3))       # 集合指纹
```

**「全表单向」是上游失校的症状**（与 §六 D5 方向指纹、§九 覆盖率陷阱同源），正常对比应 ≈1:1。
本次五个对比的正号占比：Aging **98.0%** / DM 48.6% / Y_EX 60.9% / O_EX **14.3%** / DM_EX 44.3%
⇒ **只有 Aging 异常**，该对比上所有"全上调/通吃型"结论都要打问号，并建议回查该对比的建模与归一化
（这是上游问题，不是出图或统计选择能修的）。

**哪类结论不受它影响（可直接用）**：
- **组内方向分化**：同一张表里既有 Up 又有 Down。实测 O_EX 表正号占比仅 14.3%，而 HSPB1 / HSPB7 ↑
  与 HSPA9 / HSPD1 ↓ 并存 ⇒ 这种双向才是集合特异信号；
- **跨组比较**：如"衰老 ↑ → 老年运动 ↓"的逆转（两组方向相反），不受任何单表偏移影响。

**汇报纪律**：用户问"确定吗"时，正确交付是**两句话一起给** ——
「是，逐行核过了（44/44 全 Up，全表 469 个 Down 行里 0 命中）；但这个上调与全表偏移无法区分，
不能当 HSP 特异的证据」。**不要只答第一句**（那是把送分题做成送命题）。
