# 输入口径溯源与版本切换（判定交付数字出自哪个输入文件）

> 触发场景：① 交付/专利数字被质疑「数据是你改过的 / 别人无法复现」；② 同一分析存在两个候选输入文件
> （如 `monkey_ageDA_all.csv` vs `monkey_ageDA_continuous.csv`），两版跑出的数字对不上；
> ③ 已决定换口径，需要评估连带影响与重算范围。

---

## 铁律 0：先钉血缘，再谈对错

**不要**先辩解或先选边。按顺序回答三个问题，每个都用实测：

| # | 问题 | 判据 |
|---|------|------|
| 1 | 两个文件是「同一计算的两种写法」还是「两次独立计算」？ | 坐标改写**不产生新行** —— 若坐标修正后行数不变，两表就不是同一网格的换算版；再查 tile 级 r 相关，< 0.95 即确证两次独立计算 |
| 2 | 交付数字出自哪一版？ | 用两版**各跑一遍下游**，看哪一版能**逐位**复现交付表的 n / 分类计数 / ρ |
| 3 | 差异来自**数据**还是**代码**？ | 用**两个独立实现**跑**同一输入**：结果一致 → 差异在输入；不一致 → 差异在实现 |

> ⚠️ 第 3 步是分水岭。跳过它会把「锚定器实现差异」误判成「数据被改」，从而整轮结论反转。

## 零差异自证（回应「你改过数据」）

最有力的动作不是道歉或解释，而是**用用户手上的原始输入现场重算目标文件**，逐行比对：

```
报告项：
  重算行数 vs 磁盘文件行数        ← 必须一致
  max|Δ| 逐值比对                 ← 落在 1e-16 量级 = double 机器精度（eps≈2.2e-16）
  重算脚本路径（必须零硬编码数值）
  耗时                            ← 让用户可自行复跑
```

**max|Δ| ≈ 1e-16 的含义**：比任何有意义的数值小 10 个数量级以上 → 不存在改数值的空隙。
把脚本路径 + 行数 + 耗时一并给出，用户可独立复跑验证 —— 这比任何措辞都有说服力。

## 换口径要重算什么（裁剪原则）

下游指标分两类，**先分类再决定工作量**，别整条管线重跑：

| 类别 | 例子 | 处理 |
|------|------|------|
| **纯筛选类** | 核心元件 = 「人侧 \|Z_h\|≥12 + 猴侧 p<0.05 + 同向」 = 对上游全量表的条件过滤 | **不需要重跑管线** —— 在新表上套同一公式即可 |
| **需重跑类** | 涉及聚合 / 置换 / 回归的（v5 四级分级、置换 null 分布、v6 窗口重锚定、v7 线性回归） | 必须重跑 |

## 实测案例：TileMatrix 两种口径会把显著性打没

同一份 ArchR monkey 数据，两种聚合口径：

| 环节 | all 版（1-based，原始 counts） | continuous 版（0-based，比例） |
|------|------|------|
| 聚合 | `getGroupSE(scaleTo=NULL, divideN=FALSE)` → 原始 counts 求和 | 每样本**平均可及性**（binarize 后 0~1 比例） |
| 数值变换 | **`log2(CPM + 1)`** ← 决定性差异 | **无**（直接用比例） |
| tile 过滤 | `rowSums >= 2 × 样本数` | 仅去零方差 |
| tile 数 | 5,296,656 | 5,674,190 |

下游连带效应（同一份数据的两次口径）：

| 指标 | all 版 | continuous 版 |
|---|---|---|
| ortholog 对 | 16,029 | 16,031 |
| A 类（双侧 \|Z\|≥1.96+同向） | 2,336 | 1,904 |
| 加权 Spearman ρ | −0.1955 | −0.081 |
| A 级核心元件 | 357 | 336 |
| 双侧铁证核心元件 | 16 | 37 |
| v7 外推 R² | 0.3472 | 0.2825 |
| **v6 promoter-proximal CRE 置换 p** | **0.261（不显著）** | **0.0000（显著）** |
| v6 富集倍数 | 1.035× | 1.34× |

> **教训**：口径差不是「细节」。它能把一条 claim 的置换 p 从 0.0000 打到 0.261，让整章结论失效。
> **换口径前必须先跑一次「结论稳健性对照」**（两口径并排跑全套，列出会失效的 claim），再决定是否切换。
> 核心元件名单也可换血 53%（交集仅 159 / 336）。

## 交付件可复现清单

- ✅ 产物 + **生成脚本** + **输入 md5** 三件套一起交付
- ✅ 脚本零硬编码数值；集群脚本的占位符路径（如 `/hwfssz3/...`）必须参数化
- ✅ 中间文件命名**不要带 `fix` / `repair` / `corrected`** 这类标记 —— 会被审阅者直接读成「人工改过」
- ✅ 交付包里必须有 `scripts/` 目录；只有结果 CSV 的交付包 = 第三方无法复现

## 陷阱

| 陷阱 | 后果 | 正解 |
|------|------|------|
| 用**重写版**算法去复现**正本**产物 | 残余差异被误判为「数据问题」，整轮结论反转 | 复现零差异的唯一正确做法是用**正本原脚本**（在磁盘上找，不要重写） |
| 交付目录只放结果 CSV | 「无法复现」的真实位置就在这里，跟选哪一版无关 | 生成链脚本进交付包 |
| 一轮内反复**只读探查**同一问题 ≥3 次仍无执行 | 触发系统循环检测干预，用户等待无产出 | 停下探查，直接跑一个**决定性实验**（一次跑完给出可判定的数） |
| 把方法学差异轻描淡写成「坐标差 1bp」 | 被用户当场抓住，信任受损 | 差异定性必须精确到具体环节（聚合方式 / 数值变换 / 过滤阈值） |

## 判定输出的记录模板

```
判定：交付口径 = <文件名>
依据：
  ① 逐位复现：<文件A> → n=<x> / 分类=<...> / ρ=<...>（与交付表一致）
  ② 对照排除：<文件B> → n=<y> / 分类=<...>（不一致，排除）
  ③ 实现无关性：两个独立锚定器 × <文件A> → 差异 ≤ <k> 个基因（结论对实现不敏感）
  ④ 时间线：<文件A> 生成 <时间>，交付表写入 <时间>（晚于前者）
连带影响：<逐章节替换清单>
诚实边界：<未解决项 / 无法回答的问题，如实写明>
```
