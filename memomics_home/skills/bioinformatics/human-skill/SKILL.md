# human-skill：中文论文学术文本的自检双件套

两道独立检查，可单跑也可连跑。**只诊断与改文风，绝不改事实、数据、引用、结论强度。**

> 上游：`humanizer` skill（GitHub blader/humanizer，MIT）给出 29 条通用 AI 写作特征。本 skill 是它的**中文学术封装**：把英文语境的特征映射到中文学位论文场景，并补上 humanizer 没有的**查重**能力。

## 何时用

- 「这篇读着像 AI 写的」/「去一下 AI 味」/「humanize 一下」→ 走 **A. 去 AI 味**
- 「查重」/「重复率多少」/「会不会被查重」/「学位论文和专利同源会不会被判自我抄袭」→ 走 **B. 查重**
- 投稿前 / 定稿前 → **两道都跑**

## 何时不用

- 要改写**内容**（补论证、换结论、重组织结构）→ 用 `paper-polish` 或 `academic-paper-writing`
- 要审稿人视角挑毛病 → 用 `pre-submission-reviewer` / `nature-reviewer`

## A. 去 AI 味

### 扫描（先诊断，不急着改）

```bash
python scripts/ai_flavor_scan.py <文件.md|docx> [--out report.md]
```

输出四类指标，**每一项都给行号与原文**，便于定点修改：

| 指标 | 判读 |
|---|---|
| **AI 腔词表命中** | 中文高频 AI 词（见下）每千字密度；>3/千字需处理 |
| **模板句式命中** | 「不是…而是…」「不仅…而且…」「随着…的不断发展」「值得注意的是」等 |
| **节奏均匀度** | 句长方差 + 段落长度方差；AI 文本明显偏低（每句 30–45 字整齐划一） |
| **格式噪音** | 破折号数量、加粗**数量、表情符号、弯曲引号、项目符号滥用 |

### 中文学术语境下的 AI 腔词表（本 skill 扩展）

**必删级**：赋能、抓手、闭环、加持、深度融合、全面提升、极大地、显著地（无统计依据时）、
里程碑式、开创性、颠覆性、值得深入探讨、具有重要意义

**慎用级**：此外、综上、不仅…而且、一方面…另一方面（除非确为对照）、
呈现出…的趋势、在…背景下、为…提供了新思路、拓宽了…的视野

**句尾 -ing 式中文化**：中文对应的是「…，从而…」「…，进而…」「…，为…奠定基础」「…，凸显了…」
→ 换成独立句或直接删除（AI 爱用它制造虚假深度）

**避免**（humanizer 的中文映射）：
- 意义膨胀（"标志着…的重要里程碑" → 只写做了什么）
- 三元排比强行凑数（"高效、准确、可靠" 若三项无独立依据则删到实际项数）
- 同义反复换词（"方法/方案/策略"轮换指同一物 → 统一用词）
- 虚假区间（"从…到…" 两端不在同一尺度）
- 被动/无主句（"数据被保存" → 明确施动者）

### 改的原则

1. **只改文风**。数据、数字、公式、引用编号、结论强度一律不动。
2. **改动有依据**：每处修改说明「命中了哪条特征」。
3. **别改死**：删净 AI 腔后文字会发干，靠**精确数字与真实取舍**把血补回来，不是靠形容词。
4. 交付：先给改后文本，再给 3–5 条修改说明；触及语义的改动单独列出请用户确认。

## B. 查重

### 能力与边界（必须向用户如实说明）

```bash
python scripts/similarity_check.py <论文.md> --ref <源库目录或文件> [--n 15] [--top 20]
```

| 能做 | 不能做 |
|---|---|
| **内部自我重复**：同一片段在文内出现 ≥2 次的字符占比 | ❌ 不等于知网/CNKI 结果（无全网库） |
| **对自建源库重合率**：与指定目录（专利交底书、素材包、旧稿）的 n-gram 重合 | ❌ 无期刊/网络库 |
| **最长重合片段定位**：给出 Top-N 片段 + 出处文件名 | ❌ 不查英文库 |

**典型真实场景**：学位论文由专利交底书改写而来 → 与交底书逐句同源，送知网可能被判**自我抄袭**。本脚本正是查这个。

### 口径

- 归一化：剥离 Markdown 标记/公式/图片/表格线，全角半角统一，去空白
- 单元：中文按**字符** n-gram（默认 n=15，约等于连续 15 个汉字雷同）
- 指标：
  - `内部重复率 = 重复 n-gram 覆盖字符数 / 正文总字符数`
  - `源库重合率 = 与源库共有的 n-gram 覆盖字符数 / 正文总字符数`
- 阈值参考（自检用，非官方）：内部重复 >5% 需改写；源库重合 >10% 建议重述该部分

### 处理重合的建议

1. 优先改**连续长片段**（≥30 字），短交集多为专业术语，不必动。
2. 术语与参数名保留（改了反而不准确）；改的是**句式与论述顺序**。
3. 数据表/公式无法重述的，属合理重合，如实保留。
4. 最后跑一次 `--top 30` 复核，确认最长片段已降到阈值下。

### 实测坑（已内置修复，勿踩）

| 坑 | 现象 | 处置 |
|---|---|---|
| 源库目录包含目标文件自身 | 源库重合率假性 = 100% | 脚本已自动排除目标文件；仍建议 ref 与 target 分开放 |
| 重叠 n-gram 重复计数 | 内部重复率 >100%（曾算出 124%） | 改用**位置标记法**（逐字符标 True），勿用 `n×出现次数` |
| 拿 20 字串去 15-gram 集合查 | 最长重合片段恒为空 | 用**连续 run 法**：判 `target[i:i+n] in ref`，取连续 True 段 |
| 英文/DOI/纯符号 n-gram | 假性高重合（基因名、DOI 满篇雷同） | n-gram 只保留汉字占比 ≥60% 的片段 |

**自检基线**（合成用例，改动脚本后必须复跑）：整段重复两次 → 内部重复率 = 100%；与无关源库比 → 0%；源库含该句 → 100%。

## 铁律

1. **不编数据、不编引用、不改结论强度** —— 与 `paper-polish` 同一条底线。
2. **查重结果必须说明口径**：本工具是"自建库 n-gram 自检"，不是知网，禁止把结果当成官方查重率汇报。
3. **改文风 ≠ 改写事实**：遇到"改了就动数据"的地方，停下来问用户。
4. 长文档分段处理要标注 `part i of N`，禁止"前几页认真改、后面糊过去"。
