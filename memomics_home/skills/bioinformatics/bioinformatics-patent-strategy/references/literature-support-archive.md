# 文献支撑档案（"方法来源 + 文献支撑"目录的标准做法）

> 首次落地：2026-09-11 跨物种衰老可替代性专利 · `E:/专利/文献支撑/`
> 触发：用户说"方法来源、文献支撑，都要下载下来，放在一个目录下，为后面毕业论文做准备"

## 1. 固定目录分类（四类 + 根级总表）

```
<项目根>/文献支撑/
├── 方法来源与文献支撑总表.md      ← 唯一索引，审阅人先看这个
├── 01_现有技术对标/               ← 专利直接对标 / 规避的现有技术
├── 02_方法学来源/                 ← 本方法依赖的方法论原始出处
├── 03_领域背景_<组织>与<方向>/     ← 毕业论文背景章节
└── 04_统计与算法/                 ← 统计方法、p 值合并、多重检验
```

## 2. 建表前必做两步（省掉一半返工）

1. **先读已有引用件**：项目里通常已有 `references.md` / `disclosure.md` 的引用表 —— 那里面是**引文条目，不是 PDF**。先读它拿到已列清单，避免重复劳动，也避免漏掉作者口径陷阱（如 News&Views **评论者** vs 被评论的**原始研究作者**是两个 PMID，张冠李戴会被代理人退回）。
2. **再读方法链档案**：如 `全流程溯源档案.md` 的 M0–M10 模块表 —— 每个模块就是一条"方法"，逐条配来源文献。**方法清单来自溯源档案，不是凭记忆列**。

## 3. 总表结构（每个方法一行，四要素缺一不可）

| 模块 | 方法 | 来源文献 | 本地文件 | 状态 |
|---|---|---|---|---|
| M0 | ATAC-seq 原理 | Buenrostro *Nat Methods* 2013. DOI 10.1038/nmeth.2688 | `02_方法学来源/10.1038_nmeth.2688.pdf` | ✅ 4.0 MB |
| M3 | 加权 Stouffer Z 合并 | Stouffer 1949（原始）/ Whitlock 2005 | `04_统计与算法/Kim2026_...pdf` | ✅ / ⚠️ 原文订阅 |

- **必须带"状态"列**：✅ 已下载（写文件大小）/ ⚠️ 订阅待获取 / 📘 教科书级无需单列文献
- **现有技术表必须写"与本发明的关系"**：一句话点出区别点（如"属静态位置保守性检测，无年龄梯度、无可替代性评分、无方向门控"）—— 这是代理人写"背景技术"的直接素材，比只给标题有用得多
- 每篇 PDF 落盘时会自带 `.pdf_index.json`（doi + sha256 + 下载时间）并进引用库，交付时一并说明（Zotero 可导入）

## 4. 缺口处理（诚实边界，不可省）

- 出版商订阅内容（EuropePMC `isOpenAccess=N`、Unpaywall 无免费版）→ **单列一节"待获取文献"**，给 `文献名 / DOI / PMID / 目标子目录 / 备注`
- 写明正规获取途径（学校图书馆、机构 VPN、文献互助）
- **禁止**提供或尝试任何绕过版权的方式 —— 这条要显式写进交付件与汇报里

## 5. 汇报口径（用户要求"干净清晰"）

结论先行：目录树 → 已下载篇数分类统计 → 表格（方法 → 文献 → 状态）→ 缺口清单 → 一句"我没有走任何绕过版权的途径"。

❌ 不要只丢一份文件清单就结束；用户要的是"每个方法的来源能不能追溯"这个结论。

## 6. 与其它交付件的关系

| 交付件 | 管什么 |
|---|---|
| `全流程溯源档案.md` | **数字**溯源：每个数字出自哪个脚本/模块 |
| 本文献支撑目录 | **方法**溯源：每个方法出自哪篇文献 |
| `references/library.json` | 引用库：可导出 BibTeX/RIS 供 Zotero/EndNote |

三者互补，交付时一起给。
