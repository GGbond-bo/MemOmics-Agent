# 输入口径切换 → 交付件全套数字替换（playbook）

> 来源：2026-09-11 专利输入口径 continuous → all 的全套替换实战（会话 `memomics-7839e23a`）。
> 用户说「改用 all / 换成 XX 版重算 / 把交付件数字都换掉」时按本流程走。

## 0. 🔴 前置门禁：宣告 claim 失效前，先确认它在交付件里

**本次实战教训（Agent 自己犯的错）**：Phase 1-2 算出 v6 promoter-proximal CRE 置换 p 0.0000→0.261 不显著，Agent 立刻向用户抛「① 照实删 v6 章节 ② 保留但改口径 ③ 先做其他留 TODO」三选一，并宣称「v6 章节不能再用」。

**结果**：全交付目录 grep 一次即证伪——

```bash
cd "E:/专利/交付_跨物种衰老可替代性专利"
grep -rli "promoter\|启动子\|TSS\|v6" .     # 零命中（含 docx/json）
```

v6 / v7 **从未进入任何交付件**，只是内部管线阶段（`M2/pipeline_out_all/v6_promoter_cre_*.csv`）。所谓「claim 失效」不存在，制造了一个不存在的阻塞点，白烧一轮。

**铁律**：任何「某某 claim 失效 / 某章节不能用 / 要删一条权利要求」的结论，**必须先 grep 全交付目录（含 docx / json / csv 文件名）确认该 claim 真的写进了交付件**。确认不了就不许宣告失效。判定顺序永远是：**先查它在不在 → 再谈它成不成立**。

## 1. 数字分类：口径相关 vs 口径无关

换口径前先把所有待替换数字分两类，避免「全量重算」这种既费时又引入新错的做法。

| 类别 | 判据 | 处理 | 本例 |
|---|---|---|---|
| **口径相关** | 由被切换的输入（M5 派生链）算出来 | 必须在新口径下重算 | 基因对数、A/B/C/D、核心元件数、最高置信子集、漏检率、富集倍数、整体 r、同向比例 |
| **口径无关** | 算在**各物种自身的 peak/tile 矩阵**上，与被切换的导出/聚合层无关 | **不重算**，原值保留 | 人侧年龄标签 shuffle 24×/p=0.005（基于 525,137 peaks）；猴侧 shuffle 1.17×/p=0.267（基于 6,085,841 tiles，4 种归一化下结论一致） |

**为什么重要**：本轮若把 24× / 1.17× 一起「重算」，既无必要又可能算出不同值，反而制造新的口径混乱。文档里要写明这类数字**口径无关**（本例 `结论_口径决策链.md` 已加注：「此两项检验基于各物种自身的 peak/tile 矩阵，与 M5 输入口径切换无关，故数值不变」）。

## 2. 命名陷阱清单（复现头号杀手）

文件名暗示的口径 ≠ 实际内容口径。本轮撞到两个：

| 文件 | 名面意思 | 实际内容 | 处置 |
|---|---|---|---|
| `P3_L1_data/v5_substitutability_all.csv`（16,031 行） | "all" | **continuous 旧正本** | 交付件里显式警示：文件名中的 "all" 指旧命名习惯，**不是** all 输入口径 |
| `P3_L1_data/M2_repro_gene_conservation_continuous.csv` | "continuous" | 被 all 输入覆盖后的 **all 结果** | 另存清晰副本 `M2_repro_gene_conservation_all.csv`（+ stats txt），交付件复现代码改指新名 |

**规则**：切换口径后，**产出文件必须另存为口径自明的名字**，禁止就地覆盖同名文件；同时在该口径的 README 里加一条「命名陷阱」条目列出所有歧义文件名。

## 3. 两套独立实现互证（口径切换的稳健性证据）

同一口径下跑**两套互不依赖的实现**，核心指标一致才可交：

| 实现 | 脚本 | 基因对数 | 核心元件 | 最高置信 | 漏检率 | 富集倍数 |
|---|---|---|---|---|---|---|
| 正本锚定器 | `P3_L1_data/repro_m3_from_M2.py` | 16,029 | 357 | 16 | 95.5% | 12.3× |
| 端到端管线 | `M2/repro_full_pipeline.py` | 16,010 | 357 | 16 | 95.5% | 12.3× |

差异仅 19 个基因对（tile-count 过滤细则不同），**所有 headline 指标完全一致** → 结论对锚定实现不敏感。

**选哪个做专利正数**：选**与旧口径同一脚本**的那个（本例锚定器 16,031→16,029），因为只变输入 → 干净 1:1 对比；另用管线结果做独立互证写进文档。

## 5. 基因名单必须重挂到正确层级（容易漏的语义坑）

口径切换会改变**哪些基因属于哪一层**，gene list 不能简单做字符串替换。

本例 all 口径下的实质变化：GRIA1/GRIA2/EPHA5 的**猴侧**强度大幅下降（GRIA1 猴 Z −14.68 → **−5.00**，EPHA5 −20.57 → **−6.00**），因此掉出「最高置信 16 子集」；但**人侧强度未变**，它们仍在「357 核心主清单」里。

| 层级 | all 口径内容 |
|---|---|
| 357 核心主清单 | SLC1A2 / GRIA1 / GRIA2 / NRXN1 / EPHA5 / SORL1（仅 SYT1、EPHA6 掉出）→ 主轴叙事存活 |
| 16 最高置信子集 | SLC1A2 / NRXN1 / SORL1 领衔（+ RBFOX3、CACNA1B、KCNT1、STXBP5L 等神经元/突触基因）|

**规则**：替换后必须**逐层级核对点名基因是否还在**，并把「原本挂在 A 层的基因名」按实际归属重挂到正确层级（本例 abstract 原句把基因清单含糊挂在 37 子集上 → 改为「核心元件集合由…领衔；最高置信子集以…领衔」）。不重挂 = 审查员/代理人一核对就发现基因与层级对不上。

## 6. 验收：交付件里的复现代码必须原样跑通

**所有交付件内的复现代码块，替换后必须原样复制执行一次**，输出与文末「预期输出」行逐字符一致才算完成。

```python
import pandas as pd, numpy as np
df = pd.read_csv("E:/专利/P3_L1_data/M2_repro_gene_conservation_all.csv")
zh = df["Z_human"]; zm = df["Z_monkey"]; pm = df["p_monkey"]
sd = df["same_direction"].astype(str).str.strip().str.lower().isin(["true","1","yes"])
strong = np.abs(zh) >= 12
A = int((strong & (np.abs(zm) >= 12) & sd).sum())        # 对称 min 法
B = int((strong & sd & (pm < 0.05)).sum())                # 主-参考非对称
n_pool = int((strong & sd).sum())
print(f"方法A={A}, 方法B={B}, 漏检={B-A}, 漏检率={(B-A)/B:.1%}")
print(f"富集比 = {B/(n_pool*0.05):.1f}x")
print(f"整体 r = {np.corrcoef(zh, zm)[0,1]:.4f}, 同向比例 = {(np.sign(zh)==np.sign(zm)).mean():.4f}")
# all 口径预期：A=16, B=357, 漏检=341, 95.5% | 12.3x | r=-0.0971, 同向=0.4636
```

配套把**数字台账**落盘（本例 `results/Phase4_numbers.json`：正本 / all-pipeline / all-anchor 三列全指标），换口径过程可审计、可回溯。
