# 门控与隔离的**实现级**细节（源码实测，2026-10）

用户会直接问「辩论什么时候触发？L0/L1/L2 分别什么场景？
L1 的上下文隔离是代码层还是提示词？」—— 下面每一条都是**读源码**得来的，
不是从 SOUL 自述复述。回答这类问题前先看这里，不要凭印象答。

## 一、门控在代码层，不是提示词

`webui/enforcement.py::debate_gate(es, stage, signals)`（约 L273–358），
返回 `(level, reasons, force)`。三个输入：

| 输入 | 取值 |
|---|---|
| `es.analysis_level` | `chat` / `lightweight` / `statistical` / `analysis` |
| `stage` | `before_script` / `after_script` / `conclusion` |
| `signals` | `high_impact` / `failed_retries` / `last_error` / `conflict` / `uncertainty` / `fork_options` |

**关键设计：硬信号优先**（约 L306–311）——命中高影响 / 重试≥2 / 报错 / 冲突时，
**绕过「值不值得辩」的过滤**直接进 L2 判定。软场景才需要过 `_debate_worthiness` 筛。

## 二、L0 跳过（约 L302–311）

| 触发条件 | 代码依据 |
|---|---|
| `analysis_level ∈ {chat, lightweight}` | 「无分析对象」 |
| 显式标注 `no_debate` | 调用方声明 |
| **活选项 < 2** | 「只有 ≤1 条路径，辩不出新东西」 |
| 事实查询 / 只读获取 | 「有唯一正确答案」 |
| 只读观察步骤 | 「不产生新结论」 |
| **同一议题已辩过** | 去重（`debated_topics`） |
| 线性执行 / 已知流程 | 「无方案分歧」 |
| 匹配线性命令正则且无异常信号 | 如 `ls` / `cat` / `echo` |

> 代码注释里保留了用户原话：「**怎么什么问题都辩论呢？要分清楚情况。**」

## 三、L1 轻量（约 L320–345）

| 触发条件 | 代码依据 |
|---|---|
| **`statistical` 级默认** | L320–322 |
| analysis 级**脚本设计 / 执行后**（无失败、无冲突、无分歧） | L344–345 |
| 结论合成但**没有分歧、没有高风险** | L339–342（注释：「不升 L2，避免为辩论而辩论」） |
| 预算降级：本该 L2 但已辩次数 ≥ budget（默认 3） | L349–351 |

## 四、L2 完整（约 L313–338）

| 触发条件 | 代码依据 |
|---|---|
| **高影响强制** —— 入库（`save_knowledge`）/ 报告（`generate_report`）/ 结论产物 | L313–317，`force=True` **不可降级** |
| **失败重试 ≥ 2** | L330–332 |
| **rail_review(post) 未通过 / 结果冲突** | L333–335 |
| 结论合成且有 **≥2 条活选项**或高不确定性 | L336–338 |
| ⚠️ 反向：token 预算耗尽 → **降 L0** | L353–356 |

## 五、L1 的上下文隔离 = **代码层物理切断**

`_call_llm_sync()`（`memomics/bio_tools/debate_analysis.py` 约 L1440–1445）：

```python
payload = {
    "model": model,
    "messages": [{"role": "user", "content": prompt}],   # ← 只有 1 条消息
    "max_tokens": ...,
    "temperature": ...,
}
```

**每个角色 = 一次独立的 HTTP 调用，`messages` 数组从头到尾只含它自己的 prompt。**
返回时附带 `isolation_verified: True` 和 `messages_count: 1` 作为**可断言凭证**。

| | 提示词隔离（角色扮演） | MemOmics 的做法（代码隔离） |
|---|---|---|
| 做法 | 同一对话里说「你现在扮演反方」 | **每次调用新建一个空 messages 数组** |
| 模型能看到什么 | 仍能看到前面的对话历史（正方说了什么） | **物理上看不到**任何其他角色的输出 |
| 可验证性 | 无法验证 | `messages_count: 1` 可断言 |

**所以回答「代码层还是提示词？」→ 代码层。** 级别不可被 LLM 随口改变，
隔离也不依赖模型「自觉不看别人的话」。

## 六、L1 的具体形态（`_debate_l1_lightweight`，约 L2710–2764）

- **同一个默认模型**（跟随会话当前 provider），靠**温度梯度**制造多样性：
  `_TEMP_POOL`，反方比正方 +0.1 —— 同模型同温度会给出高度雷同的答案，必须拉开温度。
- 默认 `samples=3`（可设 1–5），每组正反各 1 次调用 →
  **2N 次短调用 + 1 次裁判**（裁判是唯一能看到双方的）。
- **2026-09-18 加了一环「裁判整理」**：L1 采样大量返回 reasoning 草稿，
  直接喂裁判「卷面很乱」，所以裁判前先做一次 digest。
- 成本口径：`debate-core` SKILL.md 写「≈1/4」，**代码注释写「约 L2 的 1/3」**。
  对外回答时以代码注释为准（≈1/3），避免两处口径打架。

## 七、汇报话术模板（用户问这类问题时直接用）

> **触发**：`debate_gate()` 按「分析级别 + 阶段 + 硬信号」三输入算级别；
> 硬信号（高影响 / 重试≥2 / 冲突 / 报错）优先且不可降级；L0 的「不值得辩」有 8 条明确判据。
> **L1 隔离**：**代码层物理切断** —— 每个角色一次独立 HTTP 请求，
> `messages` 只含它自己的 prompt（`messages_count: 1` 可验证），不是同对话里的角色扮演。
> L1 = 同模型 + 温度梯度采样 3 组 × 正反各 1 次 + 裁判裁决，成本约 L2 的 1/3。
