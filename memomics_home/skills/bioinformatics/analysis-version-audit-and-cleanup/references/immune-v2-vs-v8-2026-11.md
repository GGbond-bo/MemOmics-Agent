# 实测案例：Immune snRNA-seq v2 vs v8（RUVr + MAST，2026-11-03）

数据：`Immune_exercise_clean_umap.rds` — 19,934 细胞 / 47 样本 / 24 个体 / 17 个 L3 亚群，
17 亚群 × 5 比较组 = 85 次预期检验，实际 v2 出 55 表（30 个组合因**组别缺失**跳过，非失败）。

---

## 一、两版唯一的决定性差异

| 项 | v2（用户原版，**最终采用**） | v8（我改的，**仅作敏感性对照**） |
|---|---|---|
| `k`（W 因子数） | `k = min(nruv, df_resid - 1)`，`nruv = 10` | `k = max(2, floor(df_resid / 3))` |
| 实测 k 分布 | 2–10 个 | **2–5 个，39/50 组合只剩 k=2** |
| batch 是否入模 | 否 | 部分组合入模 |
| `df_resid <= 2` 守卫 | 无 | 有（因此少 5 个表） |
| 输出表数 | 55（55 个 `_sDEG.csv`） | 50（50 个 `_v8.csv` + 2 辅助表） |
| 目录（本机） | `results/Immune_RUV_result/` | `results/Immune_v8/` |
| 目录（集群） | `<analyze>/Immune/` | `<analyze>/Immune_v8/` |
| k 溯源列 | `nRUV_used` | `k_actual` |

**为什么 v8 是缺陷而非口味**：`k=2` 比文献常用 `uruv=5` 更弱 → 欠校正 → 技术噪声没扣干净。
用户在原话里直接否决：「设置 nruv=10，最大是这么多，算到多少个就用多少个……还不如我之前的代码来的稳妥」。

## 二、50 个可比组合的全局指标

| 指标 | 值 |
|---|---|
| 显著基因合计 | v2 **17,051** / v8 **18,387** |
| 共有 / v8 独有 / v2 独有 | **14,934** / 3,453 / 2,117 |
| 显著基因 Jaccard（中位） | **0.4216** |
| 共有显著基因方向一致率（中位） | **1.0000**（最低 0.9817） |
| 全基因 coef Spearman（中位） | 0.6402 |

> 注意「显著基因变多」≠「结果变好」：v8 显著性总数更高，但那是 k 变小（欠校正）的产物。
> **只看总数会得出完全相反的结论**——必须配方向一致率和分层。

## 三、分层归因（本案例最有价值的证据）

| 分组 | n | Jaccard 中位 | coef Spearman | 解读 |
|---|---|---|---|---|
| **k 未变化** | 5 | **1.000（逐位完全相同）** | **1.000** | 新增注释列/元数据列对统计量**零影响** |
| k 变化 + batch 未入模 | 22 | 0.5168 | 0.8656 | 差异全部来自 k |
| k 变化 + batch 入模 | 23 | **0.2357** | 0.5238 | k 压缩 + batch 入模叠加，差异放大一倍 |

压缩幅度与差异单调相关：k 比值 ≤0.3 时 Jaccard ≈0.34；0.5–0.8 时 ≈0.74。

**可复用推论**：5 个 k 未变组合结果逐位相同 → 差异**唯一**来自 k。设计版本对撞时故意留一个
"不变臂"，就能把归因从推测变成证明。

## 六、v8 首跑失败的根因（与本主题相关，一并记录）

`type 映射失败：NA` —— 4 个分片同时倒在同一处。
根因：v8 用命名向量查表 `type_map[type]`，遇到未登记取值**直接变 NA** 并被守卫 `stop()`；
v2 用 `dplyr::recode`，匹配不上**保留原值**只给 warning，所以跑通。
修复：改成"查表不到就保留原值"（等价 v2 语义，同时兼容长短两种写法），并加一行打印原始取值做诊断。
**教训**：改写别人跑通的映射逻辑时，要保留其**宽松语义**（recode 的 fallback），
换成"严格查表"会把原本能过的数据变成 NA。
