# 版式几何与对齐自检

**版的"难看"几乎从不是配色问题，而是几何问题。** 本 skill 处理用户指着图说"这里没对齐/被压住/被截断"的一类投诉，
用"先算几何量 → 再改代码 → 用自检数字复验"的固定流程，而不是靠肉眼反复试。

## 何时用

- 用户指着某张**程序化画的图**（桑基/冲积、node-link 图、手绘示意图、自定义面板）说：
  "标签没跟自己对应的色块对齐" / "标签把 XX 压下来了" / "最上面被截断了" / "看着歪了"
- 你刚改完这张图，要证明真的改对了（而不只是"又出了一版"）
- **要选计数类柱状图的版式**（各亚群/各比较组上下调基因数、横向 vs 竖向、类别多且名字长）→ 见上方「计数柱状图…的版式选择与自检」
- 反例（**不要**用本 skill）：矩阵热图的纸宽反解、R base graphics/pheatmap 版式 → 用 `matrix-heatmap-geometry`

## 🔴 第一铁律：症状在标签，根因通常在**布局/坐标系**

用户描述的是**视觉现象**，不是代码缺陷。常见错配：

| 用户说 | 大概率根因（不是标签的问题） |
|---|---|
| 标签没对齐色块 / 顶端标签"掉"到色块下沿 | 布局函数算出**负高度** → 元素区间重叠 → 后画的盖住前一个，标签画在真实中心 |
| 最上面被截断、`×` 渲染成 `?` | 文字用**轴坐标**画在 `y>1` + `va="bottom"` → 超出画布 |
| 图例和脚注挤成一行 | 两套坐标系混用（axes 负 y vs figure 坐标） |
| 顶端标签被列标题压住 | ylim 上沿给标题的留白不足（改完必须复验） |

**流程：先算几何量（usable / 高度 / 区间是否重叠），再动手改。** 直接调字号、挪坐标通常治不好，会变成多轮返工。

## 布局函数的三条硬约束（写这类图的自检清单）

```python
# ✅ 布局函数必须同时满足：
TOTAL_GAP = 0.10
gap    = TOTAL_GAP / (n - 1) if n > 1 else 0    # ① 间隙 = 整列的固定比例
usable = 1.0 - TOTAL_GAP                         # ② usable > 0（写成断言/打印）
h      = usable * w / tot                        # ③ 元素高度 ∝ 权重，且 Σh + Σgap = 1.0
```

- **① 间隙必须与「权重数值」解耦。** 反例 `gap = GAP * tot / (n - 1)` 把总权重（如 102）当比例系数
  → 间隙总和 2.244 ≫ 1.0 → `usable` 变负 → 高度为负 → **相邻元素区间重叠**。
- **② 打印/断言 `usable`。** 它是这类 bug 的唯一早期信号，一行 print 省一轮返工。
- **③ 症状常具"选择性"**：同一脚本不同图行为不同（权重总和小的那张侥幸 `usable` 为正 → 完全正常）。
  用户只报其中一张时，**不要**按"个别标签问题"处理 —— 先算两张的 `usable`。

## 出图必带的三项几何自检（renderer 实测，替代肉眼）

写在 `savefig` 之前，数字直接贴给用户当证据：

```python
fig.canvas.draw(); rend = fig.canvas.get_renderer()
def _tcy(t):                                     # 文本框中心的像素 y
    b = t.get_window_extent(rend); return (b.y0 + b.y1) / 2

# ① 标签中心 vs 自己元素中心（<2px 才算对齐）
# ② 相邻元素区间重叠对数（必须 0）
# ③ 列标题 vs 顶端标签 / 主标题 的像素间距（>0 = 无重叠）
```

判据：`max|dy| < 2px` ✅ · `重叠 = 0 对` ✅ · 间距 > 0 ✅。任一不满足 → 没改完，别汇报。

## 🔴 第二类症状：文字 ⨯ 文字 互相压住（元素全对，是标注层自己叠了）

第一类的症状是"标签没对上元素"；**这一类的对齐全对，是文字自己撞在一起**。
高发场景：多面板审计图 / 对照图，标注层同时承载"坐标 + 结论 + 计数"三类信息。

| 症状（OCR 读出来是糊成一团的乱码） | 根因 |
|---|---|
| 一段长标签与加粗横幅糊在一起（OCR 出 `the onlyhregborBuMBeoiusttingicansee` 这类怪串） | 两行标签（`va="bottom"` 约占 0.09 轴高）与横幅 y 只差 0.075 → 索引区间相撞 |
| 同层两个长标签横向贴住 | 两段坐标在 x 上只差 ~18%（如 15.9% vs 33.3%），单标签宽约 17% 轴宽 → 边缘接触 |
| 轴外说明压住 x 轴刻度线 | 文字放 `y = -0.02`（轴外）且 `clip_on=False` → 落到刻度标签那一行 |
| 面板 C 表格漏行 | 行数写死，增补内容时忘了同步扩行距 |

**修法（按可靠性排序，①② 零风险优先）：**

1. **取消面板内长标签 → 改「单字形数字标记 + 轴内分层横幅」**：轨道上只标 `1 / 2 / 3`（单字形永不撞），
   完整坐标放轴内一条单独横幅；横幅之间 y 间隔 ≥ 0.10 轴高，`ylim` 同步抬高（本次 1.16）。
2. **轴外文字一律收回轴内**（`y=0.035, va="bottom"`），箭头/引线一并收回；轴外只留轴标题与刻度。
3. 多级标注按"泳道"分层：元素层 < 标记层 < 说明层 < 坐标明细层，**一层只放一行**。
4. 结构数量写成断言（`assert len(inter) == 3`）——数量变了立刻报错，而不是静默画歪。

### ⚠️ 变体三：**UMAP/降维图上的簇名标注** —— 小簇必然压字（2026-10-18 实测）

用户说「把亚群名打到 UMAP 上」时，冲突不是随机的，而是**由簇的像素体量决定的**：

- 604k 细胞的 UMAP 上，<1.5k 细胞的簇（实测 Adipocyte 427 / B cell 442 / NKT 731 / SMC 834 /
  DC 823 / Monocyte 983 / TNC+ FAP 1,075 / Mast cell 1,214）只有**几个像素**；
- 23 个簇名直接在质心铺文字 → **必然成片压字**（这不是"调调字号"能解决的）。

**先选策略再画**（三选一，不要混堆）：

| 策略 | 何时用 | 代价 |
|---|---|---|
| ① 质心 + 重叠消解（沿簇间方向推开） | 标签数 ≤12、各簇体量相近 | 推太远会指错簇 |
| ② **引线标签**（簇内点 + 短线段 + 图外文字） | 簇数多、体量悬殊（本例 23 簇）—— **最稳** | 需要算引线端点，代码略长 |
| ③ 小簇并入图外编号/清单，图上只标大簇名 | 小簇本身不是结论重点时 | 图外需配图例说明编号 |

判据同第二类症状：**重叠对 = 0**，用 `scripts/text_bbox_overlap_check.py` 复验（它扫的是
`ax.texts`，UMAP 上的簇名字也在内），把数字贴给用户而不是"看着还行"。
另：标签文字一律用**标签列原文（英文）**，中文只进图注（matplotlib 默认字体无 CJK 字形）。

**复验必须用工具复验，不能"看着好了"** → `scripts/text_bbox_overlap_check.py`（本 skill 自带，可直接重跑）：

```bash
python scripts/text_bbox_overlap_check.py <图的脚本.py> --dpi 300 --eps 4
# → texts collected / OVERLAPPING PAIRS / CHECK: PASS|FAIL / csv 明细
```

它用 `runpy` 执行绘图脚本（拦截 `plt.close` 保住 figure），在**导出 dpi** 下取全部
`Text.get_window_extent`（`ax.texts` / 轴标题 / 刻度标签 / `fig.texts`）两两求交。
判据：**重叠对 = 0** 才算改完，把数字贴给用户。OCR 只作第二证据——会把相邻文字顺序打乱，
且覆盖率有上限（实测 74 处文字 OCR 只报出 66 条）。阈值别设 0（相邻行允许亚像素相切）。

## 🔴 第三类症状：越界 —— 元素/文字跑到画布外（**静默，不报错**）

前两类内容都还在画布里；这一类**跑出边界，matplotlib 不报任何错**，肉眼只见"标签没了 / 尾巴缺一截"。
2026-10-23 一版三图连续踩了 3 处（同一根因家族）：

| 症状 | 根因 | 修法 |
|---|---|---|
| 左侧行标签**整块消失**（OCR 完全读不到） | `ax.text()` 用 blended transform（`ax.get_yaxis_transform()` / `transAxes`）时，**x 的单位 = 整个轴宽的比例**，不是小偏移量。写 `-0.75` = 向左 0.75 个轴宽（≈120 mm）→ 全在画布外 | 目标偏移换 mm → 除以轴宽 mm：左外 ≈15 mm / 148 mm ⇒ `x≈-0.10`；实测 `-0.075` 稳 |
| 右侧小注 / colorbar 标签被裁成半截 | 右对齐点写在画布边缘（`x=0.995` 已无余量）；`colorbar.set_label()` 落在 cbar 外侧 | 右缘留 ≥20 px；cbar 的 label 与面板标题重复时（标题已写 "cell shade = Jaccard"）→ **直接删**，不要挤 |
| 底部两行 caveat 只露一行 | 轴外注释 `transAxes y=-0.52`，面板下方距离不够 → 溢出画布 | 长注释改 `fig.text(0.02, 0.008, va="bottom")` 贴画布底，并把 `bottom` 边距从 0.085 抬到 0.16 |

**窄段百分比标签自动回缩**（堆叠条里 <5% 的段放不下字）：

```python
tx, ha = ups[i] + 2.5, "left"
if tx > 97.0:                     # 贴右缘 → 翻到轴内右对齐
    tx, ha = 99.2, "right"
ax.text(tx, y, f"{pct:.0f}%", ha=ha, va="center", fontsize=5.4)
```

**对称轴（symlog）顶端留白**：柱顶数值标签乘子用 `1.05`（不是 1.12），并给 `ylim` 顶端留 ≈8% 余量
（`v*1.12` 时最大柱的标签会贴到画布顶，实测顶边距只剩 12 px）。

**改完必须复验**（别用 OCR 判断越界——它读不出被裁或旋转的文字）：

```bash
python scripts/check_canvas_margins.py figures/*.png        # 四边边距全部 ≥12px 才算完
```

**定位"谁跑出去了"的两把尺子**（比猜快得多）：

1. **像素包围盒**：非白像素（`im.sum(axis=2) < 720`）的 min/max 行/列 = 内容边界 → 四边边距一眼看出哪侧贴边；
2. **artist bbox 扫描**（越界者的姓名）：重建 figure（`exec` 时把 `plt.close(fig)` 换成 `pass` 保住对象）后

```python
fig.canvas.draw(); w = fig.get_size_inches()[0] * fig.dpi
for t in fig.findobj(matplotlib.text.Text):
    bb = t.get_window_extent()
    if bb.x1 > w - 2:
        print("OVER RIGHT:", repr(t.get_text()), bb.x1)
```

实测靠它一眼点出 `'Jaccard'`（colorbar label）与 `'2%'`（`ups+2.5 = 100.5 > xlim 100`）两个越界者。

## 计数柱状图（上下调基因数 × 分类轴）的版式选择与自检（2026-10-23 实测）

同一份「各亚群 / 各比较组上下调基因数」数据，**版式选错就白画**：分类名长 + 类别多 → 必须横条。

| 版式 | 尺寸常量 | 何时用 |
|---|---|---|
| **横条**（`barh`，每类上下两条：Down 上 / Up 下） | `figsize=(8.4, 5.0)` | **10 个长名亚群（`Pure Type IIA` / `LRP1B+(I)` / `Specialized MF`）首选** —— 标签零旋转、y 轴摆得下全名 |
| 竖柱（`bar`，Down 左 / Up 右） | `figsize=(10.2, 4.6)` + `xticklabels(rotation=32, ha="right")` | 类别 ≤6 或名字短；类别多时标签互相挤压 |

- **两版式一次交付**（同骨架 × PNG/PDF/SVG），让用户挑定后再出 TIFF 定稿 —— 不要单版来回微调。
- 计数轴恒用 `symlog(linthresh=1)` + 十倍刻度（0/10/100/1,000/10,000），让 16,535 与 3 同轴可读；
  每根柱标自身数值、**按柱色着色**（红 `#B2182B` / 蓝 `#2166AC`），且只在 `>0` 时画（0 柱不标，避免"0"堆在轴线上）。
- 计数远小于刻度上限时（本例 max=67），**轴上限抬到 `max(60, 1.15 × max)`** —— 否则柱端标签会挤在轴顶端
  （接上面「symlog 顶端留白」那条：轴上限被数据决定时用 1.05 + 8% 余量，被固定下限抬高时用 1.15 即可）。
- 亚群序沿用项目定稿序（Pure I → IIA → IIX → LRP1B+(I) → RP_high(I) → RP_high(II) → OTUD1+(I) → OTUD1+(II) → RSS → Specialized MF），
  **全部类别都要画**（不要因为某类计数只有 3 就剔除 —— 「几乎不响应」本身就是结论）。

## 像素级核验（肉眼/OCR 说不清时的硬证据）

PIL 按元素**纯色**（不透明块色，容差 tol≈10）扫一列找连续段 → 段中心 与 OCR 文本框 y 对照。

- ⚠️ **OCR 的 y 是文本框顶边**，比中心高约半行高（9.2 pt @300dpi ≈ 38 px → 偏 ~19 px）。
  两处比较必须统一口径，否则这 19px 会被误读成"错位"，白改一轮。
- ⚠️ 纯色扫描会把相邻**同色**元素连成一段（只靠白描边分开）。元素已重叠时，扫出的段边界 ≠ 单个元素边界：
  先用两个**确定不重叠**的元素标定 `px_per_unit`，再反推被怀疑元素的高度 ——
  实测重叠元素的高度只剩理论值的 ~50%（ITIH4 理论 272 px / 实测 134 px），这就是"被上层盖住"的量化证据。

## matplotlib 细坑

| 现象 | 解法 |
|---|---|
| `AttributeError: 'Bbox' object has no attribute 'get_center'` | `Bbox` 无此方法 → 取中心用 `(b.y0 + b.y1)/2` |
| 顶部文字被裁（`×` → `?`） | 别用轴坐标画标题 → `fig.text(0.5, 0.972, va="top")` + 同步 `subplots_adjust(top=0.92)` |
| 底部图例与脚注撞行 | 图例在 axes 坐标（负 y），脚注改用 figure 坐标锚底（`fig.text(0.5, 0.044 / 0.016)`） |
| 负高度 `Rectangle` | 仍会渲染（自动翻转）—— 但**不要**拿它当借口，重叠才是真问题 |
| 保存后像素坐标对不上计算值 | `bbox_inches="tight"` 会裁剪平移 → 自检一律在 `fig.canvas` 坐标系里比，不做绝对像素推断 |
| 轴外标签整块不见、**无任何报错** | blended transform（`get_yaxis_transform()` / `transAxes`）的 **x 单位 = 轴宽比例**：`-0.75` = 左外 0.75 个轴宽 → 落在画布之外。先把 mm 偏移 ÷ 轴宽 mm，再写小数 |
| `colorbar.set_label()` 把右侧撑出画布 | cbar label 若与面板标题重复（标题已说明色代表什么）→ 直接删；或把 gridspec `right` 收到 0.94–0.95 |

## 改图迭代工作流（本用户偏好）

1. **每次重出前备份** `figures/_backup_<name>_vN/`（N 图 × 4 格式），可回退；不要覆盖式重出
2. **只 patch 常量与坐标**，不重写脚本；改完把自检数字贴出来（"max|dy| = 0.00px、重叠 0 对"）
3. **图内说明文字用英文**（图注/图例/列名/脚注全英文化），正文回复用中文
4. 版式定稿后**回写 `[图稿]` 记忆条目**（常量名+值，≤150 字），下轮改图直接按记忆 patch，不重读整份脚本
5. 交付时说清：改了什么、为什么（根因链）、自检数字、产物路径 4 格式 + 备份位置
6. **用户说「帮我解释这张图的意思」＝逐面板讲解，不是重跑**：每个 panel 说清
   「画的是什么 → 单位/口径是什么 → 它回答哪一问」，末尾一句收口「这张图要替你说的一句话」。
   图与文字互补：出了 Mermaid 骨架不代表可以把每 panel 的细节写少。
7. 🔴 **数据在集群/对象 GB 级 → 抽一次精简坐标 CSV，之后在本机迭代**（2026-10-18 实测）：
   每轮 ssh 重读 7 GB 对象 = 每轮 10–15 分钟，改三次就是一小时；
   ```r
   write.csv(data.frame(barcode = colnames(obj), UMAP_1 = emb[,1], UMAP_2 = emb[,2],
                        <标签列…>), "coords.csv", row.names = FALSE)   # 604k 行 ≈ 40–60 MB
   ```
   `pull` 回本机后，配色/字号/标签位置**全部本机秒级重跑**（改图迭代的第 2 条才真的做得到）。
   只有「要看表达量 / 重算降维」时才回原对象；用对象里**已有的**降维坐标（`Reductions(obj)` grep `umap`），
   不重算 UMAP。
8. **交付前第一道门 = `vision_describe` 读图事实清单**（纯本地管道，不调视觉模型）：核对 ① 标题
   ② **全部分类名一个不漏** ③ 柱端数值 ④ 图例 ⑤ 轴标签，并确认图非空白。
   本类图 PNG@400dpi 健康区间参考 **190–260 KB**（10 类目）；**<5 KB 疑似空白**。
   ⚠️ 定位清楚：OCR **只用于**「元素是否齐全 + 是否空白」这道粗门 —— 它会把 `7` 认成 `6`、
   会漏掉个别柱端数字（数值一律以脚本 stdout / 交付 CSV 为准），也读不出被裁或旋转文字，
   所以**几何对齐仍走包围盒自检**（`scripts/text_bbox_overlap_check.py` / `scripts/check_canvas_margins.py`）。

## 配套文件

- `references/sankey-layout-geometry.md` — 桑基/冲积图专项：负 usable 完整失败链、纯色段扫描脚本骨架、
  `px_per_unit` 标定法、以及一张定稿图的全套版式常量（可当模板）
- `scripts/text_bbox_overlap_check.py` — **可重跑**的「文字 ⨯ 文字」包围盒互检（runpy 执行目标脚本 →
  导出 dpi 下两两求交 → PASS/FAIL + CSV 明细）。用户报"文字重叠"修完后必须跑它并贴数字。
- `scripts/check_canvas_margins.py` — **可重跑**的画布越界检查：读 png 报四边边距 + 上下墨迹带，
  任一 <12 px 即 FAIL。改完轴外标签/脚注/colorbar 后跑它（越界是静默的，OCR 读不出被裁文字）。
