## 六组分布图（Fig_type6_by_subcluster，v8 新增图型）

**用途**：用户要"各基因集在不同 type 和亚群的分布"——纯绝对水平展示，不差分，与五效应图（变化量）互补。

**结构**：
- 行 = 22 打分，左侧三色带（🔵 Metabolic 11 / 🟡 Fiber identity 4 / 🔴 Senescence 7），组间 0.2 间隙
- 列 = 6 type × 10 亚群 = 60 列：Y_Pre → Y_Post → O_Pre → O_Post → OD_Pre → OD_Post
- type 间留 1.2 间隙（一眼可辨），亚群格间无间隙（CELL=1.0）
- 值 = 样本级均值（每 type×亚群 取个体平均），行内 z-score ±2 截断
- 标签：**type 顶部灰条标题、亚群底部 45°、基因名左侧**——全部图形外

**读图逻辑**：同一打分横向看 6 组（如 scoreOxPhos：Y_Pre 蓝 → 老年变浅/红 → 运动组变蓝=回落）；同 type 纵向看 10 亚群偏好；6 组并排对比 Y/O/OD 三系 Pre/Post 分布差异。

## ⛔ 坑 1：matplotlib y 轴坐标倒置（v8 翻车，最隐蔽）

**症状**：type 标签渲染到底部、亚群标签渲染到顶部——用户连续报"亚群还在上呀"。

**根因**：手动 `fig.add_axes` 画分块热图，matplotlib y 轴**向上增长**。脚本里
"亚群标签画在 y=26.8（大值）"→ 渲染到**顶部**；"type 标题 y=1.7（小值）"→ **底部**。
之前几轮只调数值距离（-1.9→-0.35→…）没意识到坐标方向本身就是反的。

**修复**：`ax.invert_yaxis()` 翻转后 0 在底部、大值在顶部，坐标语义恢复
（type 顶部、亚群底部）。

**铁律**：改自定义热图标签位置前，先确认 y 轴方向约定对不对，再谈距离大小。
invert_yaxis 后"贴紧底边"的小间隙是**正偏移 +0.4**，不是负偏移。

## ⛔ 坑 1b：45° 旋转文本 va='top' 会把标签压进热图（v8 尾部）

**症状**：亚群标签偏移从 +0.4 调到 +4.0 用户仍报"label 还在热图里面"——只调距离不够。

**根因**：`ax.text(..., rotation=45, va='top')` 时，45° 旋转文本的**边界框向上延伸**，
即使锚点在热图底边下方，文字顶端也会视觉压进热图色块。va='top' 的锚点是文本顶部，
45° 旋转后文本整体向右下展开，但 bbox 顶部仍接触/越过热图底边。

**修复**：`va='center'`（文本中线对齐）+ 足够大的 y 偏移（+4.0 而非 +0.4）+ 同步加大
底部留白（SUB_H=6.5）。**验证必须像素扫描**（PIL 逐行统计非白像素：热图底边 y≈2100、
标签 y≈2200-2500、y>2500 全白 = 标签完全在图外），只信 savefig 成功不够——OCR 可能
认不出 45° 小字而误报"底部无标签"。

**铁律**：旋转文本改位置 = 距离 + 对齐方式（va）双管齐下；交付前用像素扫描确认
"热图底边 < 标签区 < 图底"三段分离。

## ⛔ 坑 2：tight_layout 与 add_axes 颜色条不兼容

**症状**：用户报"Fig1 v7 的 PNG 没变、PDF 对了"（PNG 热图空白/只见 label，PDF 正常）。

**根因**：`plt.tight_layout()` 与 `fig.add_axes` 手动颜色条冲突，PNG 渲染异常但
PDF/SVG（矢量）不受影响。

**修复**：去掉 tight_layout，用 `subplots_adjust` 手动布局。交付前
`vision_describe` 验证 PNG 实际内容（OCR 主色 >60% 灰白 #e0e0e0 = 热图格没画出来）。

## ⛔ 执行纪律（用户多次发火）

- "图呢？""你执行了吗？""没有更新啊" = 上一轮只说了没做。说"改"必须同轮绑定工具调用
- 用户核对文件时间戳验证是否真更新
- 修图循环里不做环境诊断（切 Python 绘图栈绕开 R DLL 地狱），改参数→跑→交付
- **两次"patch 后没跑"教训（2026-08-15 尾部）**：patch 落盘 ≠ 图更新。每轮 patch 后
  必须 `python scripts/fig_xxx.py` 实际执行 + 确认输出文件 mtime 刷新，用户
  会逐版对比 PNG 内容（"Fig1 v7 都变了，但是 Fig7 v7 的 pdf 变了，其他没有变"——
  说明用户在看文件时间戳和内容双核对）。

## 基因集响应筛选（"哪些打分没响应可删掉"）

用户问"哪些基因集没有太多响应，可以删掉"时，用长表 `effect5_d_v2.csv`
（1100 行 = 22 打分 × 10 亚群 × 5 效应，列 score/sub/effect/d/q）直接算三指标，
不重读原始 meta：
1. `mean(|d|)` per score（50 格平均响应强度）
2. `q<0.05` 显著格数 per score（1100 检验中约 93 显著）
3. 逐效应轴方向性（Aging 平均 d≈0 且同向性差 = 该轴无故事；T2D 轴去神经 d≈0 无信号）
删除判定梯：三指标都低 → 建议删/进补充；单轴响应 → 保留降级；有反转故事 → 核心保留。
输出 = 打分 × 三指标表 + 每条一句话理由，用户拍板删哪些，不擅自改列表。
