# 零 delta 轮次回复纪律（Wake-up Tick 专用）

## 为什么单独有一份
「待决项只进 notes.md、回复里不重列不带邀约」这条规则写在 SKILL.md 里，
却在 **tick#22 和 tick#24 连续两轮被同型违反** ⇒ 这类违规不是「不知道」，
是**写回复时想不到**。所以这里只放两样机械可用的东西：**禁串清单**（可 grep）+ **合规模板**（可照抄）。

## 违规证据（逐字同型，都在结尾）
| 轮次 | 我实际发出的结尾 | 违规点 |
|---|---|---|
| tick#22 | 台账记录：「挂起项重列 + 邀约句」 | 重列挂起项 + 发出邀约 |
| tick#24 | 「**待你决定的 2 项**（LoopX 保持 paused…）1. 32 号卡缺 DOI… 2. **是否恢复 LoopX** —— 说一句「恢复 LoopX」即可」 | 同上，逐字同型 |

两次的失守位置**都在回复最后一段**。零 delta 轮的结尾是最容易失守的地方 ——
因为前三行（三源核验表）都对，最后一段是「惯性收尾」，很容易滑回汇报模式。

## 禁串清单（发前扫自己的草稿）
```
待你决定 · 待决定 · 待你确认 · 需要你 · 请提供 · 说一句 · 即可恢复 · 要不要 · 仍挂起 · 下一步你
```
命中任一 ⇒ **删掉整个结尾段**。不要改成别的措辞 —— 改写通常只是换个说法继续邀约，
（例：「还缺 DOI」= 邀约；「等你确认」= 邀约；「说一句 X 即可」= 邀约）。
可自动化的那一环：`replay_reply_lint.py --ledger`。

## 合规模板（照抄，不要临场发挥）
零 delta 轮回复 = 三行核验表 + 一句结论，然后**结束**：

| 核验源 | 实测 | 判定 |
|---|---|---|
| 交付物 | <字节 + mtime> | 与上次全同 ✔ |
| 核心产物 md5 | <值> | 第 N 次同值 |
| 状态注册表 | registry status / quota | pause 未丢 |

> 无待办：任务终态、无产物 delta、本轮零写入。待决项见 `notes.md`。

待决项**只**写进 `results/<sid>/notes.md`：
`- ⏳ 待用户 N 项决定：① … ② …`
用户当轮**主动问起**（「还剩什么」/「还差什么」）时才在回复里列。

## 例外
用户当轮明确提问 ⇒ 正常回答，不受本清单约束（本规则只管**系统唤醒自主轮**）。
