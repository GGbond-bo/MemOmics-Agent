# 轮询循环检测与产物交付（2026-10-18 实测）

跨唤醒轮询同一个后台/集群作业时，连续多轮发**几乎相同**的监控命令，平台循环检测器会注入强制干预：

```
【系统循环检测·强制干预】检测到你已连续多轮重复几乎相同的操作和表述
（工具调用循环：连续执行相同/相似的监控命令）。判定为循环失控，请立即停止重复：
1. 停止再执行重复的监控/查看动作；
2. 若任务产物已生成（图/文件已保存、命令返回成功），直接视为完成，
   禁止再做任何验证/检查动作；仅当确实不知道结果时才做一次状态确认；
3. 用 2-3 句话给用户明确结论：任务已完成 / 已失败 / 已卡死（附原因与产物路径）；
4. 结束本轮回复，禁止再次执行重复动作。
```

## 规程（每条都是踩过的）

1. **一次探测取全量**：把 `ls -la <输出目录>` + `ps -ef | grep -i "[脚]本名"` + `tail -30 <日志>`
   合成**一条**命令（单次 ssh / 单次 terminal），不要拆成 3 次调用 —— 拆开就是 3 轮"相似监控动作"，
   计数累积最快。
2. **产物存在 = 完成**：目标文件带合理体积（PNG >100KB、图表 >1KB、脚本/RDS 非 0）且进程已退出
   ⇒ 直接判完成，**不再**补 ps / 日志二次确认。`ps` 返回空本身就是终态证据，不必再验一次。
3. **拉回 ≠ 验证**：产物已生成后的下一步是 `pull`（交付动作，含体积/覆盖参数），
   不是再跑一遍监控命令。拉回只在**同一轮**做一次。
4. **单轮 ≤2 次状态探测**；唤醒 #N 与 #N+1 之间靠 task_plan / 会话锚点对齐，不重复 ssh。
5. **图类产物拉回后用一次 `vision_describe` 体检**（非空白 + 标题/图例 OCR）——这是质量检查，
   允许且必要（用户历史上批评过空白图）；但**每图只查一次**，查完即报，不追加第二遍。
6. **汇报 2-3 句 + 产物路径表**，然后结束本轮，等下一次唤醒或用户消息。

## 误判红线

- ❌ 图/表已生成，仍继续跑 list/ps/tail"确认一下" → 触发干预，白烧 token 且被判定循环失控。
- ❌ 产物都已拉回本地了，又回头 ssh 复核一次 → 同类违规。
- ❌ 把"监控命令串很短所以没事"当理由 —— 计数看的是**命令相似度与轮次**，不是命令长度。

## 与集群作业配合

集群长任务的标准收尾链（只走一遍，不回头）：

```
submit（脚本落 results/<sid>/scripts/）→ 唤醒时一次探测（ls+ps+tail）→ 产物在且进程退
→ pull 小产物（图/表/日志/脚本）到 results/<sid>/ → vision_describe 一次 → 汇报并结束
```

大文件（RDS/BAM/中间矩阵）留集群，只拉表格/图/脚本/日志；拉回后确认落在 `results/<会话目录>/`
（WebUI 只浏览 `work/` 与 `results/`）。
