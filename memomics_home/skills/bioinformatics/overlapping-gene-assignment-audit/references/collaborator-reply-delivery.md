# 交付：给合作者的说辞（中英双版）+ 附件清单 + 交付卫生

**来源：2026-10-01 实测。用户验收原话：「44d_MEF2C_AS1_audit_map 这张图很好，我给他之后，要怎么跟他说呢？你给我中文和英文版本的说辞」** ——
说明图/审计包做完 ≠ 任务完成，**还差一段可直接发送的成品文本**。

## 一、用户要的是「可直接粘贴的成品」，不是要点

| 用户说法 | 交付物 | ⛔ 禁止 |
|---|---|---|
| 「我要怎么跟他说」「给我说辞」「帮我回他」 | **两段完整正文：中文一版 + 英文一版**（可直接复制发送，含编号要点、坐标/bp/百分比、附件说明） | 只给「你可以强调这三点」式建议；只给摘要；只给英文 |

⚠️ **默认出双版**（中文版给用户本人/中文同事，英文版给国际合作方）——**除非用户点名只要一版**。
本 skill 早期写的「答复一律英文」是**不完整的旧口径，已被本轮纠正**；图内文字仍一律英文（那是另一回事）。

## 二、被验收通过的回信骨架（5 点，按此顺序写）

1. **先承认重叠存在** —— 直接给坐标 + bp，不回避、不淡化（对方已自己看到，回避只会显得心虚）
2. **拆两个口径** —— gene-span overlap（对方看到的数）vs **exon-level overlap**（UMI 真正看到的），
   给 bp / 段数 / 百分比，并解释「标准 UMI 流程按外显子计数，内含子那段根本不进计数」
3. **链方向** —— 反向 ⇒ 按来源链归属（辅助论据；**不要当唯一论据**，会被追问到具体 Cell Ranger 的 ambiguous UMI 规则）
4. **自身数据反证（最有力）** —— 用**对方关心的那张表/那份数据**：两个基因结果不同向 ⇒ 没串味。
   必须带具体数字（coef / FDR / 亚群数），不能只说「数据支持我们」
5. **主动亮出未证部分 + 可复现承诺** —— ① 明说目前确定的是「注释几何 + 计数原理」，还差
   **建库 3′/5′ 化学**与 **strandedness 参数**两步实测；② 附审计包，「**跑一条命令就能复现全部数字，
   不用信我说的**」；③ 邀请对方直接指出问题

**第 5 点是这套说辞能一次通过的关键**：主动划界比夸大结论可信得多，而且把「质疑」转成
**对方可自行执行的一个动作**（跑 verify.sh），争论就结束了。

## 三、附件清单（固定三件，别多塞）

| 建议发 | 说明 |
|---|---|
| 图（优先 **PDF 矢量**） | 屏显/打印都不糊；注明同目录另有 png/svg |
| 审计包**整个目录** | BED + `verify.sh` + `README.md`（**README 写英文**，对方可直接跑、不用再解释） |
| 点名两个最关键文件 | `overlap_exons.bed`（唯一有歧义的那 422 bp）+ `verify.sh`（一条命令复现） |

附件一律给**绝对路径**，并一句话说明「对方可以自己跑，不用信我说的」。

## 四、交付卫生（本轮真实踩坑）

- 🔴 **超长双语消息会被流式截断**：一条消息里同时塞「中文版 + 英文版 + 附件表 + 收尾」，
  英文版**在第 3 点被服务端截断**，用户拿到半截正文，必须整段重发。
  ⇒ 对策：① 中/英两版**分两条消息**发；或 ② 先把说辞落盘成 `.md` 再给路径；
  或 ③ 单条内控制长度、附件清单压缩成 3 行。**截断后的正确动作 = 原样重发完整版**
  （用户要的是能整段复制的东西），不要只在末尾补一段尾巴。
- 说辞里引用的每个数字，发之前**回磁盘核一遍**（`audit_summary.csv`、DEG 表、GTF）——
  这是发出去给外部看的，错一位数字比晚发十分钟严重得多。
- 收尾加一句「要不要我把这份说辞也存成 md 方便你转发」——用户常需转给中文同事或留档。
