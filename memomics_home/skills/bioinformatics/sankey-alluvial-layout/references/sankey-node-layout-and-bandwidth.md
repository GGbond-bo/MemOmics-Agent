## 一、v6 的真实 bug 链（gap 用了总权重数值当比例）

```
gap = TOTAL_GAP * tot / (n-1)      # TOTAL_GAP=0.022, tot=102(UP), n=10
    = 0.022 * 102 / 9 = 0.2493     ← 单段间隙
9 段间隙总和 = 2.244               ← 远超整列高度 1.0
usable = 1.0 - 2.244 = -1.244      ← 负
h_i = usable * w_i / tot < 0       ← 每个节点高度为负
```

后果（脚本里 `pos[name]=(y-h, y)`，`h` 为负 → `y0 > y1`，区间反向且互相重叠）：

后画的色块盖住前一个的下半截，而标签画在**真实中心** `(y0+y1)/2` → 顶端几个基因标签"掉"到色块下沿：
**ITIH4 偏 72 px / MEF2C-AS1 偏 53 px / PALLD 偏 27 px**（越靠顶越严重）。

**为什么只有 UP 版暴露**：DOWN 版 `tot=24` → 间隙总和 `0.022×24/9×9 = 0.528 < 1.0`，`usable` 仍为正，

## 二、v7 MIN_H 与守恒证明

```python
usable = 1.0 - TOTAL_GAP                 # 0.90
Σh 在循环中恒等于 usable：
  - 被钉住的节点各取 mh，rest -= mh
  - 剩余 free 节点按权重瓜分 rest（Σ = rest）
  → Σh = Σ_pinned mh + rest_final ≡ usable
```
- `mh = min(MIN_H, usable/n)`：节点极多时下限自动下压（本例 n=10/7，未触发）。
- 布局从 `y=1.0` 向下推进，末节点底边恰落在 `y = 1.0 − (n−1)·gap − usable = 0.0` → **不溢出 ylim**。
- 色带 `lspan = (y1−y0)/w` 逐节点计算 → 钉底后自动跟随；`Σ_pairs n_contrast = w_node`，所以色带仍**精确填满**节点。

## 四、像素级核验配方（本 skill 判据的来源）

对 300 dpi 成品 PNG：
1. **节点条定位**：按颜色 mask → 逐列算最长竖向连续 True → 取左半/右半的最大者 = 条带列。
   ❌ 别忘了底部**图例的小色块**也命中同色（本例落在同色族里）→ 用"最长连续"而不是"任意命中"筛掉。
2. **条带段**：在该列取连续 True 段，`bridge ≤ 3 px` 桥接白色描边（`edgecolor="white", lw=0.7`）。
3. **标签 band**：`|im − (34,34,34)| ≤ 90` 的墨迹 mask，只保留条带外侧 x 区间 + `[top−28, bottom+28]` y 区间
   （排掉列标题 / 图例 / 脚注），按行连通取 band。
4. **配对**：左右各自**按上下顺序**与条带配对（数量应相等；不等就打印全部原始 band 排查）。
5. **判据**：中心偏差 ≤ 3 px；**节点高 ≥ 1.5 × 标签 ink 高**；相邻条带 0 重叠。

⚠️ 标签 ink 高度（34 px）会小于 `9.2pt/72×300 = 38.3 px`（数字实高不含行距）——比较时用**同一张图里量到的 ink 高**，别混用理论值。

## 五、排查顺序（用户说"不对齐"但你量中心是 0 px 时）

1. 先确认**量的对象**：是脚本变量（恒等式，无意义）还是导出的 PNG（有效）？
2. 量 PNG：中心偏差若 ≤3 px 而用户仍说错位 → **改量高度比**（本轮真缺陷就在这里：1.00）。
3. 高度比也正常 → 量**相邻间距是否均匀**、字体是否被替换、是否有文字被裁。
4. 全都正常 → 让用户指认（`ask_user` 勾选 / 贴截图），**不要判定用户看错**
   （本轮教训：先用假数字回了"我量过，偏差 0.5 px"，用户只能重复同一句抱怨）。
