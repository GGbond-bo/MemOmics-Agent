# 矩阵热图「增删成员 / 增删分组轴」最小编辑协议

> 触发：用户看完图后说 **「XXX 这个不要了，重新画」** / 「再加一个 YYY」 / 「把 Z 单独拉出来一组」。
> 这类请求**是参数级小改，不是重设计**（用户会明说「应该很快吧」）。目标 = 一次跑完、只报「改了什么 + 新文件路径」。

---

## 一、删除一个基因集（连带它所在的轴）——四件套，缺一件就报错或留残余

以零依赖 base graphics 的「轴分组矩阵热图」（`PROGRAM` + `AXES` + `DISP` + `GAPX_AFTER` 四常量驱动）为例：

| # | 改哪里 | 改成 | 漏改的后果 |
|---|--------|------|-----------|
| ① | `PROGRAM` 向量 | 去掉该项（18 → 17） | 矩阵仍算该列，图上多一列 |
| ② | `AXES` 列表 | 删掉**整个轴对象**（6 → 5；若该轴只剩这一个成员） | `stopifnot(setequal(gene_order, PROGRAM))` 直接中断 |
| ③ | `DISP` 映射 | 删掉该项的显示名 | 无害（仅冗余），但保留会让下次读脚本的人误以为还在 |
| ④ | `GAPX_AFTER` / 任何"隔离专用间隙" | 一并删 | 少了一个成员却仍留 0.7 的异常大间隙，图上出现无意义空白 |

**脚本自检要一起改**：结尾的 `cat("程序集数:", length(PROGRAM), "| X 是否已移除:", !("X" %in% PROGRAM))` —— 让"删干净了"成为可验证的 stdout，而不是靠肉眼看图。

## 二、画布尺寸**不要手改**——它会自动收窄且色块保持正方形

只要每格物理尺寸是**常量**（`U` = in/数据单位），几何就是自解的：

```
W = 列数 × U + 左边距 + 右边距        # 少一列 = 少一个 U
H = (行数 + 顶部预留) × U + 上下边距
```

实测（18 → 17 列，`U = 0.42 in`，`MAI = c(0.95, 1.05, 0.95, 0.78) in`）：
`9.60 in → 9.39 in`（恰好少 0.42 in），**色块仍是 0.42 in 正方形，没有拉伸变形**。

⚠️ 反例：如果画布是**手填常数**而不是由列数推出来的，删成员后色块就会变宽变形 —— 先把它改成推导式再删。
⚠️ 与 pheatmap 路径的区别：pheatmap 不传 `cellwidth` 时本体是 null 单位、会随设备宽联动（见 `pheatmap-margin-only-adjustment.md`）；**base graphics 手写 `rect()` 的路径不存在这个问题**，常量 `U` 天然解耦。

## 三、验证 = OCR 数标签，不是"文件非空"

```python
# vision_describe 读 PNG，然后数两条
#   基因集标签数 == len(gene_order)（本例应 ≥17）
#   亚群标签条数 == len(SUBS)（本例 10）
# 少一条 = 45° 标签被画布底部静默裁切（图不报错、文件大小正常）
```
同时把**被删项的名字**作为负向判据：OCR 全文里**不得出现** `Stress`。正向数够 + 负向不出现 = 删除确认。

实测核验（2026-09-15 v3）：17 个基因集标签全识别 / 5 个轴名（Metabolism·Nutrient·Contractile·Inflamm-aging·Decompensation）全识别 / 10 个亚群标签无裁切 / 全文无 `Stress`。

## 四、交付：两处落盘 + 旧版归档（用户翻的是项目根 `figures/`）

```r
OUTS <- c("<项目>/figures",                    # ① 用户翻看的位置（定稿名）
          "<项目>/figures/R_version")          # ② 工作目录（版本名 + manifest）
# 写完再：旧版 file.copy 到 figures/archive_superseded/（移动而非删除，删除保护会拦）
#        然后把新图复制成不带版本后缀的规范名 → 用户下次还去同一个路径找
```
只落子目录 = 用户回「我没看到图」。**判断标准：用户下次会去哪找它？**

## 五、两条执行环境注意（本平台）

1. **`rail_review(pre)` 不要传 `required_packages`** —— 连 `grDevices/graphics/stats` 这类 base 包都会被误报 Missing 并锁死执行工具；不传即 `should_proceed=true`（脚本零改动）。详见 `platform-execution-pitfalls`。
2. `execute_r` 被会话级护栏拦住时，`terminal` 仍放行：
   `"/c/Program Files/R/R-4.5.3/bin/x64/Rscript.exe" --vanilla "<脚本绝对路径>"` —— 实测一次跑完 4 格式。

## 六、🔴 别把删掉的东西加回来

本类图上的**诊断性分组**（解离应激伪影 Stress index 等）常先经辩论得出"单列 + 加大间隙"的**过渡方案**；
但用户看过隔离版后可能直接下令**删除**。**用户裁决 > 辩论共识 > 你的设计直觉**：
- 删除后在脚本注释里保留一行"依据：用户 2026-09-15 决定移除"，避免下轮被"辩论说要保留"说回来；
- v2（隔离版）脚本**保留备查**，但**不要**在下一版默认加回；
- 交付时明确说「已移除，连带 XX 轴」——用户要的是"没了"，不是"弱化了"。

## 七、速度期望

用户对这类改动有明确的**快**预期（原话「应该很快吧」）。因此：
- 只 patch 那几行常量 → 直接跑 → OCR 一次 → 汇报「改了什么 + 新路径」。**不要**重述全部版式规格，不要趁机换配色/字号/布局（最小增量原则）。
- 汇报用「旧值 → 新值」的对照表（如画布 9.60 → 9.39 in、18 → 17 集、6 → 5 轴），比复述设计更省他的时间。
