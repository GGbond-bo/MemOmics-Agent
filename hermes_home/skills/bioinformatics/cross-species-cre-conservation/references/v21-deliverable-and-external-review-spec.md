
## 5. 图片 QC 两轨（用户说「图片记得确认对不对」时）

**一次做完，不逐张跨轮反复核**（反复核验会被判循环失控，见 §7）。

**轨道 A · 程序化（秒级，一次跑全目录）**
```python
from PIL import Image; import numpy as np
a = np.asarray(Image.open(p).convert('RGB')).astype(int)
n_color = int(((a.max(2) - a.min(2)) > 12).sum())   # 彩色像素，判据须 == 0
nonwhite = float((a.mean(2) < 245).mean())          # 非白占比，判据 5%–30%（<2% 疑空白）
```
实测本套：彩色像素全 **0**，非白占比 8.00%–25.67%，尺寸 2573×1397 – 5066×1514，体积 216–607 KB。

**轨道 B · OCR 数值对账（vision_describe，一次并行提交多张）**
把图内 OCR 到的数字与源 CSV 对账，而不是「看着像对」。本套对账点：
图2 的 16,029/3,180/1,604/150 + 通过率 19.84/50.44/9.35 自洽；图5 的 0.435/0.219/ρ=0.764/fold 4.53/p=7.7e-05 与
`v21_monkey_L1_stats.json`、`v21_senescence_signature_enrichment.csv` 一致。
⚠️ OCR 会把 `②/③`、`≥`、对数轴刻度（`10²`）读错，**报告图有误前先按 `deliverable-consistency-and-figure-qa.md` 做同字体重渲染反证**；
x 轴刻度被读成「102/103/104」属正常误认，不是缺陷。

## 7. 批量核验纪律（防被判「循环失控」）

本次实测被系统干预的原因**不是验证本身错**，而是**把一次核验拆成多轮近重复动作**。正确节奏：

1. 出图 → **一个脚本**跑完 5 张的纯度/空白/尺寸检查（一次 terminal/execute_python）。
2. **一批并行** `vision_describe`（同一轮里发多张，不要一张一轮）。
3. 核验通过 → **直接产出交付件**，不再回头「再确认一次」。
4. 汇报里给「生成了几张 / 每张尺寸内容概要 / 核验结果」即可，不复述核验过程。

配套：路径存在性告警（如系统提示「E:\专利\_archive_交底书旧版 不存在」）**是提示不是结论**——
先 `ls` 实测再答；本次该目录真实存在（23 个文件），照告警回复会误导用户。
