# 同状态唤醒多轮空转：升级催办规程（2026-10-01 memomics-afd2d418 实测，唤醒 #12）

## 触发形态

- 唤醒编号持续增长（本次到 #12），**每一轮的三源结论逐字相同**：Phase 全 complete、磁盘无新产出、无后台进程。
- 主线区残留的未勾项**全是「AI 不可代办、等用户拍板」的项**（E3d 形态）：此处 4 项 = ① 重启服务后跑 smoke ② `.gitattributes` eol 策略 ③ 提交分组 ④ 是否暂停 LoopX。
- 第 ④ 项正是**空转本身**——LoopX `registry.json`（active + quota>0）每分钟 tick；**系统文件未获用户批准前一律不动**，所以只能靠催办闭环，不能自己停。

## 每轮该做 / 不该做

| 做 | 不做 |
|---|---|
| 只跑**能改变答案**的那一条只读探针（本轮 = 部署生效性探针：服务是否已重启） | 每轮把三源仪式、skill_view 全套重跑一遍（结论不会变，纯烧 token，且堆叠上下文 → 响应变慢） |
| 若本轮**修好了自己探针的假阳性/假阴性** → 把它当成这一轮的真实交付写进汇报（本轮修了两处，见下） | 为凑门禁硬造新工作、或把「等用户」项擅自勾选/删掉 |
| 汇报 = 状态表 + 本轮修了什么 + 待办表（含跟催入口）+ 弹窗 | 逐字重复上一轮的整段表格与理由 |

### 本轮修掉的两处探针缺陷（可复用结论）

1. **假阳性**：按镜像名（`python.exe`）枚举候选进程，会把**瞬时 python 子进程**当成"服务"——它们恰在文件改动之后启动 ⇒ 误报「晚于引擎 ⇒ 已装载」。
   → 按 **cmdline** 过滤（同时含 `webui` 与 `server.py`）+ 判定前重查 PID 是否仍存在。
2. **假阴性**：加了"排除探针自身及祖先 PID"之后，**服务本体也被排掉**（探针是服务进程的子进程）⇒ 退化成「未发现候选，无法判定」，把该报的「需重启」藏了。
   → 加 **`--port <端口>`（LISTEN → pid 映射，最硬判据）** + **祖先豁免**（存活 + 早于探针 ≥5 s + 命中命令行或持 LISTEN ⇒ 重新纳入）+ **打印被排除的 PID 清单**。

## 催办升级：文字菜单 → 一次性弹窗

- 判据：**同一张「等待用户」表连续 ≥2 轮无人回应，且 AI 侧确无可执行步骤** ⇒ 把回复里的文字菜单换成一次 `ask_user(kind="clarify", multi_select=true)` 弹窗。
- 形状（本轮实证）：**一次把 4 项全列**，每项带 `desc` 说明代价，**根因项（暂停空转唤醒）标 `recommended: true`**，并**必须给一个「都先不动，保持静默」选项**——否则用户没有"不选"的出口。
- 收尾话术要点：说明这是第 N 次同状态唤醒、第 4 项是治空转的根因、"你批一句我就停掉，不再刷屏"。
- ⛔ **每议题只弹一次**；用户未答就继续等，不要每轮重弹（重复弹窗 = 另一种刷屏）。

## 同一议题的辩论：如实跳 L0

本轮又收到辩论门控（L1，理由"失败重试≥2 → 升级 L2；预算护栏降级 L1"）。**跳过并在回复里写明理由**：

- 只读探针、无候选参数可选；
- **同一 topic 本会话已辩过**（L2 裁决 + L1 复审）；
- 结论跨 12 轮未变；
- **下一步动作在用户手上** —— 辩完改变不了任何动作。

判准永远是「辩完能否改变下一步动作」，不是"门禁提示了就必须辩"。⛔ 不为凑门禁硬辩第三轮。

## 两个门禁工具在本轮的形态（易误判）

### 1. `rail_review(post)` 的 `code_executed` 传 shell 命令行 ⇒ 必判 failed

本轮只读探针跑完，图省事把 **terminal 命令行**（`.venv/Scripts/python.exe results/<sid>/scripts/smoke_x.py`）当 `code_executed` 递上去 → 判 `代码过短 (8 行)` + `使用 && 连接多步骤`，**failed**；`read_file` 读脚本全文重提 → **passed，脚本一行没重跑**。

⇒ 规则：`code_executed` **一律传脚本正文**（`read_file` 读出来原文传）。属**静态文本类 issue ⇒ 只改传参、绝不重跑脚本**。

### 2. `skill_evolution(action='record_run')` 用**未注册的自造 skill 名** ⇒ 静默 no-op

本轮为记录引擎修复，传 `skill_name="skill_evolution-engine-dir-resolution"`（自造名）→ 回执是 **`action: query_logs`** 形态：`无历史运行记录。skill '...' 尚未注册或目录不存在 — 运行后将自动创建记录`；**再传一次同样回执，什么都没创建**。换成已注册的 `wakeup-progress-check` → 立刻 `record_success: true`，`proven_scripts_updated` / `skill_json_updated` 都 true。

⇒ 规则：**`record_run` 的 `skill_name` 必须是仓库里真实存在的 skill**（拿不准就先 `skill_view`/`skills_list` 确认）；自造名不会"自动创建"，只会静默丢记录。⛔ 见到 `action: query_logs` 的回执**不要换措辞反复 record_run**（回执不变且赚循环告警）——查清 skill 名再记一次即可。

## 汇报模板（本轮定稿）

1. 一句判定：主线早已终态 + 本轮状态与上轮一致 + 仍是同一个「等你」的点。
2. 自检结果**表**（检查项 / 结果），只列本轮真跑过的那几项。
3. 「本轮顺手修掉的两个自身缺陷」——**有就写，没有就省**（这是把空转轮变成有价值轮的关键）。
4. 辩论跳过的一句理由。
5. 待办表（# / 事项 / AI 已代办 / 用户侧仅剩动作），并点明第 N 项是空转根因。
6. 收尾 `ask_user` 弹窗（multi_select + recommended + 「保持静默」出口）。

⇒ 两条结论：**(a) 修好契约 ≠ 停止唤醒**——契约干净时别再回头找「没勾的 checkbox」，直接查 LoopX registry；**(b) 系统文件（registry / task_state）未获批准一律不动**，所以这个状态**只能靠用户一句话结束**，AI 侧确实无事可做。

**收敛轮（弹窗后未答复期间）的正确形状**：

| 做 | 不做 |
|---|---|
| 一行状态确认：仍等你答复 + 本轮状态与上轮一致 | ❌ 重发同一张 4 项待办表（逐字重复 = 另一种刷屏） |

| 顺手把挂起的**解释型问题**答完（本轮答了「每次运行都在沉淀什么」「用户 skill 里有什么」「为什么这么多文件」三问，素材取自磁盘 `skills/user-scripts/INDEX.md` + `search_files(skill.json)` + 会话 assets） | ❌ 再发一次 `ask_user`（每议题只弹一次） |

| 汇报长度**逐轮递减**，直到只剩一行 + 静默 | ❌ 推进 Phase、改系统文件 |

**为什么「顺手答挂起问题」是好动作**：它把纯空转轮变成用户价值轮，且**不越 waiting_user 红线**（不推进 Phase、不动系统文件）——判据 = 该问题是「解释性问答」而非「分析推进 / 方向拍板」。

### 只读探针必触发 debate_reminder（结构性，不是议题）

只读状态探针（`ls`/`stat`/`psutil`/`print` 报告）**必然**收到辩论门控提示——因为脚本里有 f-string `print` 输出「结论行」，门控把「代码含结论输出」当成需辩论的信号。**这是误判**，如实跳 L0 并在回复里写明：只读、无候选参数、无 ≥2 活选项、**辩完改变不了下一步动作**（下一步动作在用户手上）。别为凑门禁硬辩。

### `rail_review(post)` 对只读探针的警告为非阻断（本轮实测）

本轮传探针正文全文 → `passed: true, issues: []`，两条 warning 是「代码注释过少 (1 行)」「No error handling」——对 84 行只读探针**不适用、不阻断**，如实说明即可，⛔ 不要为消 warning 给探针加 try/except 或堆注释。

## 收尾变体：用户追问「这些你沉淀了嘛？」（2026-10-01 唤醒 #18 实测）

「顺手答完挂起问题」**只做到一半**——把机制讲清楚 ≠ 把东西沉淀下去。用户连着追问两轮
（「我以后可能会用到，这些你沉淀了嘛」→「你沉淀了吗？」）说明他要的是**动作**。

核实三步（缺一步就可能答错）：

1. 读注入的**会话要求块 / 记忆**拿用户原话与「已确认」事实（权威来源）；
2. `search_files(pattern='<特征串>', path='<hermes_home>')` 扫沉淀位置判**是否已落盘**（本轮扫 0 ⇒ 确实没沉淀，当轮补写）；
3. `read_file` 索引文件（如 `hermes_home/skills/user-scripts/INDEX.md`）核**实际行数**，⛔ 不凭印象答「已经沉淀了」。

🔴 **⛔ 别用 `session_search(长中文短语)` 找用户原话**：中文长句被分词后返回
`{"results": [], "count": 0, "sessions_searched": 0}` —— **0 命中 ≠ 用户没说过**（与 `search_files` 中文假阴性同族）。

分流：环境 / 工具坑 / 数据格式类**事实** → `memory`；可复用**流程** → 对应 skill 或 `references/`。
