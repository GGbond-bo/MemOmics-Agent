# 动画优先展示页（Animation-First Showcase HTML）

> 与 `bioinformatics-html-report` 的分工：
> **分析报告**（图表+表格+参数溯源，可长）→ `bioinformatics-html-report`；
> **展示页**（给人看/演示，必须短而直观）→ 本 skill。
> 判断信号：用户说「展示」「演示」「给老师同学看」「做一版介绍」→ 走本 skill。

## 0. 用户偏好铁律（最高优先级，2026-09-16 明确纠正）

**用户原话**：「字太多了，不直观，很多时候可以用流程动画展示，你可以做到吗？很多东西不需要讲那么细」

同一交付物的实测对照：

| 版本 | 正文字数 | 文件 | 用户反应 |
|------|---------|------|---------|
| v1 文字版 | 20,588 字 | 117 KB | ❌「字太多了，不直观」 |
| v2 动画版 | **1,888 字** | 40 KB | ✅ 通过 |

**硬性预算（交付前必须核对）**：
- 正文（剥离 `<style>`/`<script>` 后的可见文本）**≤ 2,000 字**
- 每页：1 个标题 + 1 个核心视觉 + 3–6 个短标签
- 能用图/动画表达的 → **禁止**写成段落
- 细节收进「点击展开」，默认不占版面
- 已出过文字版后，**不要再交第二版文字**，直接给动画版

数正文的验证脚本见 `references/animation-recipes.md` 第 0 节。

**投影可读性硬指标（2026-09-16 用户补充）**：

> 用户原话：「把最小的字体都变大一点，**这样别人才能看清楚在干嘛**」

- **全站最小字号 ≥ 14px** —— 含角标、序号、单位、副标签、图注。这些最容易停在 9.5–11px 被漏掉
- 字级梯度：标签/正文 15–16px · 小标题 19–24px · H1 `clamp()` 下限 ≥30px
- 判定标准不是「我屏幕上看得清」，而是「**后排投影 / 录屏回放**看得清」
- 抬字号**一次抬全部档位**（只抬最小档会让层级看着乱），并配多分辨率溢出复验（坑 8）
- 交付前用脚本量一次真实最小字号，**不许凭肉眼判断**

## 1. 结构：全屏分页，不是长文滚动

```
固定 chrome：顶部进度条 #bar / 右侧圆点导航 #dots / 右下页码 #pager / 左下键盘提示
每页：<section class="slide">  min-height:100vh; flex 居中; max-width:1240px
导航：键盘 ← → 空格 / 圆点点击 / 滚轮 / scrollIntoView({behavior:'smooth'})
入场：IntersectionObserver 给 .reveal 加 .in，逐元素 70ms 错峰
```

10–11 页骨架（按需删减，但**保持「一页一个视觉重心」**）：

| 页 | 内容 | 动画/交互 |
|----|------|----------|
| 1 | 封面 | 粒子网络底纹 + 中心核 + **三层**轨道公转标签 + 流动带 + 数字条 |
| 2 | 关键数字 | 数字滚动 countUp（easeOutCubic） |
| 3 | 主流程 | N 节点流水线，火花依次点亮 + 进度轨 |
| 4 | 质量闸门 | 循环：不通过 → 打回 → 修复 → 全绿放行 |
| 5 | 多角色机制 | 点按钮：各角色依次亮起 → 证据束汇入 → 出裁决 |
| 6 | 自学习闭环 | 4 站点循环高亮 |
| 7 | 行业时间线 | 进度条推进 + 节点逐个入场 |
| 8 | **未来·循环流** | 6 节点环 + 旋转臂 + 顺序点亮 + 三股流（§2.5） |
| 9 | **未来·阶梯流** | 能力阶梯逐级爬升 + 汇流带（§2.5） |
| 10 | 路线图 | 三阶段进度条动画 |
| 11 | 收尾 | 一句话大字 |

**同页不放两个动效**——会互相抢注意力。

### 2.5 讲「未来 / 演进 / 趋势」必须用流动过程图（2026-09-16 用户点名）

> 用户原话：「去掉展示 memomics 跟别的对比，**重点在展示未来自主科研，和未来 AI 发展上，这些用更多流动的过程图展示细节**」

三条由此固化的偏好：

1. **对比页 → 删**。用户不要「我和别人比」的卡片；要的是**往前看**。删掉对比章节，把版面让给未来。
2. **未来章节不是文字也不是静态卡片，而是「有东西在流动」的图**。判断标准：这一页有没有东西在**持续运动**？
   静止的卡片列表 = 不合格。
3. **细节靠图承载，不靠文字**。一页 = 1 标题 + 1 流动图 + 2–4 个超短标签 + 至多 1 句结论。

六种流动过程图（全部零依赖，配方见 `references/animation-recipes.md` §12）：

| 图型 | 表达什么 | 流动来源 | 出现时机 |
|------|---------|---------|---------|
| **流动带** conveyor | 线性链路在推进 | 底纹位移 + 货物滑跑 | 封面底部 / 「数据→报告」 |
| **循环流** orbit cycle | 自己转起来的闭环 | 旋转臂 + 节点顺序点亮 | 「科研循环」「自驱动」 |
| **阶梯流** ladder | 一级比一级高 | 逐级抬升 + 顶点虚线上流 | 「能力演进」「阶段跃迁」 |
| **汇流带** converge | 两股态势汇成判断 | 双向/逆向流动的点阵 | 「A vs B → 结论」 |
| **链式流** chain | 多环节串成一条链，且**闭合** | 节点顺序点亮 + 进度轨扫过 + 回流弧 | 「从读到写」「端到端全链」 |
| **粒子网络** canvas | 未来感底纹 | rAF 粒子 + 鼠标连线 | 封面背景 |

**同步铁律**：任何「旋转/流动 + 顺序点亮」的组合，`setInterval` 周期必须 = CSS 动画周期 ÷ 节点数，
否则光点与点亮错位，一眼就假（循环流：10.8s ÷ 6 = 1800ms）。

### 2.6 内容骨架：先讲「是什么」，再讲「能做什么」（2026-09-16 用户补充）

> 用户原话：「在第一页补充，**什么是 agent？有什么组成。什么是科研 agent？**第一页丰富一点。
> 第二页，展示更多 MemOmics 的真实功能，**按照模块展示名字即可，选一些重要的**」

给老师 / 同学 / 评委演示**一个系统或 Agent** 时，观众的第一疑问不是「它有多强」，
而是**「这东西到底是什么、由什么组成」**。只列能力清单 → 观众没有认知抓手，看完记不住。

固化三段骨架（缺一不可）：

| 段 | 回答的问题 | 呈现方式 | 本次落地 |
|----|-----------|---------|---------|
| ① 定义 | 什么是 Agent | 组成式等式条，元素顺序点亮 | `脑·模型 + 手·工具 + 忆·记忆 + 环·循环 = Agent` |
| ② 定位 | 什么是**科研** Agent | 在①上加限定项的第二条等式 | `科研 Agent = Agent + 领域知识库 + 生信工具链 + 可验证的结论` |
| ③ 盘点 | 实际能做什么 | **按模块列名字**，不上描述句 | 12 个分析模块 + 8 项平台能力，纯名称 chip |

要点：

- **定义用等式，不用段落**。等号两侧全是短名词，观众 3 秒读完，且天然是「组成」结构。
- **「选一些重要的」= 要模块名，不要每项配一句解释**。名称 chip 就够，解释收进点击展开。
- ① 放**封面页**（与主视觉同页，用一条横条承载，不新开页）；② 紧跟其后；③ 放资产页。
- 自检：观众看完能不能一句话说出**「它是什么」**？说不出 = 缺 ①。
- 具体文案模板与模块清单写法 → `references/research-agent-deck-content.md`

### 2.7 「什么是 X」必须从页脚升为页首主体（2026-09-16 用户追加）

> 用户原话：「**就改一下第一页，把什么是 agent 放的更重要一点**」

定义等式**不能放在封面底部当补充说明**——那是视觉权重最低的位置（字号最小、被压在最下、
观众要低头找）。它回答的是观众的第一疑问，必须占据**页面主体**。

四级升级动作（缺一项都抓不住注意力）：

| 动作 | 做法 |
|------|------|
| ① 位置 | 从页面**最底部**移到 kicker 之后 → 视线落点「标题 → 一句话能力 → **定义** → 示能图 → 数据」 |
| ② 面积 | 加**面板容器**：浅渐变底 + 1px 浅边 + 圆角 26px + 阴影 + 半透明，让它成为页面最大色块 |
| ③ 字号 | 名词 `clamp(17px,1.8vw,22px)` · 结果块 `clamp(19px,2vw,25px)` · 面板标题 `clamp(21px,2.4vw,31px)` · 图标方块 37px |
| ④ 让位 | 同页示能图（轨道/大圆）**主动缩小**——本次 `min(50vh,540px,72vw)` → `min(30vh,300px,48vw)`，把纵向空间让出来 |

**时序**：四要素逐个点亮（各错开 0.9s），**结果块高亮必须落在最后一个要素点亮之后**
（`@keyframes` 高亮位移到 62%–72%），否则「汇聚 → 得出 Agent」的因果一眼就假。

**新增面板必须进封面的 z-index 白名单**（坑 4）——面板有背景色，被 canvas 压住会整块发灰。

## 2. 零外部依赖（断网也要能开）

现场演示常在别人电脑/无网环境打开 → **不引 CDN**。
全部用 CSS `@keyframes` + 原生 JS；图片一律 base64 内联。

| 效果 | 实现 |
|------|------|
| 轨道公转 | 父 `.orb{animation:spin}` + 子标签反向自转（见坑 2） |
| 数字滚动 | `requestAnimationFrame` + `1-Math.pow(1-p,3)` |
| 流水线火花 | 绝对定位圆点，`left` 百分比 + `transition:left .45s` |
| 顺序点亮 | `setTimeout` 链，每节点 ~620ms 步进 |
| 循环自播 | 动画末尾 `setTimeout(fn, 3200)` |
| 入场 | IntersectionObserver（`threshold:.22`）+ `.reveal.in` |
| 打回抖动 | `@keyframes shk` 左右 ±6px |

视觉元素用 **CSS 图形**（`radial-gradient` 点阵、`clip-path` 漏斗、CSS 三角形、内联 SVG）——
**不要 emoji 堆砌**，不够专业。

可直接复制的 CSS/JS 配方 → `references/animation-recipes.md`

## 3. ⛔ 六个必踩的坑

### 坑 1：滚轮翻页会让「高于屏幕的页」卡死

无条件接管滚轮时，页面若比视口高（封面图大、卡片竖排），
用户想滚动看下半部分，滚轮被吃掉直接翻页 → **下半部分永远看不到**。

```js
/* ✅ 仅当当前页完全放得下才接管滚轮 */
var cs = slides[cur];
if (cs && cs.scrollHeight > window.innerHeight + 40) return;  // 交给原生滚动
```

配套矮屏媒体查询压缩纵向占用，让核心页尽量一屏放下：
```css
@media(max-height:760px){
  .slide{padding:54px 6vw 54px;gap:18px}
  h1{font-size:clamp(30px,4.6vw,54px)}
}
```

### 坑 2：旋转关键帧吞掉 `translateX(-50%)` 定位

标签用 `left:50%` + `transform:translateX(-50%)` 居中，若同时加旋转动画，
**动画的 `transform` 覆盖静态 `transform`** → 标签既不居中又跟着歪。

```css
/* ❌ 定位丢失：标签偏移 + 倾斜 */
.orb span{ transform:translateX(-50%); animation:spin 26s linear infinite reverse; }

/* ✅ 把 translateX 写进关键帧，两者共存 */
.orb span{ animation:upright 26s linear infinite; }
@keyframes upright{ from{transform:translateX(-50%) rotate(0)}
                    to  {transform:translateX(-50%) rotate(-360deg)} }
@keyframes uprightR{ from{transform:translateX(-50%) rotate(0)}
                     to  {transform:translateX(-50%) rotate(360deg)} }
```

**通用规则**：元素同时需要「静态定位 transform」和「动画 transform」→ 必须合并进 `@keyframes`。

### 坑 3：分片拼接导致 `</style>` 提前闭合

单文件 HTML 分片生成易出现提前闭合的 `</style>`，后续 CSS **整段静默失效**
（页面「看起来还行」但样式全丢）。防御：**首建**时优先 `write_file` 一次性写完整文件
（或严格只让最后一段带 `</style>`）；写完检查 `<style>`/`</style>` 各出现 1 次。

> 与 §4.1 的分界：**新建**用一次性 `write_file`；**改版**用增量 `patch`（大文件重写会被输出长度截断）。

### 坑 4：`#sN > *` 通用选择器压掉子元素的绝对定位

`#s1>*{position:relative;z-index:1}` 一网打尽加层级 → `.scrollcue{position:absolute}` 被压成 relative，
**回到底部提示掉进文档流**。

```css
/* ✅ 枚举需要的元素，绝对定位的用更高特异性回写 */
#s1 .badge,#s1 h1,#s1 .gwrap,#s1 .flowstrip,#s1 .hero-stats,#s1 .scrollcue{position:relative;z-index:1}
#s1 .scrollcue{position:absolute}       /* (1,1,0) > (1,0,1) */
```

落笔前先问：「这层里有谁要脱离文档流？」

### 坑 5：封面尺寸必须 `min(vh, px, vw)` 三元封顶

只写 `width:min(580px,74vw)` → 1366×768 笔记本（视口高 ≈640）上封面总高 > 视口，
**底部数字条被推出屏幕**。`.gwrap{width:min(50vh,540px,72vw)}`，并配矮屏档
（`min(38vh,340px,54vw)` —— 只降 ~30%，**不要腰斩**，用户要的是「面积大一点」）。
预算：`固定元素 ≈440px + 封面直径 ≤ 视口高`。

### 坑 6：删章节要四处联动

删掉某一页后必须同步改：① 后续页 `id`（否则 id 重复 → `getElementById` 只取第一个，动画错位）
② JS 触发块里的 `s.id==='sN'`（否则该页动画静默失效）③ CSS 里的 `#sN{}` 选择器
④ `#pager` 的默认值。验收用 `dup` 判重 + 逐项取样确认动效仍在跑（脚本见 references §13）。
⑤ **配套交付物必须同步删**：静态图（`figures/*.png`）、报告、PPT 里常有同一章节的副本。
本次实测：用户前一轮已要求「去掉与其他 agent 的对比」，HTML 章节删掉了，
但**配套雷达图里仍留着竞品曲线**，直到这一轮才被发现。
→ 用户说「去掉 X」时，**立刻扫全部交付物**（`grep -rl X reports/ figures/ scripts/`），
不要只改手上正在编辑的那一个文件。

### 坑 7：改区块别用非贪婪正则（会只吃掉第一张卡）

`<div class="grid4">.*?</div>\s*</div>` 配 `re.S` 时，`</div>\s*</div>` 会**先命中第一张卡自身的闭合**，
于是只替换掉 1 张卡，**旧的其余卡片原样残留**在文件里（页面上表现为新旧数字同时出现，肉眼容易漏）。
本次实测：第 2 页 4 张数字卡换成 6 张新卡后，旧的 168 / 495 / 189 三张仍留在下面。

正确做法：**index 边界法**，不要靠正则匹配嵌套标签

```python
i0 = s.index(START_MARK)                 # 区块起点（文件中唯一的字符串）
i1 = s.index(END_MARK) + len(END_MARK)   # 区块终点（同样唯一）
assert '旧值特征' in s[i0:i1]             # 断言范围正确，越界立刻报错
assert s[i0:i1].count('grid4') == 1       # 确认没吃多
s = s[:i0] + new_block + s[i1:]
```

改完**必须回头 grep 旧值**确认清零（本次就是靠 `grep -n '168\|495\|189'` 才抓到残留）。
grep 到旧数字时先确认不是 JS 里的延时/尺寸——本次 `t+=350` 就是 350ms 延时，不是内容。

### 坑 8：全局抬字号必须配多分辨率溢出复验

用户嫌字小 → 映射表全局替换 `font-size:Npx`，**一次性把所有档位一起抬**（本次 57 处，最小 9.5px → 14px）：

```python
m = {9.5:14, 10:14, 10.5:14.5, 11:14.5, 11.5:15, 12:15.5, 12.5:16,
     13:16.5, 14.5:18, 15:19, 16:20, 19:24, 26:30}
```

**别只抬最小那几档**——中档不动会让字级层级看着混乱，用户要的是"整页都看得清"。
抬完必须**在 ≥3 档分辨率复验溢出**：投影 1920×1080 / 笔记本 1366×768 / 矮屏 1280×600，
逐页量「最底部子元素 bottom − 页高」，>2px 即溢出。矮屏档靠 `@media(max-height:760px)` 压缩，
**必须实测、不许靠推理认定"应该能放下"**。同时复核最小字号（本次目标 ≥14px）。

### 坑 9：同一个数字只能有一个口径来源

页面数字、配套静态图、报告里的同一指标必须**读同一个采集脚本的同一个 key**。
本次踩雷两次：① 首页写 350、第 2 页写 352（同一指标两个值）；
② 静态图的「知识库条目」算成 `kb_yaml + paper_summaries = 174`，页面却是 `169+1 = 170`。
修法：在 `collect_stats.py` 里定义**唯一口径**（如 `kb_entries = **/*.yaml + **/*.md`），
页面与图都读该 key；改完 grep 全量核对。递归/非递归 glob 也会造成差异
（`results/*/log/run_record` = 504 vs `results/**/run_record` = 536），必须统一。

### 坑 10：溢出检测比对「slide 自身高度」= 永远报零溢出（2026-09-16 实测）

`.slide` 是 `min-height:100vh`（无固定 height）→ **内容超长时元素自己被撑高**，
于是 `子元素bottom − slide.height` 恒 ≈ 0，脚本一路报「无溢出」，
而实际上内容早已被推出**视口**（`#s1` 还有 `overflow:hidden`，超出的直接看不见）。

```js
/* ❌ 盲点：slide 会跟着内容长高 */  b - r.height
/* ✅ 正确：跟视口比 */              b - window.innerHeight
```

本次实测代价：768 视口下封面底部的 `hero-stats`（4 个数字条）整块被推出屏幕，
而旧脚本报「零溢出」。**修完必须加一条关键元素可见性断言**：


### 坑 11：`#s1` 的 padding 优先级高于 `.slide`，矮屏媒体查询压不动它

## 坑 16：残留检查只扫汉字 → 漏掉 CJK 标点（英文版混入中文句号）

做**多语言版本**时，替换完若只校验「还有没有汉字」（`[\u4e00-\u9fff]`），
**CJK 标点与全角字符会被整类放过**——它们不在汉字码位内：

| 字符 | 码位 | 常见来源 |
|------|------|---------|
| `。，、；：？！` | U+3001/U+3002/U+FF0C… | 句尾/句中，替换 key 若不含标点就会残留 |
| `「」『』《》` | U+300C/U+300E/U+300A | 引号包裹 |
| `（）` | U+FF08/U+FF09 | 全角括号 |
| 全角字母数字 `Ａ１` | U+FF21…/U+FF10… | 全角输入残留 |

**本次实测**：翻译表 268 条全部命中、汉字残留 0、结构校验全过 —— 但页面渲染出
`directing an Agent。`（中文句号）。根因是替换 key 写成 `会拆解问题…Agent`（不含 `。`），
句号在 key 之外原样保留。**只有截图 OCR 才抓到**。

修法：校验器必须**两类都查**，且报告出现位置便于定位：

```python
zh   = re.compile(r"[\u4e00-\u9fff]")                                    # 汉字
punc = re.compile(r"[\u3000-\u303f\uff01-\uff60\u300a\u300b\u3008\u3009]")  # CJK标点+全角
for name, pat in (("汉字", zh), ("CJK标点", punc)):
    hits = list(pat.finditer(s))
    print(f"{name}: {len(hits)}" + ("  ✓" if not hits else "  ✗"))
    for m in hits[:10]:                    # 打印前后文，一眼定位
        a, b = max(0, m.start()-60), min(len(s), m.end()+40)
        print(f"   ! U+{ord(m.group(0)):04X} | ...{s[a:b]}...")
```

**更稳的替换 key 写法**：把**句末标点一起纳入 key**（`'…Agent</b>。' → '…Agent</b>.'`），
而不是事后单独扫标点。两者都做：key 带标点（治本）+ 校验器查标点（兜底）。

## 坑 17：拉丁文字比汉字宽 → 溢出与「字号回退」双杀

中→英（或其他拉丁语系）时，**同样字号的英文占宽约为中文的 1.6–1.9 倍**，带来两个连锁问题：

| 症状 | 根因 | 修法 |
|------|------|------|
| 页高溢出（本次 600px 档最高 +83px） | 文字换行数变多，纵向累积 | 分区高度分级压缩（见下） |
| 最小字号偷偷掉回 13px | 为塞下内容顺手写了 `font-size:13px` | 字号底线 ≥14px **不可为排版让路**，改用压缩间距 |

**主次不能颠倒**：先保字号（用户硬要求），再用间距换空间。

三段修法（本次实测把「3 页溢出 + 最小 13px」修到「三档全绿 + 最小 14px」）：

1. **加宽行宽，让英文少换行**（最省力的 5px 起效）
   `.lead{max-width:70ch}` → `104ch`：3 行变 2 行，直接省一行高度。
2. **压缩间距而非字号**：页面 `padding/gap` → 固定尺寸（`.cycle`/`.stream .lane`）→ 卡片 `padding` → 隐藏次要信息（DOI/统计行）。
3. **高度分级媒体查询**，且**必须重算驱动元素**（英文版的高度驱动元素与中文版可能不同）：
   ```css
   @media (max-height:1100px){ /* 1080 也需一档：英文在 1080 就会溢出 */ }
   @media (max-height:900px) { }
   @media (max-height:700px) { }
   ```
   ⚠️ 中文版只需 900/700 两档，**英文版必须多一档 1100**（1080 投影下就溢出了）。

**诊断先行**：先用脚本量出「哪一页、哪个子元素、超多少」，再动手（坑 12/13）。
本次 600px 档的真凶是 `#s8 .streams`（3 张流卡 × 98px），不是圆环 —— 压圆环无效。

## 2.12 多语言版本：文本替换式 i18n（不重写页面）

> 用户原话：「能不能按照这个做一个**英文版**的？我有些同学是的外国人」

**不要复制一份 HTML 再逐处手改**（40KB+ 手改必漏、且动画/交互可能被改坏）。
标准做法 —— **翻译表 + 最长优先字符串替换**，结构零改动：

```python
T = { '中文原文': 'English', ... }        # key 用「完整唯一串」，含实体与标点
for k in sorted(T, key=len, reverse=True):  # ⚠️ 必须最长优先，否则短 key 吃掉长 key
    s = s.replace(k, T[k])
```

要点：

| 项 | 做法 |
|----|------|
| key 粒度 | 带上下文（`'<span class="av">生</span>'` 而非裸 `'生'`）——避免短字误伤别处 |
| 同名不同义 | 用上下文 key 区分（轨道小写 `>注释<` vs 卡片标题 `<div class="t">注释</div>` → `Annotate`） |
| 单字图标 | 中文字符图标（文/译/库/数）→ 2–3 字母拉丁码（`LIT/TRN/KB/DAT`）+ 英文专用 CSS 降字号 |
| 注释与 `<title>` | 一并翻译（含 `<!-- -->`、`/* */`、`lang="zh-CN"` → `lang="en"`），否则残留检查一直报警 |
| 交付 | **独立文件**（`X_EN.html`）而不是页内切换——两版各自可独立投屏，也让中文版零风险 |
| 验证脚本 | 参数化（`verify_showcase.py en`），**中英共用同一套验收标准**，并跑一遍中文版确认未回归 |

**替换式 i18n 的验收清单**：① 翻译表命中数 = 条目数 ② 汉字残留 0 ③ **CJK 标点残留 0**（坑 16）
④ `section`/`script`/`svg` 计数与源文件一致 ⑤ 三档分辨率溢出为 0 ⑥ 最小字号达标 ⑦ 零 JS 报错
⑧ 交互实测（马车在跑 / 模块点击有响应 / 页码与圆点一致）⑨ 中文版回归测试。

### 2.13 翻译必须核对「情态/时态」——限定语最容易在这里变形（2026-09-17 辩论实测）

翻译页面上带**行业判断/趋势论断**的句子时，逐词对应正确 ≠ 证据强度相同。
最隐蔽的失真是**时态/情态的迁移**：中文没有时态，趋势句与既成事实句形态相同；
译成英文时若用**简单现在时**，读者会读成「已经在发生的事实」。

本次实测（辩论裁判点出的问题）：

| 中文 | ❌ 初译（简单现在时，像既成事实） | ✅ 改（进行时，保留趋势） |
|------|--------------------------------|------------------------|
| 重心**转向** X | the centre of gravity **shifts** to X | the centre of gravity **is shifting** to X |
| 人从操作者**变成**提问者 | People **move** from operator to questioner | People **are moving** from operator to questioner |

**对照规则**：

| 中文形态 | 英文应选 | 例 |
|---------|---------|-----|
| 将/会（未来） | `will` | 将被大幅替代 → will be largely replaced |
| 正在转向 / 趋势 | **进行时** `is shifting / are moving` | 重心转向 → is shifting to |
| 已经是事实 | 简单现在时 | 平台跑过 536 次 → 352 skills |
| 建议 / 应然 | `should / need to` | 需要强化生物学认知 → needs to strengthen |

**流程**：定稿前把带论断的句子送 `debate_analysis` 复核证据强度（§2.11），
并在中英对照表里**逐句标注时态选择依据**。判据：英文读者读到的是「趋势」还是「既成事实」？
两者不同即不合格。

## 坑 15：矮屏压缩必须限定页面作用域，否则会改动用户说「不要动」的页

用户常要求「第 3–7 页不变」。若为消第 8/9 页溢出而写全局 `.slide{padding:30px;gap:12px}`，
等于**把所有页的节奏都改了**（违反用户明确指令）。
→ 压缩规则一律带页面 id：

```css
@media (max-height:900px){ #s7,#s8{padding-top:30px;padding-bottom:30px;gap:13px} #s8 .cycle{width:min(42vh,520px,78vw)} … }
@media (max-height:700px){ #s7,#s8{gap:4px} #s8 .stream{padding:7px 12px} … }
```

同名媒体查询可**追加**覆盖（后写的生效）——迭代微调不必重写旧块。
本次 600px 档从 +150px → +88 → +4 → 0，就是靠**追加同名块逐步收敛**（补丁 v6→v7→两处常量微调）。
压缩收益排序（从大到小）：**页面 padding/gap → 固定 vh 尺寸（`.cycle`/`.gwrap`）→ 卡片 padding → 行高/边距 → 隐藏次要信息（DOI、统计行）**。
⚠️ 缩小 `.cycle` 这类 `aspect-ratio:1` 的元素时注意：**两栏布局总高由较高那栏决定**（坑 13），压错栏白改。

### 4.1 改版 = 增量 patch，**绝不重写整文件**（2026-09-16 实测教训）

40KB+ 的单文件 HTML **不要试图一次性重写**——会撞上输出长度上限被**截断**，交半截文件比不改更糟。
本次实测：试图重写整页 → 直接被截断（`[System: previous response was truncated by output length limit]`）；
改成分区域 `patch` 后 **11 处改动一次全部成功**。

改版顺序（每步都是一个 `patch`，改完立刻用浏览器验一次再往下）：

| 顺序 | 改哪里 | 注意 |
|------|--------|------|
| 1 | CSS：**新增**样式 → 插在 `@media` 块之前 | 插在媒体查询之后会被响应式规则压掉 |
| 2 | CSS：**改**既有尺寸/间距 | 先算总高预算再定值（坑 5），改完回头核对矮屏档 |
| 3 | HTML：逐页改 / 在被删页的位置插新页 | id 重新编号 + 触发块同步（坑 6） |
| 4 | JS：触发块 + 新增动画函数 | `if(s.id==='sN')` 一处不对该页动效就静默失效 |
| 5 | chrome：`#hint` / `#pager` 默认值 | **最常漏的一处** |

**锚点要唯一**：`old_string` 用「整行 + 上下文」；同页有多个结构相同的块时（如 6 个 `cyc-node`、
6 个 `rung`），**用所在段落独有的文本或注释行做锚**，不要拿结构相似的片段硬打。
每次 patch 后**读 diff**，确认「有 `-` 必有对应 `+`」、没有把标签吃掉。
