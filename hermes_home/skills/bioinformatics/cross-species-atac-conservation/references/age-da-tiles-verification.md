# M2 age-DA tiles 全表核对 + 猴侧 FDR 全灭是常态（非 bug）

> 2026-09-11 实测。用户自跑 age-DA 全表核对，凡做猴/人 age-DA tiles、写 M3 聚合脚本前必读。

## 核心结论
- **猴侧（20 例）age-DA tiles：全局 BH FDR 校正后 q<0.1 = 0 行**，up/down 文件为空。
  这是**数学必然，不是代码 bug**：~530 万 tiles × 全局 FDR + 猴侧 Pearson 自由度仅 n−2=18，
  p 值门槛被压缩到极惨烈，无一存活。
- **方案正确定位**：专利方案中猴侧角色是**方向门控 w(Z₂)**，门槛 = **名义 p<0.05（未校正）**，
  不是 q<0.1。
  ```
  w(Z₁,Z₂) = +1  当 sign(Z₂)=sign(Z₁) 且 p<0.05
  w(Z₁,Z₂) = −1  当 反向且 p<0.05
  w(Z₁,Z₂) = 0   当 p≥0.05（方向不可靠）
  ```
- M2 真正需要的产物是 **all.csv 全表**（供 M3 聚合到基因后在基因窗口内用 p<0.05 判方向）。
  **up/down 对猴侧不是必需产物——空就让它空**。

## 核对配方（用户自跑产物 · 先核实输入再写 M3，禁止拍脑袋）
1. 行数对账：猴 ≈5,296,656 / 人 ≈5,555,247
2. 列 = chr/start/end/r/p/q（ArchR 坐标在 rowData(se)，不填 rowRanges；CSV 前 3 列 chr/start/end）
3. tile 宽度 500bp 校验：相邻 start 差值 = 500，且 end = start+499
4. up/down 计数对账：人 22/28、猴 0/0 —— 不符先查筛选口径（q 是否未校正、r 符号方向），不要直接怀疑文件
5. 猴侧方向门控可行性：p<0.05 未校正仍有 31 万 tiles → 方向信息存在，M3 可行

## 教训
- 用户自跑验证时"up/down 空"会以为代码错——先按上述配方用数字对账，再下"是 bug"或"是正常"的结论。
- 人侧 expected：40 例 + 全局 FDR → q<0.1=50（up22/down28）；若用户跑出人侧也是 0/0，那才需要查代码。
- ⚠️ **rail_review(post) output_dir 作用域陷阱**：把 output_dir 指向整个项目根目录（如 E:/专利）
  会把**历史遗留文件**（如 P3_L2_data/l2_enrichment_16genes.png 空白图）误判为"本次产出问题"，
  触发 false-positive 审查失败。output_dir 应指向**本次分析的专属输出目录**；对 flagged 文件先判断
  是否为本次产物，历史遗留单独询问用户是否处理，不要盲目重新生成。
