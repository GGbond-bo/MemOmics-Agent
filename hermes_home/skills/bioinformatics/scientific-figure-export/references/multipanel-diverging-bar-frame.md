## 1. 刻度策略：两阶段演化 + 现判据

先算 `max(各面板极值) / min(各面板极值)`：

| 量级比 | 默认选择 |
|---|---|
| ≤ ~10× | 共享刻度（含 symlog），跨组直读 |
| > ~10×（本例 Aging 5,218 vs Ex_Young 15 ≈ **350×**） | **每面板独立绝对刻度（freescale）** |

### ⚠️ 这条规则的真实演化史（两轮，方向相反，别只记住一半）

| 轮次 | 用户诉求 | 用户选定的版本 |
|---|---|---|
| 第 1 轮 | 「多出几个版本我自己挑」 | 选了**独立绝对刻度**（`..._combined_freescale`），否掉共享 symlog 版——共享刻度下小面板的柱全塌成 0 |
| 第 2 轮（v3） | 「Aging 这里，x 轴改成统一标准…**这样 Aging 衰老的才能展示出来**」 | 改为**五面板统一 symlog 轴 + 十倍阶梯刻度** |

**⇒ 正确判据不是"哪个刻度更对"，而是"这一轮的叙事目标是什么"：**

- 目标 = **每组的内部细节 / 组间可比性** → 独立绝对刻度，柱长 = 数值一比一，
  图注写 `Independent absolute scale per panel`（否则读者会跨面板比柱长）
- 目标 = **"哪一组是主导效应"**（本例要让 16,535 的衰老效应压过运动组的两位数）
  → **统一 symlog 轴**，图注写 `Unified symmetric-log scale across panels · decade ticks`

🔴 **统一 symlog + 逐柱数值标签是合法组合**（v3 定案）：
symlog 压掉了柱长与数值的比例关系（比例墨迹问题），但**逐柱数值标签把精确值补回来了** →
长度比承担"衰老 ≫ 运动"的结论，数字保证读者仍能读到真值。
**判据：有没有逐柱数值标签。** 有标签 → 放心用统一轴；无标签 → 统一轴会牺牲小组可读性，回头用独立刻度。

## 1b. 统一 symlog 配方（v3 实测）

```python
ax.set_xscale("symlog", linthresh=LINTHRESH, linscale=1.0, base=10)
ax.set_xlim(-XMAX, XMAX)                      # XMAX = TMAX * 1.30
```

### 🔴 linthresh 不能凭直觉给 10 —— 线性段会吃掉大半个轴宽

```
内部 _linscale_adj = linscale / (1 - base^-1) = 1 / (1 - 0.1) = 1.1111
线性段占比 = adj·lt / (adj·lt + log10(t/lt))

lt=10, t=16535 → 11.111 / (11.111 + 3.218) = 0.775   ← 半轴宽的 77% 浪费在 [0,10]
                                                        10/100/1,000/10,000 全挤在最外侧 13%
lt=1,  t=16535 →  1.111 / ( 1.111 + 4.218) = 0.208   ← 每个数量级均分 ≈19% 半轴宽 ✅
```

实测压缩力（`linthresh=1`, `XMAX = TMAX·1.30`，TMAX = **单行**最大值 5,218）：

| 值 | 占半轴宽 |
|---|---|
| 15 | 34% |
| 61 | 42% |
| 380 | 68% |
| 5,218 | 98%（贴边 → 该柱标签必须内嵌） |

### 刻度阶梯：纯十倍，别用 1-2-5 混合

```python
LADDER = [0.0] + [10.0 ** k for k in range(1, 7) if 10.0 ** k <= TMAX]
TICKS  = sorted(set(LADDER + [-v for v in LADDER if v > 0]))
TLAB   = [f"{abs(v):,.0f}" for v in TICKS]     # 背离图两侧都标绝对值，中心 0
```

- 混合阶梯（1-2-5）会产生 50↔100、500↔1,000 这种 **0.3 个数量级**的相邻刻度 → 标签拥挤，
  且 `vision_describe` 的 OCR 会把两个读成一串（实测读到 `10010`、`5,0001,000` —— 反推旧版用的混合阶梯）。
  纯十倍阶梯间隔恒为 1 个数量级，干净且"有梯度"。
- 🔴 **`TMAX` 取单行最大值，不是面板合计**：曾把 Aging 面板合计 16,535 当 TMAX → 算错刻度上限。
  区分方法：脚本里同时打印 `面板总计 Up` 和 `单行 max`。

## 2. 几何配方（figure 坐标，实测可用）

```python
FW, FH = 7.087, 3.45          # 180 × 88 mm ≈ Nature 双栏满宽单图
LM, RM, BM, TM = 0.126, 0.014, 0.135, 0.300   # v3：LM 从 0.176 左移到 0.126（左侧重排省下的空间给柱区）
GAP = 0.0130
PW = (1.0 - LM - RM - GAP * (N - 1)) / N       # 面板宽
PH = 1.0 - BM - TM                             # 面板高（顶区 = 1-TM → 1.0）
fig = plt.figure(figsize=(FW, FH))
for i, ... in enumerate(PANELS):
    ax = fig.add_axes([LM + i * (PW + GAP), BM, PW, PH])
```

**关键手法：非绘图"家具"一律画在 figure 坐标里，不进 axes。**

```python
fig.text(x, y, s, ha=..., va=..., rotation=...)                       # 文本
fig.add_artist(Line2D([x0, x1], [y, y], color=..., lw=..., solid_capstyle="butt"))
```

`Line2D` 用 `fig.add_artist` 时按 figure 坐标，**不裁切、不需要 `bbox_inches` 补偿**，
比 `ax.plot(..., clip_on=False, transform=ax.transAxes)` 稳得多，也不会把画布撑大。

## 3. 顶部（标题带）——把"5 个裸组名"变成有层级的读图入口

自下而上（figure y 为实测值，对应 88 mm 高，v3 沿用未改）：

| y | 元素 | 说明 |
|---|---|---|
| 0.750 | 贯穿全宽细线 `#C8C8C8` lw 0.7 | 分隔标题带与柱区 |
| 0.789 | `ΣUp ↑ / ΣDown ↓` 彩色计数（红/蓝各自上色，6.6pt bold） | 组级总量，一眼见量级 |
| 0.830 | 每组标题下 **1.5pt 家族色条**（宽度 = PW） | 把面板归属沉到视觉层 |
| 0.862 | 左端**面板字母 a–e**（8.4pt bold，`ha="left"`）+ 居中组名（8.2pt bold） | 字母满足期刊规范 |
| 0.930 | **家族超标题细线**（1.4pt，横跨该家族全部面板）+ 其上 0.014 处家族名（7.2pt bold） | 见下 |

**家族超标题**：把面板按语义分族（本例 `Condition contrast` / `Exercise response (Pre → Post)`），
每族一条横跨其面板范围同色细线 + 居中标题。家族色选**沉静、不与红蓝柱冲突**的一对
（本例墨紫 `#3D3B4F` / 深青 `#0F5F6E`）。

**共享图例只画一次**（右上 `y≈0.945`，色块 0.011×0.022 + 6.4pt 文本）。
**⛔ 不要每面板重复图例**——那是多面板图最常见的噪声来源。

## 4. 左侧（标签区）——单调"模块竖带"，**不要再放家族括号**

### 🔴 必须先做压叠的定量诊断（别凭感觉猜"为什么重合"）

把文字块宽度换算成 fig fraction，再与相邻标签的 x 位置比：

```
宽度(fig fraction) ≈ 字符数 × 0.5em × 字号pt ÷ 72 ÷ 图宽in
例：13 字符 × 0.5 × 6.6pt ÷ 72 ÷ 7.087in ≈ 0.085
```

**反面案例（v2 的真 bug，用户原话"右侧亚群跟来源重合了"）**：

| x | v2 的元素 | 问题 |
|---|---|---|
| 0.116 | 旋转轴名 | — |
| 0.137 | 旋转分组名（家族色） | ← **被亚群名穿过** |
| 0.150 | 分组竖括号 | ← **被亚群名穿过** |
| 0.170 | 亚群名右对齐 | 宽 ≈0.085 ⇒ 左缘 ≈ **0.085**，实打实跨过 0.150 与 0.137 |

⇒ 右对齐基准在 0.170、名字宽 0.085，就必然压到左边 0.150 的括号上。
**这是算术问题不是审美问题**，改版前先把这段算出来。

### ✅ v3 定案版式：`轴名 → 亚群名(右对齐) → 模块竖带 → 柱形图`

| x | 元素 |
|---|---|
| 0.008 | 旋转 90° 轴名（如 `Subpopulation`，6.6pt bold） |
| 0.090 | 亚群名，**右对齐**（6.4pt）——**整体落在模块竖带左侧**（13 字符左缘 ≈0.005，与轴名 0.008 相邻不压） |
| 0.098–0.126 | **模块竖带**：浅底矩形 `#F4F4F4` `zorder=0` + 右缘竖线 `lw=1.7` + 上下端封口 `lw=0.8` + 居中旋转模块名（`rotation=90`, bold, 7.6pt） |
| 0.126 | 柱区起点 `LM` |

- 把"家族 / 来源"这类分组信息做成**一条模块竖带**（本例写 `MF`），
  **不要**在亚群名左边再放家族括号 + 旋转家族名 —— 一定会压叠。
- 想保留 Pure / Derived 的分块信息又不想加标签争位置 → 用**极浅虚线分隔**
  （`#D0D0D0`, `lw=0.6`, `linestyle=(0, (1, 1.6))`），不写文字就不会与名字重叠。
- 省下的横向空间回给柱区：`LM` 0.176 → 0.126，每面板宽 +2 mm。
- 模块竖带的 y 范围取 `BM-0.004 → BM+PH+0.004`（略超面板上下缘，视觉上"夹住"整列）。

**行对齐必须与 axes 的 `ylim` 严格镜像**，否则手画标签整体漂移：

```python
YROW = np.arange(n)[::-1]              # 第 1 行在顶
ax.set_ylim(-0.62, n - 0.38)
def yfrac(r):                          # 行 r 对应的 figure y
    return BM + (PH / (n - 0.38 + 0.62)) * (YROW[r] + 0.62)
```

**分组只能取现有行序里的连续段**。若逻辑分组要求重排行序 ⇒ **先问用户**：
重排 = 改结构，超出"整体结构不变"的授权范围。

## 4b. 逐柱数值标签（用户要求"每根柱都标，贴近，但是又不重合"）

柱子数量多（每面板 16 根 = 8 上调 + 8 下调）时，全部外侧会撞面板边界 / 邻面板。
按"柱端占半轴宽的比例"分流：

```python
tr = ax.xaxis.get_transform()                      # 必须在 set_xlim 之后取
f0 = float(tr.transform(0.0)); f1 = float(tr.transform(XMAX))
def frac(v, plus=True):                            # 0 = 轴线中心, 1 = 轴最右/最左
    fv = float(tr.transform(v if plus else -v))
    return (fv - f0) / (f1 - f0) if plus else (f0 - fv) / (f0 - float(tr.transform(-XMAX)))

# frac > 0.80 → 柱内白字右对齐（长柱贴边，外侧放不下）
ax.annotate(f"{v:,.0f}", xy=(v, y), xytext=(-2.2, 0), textcoords="offset points",
            ha="right", va="center", fontsize=4.7, color="white", zorder=6)
# 否则 → 外侧彩色字（上调贴右 ha="left"，下调贴左 ha="right"）
ax.annotate(f"{v:,.0f}", xy=(v, y), xytext=(+2.5, 0), textcoords="offset points",
            ha="left", va="center", fontsize=4.7, color=UP, zorder=6)
```

四条必守：

1. 一律用 `textcoords="offset points"`（点数偏移）。**不要用数据单位 pad** ——
   symlog 下同样的数据单位偏移在不同 x 位置视觉宽度差异巨大。
2. `frac(...)` 要处理两侧：右侧 `(fv-f0)/(f1-f0)`，左侧 `(f0-fv)/(f0-tf(-XMAX))`。
3. 值为 0 的柱把 pad 提到 **4.2 pt**，否则左右两侧的 `"0"` 会贴在一起。
4. 条形色够深（`#B2182B` / `#2166AC`），内嵌用纯白字对比度足够。

✅ **刻度标签在轴下方、柱值标签在轴内 → 不同纵向带，天然不会互撞**，
不必为"最外侧刻度 vs 末端柱值"让位。真正的风险只有"外侧标签越出面板边界撞邻面板"。

## 5. 结构不变的改图纪律（用户说"在这个基础上优化 / 有三个问题"时）

1. **先按文件名定位生成脚本**：用户会按文件名指认基线（"`fig_xxx_v2_optimized` 有三个问题"）→
   到 `results/<sid>/scripts/` 里 `search_files` 找到**生成它的脚本**，读一次拿数据配方与版式常量，
   再按问题编号逐条改；**不要重写、不要重新推导数据**。
2. **复用已算好的计数表**，一个统计量都不重算（本例读 `deg_subcluster_updown_coef025_matrix.csv`）。
3. 未被点名的要素**零改动**（顺序 / 配色 / 背离方向 / bar 高 / 白描边 / 顶部标题带）。
4. 新脚本命名递增（`_v2_optimized` → `_MF_v3_optimized`），**文件头 docstring 写清"基线是谁 + 改哪几处"**，
   并逐条对齐用户提出的问题编号。
5. 🔴 **用总量复核证明"结构没变"**：改完把每面板 `ΣUp / ΣDown` 与基线逐个对照并写进汇报
   （本例 Aging 16,535↑/380↓、DM 125/144、Ex_Young 61/38、Ex_Old 231/1,091、Ex_DM 107/119 逐项吻合；
   剔除两亚群后校验 23,178−2,206−4,057 = 16,915 ✓）。
   这是"我没动数据"最硬的证据。**保留首次运行时的汇总打印**，改版后重跑即可自动对照。
6. 剔除的行必须写进图注（本例 `RSS and Specialized MF excluded`）。
7. 附加元素（如底部共享轴名 + source data CSV）在汇报里**单独列出**"这几处不属被点名的区域"。
8. 定稿后把版式常量写进记忆 `[图稿]` 条目（常量名+值），下轮改图只 patch 对应常量，不重读整个脚本。

## 6. 出图自检（像素健康**必要但不充分**）

**① 像素健康**（区域带墨率）：

```python
a = np.asarray(Image.open(png).convert("RGB")); H, W, _ = a.shape
nonwhite = (a < 245).any(axis=2).mean()*100
top  = (a[:int(H*0.30)]      < 245).any(axis=2).mean()*100
left = (a[:, :int(W*0.18)]   < 245).any(axis=2).mean()*100
band = (a[:, int(0.098*W):int(0.126*W)] < 245).any(axis=2).mean()*100   # 模块竖带
```

v3 实测：2834×1380 @400dpi = 180.0×87.6 mm、非白 20.10%、1319 色、顶部区 9.23%、左侧区 5.67%、
模块竖带 5.53% → 非空白非黑底，且"该有墨的地方都有墨"。
⚠️ 带墨率只证明"那里有东西"，**证明不了"那里是什么"**——必须接 ②。

**② 文字真渲染核验（裁切 + OCR）**：

- 顶部条带 → `im.crop((0,0,W,int(H*0.135))).resize(2×, LANCZOS)` 再 OCR。
- 🔴 **旋转文字 → 先转正再 OCR**：`im.crop((0,0,int(W*0.195),H)).rotate(-90, expand=True)`。
  未转正时 OCR 只回乱码片段（本例读出 `srefik` / `Jeriv` / `ndn` / `Del`），转正后立刻读出真实文字。
  **看到旋转文字的乱码，先怀疑没转正，别怀疑渲染失败**——也不能据 OCR 缺失判定"没渲染"，
  要交叉核对该区域带墨率 > 0。（本例 `MF` 与 `Pure fiber types` 都读不出，但竖带带墨 5.53% 证明在案。）
- OCR 里 `10010` / `5,0001,000` 这类粘连 = 相邻刻度标签被合并读取 → 可反推刻度阶梯密度是否过密。

**🔴 禁止用"精确颜色像素计数"判定文字是否存在**：
按家族色 teal `#0F5F6E` + 三通道差和容差 40 计数 → 命中 **0**，据此几乎误判"家族标题没渲染"；
实际渲染在案（放大 OCR 清清楚楚）。根因是**抗锯齿把核心色压深了**（实测读出 `#004060`，差和 = 60 > 40）。
⇒ 验"有没有字"就用 OCR；要验颜色只能作辅助，且必须**宽容差 / 色相距离**。
