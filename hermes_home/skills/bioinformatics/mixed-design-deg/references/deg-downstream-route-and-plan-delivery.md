# DEG 下游研究路线 + 方案文档交付模式（人骨骼肌 6 组混合设计实例）

> 场景：用户手上已有多个对比的 DEG 结果表，问「我这么多 DEG 该怎么研究？能给我规划吗？」
> 或直接说「**只要方案文档，先不跑**」。本文覆盖两件事：① 这类数据的下游路线骨架；
> ② 方案文档该怎么交付（含 md → docx）。

---

## 1. 「只交方案文档、不跑分析」= 一种独立交付模式

**触发原话**：「只要方案文档，先不跑」「不需要执行」「你先给我规划」「不需要执行」。

**⛔ 该模式下的硬约束**：不创建 task_plan、不跑任何脚本、不出图、不调 debate（零参数决策）。
只交付：

| 文件 | 说明 |
|---|---|
| `<会话>/task2/results/<主题>_plan_v1.md` | 主文档（含 Mermaid 路线图） |
| `<会话>/task2/results/<主题>_plan_v1.docx` | 可编辑版，用 `scripts/plan_md_to_docx.py` 转换 |

**用户认可过的 13 节骨架**（顺序即优先级）：

| 节 | 内容 | 为什么必须有 |
|---|---|---|
| §0 一句话定位 | 这批数据**真正的价值**在哪 | 用户要的是判断，不是清单 |
| §1 家底 | 全部为**实测**数字（样本/分组/两法规模/模型/阈值） | 后续所有判据的基准 |
| §2 已完成产出 | 逐条列路径 + 标「复用，勿重跑」 | 防止下轮重跑 |
| §3 **全局红线** | 会导致结论必假的方法学陷阱 | **最高价值段落** |
| §4–§8 分步 | 每步：做什么 / 判据 / **必附校正** / 工具 / 产出 | 可执行化 |
| §10 脚本落地清单 | 脚本名-输入-输出-要点 表 | 执行时直接照做 |
| §11 文献依据 | ≥5 篇带 PMID/DOI；**查不到的缺口如实标「不编」** | 用户会逐一核 |
| §12 Limitations | 全部已知偏倚与功效限制 | 投稿必需 |
| §13 缺口清单 | 需要用户补的数据/信息（表格式） | 唯一合法的「问用户」位置 |

**三条写作要求（踩过坑）**：

1. **数字必须从既有报告读取复算**，⛔ 不凭记忆写 —— 用户会逐一核对（本实例中我凭记忆写的
   「N≈27,015」与报告里的「老法 17,395 基因 / 新法 9,581 基因」是两个不同口径，必须回读）。
2. **上一轮给用户的建议被实测推翻时，文档与回复都要显式写明「已纠正」并给替代方案** ——
   本实例：曾建议「取 Aging 与 Ex_Old 的反向交集当逆转基因集」，被审计报告推翻（共享项伪相关），
   改为距离法后**主动在回复里点名纠正**。隐藏修订会被当成新错误。
3. **每个判据写清伴随的校正**（OR / Jaccard / 供体级配对），⛔ 不能只写「取交集」。

## 2. 这类数据（多组 × 配对）的下游路线骨架

```
Step 1  DEG 分布展示（已完成）
Step 1.5 口径统一（新增·先于一切重合分析）
        1a 正负号语义锁定（谁减谁，逐文件核）
        1b 两法可信度分级 Tier1/2/3
        1c 基因宇宙 N 实测（交集期望 + 富集背景都要用）
        1d 供体 Pre/Post 配对关系确认
        1e 假基因 / 未注释 lncRNA 筛查（进主结论前）
        1f BH 家族大小记录（各亚群基因数差异）
Step 2  重合分析（方向感知）
        2a 运动共同 DEG：E_Y ∩ E_O ∩ E_D，同向取交 + 多重集显著性
        2b 逆转衰老：距离分析法（⛔ 不取反向交集）
        2c 逆转糖尿病：同法；⚠️ 老法功效≈0，仅细胞级支持须声明
        2d 运动反应是否随衰老/糖尿病衰减（需先补两个 DiD）
Step 3  富集（背景 = 实际检测基因 N；GSEA 主 / ORA 辅；三池分开）
Step 4  细胞层 + 调控层（比例配对 / 程序打分 / 轨迹 / SCENIC / CellChat）
Step 5  验证（独立数据集 / 文献真值集 / leave-one-donor-out / 湿实验）
```

**为什么把「逆转」放在故事核心**：同一批供体同时提供衰老与运动两个方向 —— 这是本设计
最独有、公开数据最难复制的部分。OTOH **DEG 数量本身没有故事**（组间 vs 配对功效不等，不可比）。

**编排原则**：每层只答一个生物学问题；每层产出即可独立成图；辩论只在「辩完能改变下一步动作」时做。

## 3. 必须写进 Limitations 的清单（本类设计固定七条）

1. 全体女性（若数据如此）→ 不可外推男性。
2. 年龄匹配不齐（实测 O 均 68.6 vs OD 均 72.4）→ 糖尿病对比含轻度年龄混杂。
3. 组间（Aging/DM）与配对（Ex_*）**功效不等**，不可横向比较显著基因数。
4. 老方法在弱信号对比上**实质无功效**（实测 DM=1 / Ex_Young=22 / Ex_DM=4）→ 这些线仅细胞级支持。
5. 细胞级 SE 低估 ~26 倍 → 显著数不可作为方法优劣证据；效应量阈值若为 0.25 属**自定标准**
   （文献中 0.25 实为 Seurat v3/v4 `FindMarkers` 出厂默认，不是 MAST 参数）。
6. 假基因 / 未注释 lncRNA 进主结论前须筛查。
7. 缺两个 DiD 对比 → 「运动效应是否随年龄/疾病改变」目前无法直接回答。

## 4. md → docx（`.venv` 常无 python-docx）

**⛔ 不要为此安装新包** —— 先探解释器（符合「缺包先查用户环境」铁律）：

```bash
for P in ".venv/Scripts/python.exe" python python3; do
  printf '%s -> ' "$P"; $P -c "import docx,sys;print('HAS_DOCX',sys.executable)" 2>&1 | tail -1
done
```

实测：`.venv/Scripts/python.exe` **无** `docx`；系统 `python`（Python312 全局）**有** ⇒ 直接用系统 python 跑。

```bash
python <会话>/scripts/plan_md_to_docx.py <会话>/task2/results/<主题>_plan_v1.md
# → OK: ..._plan_v1.docx 46933 bytes, paragraphs: 84 tables: 14
```

转换器要点（`scripts/plan_md_to_docx.py`，可直接复用）：4 级标题、管道表格 → Light Grid 表
（首行加粗 8.5pt）、代码块 Consolas 8.5pt、引用斜体灰、列表 Bullet/Number、行内 `**加粗**` 简易解析、
**中文必须同时设 `font.name` 与 `rPr.rFonts` 的 `w:eastAsia`**（只设前者中文会回退）。
