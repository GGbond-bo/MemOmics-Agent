# 图几何声明的独立验证 —— 自检为什么会自证清白

适用：任何「文字要与某个几何体对齐」的图。热图（行名 ↔ 行色块）、桑基图（标签 ↔ 节点色条）、
UMAP（簇名 ↔ 簇）、DotPlot（行名 ↔ 圆点）、带注释条的矩阵图。

## 一句话

**共源自检不是证据。** 判「是否对齐」的脚本若与绘图代码共用同一套坐标假设，Δ 会恒等于 0 ——
你以为在测量，其实在做同义反复。

## 三层假 PASS 的演进（同一类缺陷，三次实测）

| 层 | 自检形态 | 报出的数字 | 真实情况 |
|---|---|---|---|
| L1 | matplotlib **对象级** `get_window_extent()`，且在 `plt.close()` 之后取值 | 「重叠 190 对」「标签↔色块 max = 1227.5 px」 | 全是 1×1 px 退化 bbox 的假数字；真实错位 60.5 px |
| L2 | 改为量**导出 PNG** 的色带中心 + `transData.inverted()` 自校准 | 「max = 0.5 px」「max = 3.3 px，容差 6 px → **PASS**」 | 仍 PASS，用户仍说错位 |
| L3 | **独立读数**：对同一张成品 PNG 跑 `vision_describe` OCR，取文字 y | 标签 pitch 120 px = 行高 120 px，**但标签比该行格内数值恒偏 ≈59 px** | 半行高真实错位 |

**L2 → L3 的教训**：把「对象级」换成「像素级」只解决了**坐标系混用**（100 dpi canvas vs 300 dpi 导出、
close 后 bbox 退化），**没有解决假设同源**。修一层不等于修好 —— 换完方法要再问一次「这条读数和绘图代码
共享哪些前提」。

## 独立读数配方（唯一仲裁口径）

1. 对**最终交付的那张 PNG**跑 `vision_describe`（不是中间图、不是 SVG/PDF —— 交付物才是被判的对象）。
2. 取两组文字的 y：
   - ① 行标签（亚群名 / 基因名 / 簇名）
   - ② **该行格内的数值文本**
   第 ② 组是关键：数值是绘图流程内部独立画上去的，**不经过标签布局路径**，是图内天然的基准尺。
3. 两组出自**同一次 OCR** ⇒ **只做组间差分，不与任何计算出来的布局数字比绝对 px**。
   OCR 的 y 是文字框上沿（实测整体偏 ~18 px），差分把这个常数项消掉。
   跨工具比绝对 px（OCR y ↔ `transData` 算出的 y）= 又一次坐标系混用。
4. 判定：
   - 标签 pitch ≈ 行高，且「标签 y − 同行数值 y」组内方差小、均值 ≈ 半行高或整行高 ⇒ **真错位**。
   - 该均值 ≈ 0（± 几 px）⇒ 对齐。

## 本次实测（47_MEF2C_log2FC_heatmap_5contrasts_10subclusters.png，1530×1650 @300 dpi）

| 量 | 值 |
|---|---|
| 行 pitch = 行高 | 120 px（10 行占 1200 px） |
| 格内数值 y（前五行） | 312 / 433 / 552 / 673 / 793 |
| 亚群名 y（前五行） | 254 / 373 / 494 / 612 / 733 |
| 差（数值 − 标签） | 58 / 60 / 58 / 61 / 60 → **均值 ≈59 px ≈ 半个行高** |

**签名：pitch 正确 + 半行高恒定偏置** ⇒ 标签被钉到了行边界（或相邻元素的中心），
不是字体渲染噪声。不要用「几 px 容差内算对齐」把它糊过去 —— 容差是给抗锯齿留的，不是给半格留的。

## 汇报与提问纪律

- 用户说错位、你的自检说对齐 ⇒ **先跑独立读数再开口**。此时你手里还没有测量结果。
- `ask_user` 的提问文本**不要先下结论**：写「我量过，没量出错位」= 逼用户把同一句抱怨再说一遍。
  正确写法 = 只问「哪一张图、哪一处」，把判断留到拿到可仲裁的证据之后。
- 汇报对齐必须给**逐项 Δ 数值 + 容差 + 基准是什么**，禁止只说「已对齐」。
- 修好之后**报同一口径的复测数字**（哪个基准、多少 px、容差多少），而不是「已修复」。

## 桑基图上的同类风险（待验证的假设，不要当结论用）

桑基图脚本里的对齐自检通常写成 `ax.transData.transform((LX, (y0+y1)/2))` 对比文字 bbox 中心 ——
**结构上同样是共源**：节点区间 `(y0,y1)` 由与绘图同一套 `layout()` 算出来。
另外小权重节点会引入另一种「看起来错位」：色条 9 px 而标签文字 38 px，即使中心严格对齐，
视觉上仍像没对齐 —— 这类要判的是**最小可视高度 / 标签与色条的尺寸比例**，不是 Δ。
判之前先按上面的配方量一次，别把「比例问题」误诊成「偏移问题」（或反过来）。
