# 效应值矩阵热图（effect × 亚群）诊断与配方

来源：MEF2C × 5 对比 × 10 亚群 log2FC 矩阵（human skeletal muscle，donor-paired dreamlet）。
本文件记录**色标失配的量化诊断**与**数值型矩阵热图的成图配方**，是铁律 4 的实证附页。

---

## 一、色标失配：本类图最常见的"整张图没信息"

**症状**：用户看图说"不合格 / 看不出变化"，但几何审计全过（0 越界、0 重叠）、50 格数值齐全、
10 个亚群名与 5 个列标题都在、四格式导出正常。

**根因**：色标边界由习惯给出（±0.5、±2、±3），而数据范围小得多。

| 项 | 本案数值 |
|---|---|
| 数据范围 | −0.152 ~ **+0.451** |
| 色标（错） | `TwoSlopeNorm(vmin=-0.5, vcenter=0, vmax=0.5)` |
| 负值端利用率 | 0.152 / 0.5 = **30%** → 色块接近白 |
| 正值端利用率 | 0.451 / 0.5 = 90% → 饱和红 |
| 后果 | 红蓝不对称；**衰老（负值）那一列整列发白，"下降"看不见**——而"衰老→运动回补"正是全图主结论 |

**出图前一行判据**：

```python
M0 = float(np.max(np.abs(M)))
util = M0 / VMAX          # 任一侧 < 0.5 → 该侧塌陷，必须收紧
```

**修法（安全、无副作用）**：`TwoSlopeNorm(vmin=-M0, vcenter=0.0, vmax=M0)`。
`TwoSlopeNorm` 的 `vcenter` 固定把 0 映射到色带中点（白），收紧边界**不改变 0 的颜色**，只放大两侧对比。
⚠️ 收紧后**必须同步改刻度**（±0.5 的 `[−0.4,−0.2,0,0.2,0.4]` 改成贴合边界的三到五档），
否则刻度落在数据范围外，看起来像空轴。

**两侧量纲不同的情形**（如 logFC 负向只到 −0.2、正向到 +0.5）：可用非对称边界
（`vmin=-0.25, vcenter=0, vmax=0.5`），0 仍居中白；但期刊图更常见对称制，取舍前跟用户确认。

## 二、数值型矩阵热图配方（每格标数值）

适用：对比 × 亚群、处理 × 时间点 这类**小而密**的效应值矩阵（≲100 格）。

| 元素 | 做法 | 理由 |
|---|---|---|
| 单元格数值 | 100% 格全标、`%+.2f`、负号用 typographic minus `−`（U+2212） | 读者要读出确切值而非靠色深猜；U+2212 与 `+` 视觉等宽，正负栏对齐 |
| 数值颜色翻转 | `abs(v) > 0.30 → 白字`，否则深灰 `#1A1A1A` | 饱和色块上的深字读不出 |
| 名义显著标记 | 名义 P < 0.10 追加 `†`，含义写进脚注 | 避免"全不显著"时图面信息只剩颜色 |
| 最强格标记 | 最小 FDR 格加**虚线框**（`lw=0.9, ls=(0,(2.2,1.5))`），脚注点名该格坐标与 FDR 值 | 把"最接近显著"直接说在图里，不让读者自己找 |
| 单元格分隔 | `edgecolors='white', linewidth=0.7` | 期刊热图惯例 + 消抗锯齿缝 |
| 色标 | 竖放右缘，宽度 ≥ 0.14 in，刻度 3–5 档 | 过窄（< 0.12 in）读数困难 |
| 列标题 | 助记符 + 第二行均值（如 `Ex_Old\nmean +0.25`） | 长定义移进脚注 key，避免列标题超出格宽压叠 |

⚠️ **诚实性约束**：若全部检验都不显著（本案 50/50 的 FDR ≥ 0.333），图注必须**明写
"no pair was FDR-significant"**，不能只靠颜色深浅暗示"有变化"。**方向一致 ≠ 统计显著**，
汇报时要把"方向一致（9/10 亚群同号）"与"无一显著"分开陈述。

## 三、脚注五要素（缩到最短仍让图自洽）

1. **对比定义 key**：`Aging = Old − Young; DM = (Old+DM) − Old; ...`（列名是助记符，必须给展开式）
2. **模型口径**：`donor-paired dreamlet models (human skeletal muscle biopsy)` —— 什么模型、什么分析单位
3. **显著性声明**：全不显著就写 "no pair was FDR-significant"
4. **符号说明**：`† = nominal P < 0.10`；虚线框含义
5. **数据源**：`Source: results/45_...csv; results/46_...csv`

⚠️ **用户偏好（本案实测）**：数据源**文件名进脚注**会被认为"太长、不像期刊图注"。
若用户嫌脚注长，优先砍**第 5 条**（数据源）→ 再砍第 2 条（模型口径），保留 1/3/4。
表格类输出仍要在正文给全路径。

## 四、反馈处理：用户说"不合格"时先量，别先猜

本案用户连续两轮只说"不合格"，未指方向。有效顺序：

1. **先跑几何审计拿硬数字**（越界数、重叠对数、各元素是否齐全）
   → 本案 0 越界、190 个"重叠"全是 1 px 假阳性、元素齐全 ⇒ **几何不是问题**
2. **再算参数与数据的匹配度**：色标 vs 数据范围、字号 vs 画布、格高宽比 vs 惯例
   → 抓到色标失配（这是**有把握的客观缺陷**）
3. **把候选修复列成可勾选项**交用户确认（`ask_user` multi_select），
   每项标注"客观缺陷"或"我的判断"，只对有把握的项写"建议直接改"

不要把"我重新调了一版"当回答 —— 用户要的是**能说出根因**的诊断。
也不要只凭目测下结论：目测说不了"0 越界"，也算不出"30% 利用率"。

---

## 五、审计脚本的两个坑

1. **重叠阈值**：`ix > 0.5 and iy > 0.5`（px）会把相邻文字 bounding box **边界相接**判成重叠。
   本次实测 190 个报错全是 1×1 px，真重叠 0 个。→ 阈值提到 `> 2 px`，且**只输出 top-N 最大的几对**。
2. **报告要能一眼判读**：输出形如

   ```
   canvas px = 510x550 | text objects = 93 | OUT-OF-CANVAS = 0 | OVERLAPPING(>2px) = 0
   FIG_SIZE 5.10 x 5.50 in = 129.5 x 139.7 mm
   ```

   三个数字 + 阈值写明，用户/下一轮 agent 不必回头读代码。

## 六、SVG 源码级定位（比读图准）

判断"某段文字到底在不在图里、在什么位置"时，从 SVG 提取文字比 OCR 可靠。matplotlib 的
`svg.fonttype: 'none'` 会把文字保留为 `<text>`，但文字被包在 `translate(x y)` 的 `<g>` 里，
**逐行扫描时跟踪当前 translate** 才能拿到真实坐标（一次性正则 + 非贪婪会漏或误配）：

```python
lines = open(svg_path, encoding='utf-8').read().split('\n')
cur, recs = None, []
for ln in lines:
    m = re.search(r'transform="translate\(([-\d.]+)\s+([-\d.]+)\)', ln)
    if m: cur = (float(m.group(1)), float(m.group(2)))
    for t in re.findall(r'<text[^>]*>(.*?)</text>', ln):
        recs.append((cur[0] if cur else -1, cur[1] if cur else -1, t))
```

实测用途：确认"10 个亚群标签 + 5 个列标题 + 5 行脚注"是否真的都渲染出来了，
以及列标题与 mean 行的 y 间距（本案 332 vs 339 pt → 7 pt，偏挤，是候选改进项）。
