# Grill Me：连环拷问打磨方案

对用户（或 AI 自己）提出的**方案 / 设计 / 计划**进行不留情面的连环面试。
目的是在方案落地前暴露：漏洞、假设、边界、成本、风险、被忽略的替代方案。

## 什么时候用

### 触发场景
- 用户提出分析/开发需求、**正式方案生成之前**（先确认需求 + 拷问方案要点，避免生成错方案）
- 方案 / 设计 / 计划刚产出、还没开始实施时（先拷问再动手）
- 重大决策落地前（选型、架构、分析方法、阈值选择）
- `rail_review` / `debate_analysis` 之前的**预检**（先被拷问一遍，再进正式评审）
- 多个候选方案选型时（对每个方案轮流拷问，再比较）
- 用户说"拷问一下""帮我挑毛病""这个方案行不行""还有没有坑"时

### 不触发场景
- 纯事实查询 / 数据获取（没有"方案"可拷问）
- 代码 bug 修复（走 systematic-debugging 流程）
- 用户明确表示"不用审了，直接做"
- 单条消息闲聊（不自动开始，等用户示意或方案出现）

## 玩法（5 步）

1. **接案**：确认被拷问对象（方案/设计/计划全文），复述一遍你理解的方案核心，
   让方案提出者确认"你没理解偏"。
2. **考官人设**：化身苛刻的审查者——默认怀疑一切结论，每个回答都追问
   "凭什么？""如果…怎么办？""边界在哪？"。不客气，但就事论事。
3. **连环追问（核心）**：每个回答后**必须继续深挖至少 1 轮**，不允许回答者
   用"以后再说""先做了再看"糊弄过去。至少覆盖 5 个攻击面：
   - **假设**：哪些前提没验证？若前提错了会怎样？
   - **边界**：适用范围的边界在哪？超出边界会怎样？
   - **反例**：什么情况下这个方案会失败？
   - **成本**：时间/算力/token/维护成本被低估了吗？
   - **替代**：有没有更简单/更便宜的方案被忽略了？
4. **收敛**：当追问 3 轮仍无法击破、或问题已全部闭环时结束。
   一般 5-8 轮，不无限拖。
5. **产出拷问报告**：
   - **弱点清单**：按严重度列出被击破的漏洞（🔴 致命 / 🟠 严重 / 🟡 一般 / 🟢 优化）
   - **修复建议**：每个弱点给 1-2 条可执行对策
   - **加固后的结论**：修改后的方案要点 / 或判定方案不可行并给替代方向
   - **未决问题**：仍需要数据/实验回答的问题（留给后续验证）

## 与 MemOmics 其他机制的关系

| 机制 | 分工 |
|---|---|
| grill-me（本技能） | 方案**落地前**的快速拷问，5-8 轮，轻量，产出弱点清单 |
| rail_review | 分析**执行后**的铁轨审查（pre/post），查过程合规 |
| debate_analysis | 结论**裁决**：多角色辩论定置信度（L1 轻量 / L2 完整） |
| skill_evolution | 裁决与经验**回流**知识库 |

建议链路：方案 → grill-me 拷问 → 实施 → rail_review(pre) → 执行 → debate 裁决 → rail_review(post) → 沉淀。
