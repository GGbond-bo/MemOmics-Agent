# 重叠基因的 reads / UMI 归属审计

用户（或合作者）问：「**If we are counting reads in the overlapping region, how can we
distinguish gene A vs gene B reads?**」——这是一道**方法学题，不是排版题**，也**不是**再去测
一个组学能答的题。答案要用 **注释几何 + 计数原理** 给，并做成**可复现包**。

⛔ **不要用 ATAC 回答「read 算谁的」**：ATAC 测染色质可及性，回答的是「这个位点开不开放」，
它根本没有 read→基因 的归属问题。给 ATAC 是答非所问。

✅ **但反过来成立，别把这个方向也一起挡掉**：合作方若问的是「**这个位点在处理前后变多变少、
是不是说明处理也影响了宿主基因**」，ATAC 恰恰是唯一能答的数据 —— 前提是**按 TSS 窗口分区**
统计，而不是按基因分区。判据、三个陷阱与结论上限见 §七（2026-10-02 实测）。
回绝一个**可答**的问题，比给一个错设计更糟。

## 〇、先分清对方在问什么（这条排在技术之前）

| 用户的问法 | 你要做的 | ⛔ 禁止 |
|---|---|---|

| 「我们要给他看 GTF 还是去做 ATAC？」 | 直接给判断：**归属题** GTF 够、ATAC 答不了；若对方问的是**可及性题**（位点处理前后变不变）则 ATAC 才是对的（§七） | 两个都做一遍 |
| 「**帮我整理成回他的说辞**」 | 出可直接发送的中英双版正文，数字全部已核实（§六） | 只复述不产出、只给一版 |
| 「这个重叠到底会不会污染我的结论？」 | 走 §一→§五 全流程，出审计包 | 只口头保证「没问题」 |

**2026-10-01 实测教训**：用户问「合作方说的是什么意思」，我转去把另一张图做了十几轮
（补丁→重跑→像素审计→辩论→量化），被直接打断「关桑基图什么事情？」。
**解读类问题 = 只解读 + 核实事实，交付完再问下一步。**

术语对齐：对方说的 "overlapping region" 几乎总是指 **gene span 重叠**（GTF 里两行 start/end 相交），
而这**不是** UMI 计数看到的重叠 —— 抓住这个错位，问题就解决了一半。

## 一、核心判据：「重叠」有两个口径，混淆就错

| 口径 | 含义 | UMI 计数能看到吗 |
|---|---|---|
| **gene-span overlap** | 两个基因的**注释跨度**相交（合作者通常看到的就是这个数） | ❌ 跨度里绝大部分是内含子 |
| **exon-level overlap** | 两个基因的**外显子**相交（合并外显子块后再求交） | ✅ 只有这部分可能产生归属歧义 |

实测样本（MEF2C / MEF2C-AS1，GENCODE v32 GRCh38，可直接当答复模板）：

| | MEF2C | MEF2C-AS1 |
|---|---|---|
| Ensembl | ENSG00000081189 | ENSG00000248309 |
| 坐标 | chr5:88,717,117–88,904,257 | chr5:88,883,328–89,466,398 |
| 链 | **−** | **+** |
| 类型 | protein_coding | lncRNA |
| 合并外显子 | 36 块 / 11,755 bp | 22 块 / 7,865 bp |

- **span overlap = 20,930 bp**（chr5:88,883,328–88,904,257）
- **exon overlap = 422 bp in 3 段**（139 / 17 / 266 bp）= span 的 **2.02%**、MEF2C 外显子的 3.59%
- 其余 **20,508 bp 是内含子**，标准 UMI 流程不涉及
- 配置 = **5′ 相向（head-to-head / divergent）**，**3′ 端相距 ~750 kb 且完全无重叠**
  ⚠️ **术语精度（2026-10-02 自纠）**：head-to-head 在文献里指 **5′ 端相向**，**不等于共用双向启动子**。
  本例两个 TSS 相隔 20,930 bp、**各自有独立启动子**、转录本**相向汇入**重叠区 ⇒ 对外措辞写
  「**5′ 相向、重叠区两端各有一个 TSS**」，⛔ 别写成「共用启动子 / 双向启动子」——
  合作方一眼能看破，而且会**直接误导后面的 ATAC 设计**（共用启动子 ⇒ 天然认为一段可及性同时管控两个基因；
  各自独立启动子 ⇒ 必须分区统计，见 §七）。

**三条支柱（按可靠性排序）**：
1. **注释几何**——可 100% 复现，是主证据；
2. **计数原理**——UMI/read 计数默认**只数外显子**、按**链**归属 ⇒ 反义链 reads 不计入正向基因；
3. **实测反证**（有定量结果时最有力）——两个基因的差异表达若**不同向**，本身就是「没混在一起」
   的证据。实测：MEF2C-AS1 运动后多亚群显著上调（coef 0.27–0.72，FDR≈0），MEF2C 全部未达阈 ⇒
   若真有 UMI 串味，两者应同向同幅变化；实测相反。

## 二、五步工作流

1. **按 Ensembl gene ID 解析，绝不用 symbol**——`MEF2C` 是 `MEF2C-AS1` 的**真前缀**，
   用 `grep MEF2C` 会同时命中两个基因（脚本里务必用 `ENSG...` 精确匹配）。
2. **从 GTF 取两类区间**：gene span（`$3=="gene"`）与 exon 块（`$3=="exon"`），
   外显子**先按基因合并**（合并后再求交，否则算出的重叠是逐块碎的、数字虚高）。
3. **求两种重叠**：span∩span、merged-exon∩merged-exon（bedtools `intersect`，无 bedtools 用 awk 兜底）。
4. **出审计包**（见 §三）——BED6 + `verify.sh` + `README.md` + 汇总 CSV。
5. **出索引图**——把「每个 BED 覆盖哪段区间 + 3 段外显子重叠落在哪」画成一张图。
   既是真实交付内容，也顺带满足 `rail_review(post)` 的「每步至少 1 张图」（否则纯 BED/命令包必判 failed）。

## 三、审计包结构（本 skill 的交付契约）

```
<out>/audit/
├── <A>_span.bed                基因跨度（BED6）
├── <A>_exons_merged.bed        合并外显子块
├── <B>_span.bed
├── <B>_exons_merged.bed
├── overlap_gene_span.bed       ← 合作者看到的那个数
├── overlap_exons.bed           ← 唯一可能产生归属歧义的部分（必须单独成文件）
├── audit_summary.csv           全部数值一张表（含链方向、占比、分母说明）
├── verify.sh                   一条命令从原始 GTF 复现全部数字
└── README.md                   方法 + 逐步命令 + 诚实边界
```

- 坐标系必须写明：**BED = 0-based half-open；GTF = 1-based inclusive**
  （`start_bed = start_gtf − 1`，`end_bed = end_gtf`）。写错一位，第三方复现就对不上。
- `verify.sh` 自带断言（`span == 20930 && exon == 422` → `PASS`），并**同时支持**
  bedtools 与**纯 awk 兜底**（对方机器没装 bedtools 也能跑通）。可直接复用
  `scripts/gtf_gene_overlap_bed_pack.sh`（改两个基因 ID 即可）。
- 出图脚本与 BED 生成脚本分开落盘（`scripts/`），产物进 `results/<sid>/`。

## 四、交付口径：诚实边界（README 必写，不许省）

可以主张：注释几何（可复现）、计数原理（外显子 + 链）。

**不能主张**（除非实测过）：
- ❌ 「重叠区不产生 UMI」——那是**条件性**结论，依赖建库方式；
- ❌ 「我们用的是链特异性建库」——除非查过流水线设置。

**必须列为待确认项**（问数据方，三项都要）：
1. 建库化学：**3′ 还是 5′**？（3′ 时 UMI 落在 3′ 端，重叠在 5′ 端 ⇒ 影响很小；
   5′ 库则此论证**失效**）
2. 链设置：Cell Ranger `--soloStrand` / featureCounts `-s` / alevin `-l` 到底设了什么；
3. 是否开了 `--include-introns`（开了就不止数外显子，422 bp 的论证要重算）。

**要「实测级」答复时的最小增量**：① 只用唯一外显子（剔除重叠段）重定量，看结论是否移动；
② 有 BAM 就 `samtools view -b in.bam chr5:<ov_s>-<ov_e>` 数 reads 并报 strand(FLAG 0x10/0x20)/MAPQ/NH。
**没有 BAM 就明说没做实测**，不要用「按原理可区分」冒充「实测分离」。

## 五、坑表

| 坑 | 根因 | 处置 |
|---|---|---|
| 🔴 bash 里 awk 解析 GTF attributes 用转义引号 `split($9,a,"gene_name \"")` → 警告；改成 `split($9,a,"gene_name ")` 后**脚本静默算出 0 结果**（数字全 0、断言全 NOT PASS），看着像"数据变了" | awk 正则字面量里的 `\"` 不是合法转义；改法一回（去转义）会让 `sub(/".*/,…)` 所在的整条 awk 程序解析异常 | 用**不含任何转义引号**的稳写法：`if (match($9, /gene_name "[^"]+"/)) nm=substr($9,RSTART+11,RLENGTH-12); else next`。详见 `references/awk-gtf-attribute-parsing.md` |
| 🔴 改脚本后只看 `\| tail -25` 的回执 → **stderr 里的 awk 报错被 tail 吃掉**，只剩一份"数字全 0"的干净报告 ⇒ 误判成数据问题，白烧一轮 | tail 同时截掉了错误行（错误在最前、报告在最后） | 复现类脚本一律 `> log 2>&1` 全量落盘，**先读全量**；数字全 0 时第一步就是查 stderr，不是查数据 |
| 用 `grep <symbol>` 抓基因 → 命中反义基因 | 反义 lncRNA 的 symbol 常是真基因 symbol + `-AS1` 后缀（真前缀） | 一律用 Ensembl ID |
| 拿 span overlap 当"计数风险"上报 | 口径混淆（§一） | 必须同时给 exon-level 数字，并说明「只有这部分能被 UMI 看到」 |
| 外显子**未合并**就求交 → 重叠段数虚高、数字偏大 | 一个外显子被多个转录本共享，逐块求交会重复计数 | 先按基因合并（区间排序 + 邻接合并）再求交 |
| `rail_review(post)` 判「未生成任何图片」failed，但产物是纯 BED/CSV/命令包 | 审查器按分析产出标定 | 补一张**审计索引图**（BED↔区间对照表 + 3 段重叠落点），是本类交付的真实内容，不是凑数；属**静态判定 ⇒ 不要重跑 BED 生成脚本** |
| 用户问「合作方这话是什么意思」时，顺手把某张图的改法也一起做了 | 多选表单里勾的次要项被当成主任务（用户当场纠正） | 只做与用户**当前问题**直接相关的那一件；跨主题的勾选项先确认归属，再动手（见 `platform-execution-pitfalls` 同条） |
| 合作方要「用 ATAC 统计重叠区处理前后的变化」→ 直接回「ATAC 答不了」 | 把「ATAC 答不了 read→基因 归属」错推广成「ATAC 对这个问题没用」（§〇 的 ⛔ 只针对归属题） | 走 §七：ATAC **能**答「位点是否重塑」，只需把统计单位从**基因**换成 **TSS 窗口**；回绝一个可答的问题比给错设计更糟 |
| 把 **span overlap 整段** 当成 ATAC 的统计单位 | 该段含两基因内含子 + 两侧各一个启动子，平均成一个数什么也说不清；且反义 lncRNA 转录本身就会抬高该处可及性 ⇒ **循环论证** | 拆成两个 TSS 各 ±2 kb 窗口分别统计（§七 7.1/7.2） |
| 引用刚核过的文献时不说清核到哪一层 | 用户硬要求「查证原文再答」（2026-09-01 起）；只核到标题却不声明 = 暗示读过正文 | 写「已核实（标题/刊/年/DOI 逐字）」并显式声明「**未读正文数据**」，数值到正文级之前不引用（`bioinformatics-fact-retrieval` §4） |
| 用户问「怎么跟他解释」，我交了**五层判据 + 流程图 + 判据表 + 中英长文** → 用户回「**不要太复杂，简单点**」 | 把**自证结构**当成**答复结构**：层数多 ≠ 更可信，反而像自己不确定 | 默认 **3 点 + 1 句结论**（§6.1）；分层判据与条件性论证（UMI 锚点/建库化学）留到被追问再展开；简化不删边界（§四 待确认三项仍要能立刻亮出） |

### 6.1 复杂度上限：默认 **3 点**，不是 5 层（2026-10-02 用户当场纠正）

实测事故：用户问「**你给我解释一下如何划分这两个的重合区域，也算是我要给他的解释**」，
我交了「① 链方向 ② 外显子/内含子 ③ UMI 锚点位置 ④ 唯一外显子重定量 ⑤ 参数自检」**五层判据**
（配 mermaid 流程图 + dsh-ui 判据表 + 中英双版全文），用户只回一句：**「不要太复杂，简单点」**。

- **5 层是"我的论证结构"，不是"给他的答复结构"。** 对方要的是「能不能分开、凭什么」，
  不是方法论课程；层数越多越像"连你自己都不确定"，反而削弱可信度。
- **默认骨架 = 3 点 + 1 句结论**（已验收，可直接复用，中英各一版）：
  ① **靠链分开**（A 负链 / B 正链；read 带来源链，链特异定量按链归属）
  ② **真正会冲突的窗口很小**（span 20,930 bp → 外显子级仅 422 bp / 3 段，其余内含子不计）
  ③ **数据自证没混**（一升一平：A 显著上调、B 全部不显著；若真串味应同向同幅）
  → 收尾一句：「三条独立证据指向同一结论：能分开。」
- 分层判据 / 流程图 / 判据表 / **条件性论证**（尤其 ③ UMI 锚点那条依赖 3′/5′ 建库化学）
  一律**留到被追问时再展开** —— 前置未确认就讲出来，等于自己递一个漏洞（§四）。
- **简化 ≠ 删边界**：删掉的是"层"，不是"诚实"。对方追问「凭什么这么确定」时，
  仍要立刻亮出 §四 的待确认三项（建库化学 / strandedness 参数 / `--include-introns`）。
- 附带收益：3 点的篇幅天然规避 §六 的「超长双语消息被流式截断」坑。

## 七、ATAC 侧：可及性统计的正确设计（2026-10-02 合作方设想裁定）

场景：合作方说「在 ATAC 真实数据上统计 A 与 B 的**重合区**处理前后变多变少，是不是说明处理也对 B 有影响？」

**裁定：方向对，统计单位错。** 别回绝（这是可答的问题），也别照做（会得到循环论证）。三点必须改：

### 7.1 「重合区」不能整体统计 —— 按 TSS 窗口分区

| 统计单位 | 能不能做 | 它回答什么 |
|---|---|---|
| span overlap 整段（本例 20,930 bp） | ❌ | 含两基因内含子 + 两侧各一个启动子，峰/非峰平均成一个数，什么也说不清 |
| 左界 TSS 窗口（本例 ≈88,881–88,886 kb） | ✅ | 只有 A（反义 lncRNA）的启动子 ⇒ 变化 = A 侧调控活动变化 |
| **右界 TSS 窗口（本例 ≈88,902–88,906 kb）** | ✅ | 只有 B（宿主基因）的启动子 ⇒ **这才是能回答「处理是否影响 B」的那一段** |
| exon overlap（本例 422 bp） | ⚠️ | 只占 2%，看它不如看两端 TSS |

### 7.2 循环论证陷阱（不拆开就必然踩）

反义 lncRNA **转录时 Pol II 占据该区 → 核小体置换 → 该处可及性本身就升高**。
⇒ 「A 上升」与「A 所在段可及性升高」是**同一生物学事件的两种读法，不是两条独立证据**。
整段平均 = 测到的就是 A 自己的活动 ⇒ 用它证明「处理影响了 B」= 用 A 的变化去证明 A 的变化。

拆开后才有判别力 —— 下面这张表就是合作方真正想要的东西：

| ATAC 结果 | 说明 | 结论能到哪 |
|---|---|---|
| 只有 A 侧 TSS 变 | A 独立响应，B 未被牵动 | 作用在 lncRNA 自身调控区 |
| **两侧都变** | 共享区被整体重塑 | B 启动子区被牵动（**这才支持合作方猜测**） |
| A 侧开、B 侧闭 | 转录干扰 / Pol II 碰撞 | 与「B 表达不变」有张力，需再验 |

### 7.3 结论上限与前置验证（缺一不可）

1. **可及性 ≠ 表达**：ATAC 结论只到「**处理重塑了 B 启动子区可及性**」，⛔ 不能写「说明处理影响了 B 表达」
   （开放是转录的**必要不充分**条件；还要 Pol II 起始/暂停释放、延伸、RNA 稳定性）。
2. **方向不能预设**：已核实 PMID 40623475（Mol Metab 2025，DOI 10.1016/j.molmet.2025.102206）标题层面为
   "Endurance training promotes chromatin **closure**…" ⇒ 运动后**倾向闭合**，「应该升高」不是默认值。
3. **先验 lncRNA 的定量前提**：`-AS1` 跨 583 kb、15 个 TSS、与宿主基因相反链大量重叠 ⇒ 先确认定量走的是
   **链特异性**计数（featureCounts `-s 2` 类）且信号非多重比对产物；前提不真，后面 ATAC 全白做
   （与 §四「诚实边界」同一逻辑）。
4. **文献空白即卖点**：检索 `MEF2C-AS1` 命中 6 篇全为肿瘤 ceRNA / 5q14.3 结构重排，**0 篇骨骼肌或运动**
   ⇒ 「A 变 → B 变」**没有文献支持**（反义 lncRNA 常独立受调控），只能靠证据不能靠假定。
   若 ATAC 真做出「两侧都变」，那就是该位点在运动领域的**首个**证据。

### 7.4 论证纪律（本轮的做法可直接复用）

- **先给判据、再给设计**：一句话给「方向对 / 做法要改」，随后用 §7.1/7.2 两张表把
  「能答什么 / 不能答什么 / 拆开后怎么判读」摆平，不要先铺垫文献背景。
- **说清自己核到哪一层**：引用时必须写明是**检索层**（标题/刊/年/DOI 逐字比对）还是读过了正文
  —— 本轮明确标注「未读正文数据」，这是用户硬要求（见 `bioinformatics-fact-retrieval` §4）。
- **数据来源不替用户假定**：自有运动前后 ATAC / 公共 multiome / 先验 RNA 前提，三选一**必须弹窗问**
  （`ask_user`，kind=clarify），不要顺手开跑。
