# Case Study: Self-Evolution Missed — `skill_evolution(record_run)` Gate

## Date
2026-07-29

## Trigger
CellBender 6-sample brain run completed successfully. User asked "之前的触发了吗？" — meaning the self-evolution record_run mechanism. It had NOT triggered.

## Root Cause Analysis

### The Asymmetry in SOUL.md Iron Laws

| Iron Law | Phase | Enforceable? | Why |
|----------|-------|:---:|------|
| 1-6 (skill_view, rail_review, debate...) | Pre-execution | ✅ Yes | Tool call required BEFORE analysis → LLM can't skip without being noticed |
| 7 (record_run) | Post-execution | ❌ No | AFTER analysis → skipped silently, no one notices until next session |

**The core problem**: Pre-execution iron laws are "gatekeeping" — you can't enter analysis without passing them. Post-execution iron law 7 has no gate — it's a "reminder" that LLM can forget.

### Why LLM Forgets Post-Execution Steps

1. Context saturation — after a long analysis pipeline, the "record" step is at the bottom of the priority stack
2. No enforcement mechanism — no tool blocks the next action if record_run is skipped
3. LLM's completion bias — model "closes" the task after seeing output files exist

## Fix: Iron Law 24 — Auto-Record Gate

```
terminal completes → _pending_record = True (gate LOCKED)
    ↓
agent tries next terminal → BLOCKED ⛔ "record_run first!"
    ↓
agent calls skill_evolution(action="record_run") → _pending_record = False (gate UNLOCKED)
    ↓
next terminal allowed
```

**Dual guarantee**:
- L1: SOUL.md iron law 24 (LLM-level enforcement, same tier as iron laws 22/23)
- L2: `run_log.json` disk anchor (auto-generated by pipeline scripts, survives LLM amnesia)

## Lessons Learned

1. **Post-execution steps need gates**, not just reminders. Without a gate, they're optional.
2. **Disk anchors beat LLM memory**. `run_log.json` is permanent; LLM context is transient.
3. **Self-evolution must be automatic**, not dependent on LLM "remembering" to call record_run.
4. **The six-stage loop's weakest link is Stage 6 (self-evolution)** — because it's the only stage that happens AFTER the user sees results.

## Related Iron Laws
- Iron Law 7 (original record_run rule) — kept as documentation
- Iron Law 12 (output existence verification) — record_run pre-gate
- Iron Law 24 (auto-record gate) — NEW, closes the loop
- Iron Law 23 (self-audit) — catches gate violations at end of turn
