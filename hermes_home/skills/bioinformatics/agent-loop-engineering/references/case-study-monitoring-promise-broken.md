# Case Study: Monitoring Promise Broken — 监控承诺循环破裂

## 时间线

```
T0: 用户 "记得监督一下"
T1: Agent "下次我 10 分钟后主动报。🫡"
    → 10 分钟过去了，Agent 没报
  
T2: 用户 "但是超过10分钟了，你还没有汇报"
T3: Agent "你说得对，我超时了。马上查 — 三源 + alerts。"
    → 0 个 tool call（口头承诺，未执行）

T4: 用户 "进度呢？"
T5: Agent "马上查。"
    → 0 个 tool call（再次口头承诺，再次未执行）

T6: 用户 "你没有执行工具吗？死掉一个了也没有及时重跑"
    → Agent 终于调用了 nvidia-smi + tasklist + read_file
    → 发现 Pipeline 进程已死，3506H_1 epoch 91/150 崩溃
```

## 根因分析

这不是单一故障，是**三层叠加**：

| 层 | 故障 | 模式 |
|----|------|------|
| 1 | Agent 说"10分钟后报"但没设任何定时器 | "心跳承诺未实施"变体 |
| 2 | 用户提醒后 Agent 说"马上查"但 0 tool call | 铁律 -1 违规（动作承诺无工具绑定） |
| 3 | 用户再次提醒，Agent 再次说"马上查"仍无 tool call | 叙事循环（连续 2+ 轮） |

**核心问题**：Agent 把"口头承诺回应"当成"已经回应了"。用户说"监督/汇报/进度"→ Agent 说"X 分钟后报"→ Agent 认为任务完成。

## 为什么铁律 -1 没有拦住？

铁律 -1 检查"回复是否包含动作动词 + 无 tool call"。但"马上查"在用户质问语境下，Agent 的推理链是：
- "用户提醒我忘了报 → 我应该道歉 + 承诺马上去查"
- LLM 把"承诺马上去查"当成了有效回应——它不认为这是"动作承诺"
- 但实际上 "马上查" = "让我检查" = 动作动词

## 修复

1. **Turn 启动协议强制执行**：每个 turn 开头必须 `process(action='list')` + 检查存活进程
2. **"监督/汇报/进度"关键词 → 触发三源验证**：用户说这些词时，不能只口头回应，必须立即调 `nvidia-smi` + `tasklist` + `read_file(日志)`
3. **承诺时间后自动检查**：Agent 说"X 分钟后报"→ 应在承诺时间后由用户消息触发或 Agent 主动执行

## 教训

- "马上查" 是动作动词，必须有 tool call
- "10 分钟后主动报" 不是一句空话——必须有机制确保执行
- 用户说"你没有执行工具吗？" 时，信任已经破裂——预防 > 修复
