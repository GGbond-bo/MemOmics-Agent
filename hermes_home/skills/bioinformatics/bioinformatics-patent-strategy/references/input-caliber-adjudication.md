# 输入口径判定法（input-substitution test）

> ⚠️ **2026-09-11 终局更新：本文档\"判定\"章节的结论（all 版证伪）已被用户决策覆盖**——
> 用户拍板「**改用 all**」为交付口径（理由：all 由其自有代码产出、可复现；continuous 虽能逐位复现正本，
> 但被用户视为\"修复版\"而拒绝）。**方法仍然有效，结论已过期**。改用 all 后的全套数字与交付件替换清单
> 见 `bioinformatics-patent-strategy` SKILL.md 的「口径终局」条 +
> `E:/MemOmics-Agent/results/memomics-7839e23a/results/ALL版替换对照表.md`。
>
> **本条带来的方法论修正（重要）**：三列对账表判\"哪版复现正本\"只回答**统计归属**，回答不了**该用哪版**——
> 后者还要叠加用户的**可复现性 / 血缘可信度**诉求。二者冲突时，用户可能宁可牺牲与正本的一致性，
> 也要选\"自己能跑出来的那版\"。因此对账跑完**必须把「统计归属」与「建议采用」分开陈述**，
> 并明确提示换口径的连带代价（本次 = 核心元件名单换血 53%、v6 promoter-CRE 置换 p 0.0000→0.261 失效）。

**何时用**：交付物（专利/论文/报表）已有"正本"汇总数字，磁盘上却存在 ≥2 份候选输入文件
（同名或近名 CSV，如同名 `monkey_ageDA_*.csv` 行数与首行坐标不同），需要判定**正本数字到底
由哪份输入产生**——而不是靠文件名、时间戳或"哪个看起来更对"来猜。

**与逐基因比对的分工**：逐基因一致性检验（Z 值逐行比对）能判"两份表是不是同一份输入"，
但回答不了"哪份输入产出正本**汇总**数字"；后者最硬的证据是**换输入跑全流程 → 三列对账**。
两者互补：逐基因比对定位差异位置，全流程对账判定汇总口径。

## 步骤

1. **固化一条端到端流水线脚本**（输入路径参数化），一次跑完 M3→M7 出全部汇总数字
   + `REPRO_SUMMARY.md` 对账报告（每次换输入只是换一个参数/输出目录）。
2. **候选输入各跑一遍**，输出目录分开、日志名分开（避免同日志名 `Device or resource busy`），
   各产出 `stats.json`。
3. **建三列对账表**：`指标 | 正本 | 候选A | 候选B`。行至少含：ortholog 对 / A / B / C / D /
   置换均值 / 置换 p / 加权 ρ（缺一行都可能漏判）。
4. **判定规则（按证据强度排序）**：
   - 🔴 **效应量列（A/B/C/D）相对偏差**：任一候选出现 >5% 相对偏差即淘汰；正本候选应落在 ≤1%。
   - 🔴 **相关系数（ρ）逐位一致**：ρ 是全局统计量，最敏感也最难巧合一致；同位数 ≫ 其他指标吻合。
   - 🟡 **置换均值/零分布位置**：是输入分布的指纹，对口径变化极敏感；差 <1% 是正本信号。
   - 🟢 **行数（ortholog 对）只作辅助**：受下游过滤影响，**不能单凭行数判口径**。
5. **残差归因法（关键）**：把残差与"换输入后残差的变化量"比较——
   - 换输入只让残差从 −21 变 −19（变化 2）→ 残差主体来自**下游步骤**（桥接/去重/阈值），不是输入表；
   - 残差随输入大幅变化 → 才归因输入表。
   不要看到"没跑出一模一样"就回头怀疑输入口径。

## 实测样本：专利 v5 双口径 M3→M7 对账（2026-09-11）

| 指标 | 正本 | all 版（1-based, divideN） | continuous 版（0-based） |
|------|------|---------------------------|--------------------------|
| ortholog 对 | 16031 | 16010 | 16012 |
| A 保守·可替代 | 1904 | **2335（+22.6%）** | 1905 |
| B 反向 | 3487 | 3070 | 3474 |
| C 单侧 | 7562 | 7677 | 7554 |
| D 无 | 3078 | 2928 | 3079 |
| 置换均值 A | 2012.71 | 2617.14 | 2011.42 |
| 置换双侧 p | 0.0008 | 0.0000 | 0.0006 |
| 加权 Spearman ρ | −0.081 | **−0.195** | **−0.081** |

**判定**（仅为**统计归属**判定，非最终采用结论——最终用户选 all，见文首）：all 版**与正本不符**（A +431、ρ 劣化一倍余、零分布位置偏 30%）；continuous 版**与正本一致**（A 差 1、ρ 逐位一致、置换均值差 1.29）。
M6 侧同向复现：正本 `15178 / 402 / 222·5840·8714` ↔ continuous `15182 / 404 / 223·5841·8714`。

**残差**：16031→16012（−19，0.12%）。换输入只让残差由 −21 变 −19 →
残差来自 **M3 桥接步骤**（ortholog 表版本 / 去重口径 / tile-hit 阈值），不影响任何结论
（A 只差 1、ρ 完全一致）。

## 与用户沟通的写法（用户偏好）

- 用户坚持"用我给你的文件"时**不要争辩、不要解释坐标/归一化道理**——**直接跑对账表**。
  数据出结论比论证有力：本次跑完，用户当场接受"all 版证伪、矛盾消除"。
- 结论段固定四段结构：① 三列逐项对账表 → ② 判定（候选X证伪 / 候选Y确认，各附数字理由）
  → ③ 残留缺口（多少、来源归因、是否影响结论）→ ④ 下一步 **2 选 1**（做完 vs 定稿）+ 明确建议项。
- 残留缺口再小也要单列并给归因：**"可复现"是专利/交付附件的硬指标**，0.12% 的残差也要有解释，
  不能含糊成"基本一致"。

## 反模式

- ❌ 只用行数 / 文件时间戳判定正本 → 同名文件差 2 行就可能骗过。
- ❌ 只做逐列/逐基因比对、不做全流程对账 → 回答不了"哪份输入产出正本汇总数字"。
- ❌ 判定后立刻改文档/改数据 → 必须先把两选项摆给用户拍板（沿用 336 vs 37 的惯例）。
- ❌ 跑出一个候选不吻合就下"数据不可复现"结论 → 先跑第二个候选，正本往往在另一侧。
