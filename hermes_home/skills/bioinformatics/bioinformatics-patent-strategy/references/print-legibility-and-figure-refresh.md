# 附图缩印可读性修复 + 图源变更后 docx 重出（图文一致性四期）

> 来源：跨物种衰老可替代性专利（memomics-7839e23a，2026-09-12，v15）。
> 一期管「图有没有内容」、二期管「源图有没有重出」、三期管「图里的东西是不是真的」——
> **四期管「缩印后还看不看得清」**。三期全过（图有内容、已重出、无伪曲线无遮挡）的图，
> 仍可能在 A4 纸尺寸下糊成一团。本次即此情形。

## 触发场景

用户上传渲染图并说这类话时启用：
- 「这张图修改一下，**看不清楚**，**一堆小点点**，**干净一些**」
- 「图太小了看不清 / 印出来是灰的 / 框里的花纹糊了」

## 1. 根因：黑白线条版的填充图案在缩印后退化成灰块

`patent/figures_bw/` 的合规性来自「彩色像素 = 0.000%」——但**合规 ≠ 可读**。
为了让黑白图仍能区分系列，脚本常用影线填充：

```python
ax.barh(..., hatch='///')   # 基线①
ax.barh(..., hatch='xx')    # 基线②
ax.barh(..., hatch='..')    # 基线③
```

问题不在影线本身，而在**用错了地方**：

| 图的性质 | 影线有没有必要 | 处置 |
|---|---|---|
| **单链流程图**（方框靠 ①②③④⑤ 序号区分先后） | ❌ **纯冗余**——序号已经把信息表达完整 | **删除填充，改纯白底黑框 + 反白标题条** |
| **多系列对比图**（基线①②③ vs 本方法，同轴并列） | ✅ 必要——黑白下没有颜色只能靠图案 | **保留**，但优先改用「线型 + 空心/实心标记」替代点纹/交叉纹 |
| 直方图空分布（实心灰 + 本方法黑柱） | 可用 | 保留粗影线，或用灰度区分度更明确的实心/空心 |

**关键判据**：问「这个图案在替我表达什么信息？」——若答案是「没有，只是好看/默认」，删。

## 2. 修法（本次实际改动）

1. **5 个流程方框统一为纯白底黑框**，删除 `hatch` 参数与任何浅灰 `facecolor`；
2. **标题条改反白**（黑底白字）——用明暗对比承接线序，不靠图案；
3. **字号同步上调**：方框标题 10.5 → 11.5 pt，方框正文 8.4 → 9.4 pt；
4. 在脚本里留一行变更注释，防后人「优化」回去：

```python
# 主体框：纯白底黑框（v15 修订：去填充图案——缩印后点纹/交叉纹糊成灰块，看不清）
```

## 3. ⭐ 客观验收：双指标量化「可读性」，不靠肉眼

肉眼评「清楚了没有」无法进验收脚本。用下面两个可复现指标替代，**改前改后各测一次**：

```python
from PIL import Image
import numpy as np
a = np.asarray(Image.open(p).convert("RGB"))
ink   = float((a.mean(axis=2) < 250).mean())          # 墨迹占比（非白像素）
color = float((a.max(axis=2).astype(int) - a.min(axis=2).astype(int) > 12).mean())  # 彩色像素
print(f"尺寸 {a.shape[1]}x{a.shape[0]} | 墨迹 {ink:.4f} | 彩色 {color:.6f}")
```

本次实测（3129×1122）：

| 指标 | 改前（带点纹） | 改后（纯白底） | 判读 |
|---|---|---|---|
| 墨迹占比 | **0.1977** | **0.1565** | ↓ 21%，图案墨迹被去掉 |
| 主色 #e0e0e0（白桶）占比 | 61.9% | **71.0%** | 白底变干净 |
| 中间灰 #c0c0c0 / #a0a0a0 / #808080 | 14.0 / 9.0 / 4.6% | 8.3 / 8.2 / 2.4% | 灰块显著减少 |
| 彩色像素 | 0.000% | 0.0000% | 黑白合规未被破坏 |

**OCR 侧指标**（`vision_describe`，同一张图改前改后各跑一次）：

| | 改前 | 改后 |
|---|---|---|
| 识别文本条数 | 12 条 | **23 条** |
| 关键框文字置信度 | 0.53–0.98，出现乱码（`MA`、`置换定减+分级`） | **0.98–1.00**，五个框标题 + 副标题全部正确读出 |

⇒ **验收判据：墨迹占比下降 + 白底占比上升 + OCR 条数/置信度上升，三者同向才算「变清楚了」。**
只报「我改干净了」不算。

## 4. 图源变更后：docx 必须重出，且探针会立刻报 FAIL（这是设计意图）

验收脚本（如 `17_verify_v15.py`）里有一条：

```python
chk("① 内嵌图字节 = 黑白版源文件（证明确用黑白图）", _bw == _emb, ...)
```

**源图一改、docx 未重出 → 这条断言立刻 FAIL**（本次 273,564 B vs 245,274 B）。
- ✅ 正确处理：**重跑成文脚本**（`16_gen_disclosure_docx_v15.py`，其 `FIG` 常量指向 `figures_bw/`）→ 重跑验收 → 恢复 48 PASS / 0 FAIL。
- ⛔ 不要把它当成探针 bug 去改断言——它正是「源图改了但正文 docx 没跟上」的报警器。
- 收官必做：解包 `word/media/*` 与 `figures_bw/*.png` 做 **SHA256 逐字节比对**（本次 5/5 全等）。

## 5. ⛔ 不要用「文件大小没变」判断 docx 有没有被替换

本次踩坑：v15 docx 由 WPS 打开保存过一次，字节数 **1,452,866 → 1,217,101 B**，
但**内嵌的 5 张图全部被换成了 `figures_bw/` 的新版**（压缩与冗余被 WPS 重排）。
⇒ 判定「docx 里是哪一版图」**只能**靠解包比对字节/SHA，任何基于文件大小、mtime 的推断都不可靠。

## 6. 「文件被占用」的判定：改名测试是决定性判据

`~$xxx.docx` 存在 + `open(path,'r+b')` 抛 `PermissionError: [Errno 13]` 时，
**不能直接下结论「文件被锁，等用户关闭」**——本次该结论错了，白等一轮。

| 测试 | 结论 |
|---|---|
| `mv <docx> _tmp.docx` **成功** | **无真锁**（`~$` 是 0 字节残留孤儿，WPS 已退出或从未独占）→ 直接继续写 |
| `mv` 失败（PermissionError / 共享冲突） | 真锁，需用户关闭编辑器 |

配套动作：改名成功要**立刻改回原名**（`mv _tmp.docx <docx>`），再做写测试 `open(p,'r+b')`。
本次改名成功后写测试即通过，`~$` 文件零字节证实为残留。
