# 成稿自洽性自审执行手册

> 配套 `cn-degree-thesis-writing` 铁律 6。稿子写完（或用户说"检查一下""跑一轮拷问""有没有问题"）时执行。
> 来源：2026-09-16 硕士学位论文第 1 章+第 3 章实审，**一次审计击破 2 处硬伤**。

## 为什么先跑这四类

成稿最致命的漏洞**不是文风，而是数字与引文自相矛盾**。这类漏洞有两个特点：

1. **能靠独立重算当场击破**——不需要任何外部数据，只用稿子自己报的数字；
2. **杀伤力最大**——审稿人拿起计算器就能验，一旦被抓，全文可信度一起崩。

而且它们在"自己写的稿子"里**几乎必然出现**（人写数字链时不会自己反算）。上一轮实测的两处硬伤都属于
「**论文自己的数据推翻了论文自己的结论**」级别——不是小瑕疵。

## 四类审计

| # | 审计 | 怎么做 | 2026-09-16 实测命中 |
|---|------|--------|---------------------|
| 1 | **算术自证** | 把文中「显著高于/低于 X」的 X **用文中自己的边缘总数重算一遍** | 原文称「150 显著高于三条件独立期望」。实算 16 029×19.8%×64.9%×8.79% = **181** → 150 其实**更低**，方向反了。换基准（1 604×8.79% = 141）也只高 6.4%，且**无任何统计检验**，「显著」无从谈起 |
| 2 | **因果自洽** | 文中给的**机制解释**能否推出它报的**方向**？再用文中另一处数字反验 | 原文用「三层证据正相关」解释交集偏大；但实测 L1∧L2 = 1 604 **低于**两者独立期望 16 029×19.8%×64.9% = **2 064** → 实际**负相关**。**论文的数据推翻了论文的解释** |
| 3 | **计数对账** | 分母 − 分子 = ? 各处组数/条数能否闭合；"大多数"这类措辞是否属实 | 表 3.4「落入区间 **19 组**」+ 正文「**18 组**（即大多数）落在区间之外」→ 175−19 = **156**，且 18 是少数不是多数。全库 grep「156」**0 命中**，说明数字根本没进正文 |
| 4 | **引文-论断对齐** | 统计每个 `[n]` 的被引次数，**≥2 次的逐处读上下文**，看同一文献是否在支撑互不相干的论断 | `[7]` 被引 5 次、`[9]` 4 次、`[15]` 4 次。逐处读发现 `[9]`（Zhang X, *Cell* 2026 食蟹猴脑图谱）被同时挂到三类论断：① 人脑取样受伦理约束（❌ 不是该文献的内容）② liftOver 坐标迁移（❌ 与比较基因组学无关，明显错引）③ 猴脑图谱本身（✅） |
| 5 | **原文核对具体数字**（有全文时必做） | 拿**已下载的原文全文（PMC XML / PDF）**逐字核验文中引用的具体数字，**别信记忆** | 「约 160 万个细胞核、142 个皮层区域」→ 对原文摘要 `snATAC-seq for ~1.6 million cells from 142 cortical regions of two male cynomolgus monkeys` → ✅ **通过**（顺带发现可补"2 只雄性"更准确） |

## 批量扫描 Python 模板

一次性跑完，**不要一轮一条地挤**（同类只读调用连打会被判循环失控，见 `platform-execution-pitfalls`）。
落成 `.py` 用 `execute_python: exec(open(r'<路径>', encoding='utf-8').read())` 跑
（**脚本内不要用 `__file__`**，exec 不注入该变量）。

```python
import re, os
d = r"<论文目录>"
txt = open(os.path.join(d, "论文.md"), encoding="utf-8").read()

# ① 数字一致性：全文关键数字出现次数（口径不一致会露头）
for n in ["16 029", "3 180", "1 604", "1 409", "10 401"]:
    print(f"{n:10s} x{len(re.findall(re.escape(n), txt))}")

# ② 取某数字的全部上下文（判断是否同一对象的两种名字）
for m in re.finditer(r"1 604", txt):
    print("...", txt[max(0, m.start()-110):m.start()+70].replace("\n", " "))

# ③ 引文频次（≥2 次的必须逐处读上下文）
from collections import Counter
sec = txt.split("# 第1章")[1].split("# 第2章")[0]      # 限定章节，避免全文噪声
cnt = Counter()
for m in re.finditer(r"\[([\d,\s]+)\]", sec):
    for x in m.group(1).split(","):
        if x.strip().isdigit(): cnt[int(x.strip())] += 1
for k, v in sorted(cnt.items()):
    if v >= 2: print(f"[{k}] 被引 {v} 次")

# ④ 【待填】清单：按小节归组（交付时直接改写成清单表格）
cur, hits = "", {}
for i, ln in enumerate(txt.split("\n"), 1):
    m = re.match(r"^#{1,4}\s+(.*)", ln)
    if m: cur = m.group(1).strip()
    if "【待填】" in ln: hits.setdefault(cur, []).append((i, ln.strip()))
for s, v in hits.items():
    print(f"### {s} ({len(v)} 处)")
```

**算独立性期望的写法**（审计 1/2 用）：

```python
n, L1, L2, L3, core = 16029, 3180, 10401, 1409, 150
p1, p2, p3 = L1/n, L2/n, L3/n
print("全独立期望 =", round(n*p1*p2*p3, 1))        # 181.4 → 实测 150 更低
print("L1∧L2 独立期望 =", round(L1*L2/n, 1))        # 2063.5 → 实测 1604 更低 = 负相关
```

## 报告纪律（决定报告能不能被采纳）

1. 🔴 **必须同时报「已核验通过」的项**。只列问题 = 全盘否定，作者会连真问题一起怀疑。
   固定加一节 **「✅ 这些不要动」**，把算对的、引对的逐条列出（实测：160 万/142 区、逐级收缩链、
   0.94%/8.8%/32%/175 五个算式全部算对，都应明确确认）。
2. 🔴 **不做无证据的「看起来不对」**。每条弱点都要带**重算数字或原文引文**；
   只有怀疑没有算式 → 放进「未决问题」，**不要**放进弱点清单。
3. 🔴 **先算再下结论，防误报**。怀疑两处数字矛盾时先分清是不是**同一对象**——
   实测差点误报：`L3 单独通过数 1 409` 与 `L1∧L2 = 1 604` 是两回事（后者已在正文定义为 L3 判定前一步），
   **不是**矛盾。**误报一条比漏报三条更伤信用**。
4. **成本面给两条路**：补统计支撑常比改文字贵 → 给「A 零成本改写（推荐）/ B 补检验（可后续，可复用已有
   `nperm=5000 / seed=42` 置换框架）」并说清代价差，让用户裁决。
5. **弱点按严重度分级**：🔴 致命（论断错/算术错，必改）/ 🟠 严重（引文张冠李戴、新颖性声明缺检索范围）/
   🟡 一般（表缺出处、编号不对应、内容重复、过度概括）。
6. **语气对事不对人**：即使作者是用户自己，也只说"这一句的方向反了、重算数字是 X"。

## 依赖外部信息时的处理

弱点常牵出「需要作者才能补」的项（检索式与日期、样本 23 vs 20 的差值原因、参考基因组版本号）。
这些**不要自己编**——归入「未决问题」并向用户提问，与铁律 5（【待填】）同一原则。
