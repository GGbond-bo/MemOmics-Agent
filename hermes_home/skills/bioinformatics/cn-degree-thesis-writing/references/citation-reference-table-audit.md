# 文献表 ↔ 正文 双向一致性核查手册

> 来源：2026-09-16 吉林大学硕士学位论文（54 条文献表）全量核查。
> 配套脚本：`scripts/audit_citations.py`（可直接复跑）。

## 0. 触发时机

- 论文/报告**定稿前**（交付 DOCX 前必跑一次）
- 用户说「检查一下」「文献有没有问题」「引文核查」「跑一轮核查」
- **任何一条文献被新增/删除后**（编号会顺延，必须复跑）
- 与「铁律 6 自洽性自审」同批做，两者互补：
  - `manuscript-consistency-audit.md` 管 **引文 ↔ 论断**（挂错地方）
  - 本手册管 **引文 ↔ 文献表**（挂不上 / 多出来）

## 1. 为什么必须全量核查，抽样或快速正则都不算数

"快速正则只找 `\[\d+\]`" 会同时**漏掉三类真实引用**并**制造一类幻影引用**，两个方向都会得出错误结论：

| 类型 | 例 | 只找 `[\d+]` 的后果 |
|---|---|---|
| 漏 | 区间 `[28-31]` | 28/31 被当成未引用 |
| 漏 | 逗号 `[9,16,17]` | 整体匹配不上 |
| 漏 | 连排 `[35][36]` | 部分漏 |
| **幻影** | 数值区间 `[30, 500]` | 被读成 `[30]` + `[500]` |

**实测代价**：快速正则报「15 条未被引用」，全量核查后真孤立只有 **10** 条；同一份稿子里 `[30, 500]`（目标区间）被数出 **13 次幻影命中**，凭空报出一个 `[500] 超范围引用`，并把真引用 `[30]` 的计数从 2 虚增到 15。

🔴 结论：**报数前必须跑脚本，不准用肉眼或简易正则下判断。**

## 2. 核查算法（4 步）

1. **抽文献表定义行**：`^\[(\d+)\]\s+(.+)$`
2. **正文扫描前先剔除定义行**（否则文献表会把自己当正文引用）
3. **引用展开**：`\[([\d,\-–—\s]+)\]` → 按 `,` 切分 → 每分量再按 `-–—` 展开区间（加 `b-a<60` 防跑飞）
4. 🔴 **假阳性过滤**：方括号内**任一分量 > 文献表最大编号** → 整个括号判为**数值区间，不是引用**
   （`[30, 500]`、`[10, 1000]`、`[1, 100]` 这类。）

**输出三张单子**：孤立文献（有定义无引用）／超范围引用（有引用无定义）／缺号（编号不连续）。
退出码：0 = 双向对齐；1 = 存在孤立或超范围（便于串进交付流水线做门禁）。

**兜底盘点**：中文稿可能出现全角 `［］`，用 `[\[［][^\]］]{0,30}[\]］]` 扫一遍含数字的方括号并计数，
确认半角正则没有漏掉任何形式；同时人工扫一眼列表里有没有 `[图 3.2 …]` 这类**图表夹注**被误当引用。

## 3. 孤立文献的三分类处置（🔴 不要为凑对齐硬塞引用）

| 情形 | 判据（用工具实查，不靠印象） | 处置 |
|---|---|---|
| ① 正文写了该事物但没挂号 | grep 到该工具／数据集／专利名确实出现在正文 | **在首次出现处补号**（而非删条目） |
| ② 全文 + 素材包零提及 | grep 论文各分部 **+ 原始素材包**，均 0 命中 | **删条目**，其后编号整体顺延；删完复跑核查 |
| ③ 对比文件用 D1–D5、文献表用 `[35]–[39]` | 两套编号并存，读者对不上 | 表首列**并列两种编号**（`D1 [35]`），把映射钉死 |

🔴 判定 ② **必须实查原始素材包**，不能只看论文正文。若真实流程里做过该步骤（只是正文没写），
正确动作是**补写该步骤并保留引用**，而不是删文献表条目——这类判定吃不准就问用户，别自己拍。
（实测：`[54] CellBender` 正文与素材包双双零提及 → 删条目、原 `[55]` 顺延为 `[54]`；
但正因为不能确定"用户流程里到底跑没跑"，处置后**主动回报并请用户确认**。）

删条目后要顺手检查：正文里有没有引用已删编号、参考文献分节标题下的条目数是否还自洽。

## 4. 著录信息双源核验（卷/期/页一律不得采信粘贴或记忆）

```python
# Crossref —— 卷/期/页/作者
urllib.request.urlopen('https://api.crossref.org/works/' + doi, headers={'User-Agent': ...})
#   → message.volume / message.issue / message.page / message.author / message.issued

# Europe PMC —— 交叉验证 + 拿 PMID
'https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=DOI:"<doi>"&format=json&resultType=core'
#   → journalInfo.volume / journalInfo.issue / pageInfo / pmid
```

- **两源一致才著录**；两源不一致 → 再找第三源（出版社页／PubMed 记录）裁定。
- **与用户所给不一致 → 以实证为准，并在回复里点明这处出入**（不要悄悄改，也不要照抄错的）。
- 实测：用户给 `38(18): 4639-4642`，Crossref 与 Europe PMC **均为 38(19)** → 按 `38(19)` 著录并回报。
- DOI 存疑时用 `10.1093/xxx/btac562[doi]` 走 PubMed 反查，确认条目真实存在再收录。
- 电子资源条目（`[DB/OL]`）**必须有 URL**；只有机构名没有地址 = 著录不合格，补 URL 或改著录类型。

## 5. 批量改稿的原子落盘（防漏改 / 防同文件并发互相覆盖）

一处一轮手改，在"同文件多处 + 跨文件"的修订里既慢又必然漏。用一个脚本一次落盘：

```python
EDITS = [(filename, old_text, new_text), ...]      # 三元组列表
cache = {}
for fn, old, new in EDITS:
    p = os.path.join(BASE, fn)
    txt = cache.setdefault(p, open(p, encoding='utf-8').read())
    if txt.count(old) == 0:                        # 🔴 断言命中
        print('❌ 未命中:', fn, old[:60]); sys.exit(1)
    cache[p] = txt.replace(old, new)
    print('✅', fn, '<-', old[:50])
for p, txt in cache.items():                       # 每文件只写一次
    open(p, 'w', encoding='utf-8').write(txt)
```

三个要点：
1. **断言 `count(old) > 0` 否则整脚本退出** —— 未命中就报错，绝不静默跳过（"以为改了其实没改"是最贵的一类 bug）。
2. **按文件缓存、最后统一写回** —— 避免同一文件被并发编辑互相覆盖，也避免重复解析。
3. **逐条打印 ✅/❌ + 替换前后片段** —— 便于回读核对，且日志本身就是交付证据。

改完必须**复跑核查脚本**（编号顺延过的稿子尤其），确认双向对齐后才重新出 DOCX。
