## 一、派生变体脚本：断言式字符串替换（不重写、不污染主图）

**为什么不用 write_file 重写**：全量重写会漂移版式（标签位置/几何/配色），且无法用 diff 证明
「除星号判据外零改动」。断言式替换把「只改了这 5 处」变成可验证事实。

```python
import io
SRC, DST = "scripts/fig_A2_5effects_v4.R", "scripts/fig_A2_5effects_v5_rawp.R"
s = io.open(SRC, encoding="utf-8").read()

def rep(old, new, n=1):
    global s
    c = s.count(old)
    assert c == n, "MATCH FAIL(%d!=%d): %r" % (c, n, old[:70])   # 命中数不符即中止
    s = s.replace(old, new)

rep(...)   # 逐处替换，每处一次调用
io.open(DST, "w", encoding="utf-8").write(s)
```

### 5 处改动对照表（本次实测）

| 处 | 校正版（v4） | 探索版（v5） | 备注 |
|---|---|---|---|
| 星号矩阵 | `QM <- tapply(eff$q, ...)` | `PM <- tapply(eff$p_np, ...)` | 同一张交付表的两列，故两版除判据外完全可比 |
| 判据 | `stq <- star_Q[...]`；`if (stq < 0.05)` | `stp <- star_P[...]`；`if (stp < 0.05)` | **变量名必须同步改**——留着 `star_Q` 装 raw p 就是「名字说 A 实算 B」 |
| 图注 | `* FDR<.05 (BH/effect)` | `* uncorrected p<.05 (Mann-Whitney U / Wilcoxon signed-rank; FDR NOT applied - exploratory)` | 见 §三 模板 |
| 输出/交付名 | `..._v4` / `FigA2_program_5effects.*` | `..._v5_rawp` / `FigA2_program_5effects_rawp.*` | **独立交付名 = 绝不覆盖校正版** |
| QA 打印 | 只打 q 计数 | 同时打 raw p 与 q 计数（对照） | 分母用代码算（见 §六） |

⚠️ 若原脚本的收尾是「拷贝到根目录交付位 + 先归档旧文件」，派生时**必须把归档那段换成独立命名**
（`DELIV = "FigA2_..._rawp"`），否则探索版会顶掉校正版的交付位。

## 三、图注模板（对应画图规范「显著性符号必须写清：误差/检验/校正/符号定义」）

**English（可直接贴论文）**

> **Figure X (exploratory, uncorrected).** … Cell color encodes the standardized effect size
> (Hedges' *g* for independent contrasts, *d*<sub>av</sub> for paired contrasts; positive = higher in
> the second group of each label). **Asterisks mark uncorrected *p* < 0.05** (Mann–Whitney *U* test for
> independent contrasts, Wilcoxon signed-rank test for paired contrasts); **multiple-testing correction
> was NOT applied in this panel — it is exploratory and hypothesis-generating only.** n = 24 donors
> (…). Effect sizes and the corresponding Benjamini–Hochberg *q* values are provided in
> `<表文件名>`; the FDR-controlled version of this panel is `<校正版文件名>`.

**中文对照**：星号为**未校正** p < 0.05（独立比较用 Mann–Whitney U、配对比较用 Wilcoxon 符号秩）；
**本面板未做多重检验校正，仅作探索性/假设生成用途**。校正版见 `<文件名>`。

四要素缺一不可：**未校正声明 + 检验名 + 校正状态 + 探索性定位**；再补 n 与效应量类型。

## 四、风险量化文档（必须随图交付）

只写「未校正」不算披露。文档至少含：**图注原文 + 每效应风险表 + 可检出性下限 + 使用规则 + 复现命令**。

风险表列：`效应 | 图上实绘星号数 | 同格数下校正版 q<0.05 | π0 | 纯噪声下期望假阳性 | 判读`

- **期望假阳性 = π0 × α × m**（m = 该口径下的检验格数）
- 判读规则：**观测 ≪ 期望 ⇒ 该栏纯噪声**（⛔ 不可解读为效应）；观测 ≫ 期望 ⇒ 真信号主导
- ⚠️ **两个分母都要写明**：图上实际绘制格数（本例 17 program × 10 subtype = **170**）
  ≠ 检验族格数（22 × 10 = **220**，多出的 50 格是未纳入该图的程序）。族名/分母混用 = 口径事故。

使用规则（硬性，抄进交付文档）：① 正文与图注同时声明未校正 / exploratory；
② 禁止用于临床、因果、生物标志物确证，禁止与校正版混排比较；③ 论文主图建议用校正版，
本版作补充材料；④ 引用本图必须连同风险表一并提供，不得只给图片。

## 五、噪声主导栏的视觉区分（**建议**项，最终由用户拍板）

π0 ≈ 1（观测 ≤ 期望假阳性）的效应栏，**建议**用空心星 / †角标 / 灰化区分，并在图注写明「噪声主导栏」。

理由：读者默认把星号读成「FDR 显著」，**仅靠图注文字不足以抵消**（缩略图、灰度打印、跨版本并排时尤甚）。
最有力的说服证据不是「引用规范不允许裸标」，而是**用户自己的数字**：
本例 T2D 的 raw p<.05 格数（6）**低于纯噪声期望（10.6）** ⇒ 裸标等于在图上凭空造 6 个空信号。

🔴 **但这是用户的决定 —— 摆 `ask_user` 让他选，⛔ 不要自己决定后直接出图，也⛔ 不要在他否决后反复劝。**

**实测结局（2026-09-28）：用户看过风险量化后选了「A. 保持现状（全部实心星号，不加区分）」。**
⇒ 按**零改动交付**处理：不改脚本、不重跑、不覆盖任何文件（v5 本就是实心星号，选择 A = 无需任何动作），
改由下面四条承担误导风险，缺一条都不行：

1. **图注四要素齐全**（未校正 + 检验名 + FDR 未应用 + 探索性定位）—— 见 §三
2. **风险量化文档随图交付**（π0 / 观测量 / 期望假阳性 / 判读）—— 见 §四
3. **汇报时显式点名噪声主导栏**，把判读直接写进正文：「T2D 的 2 颗星低于纯噪声期望 8.2，该栏星号纯属
   偶然，不得解读为生理效应」—— 图上不做区分，就靠这句话挡误读
4. **校正版并存可随时切回**（用户改主意时零成本）

⚠️ 用户选 A 后**不要再重开这个话题**（知情选择已成事实）；也⛔ 不要把"没做视觉区分"讲成"已做区分"。

## 六、自查项：计数打印的分母

QA 打印里把分母写成常量族大小（220），而实际绘制格数 = 17 × 10 = 170 —— 与「变量名说 A 实算 B」
同一类错。⇒ **任何计数打印的分母都用代码算当前对象维度**：
`m <- length(which(startsWith(colnames(PM), paste0(e, "|")))) * length(PROGRAM)`，不写常量。

## 七、辩论裁判失败时，如何榨取辩论的价值

门控要求辩论、而 **judge 那一路失败**（路由被标记近期失败 / 预算耗尽 / 超时）时的处置：

- L1 失败 → 引擎回填（`decision_source: engine_backfill`、`confidence: low`、`verdict: need_more_info`）；
  **失败重试 ≥2 会把门控升级到 L2** —— 照跑，但不要为「刷出裁决」反复重投。
- L2 也可能只差裁判一路（本次 7/8 席位返回）。**席位论点仍然可用**：pro/con 各自独立调用、互相看不到对方，
  因此「多席位重复提出同一条要求」是很强的信号。
- **场景分类器的 `rubric_keys` 就是交付检查清单**（本题面为 stats_design）：
  multiple_testing_integrity / exploratory_positioning / annotation_sufficiency / visual_nonmisleading /
  delivery_governance / evidence_traceability / **risk_quantification**。
  逐条自查并把重复出现的要求落实（本场席位共识：噪声栏视觉区分**建议** + 族口径写明 + 版本治理；
  ⚠️ 事后用户否决了视觉区分那条 —— **席位共识是输入不是决定**，最终以用户拍板为准，见 §五）。
- 汇报如实写「judge 失败、无正式裁决，以下按席位共识执行」—— 不要包装成有裁决，也不要因裁判失败丢掉整场。

## 九、收尾两种形态：零改动收尾 vs 收尾纪律（2026-09-28 实测踩坑）

出完图到定稿之间，用户还会拍板 1–2 个版式取舍。这时的**收场方式**本身是个坑位。

### 9.1 「保持现状」= 零改动交付，不是新一轮执行

用户勾「A. 保持现状」时：**产物已经满足该选项** ⇒ 只做三件事，⛔ 绝不重跑：

1. **核验磁盘**：`ls -la` 全部相关产物（含交付位 + 版本位 + 风险文档），确认**非空 + 时间戳**
2. **显式声明零改动**：「本轮唯一改动 = `task_plan.md` 追加一行收尾决策；无新图、无新表，净产物为零，
   属确认型收尾」—— 见 `deg-mixed-design` §核心原则 7
3. **写进 `task_plan.md`**：在该 Phase 下追加 `[x]` 收尾决策行（含勾选项 + 该选择意味着什么 + 星号计数），
   否则下个会话会把同一个版式问题再问一遍

⚠️ **不要为了"响应"而重跑**：白烧算力，且新产物与已核验版本之间产生版本歧义。

### 9.2 回合收尾纪律：⛔ 不许以正文问句结尾（本场真实事故）

**事故经过**：图 17:43 已出完落盘；我把「T2D/ExT2D 要不要视觉区分」写成**正文末尾的问句**收尾。
用户下一轮：「**你到底在干什么？这么久不出结果**」—— 他把没有结论的回合读成了"卡死/没产出"。

**正确收尾模板**（顺序不可换）：

```
① 判决句：       「A 已生效 —— v5 无需任何改动。」（第一行就给结论）
② 交付事实：     路径 + 字节数 + 尺寸 + 星号计数（让"已完成"不可误读）
③ 零改动声明：   「本轮无新图/无新表，只更新了 task_plan.md 一行」
④ 风险提示：     图上未做区分 ⇒ 引用必须带「uncorrected」图注；点名噪声主导栏的实际数字
⑤ 待决项：       仅当确有未决项时 —— 且必须走 ask_user（带选项），⛔ 不用正文问句
```

**被质问「你在干什么 / 怎么这么久」时的应答纪律**：

- **第一步是核验磁盘，不是解释**：`ls -la` 产物 + 时间戳；用 `vision_describe` 证明图非空（尺寸 / 面板名 /
  程序名 / 色标 OCR 可读）；然后**逐项列表汇报「文件 / 大小 / 时间」**
- ⛔ 不要凭记忆复述"我做了 X"——用户要的是「产物在哪、能不能用、为什么我以为卡住了」
- **主动认领沟通失误**（"我把版式取舍写成了正文问句，看起来像没下文 —— 图本身没有延误"），
  但⛔ 不要把"图已出好"说成"还在跑"
- **顺手核实系统提示的路径告警再转述**：本场系统报 `pathway_score_CLEAN_v3.xlsx` 不存在，
  实测**存在**（20,126 B，9月15日 19:30）⇒ 转述前先 `ls -la`，⛔ 不要把误报当事实传给用户平添动作。
