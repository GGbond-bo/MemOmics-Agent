# 按高校规范撰写学位论文并交付 DOCX

## 何时用

- 用户说"我要写毕业论文 / 学位论文"，并给出**学校的规范文件**与**写作素材**（专利交底书、项目结果、素材包）。
- 用户说"按硕士格式 / 按我们学校的要求"。
- 已交付论文需按规范修订或出下一版。

**不适用**：给论文做语言润色（走 `paper-polish`）、投稿前审稿视角体检（走 `pre-submission-reviewer`）、生成纯 PDF 报告（走 `pdf-report-generation`）。

## 铁律（先说三条，违反即返工）

1. **先读完全部规范附件再动笔。** 学校通常给一主件 + 若干附件（封面/扉页、声明页、参考文献标准、专业学位名称表）。附件里藏着封面字号、声明页字号、参考文献著录格式等硬指标，只看主件必漏。
2. **零虚构。** 数字、结论、引用一律取自素材包并标注出处；检索不到对应原文时**留【待填】并显式列出**，绝不编造条目凑数。封面/作者/申请人/致谢等个人信息**不代填**。
3. **格式是硬交付，不是装饰。** 页眉、页码、图表题注位置、字体字号都是规范明文条款，逐条对照实现并用脚本验证——不要凭"看起来差不多"交付（见坑表第 1 条）。

## 工作流

```
① 规范整理   读全部附件 → 出"要求 → 实现"对照表（标【硕】/【博】/【通】+ 🔴硬性/⚪选做）
② 素材盘点   素材包目录先全列 → 读索引/方法/参数/结果/图注/来源/脚本 7 类核心文件
③ 母本分片写  Markdown 分片落盘（前置 / 第1-2章 / 结果讨论结论 / 参考文献附录）
④ 渲染出稿   一个脚本：合并 MD → 解析 → DOCX（分章分节 / 逐节页眉 / 分节页码 / 题注 / 公式）
⑤ 校验交付   unzip 读 header*.xml + footer*.xml 逐节断言 → 报产物路径与关键指标
⑥ 扩写修订   只改指定项 → 同步交叉引用/目录页码/附表清单 → 重跑渲染（见 ⑥ 节）
```

### ③ 母本分片写（关键）

**一次 `write_file` 写一章**，不要一次写完全文——单次输出过长会被流式截断，整段返工。

分片建议：

| 片 | 内容 |
|---|---|
| `part1_front.md` | 封面要素表、原创性声明、授权声明、中文摘要+关键词、Abstract+Keywords、目录、插图附表清单、缩略词表 |
| `part2a_ch1.md` | 绪论（背景/现状/问题/思路/创新点/结构） |
| `part2b_ch2.md` | 材料与方法 |
| `part3_ch3_ch4_ch5.md` | 结果 + 讨论 + 结论 |
| `part4_refs_appendix.md` | 参考文献、附录（脚本清单/数据字典/结果节选）、作者简介、致谢 |

> ⚠️ **绪论与材料方法从一开始就分两片写。** 这两部分都是会被反复要求扩写的（"再补充一些背景"、"把实验细节补齐"），合在一个文件里时改任何一处都要重写整片。拆片/改名后**必须同步渲染脚本的 `PARTS` 列表，并删掉旧片文件**——留着废弃分片＝多版本产物并存（用户明确反感），且下一轮极易改错文件。实测：`part2_ch1_ch2.md` 扩写后拆成 `part2a_ch1.md` + `part2b_ch2.md`，`PARTS` 与旧文件同轮一起处理。

Markdown 里用**约定标记**让渲染脚本可解析（本库模板按这套约定）：

- `# 第N章　标题` / `# 参考文献` / `# 附录A　…` → 章级（另起节 + 页眉）
- `## 1.1　…` → 一级节标题；`### 1.1.1　…` → 二级节标题
- `**表 3.1　表题**` → 表题（表**上方**，黑体居中）
- `![alt](figures/x.png)` → 居中插图；`**图 3.1　图题**` 必须写在**图片行的下方**（图题在图下，黑体居中），其后接 `图注：…`
  ⚠️ **行序即版式**：渲染脚本按 Markdown 行序逐行输出 → 图题行若写在图片行**之前**，成品里图题就跑到图**上方**，与\"图号和图题排于图的下方\"相反。实测 10 张图全错、需全稿返工。母本里一律**图片行在前、图题行在后**，并给图片段加 `paragraph_format.keep_with_next = True`（图与图题同页）
- `> 引文` → 楷体缩进块；`---` → 前置部分分页；4 空格缩进 + 行尾 `（2-1）` → 公式行
- 标准 Markdown 表格 → 渲染为带边框表（表头加粗）

### ④ 渲染

直接用 `templates/thesis_docx_builder.py`（本库模板，参数区改成自己的路径与字体即可）：合并分片 → 逐行解析 → 出 DOCX。它已实现分章分节、逐节页眉、分节页码、题注字体、首行缩进 2 字符、公式居中。

### ⑤ 校验（必做，一次脚本跑完）

```python
import zipfile, re, os
z = zipfile.ZipFile(docx)
media = [n for n in z.namelist() if n.startswith("word/media/")]
print("图片:", len(media), [f"{z.getinfo(m).file_size:,}B" for m in media])
for i in range(1, 20):
    n = f"word/header{i}.xml"
    if n not in z.namelist(): continue
    x = z.read(n).decode("utf-8")
    txt = re.sub(r"<[^>]+>", "", x).strip()
    if txt: print(f"header{i}: 「{txt}」 字体={'楷体' in x} 单划线={'pBdr' in x}")
x = z.read("word/document.xml").decode("utf-8")
print("页码格式:", "upperRoman" in x, "decimal" in x, "| pgNumType:", x.count("pgNumType"))
```

**必须成立的断言**：① `word/media/` 张数 == 论文插图数；② **每个 header*.xml 都有非空正文 + 目标中文字体名（如 楷体）+ `pBdr`**；③ 前置 `upperRoman` 与主体 `decimal` 都存在。
⚠️ `document.xml` 里查不到 `PAGE` 是正常的——页码域在 `word/footer*.xml`，别据此误判"页码没生成"。

**查正文文本**（核实某类夹注、术语、工具名是否真的出现在稿里）同样要**先剥标签再匹配**——Word 会把一句话拆进多个 `<w:r>/<w:t>`，直接 `grep` 内部 XML 会漏检：

```python
t = re.sub(r"<[^>]+>", "", re.sub(r"</w:p>", "\n", z.read("word/document.xml").decode("utf-8")))
print("方括号夹注:", len(re.findall(r"\[图[^]]*\]", t)), "| 关键词命中:", t.count("CellBender"))
# 查"全稿有没有某词"要扫 word/*.xml 全部：页眉/页脚/脚注不在 document.xml
for n in z.namelist():
    if n.startswith("word/") and n.endswith(".xml") and "关键词" in z.read(n).decode("utf-8", "ignore"):
        print(n, "命中")
```

### ⑥ 后续轮次扩写 / 修订（几乎必然发生）

首版交付后，用户几乎一定会追加要求："再补充一些背景"、"多下载文献"、"把 XX 的实验细节补齐"、"这段不要动，只改我列的几项"。按下面的顺序做：

**1. 先读回现状，不要凭记忆改。** 读上一版的对应分片 + 已整理好的规范对照表；素材增补（如用户新给的来源论文）要先完整读透再落笔。

**2. 只改指定项。** 用户说"只改我列的这几项 / 已经没问题的就不要动" → **零润色、零重构**，顺手发现的其它缺陷**单列出来问**，不要擅自改。

**3. 扩写必然引发三处交叉引用漂移，必须逐处同步（最容易漏、代价最大）。** 新增小节或新增表格会顶掉后面的编号：

```bash
# 改完分片后，先全文找交叉引用，再决定要不要改号或改指向
grep -n "表 [0-9]\.[0-9]\|图 [0-9]\.[0-9]\|见 [0-9]\.[0-9]\.[0-9] 节\|见 [0-9]\.[0-9] 节" results/thesis/part*.md
```

| 漂移点 | 典型症状 | 处理 |
|---|---|---|
| **正文交叉引用** | 章节重排后正文仍写"见 1.2.2 节"，而该内容已挪到 1.2.5 | 逐处改指向；**新增表格会让后面所有表号顺延**（如原表 1.1 → 新表 1.2） |
| **目录页码** | 第 1 章扩写约 +10 页，目录里第 2 章仍在 11 页 | 全篇页码顺延重排；仅"示意"也须单调递增，否则读者一眼看出是坏的。**有 WPS/Word 时必须换成实测值**（`scripts/wps_pages.py` + `wps_writeback.py`），实算值只能兜底并标注"估算" |
| **插图附表清单** | 清单里没有新增的表 | 同步补入并改既有表号 |

改完再重跑渲染脚本出 DOCX——**不要手工改 DOCX**，否则下一轮渲染会全部覆盖。

**6. 页码必须取「办公套件实测分页」，不要把手工步骤推给用户。** 用户说**「你自己看好页码呀」**＝不接受
"你去 Word 里 Ctrl+A→F9"。先探测 COM（`reg query "HKCR\KWPS.Application\CLSID"`，本机通常装了 WPS；
脚本用 `WPS_PROGID` 可在 WPS/Word 间切换），再走
`scripts/wps_pages.py <docx>` → `scripts/wps_writeback.py <thesis目录>` → **重渲染**。
页码是纯数字替换、不回改版式，故实测值继续有效。**警告**：按版心实算的页码只能兜底，且必须显式标为
"估算"——实测同一稿 实算 94 页 vs WPS 实测 **86 页**（差 8 页，目录全错）。完整口径/映射规则/两个污染坑
→ `references/pagination-with-wps-com.md`。

**7. 图号/表号必须与出现顺序一致，清单必须完整无重复。** 扩写插入新图新表后几乎必然错位（实测：
图2.2 排在图2.1 之前、表3.3 排在表3.2 之前、表3.10 漏登记且重复一行）。跑
`scripts/audit_and_renumber_figures_tables.py --dir <thesis目录>`（加 `--apply` 生效）一次体检三件事：
① 出现序 vs 编号序 ② 清单漏登记/重复行 ③ **每张图/表是否真有正文引用**（只有图题、正文从不引用的
"哑图"审稿人必问；实测 7 张图里 5 张缺引用）。`--apply` 用**双射置换**重编号，正文引用/目录/清单
自动跟随，不需要逐处手改。

**4. 数据来源论文要"挖全实验细节"，且逐字转录。** 素材包里的数据若来自某篇已发表论文（尤其用户是共同作者时），论文里必须交代：伦理审批号（机构 + 批件号）、动物/样本来源与饲养条件、组织采集与保存流程（麻醉剂/试剂厂家货号、时间窗、冻存方式）、细胞核提取缓冲液配方与耗材货号、文库构建试剂盒（厂家 + **货号**）、测序仪器与读长、比对软件与参考基因组版本、QC 阈值。抽取用脚本定位标题后取整段（见 `references/data-source-paper-mining.md`），**转录而非转述，不推断缺失项**。
⚠️ **队列规模对不上时留钩子，不要编原因。** 实测：来源论文队列 23 只动物，本文猴侧矩阵 20 例样本 → 差额原因论文未写明时，正文写"⚠️ 须由作者核实"并指出核对依据（如原论文样本—脑区对应表），**绝不写"因为某某样本质控未通过"这类未经核实的解释**。

**5. 扩写背景时批量补文献。** 用户说"多下载一些文献 / 再补充补充背景" → 按论文章节拆主题并行 `search_papers`，只收带 PMID/DOI 的可核验条目，再走 OA 下载路径（出版商 403 时的正解、curl TLS 失败的归因、Europe PMC REST 全文 XML 的用法）见 `references/literature-supplement-download.md`。**背景每扩一节，参考文献表与正文引用编号要同轮更新**，并做一次"文献表 ↔ 正文引用"双向覆盖检查（有无孤立条目 / 有无引而未列）。

## 坑表（实测）

| 坑 | 现象 | 正解 |
|---|---|---|
| 🔴 **新增分节时页眉文本漏传** | `doc.add_section(WD_SECTION.NEW_PAGE)` 后调 `setup_section(sec, header_text=None)` → **页眉部件存在但内容为空**；脚本 exit 0、回执毫无异常，只有打开 Word 才看不出"这一节没页眉"（实测：12 节的论文全篇页眉为空，而规范把"页眉=章的编号及标题"列为硬性项） | 把章标题**显式传进**页眉：`setup_section(sec, header_text=title)`，**每新增一节都设一次**，不依赖"继承上一节"。校验脚本逐节断言正文非空 |
| 分节页码不重起 / 全篇一套编号 | 规范要求前置罗马数字、主体阿拉伯数字且主体从 1 重算 | XML 注入 `w:pgNumType`（`w:fmt`=`upperRoman`/`decimal`，`w:start`=1）；**只给主体第一节设 `start`**，后续节不设即自动续号 |
| 中文字体不生效（回落默认字体） | 只设 `run.font.name` | 同时写 `w:rFonts` 的 `w:ascii` / `w:hAnsi` / `w:eastAsia` 三个属性（模板里 `set_run()` 已封装） |
| 用 `add_heading` 做章节标题 | 规范要求章标题黑体三号、节标题黑体四号等自定义字号，内置 Heading 样式不受控 | 用普通段落 + 手工字体字号；**不要**依赖 Heading 样式层级 |
| 目录想用 Word TOC 域 | TOC 域只收 Heading 样式条目 → 自定义标题下目录为空 | 排**静态目录文本**（含"…………"与页码），并在交付说明注明"页码以 Word 更新域后为准" |
| 参考文献表凑数/编造 | 检索未命中数据集原文，容易顺手编一条 | 只收**可核验**条目（带 PMID/DOI 的文献、对比专利原文、数据/工具资源）；未确定的留【待填】并在正文说明节写明"须由作者补齐" |
| docx 生成脚本在分析内核里跑不了 | `import docx` → ModuleNotFoundError | python-docx 常装在**系统 Python**而非分析内核。这类一次性生成脚本直接 `terminal` 调系统 Python（先 `python -c "import docx"` 确认）；**不要**把 docx 写进 `rail_review` 的 `required_packages`（会误报 Missing 并硬阻断，见 `platform-execution-pitfalls`） |
| 用 `exec(open(path).read(), {'__name__':'__main__'})` 跑脚本 | 脚本里出现 `__file__` → `NameError: name '__file__' is not defined`（exec 未注入 `__file__`） | 生成脚本里**不要用 `__file__`/`sys.path.insert(0, dirname(__file__))`**；需要基目录就写硬编码常量。详见 `platform-execution-pitfalls` |
| 🔴 **扩写后忘同步交叉引用** | 第 1 章由 3 节扩成 6 节、新增 1 张表 → 正文"见 1.2.2 节"指向已挪走的内容、表号错位、目录页码断裂 | 渲染前先 grep 全文交叉引用（`表 N.M` / `图 N.M` / `见 N.M.K 节`）+ 目录页码 + 插图附表清单，三处一起改；见 ⑥ 的 grep 命令 |
| 用户给的来源论文读不进来 | `read_file("X.docx")` 返回 `Cannot read binary file`；`ls` 能看到但 bash 打不开该名字 | 先查真实文件名（`os.listdir` + `repr()`，中文名常带 U+200B 零宽空格），再走 python-docx 抽取；完整脚本见 `references/data-source-paper-mining.md` |
| 从 docx 抽方法段时**读错章节** | 先按"非空段落"建列表 → 索引与原始段落索引错位，按错位索引去读，实际读到的是 Discussion 而不是 METHODS（且开头几句很像，不易察觉） | 一律**保留原始段落索引**（不要先过滤空段），按**标题字符串**定位（`t.startswith(标题名)`）再向后取段，不要用"第 N 个非空段"这种脆弱定位 |
| 🔴 **正文图表用括注式 / 方括号夹注** | 中文学校规范惯例是"如图 X.Y 所示""如表 X.Y 所示"；`（图 3.2、图 3.4）` 与 `[图 3.2 三柱分布]` 都不对（实测用户点名要求整改） | 正文改叙述式；**`[图 X.Y 简称]` 的真身是母本图片 alt 文本** —— 图片渲染失败或用户看的是 `.md` 预览时，`![alt](src)` 会显示成 `[alt]`。alt 必须写**完整图题**。诊断/批量修复 → `cn-degree-thesis-writing` 的 `references/figure-table-intext-citation.md` + `scripts/check_intext_citations.py` |
| 🔴 **直接在 DOCX 内部 XML 上 grep 找词** | Word 把一句话拆进多个 `<w:r>/<w:t>`，跨 run 的连续字符串 `grep -o` 会**漏检**（报 0 处而正文其实有）；只读 `document.xml` 还会漏页眉/页脚/脚注（在 `header*.xml`/`footer*.xml`/`footnotes.xml`） | 先剥标签再匹配：`re.sub(r"<[^>]+>","",re.sub(r"</w:p>","\n",raw))`；查"全稿有没有某词"要扫 `word/*.xml` 全部 |

## 交付汇报要点

1. **产物清单**：DOCX（可编辑，主交付）+ Markdown 母本（便于继续改）+ 生成脚本 + 图件目录 + 引用库文件路径与大小。

5. **待填项显式列出**：哪些字段必须用户补（数据来源编号、个人信息、待扩充引用），并说明"我没有代填/编造"。
