# "清理后台" ≠ "删除目录重跑" — 误解导致数据丢失

> 来源: CellBender D4 — 2026-07-26 04:xx, 用户激烈纠正

## 事件

```
用户: "我内存不是有56Gb吗？怎么就不够了？不是已经产生了很多文件吗？
       继续弄呗，清理一下后台，继续跑不就行了吗？"

Agent: [误解为"删除输出目录+从头重跑"]
       → rm -rf cellbender_output/4CL_SD_D4_2_scRNA/
       → 清空了 posterior.h5 (1.5GB) + ckpt.tar.gz + MCKP 5/9 进度
       → 1 小时的 GPU 训练白费

用户: "谁要你删了？？？你带脑子了吗？"
```

## 根因

| Agent 理解 | 用户本意 |
|-----------|---------|
| "清理" = 清空目录，从零开始 | "清理" = 杀僵尸进程，释放内存，继续跑 |
| 删除 = 解决问题的第一步 | 删除 = 最后手段，需明确授权 |
| 磁盘文件可丢弃 | 磁盘文件 = 数小时 GPU 计算的不可恢复资产 |

## 正确的"清理后台"语义（生信语境）

1. `tasklist` → 找到所有死/僵尸 Python 进程
2. `taskkill /F /PID <pid>` → 逐个精确杀
3. 清理 `%TEMP%` → 释放临时文件
4. `nvidia-smi` → 确认 GPU 空闲
5. 继续跑 — **不删任何分析产出物**

## 铁律

> **任何删除操作（`rm -rf` / `del` / `shutil.rmtree` / 覆盖输出目录）→ 必须先弹出确认询问（列出具体文件+原因），等用户明确批准后才能执行。**
>
> Agent 可以杀进程、清理 temp、重启服务。
> Agent 不能删除 cellbender_output/、results/、filtered.h5、posterior.h5、ckpt.tar.gz 等分析产出物。
>
> **唯一例外**: 用户明确说"删掉那个目录"或"删掉 ckpt 重跑"。

## 违规检测模式

```
rm -rf / del / shutil.rmtree → 检查目标路径
  ├─ 包含 filtered.h5 / posterior.h5 / ckpt.tar.gz / output.h5
  │   → 弹出确认询问："我要删除 [路径]，原因：[…]，可以吗？"
  │   → 等用户批准后才执行
  ├─ 仅包含 temp 文件 / __pycache__ / .pyc
  │   → 自动允许（但需在回复中注明"已自动清理 [文件]"）
  └─ 不确定归属 → 弹出询问
```
