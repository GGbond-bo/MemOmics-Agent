# PyTorch 2.6+ CellBender Checkpoint Incompatibility Fix

## Problem

PyTorch >= 2.6 changed `torch.load()` default from `weights_only=False` to `weights_only=True`. CellBender 0.3.2's `checkpoint.py` calls `torch.load()` without `weights_only=False`, causing:

```
_pickle.UnpicklingError: Weights only load failed.
Unsupported global: GLOBAL cellbender.remove_background.model.RemoveBackgroundPyroModel
```

This affects ALL CellBender checkpoint loading — not just the problematic `4CL_SD_D4_2` sample.

## Symptoms

- Log shows `Successfully unpacked tarball` followed by `_pickle.UnpicklingError`
- Not a CKPT corruption — the file is valid, PyTorch just refuses to load it
- `sitecustomize.py` v4 patches `torch.save` but NOT `torch.load`

## Fix (30 seconds)

Edit `C:\Users\<user>\AppData\Local\Programs\Python\Python312\Lib\site-packages\cellbender\remove_background\checkpoint.py`, line 189:

```python
# BEFORE:
load_kwargs = {}
if force_device is not None:
    load_kwargs.update({'map_location': torch.device(force_device)})

# AFTER:
load_kwargs = {'weights_only': False}
if force_device is not None:
    load_kwargs['map_location'] = torch.device(force_device)
```

**Why this line**: All 4 `torch.load()` calls in `load_from_checkpoint()` use `**load_kwargs`. Adding `weights_only: False` here propagates to all 4 calls (lines ~229, ~235, etc.) without touching each one.

## Why it's safe

The CKPT files are generated by CellBender itself during training. They are trusted. `weights_only=False` just allows PyTorch to load the `RemoveBackgroundPyroModel` class that it already knows.

## Verified

- 2026-07-26: `4CL_SD_D4_2_scRNA` CKPT loading succeeded after this fix
- The same fix applies to ALL samples, not just problematic ones
