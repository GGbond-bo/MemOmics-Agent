## 专业编辑视角论文解读

### 触发条件
- 用户说「从专业编辑角度说」「编辑视角」「研究思路」「做了什么」「这篇文章讲了什么」
- 用户说「帮我解读一下」+ 含「不满意/重新/之前的不好」的重做信号
- 用户要理解「作者的研究思路」而非快速了解论文概要

### 与 paper-summary 的关系
- **paper-summary**：字段导向（8个模块），适合快速了解论文概要
- **本 skill**：叙事逻辑导向，适合理解作者的研究思路、写作策略和概念框架
- 两者可互补：先用 paper-summary 提取文本/图表，再用本 skill 做编辑视角分析

### 执行流程

```
Step 1: 提取 PDF 文本（双栏期刊必须重排，不能直接用默认块序）
  ├── pymupdf 提取文本层（PDF 有文本层就不要 OCR）
  ├── 双栏排版：按 x0 分栏（左≈40 / 右≈306）→ 栏内按 y0 排序 → 先读完左栏再读右栏
  │     └── 验收：相邻块首尾语义是否连续；不顺 = 栏判错或图注混入
  ├── 剔除图注块（`Fig. N |` / `Extended Data Fig. N |` 开头）与图内碎片（裸数字串/化学符号）
  ├── 图内标签乱码（Type3 子集字体）= 字符码定值偏移，可暴力解码（Nature 语料为 +29）
  ├── 出图：由 caption 顶部反推图区矩形 + get_pixmap(clip=..., dpi≥500) 渲染，别裁正文
  └── 完整配方含代码：references/pdf-layout-recovery.md

Step 2: 判断文章类型
  ├── 综述文章 → 概念框架分析（非实验流程）
  ├── 实验研究论文 → 实验设计+分析管线
  └── 方法论文 → 技术创新+验证逻辑

Step 3: 按输出模板生成编辑视角解读
```

### 输出模板（综述文章专用）

#### ① 基本信息表
| 字段 | 内容 |
|------|------|
| 标题 | 完整标题 + 中文译名 |
| 作者 | 全部作者 + 通讯标注 |
| 期刊/年份 | 期刊名, 年份 |
| DOI | DOI |
| 文章类型 | 综述/研究论文/方法论文 |

#### ② 核心问题：作者为什么要写这篇文章？
- **2-3句话**说清：科学问题 + 领域gap + 引用的先例框架
- 综述文章 → 引用 Hallmarks of Cancer/Aging 等先例
- 实验论文 → 说清填补了什么空白

#### ③ 🔥 研究思路：作者的逻辑链（Mermaid Flowchart TD — 必出）
- 综述文章 → 展示**概念框架**（各部分层级关系和逻辑依赖）
- 实验论文 → 展示实验设计+分析管线
- 色彩分区：问题(蓝色系) / 方法(绿色系) / 发现(橙色系)
- 不超过25个节点

#### ④ 核心贡献逐项拆解
- 综述 → 拆解每个核心概念/章节，侧重**机制而非结果**
- 每项包含：核心逻辑（一句话）+ 细节 + 衰老/疾病关联 + 可修饰性（如适用）
- 不同于 paper-summary 的"核心发现"（后者侧重具体数据结果）

#### ⑤ 文章的结构化写作逻辑（编辑视角）
- 叙事架构分析（总-分-总/递进/并列）
- 每个章节的展开模板（如：机制→功能→疾病→可测量性→可修饰性）
- 综述文章的交叉引用逻辑（各部分如何相互关联）
- 作者的写作策略

#### ⑥ 与你的研究关联
- 基于用户研究方向（从 MEMORY/USER PROFILE 推断）给出3-5条具体关联点
- 每条含：关联点 + 可借鉴的方法/参数 + 下一步建议

#### ⑦ 结尾提示
> 📄 需要导出为 **HTML 完整报告** 吗？回复「**做成 html**」即可。

### 输出模板（实验研究论文）

当用户要求解读实验研究论文时，模板调整为：

- ② 核心问题 → 同上
- ③ 技术路线图 → 展示实验设计+分析管线（而非概念框架）
- ④ 核心发现 → 侧重具体数据结果（P值/log2FC/效应量）+ 生物学意义
- ⑤ 写作逻辑 → 分析实验部分的组织方式
- ⑥ 方法管线亮点 → 步骤→工具→参数 三列表格

### 通用附加章节（用户要「详细专业一点」时必给）

「详细专业一点」= 不止复述作者说了什么，还要给出**判断**。在既有模板之上追加三块：

1. **关键数字块**：把全文可引用的硬数字集中成表——规模（化学空间/样本量/搜索空间）、性能提升、模型精度（R²）、统计量（P 值、Spearman R²）、穷举规模（训练了多少模型）。解读里凡是"提升了/改善了"都必须带数字，不接受"显著提升"这类无数字表述。
2. **创新性定级（这篇文章为什么能上这个刊）**：按四轴写，每轴一句话说清它比既有工作多给了什么——**范式层**（改变了领域怎么看问题）/ **领域层**（给出了新的可操作原则）/ **数据效率层**（用多小的代价换到多大的一般性）/ **严谨层**（验证链有几重）。
3. **批判性阅读（该打问号的地方）**：3–6 条，分"作者自己承认的局限"与"作者没说但存在的问题"两类。固定要查的点：
   - 结论的适用边界——体系/状态/物种/骨架族是否被刻意收窄（如只做溶液态、只做人工砌块库）
   - 机制是**直接观测**还是**间接推断**（有无瞬态/时间分辨类直接证据；只有能量匹配+干预实验=间接）
   - 相关 vs 因果——模型特征重要性 ≠ 因果，看作者是否用实验补了因果链
   - 成功是否依赖**不可先验保证**的条件（如优化器恰好采样到有代表性的区域）
   - 必须写一节**反例/离群点**：作者如何处置异常样本，往往藏着后续机理入口
   ⛔ 没有批判性章节 = 解读不合格；只写优点会被要求重做。

### 与 nature-reader 的分工
- **nature-reader**：全文中英对照精读，侧重翻译和术语
- **本 skill**：专业编辑视角解读，侧重研究逻辑和写作策略
- 两者可结合：先用 nature-reader 精读，再用本 skill 做编辑分析

### 与 literature-full-summary 的分工
- **literature-full-summary**：9项结构化摘要（给人看的方向）
- **本 skill**：更深入的编辑视角分析（叙事逻辑+结构化写作+研究思路）
- literature-full-summary 适合批量处理多篇文献；本 skill 适合单篇深度解读

### Pitfalls
- 综述文章不要用"技术路线图"模板（无实验流程），改用"概念框架图"
- 实验论文不要用"概念框架"模板（无理论框架），改用"实验设计+分析管线"
- 用户说"重新解读/不满意"时，必须调整模板（不能用同一个模板重跑）
- 解读深度要匹配用户的专业水平（生信领域用户需要机制细节）
- **双栏期刊不要用 pymupdf 默认块序**：`get_text()` 按流顺序返回块，会跨栏交错，段落级中英对照直接错位。必须按 x0 分栏 + 栏内 y0 排序 + 语义连续性验收（见 `references/pdf-layout-recovery.md`）。
- **图注块会被误当正文**：图注宽度与正文几乎一致（双栏期刊约 255–260 pt），靠宽度筛不出来，必须靠 `Fig. N |` / `Extended Data Fig. N |` 前缀剔除，否则图注散文插进正文序列。
- **图内文字乱码 ≠ 信息不可得**：Type3 子集字体提取出来是偏移字符码（Nature 语料为 +29，暴力试偏移即可还原）。还原不了就在 `translation_notes.md` 标注"以渲染图为准"，**不要猜**、也不要把乱码原样贴进交付。
- **裁剪图后必须抽查**：用 `vision_describe` 看一张主图，确认 OCR 出来的只有图内标签、没有正文段落；混入正文说明矩形画错了。
- **长解读文件分块写**：双语长文（paper.md 级）用 append 分 3–4 次写，单次全量易超长/超时；每块主题要明确不同，避免形态相似的分块触发系统循环检测提示。
- **只输出对话不落文件 = 交付不完整**：完整精读应交付 `paper.md` + `source_map.json` + `translation_notes.md` + `figures/`，收尾前校验（`**Original:**` 与 `**中文:**` 块对数量一致、图片链接全部真实存在）。
