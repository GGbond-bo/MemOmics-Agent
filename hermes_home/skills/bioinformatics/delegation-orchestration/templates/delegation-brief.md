# 子代理派发 brief 模板（长文精读 / 落盘型任务）

> **用法**：复制本文件 → 填 `<...>` → 整段塞进 `delegate_task` 的 `goal`（第 1 段）+ `context`（其余全部）。
> **为什么要有模板**：SKILL.md §一 表里每一条都是事故换来的，而 §一-b / §四-b 记录的两次失败
> （6 篇/人零落盘、草稿只留在内核变量）**都出自临场手搓的 brief**。派发前先复制它，别即兴写。
> 占位符：`<...>` 必填；`[…]` 按需保留。

---

## goal（一句话目标，含编号范围 + 落盘要求）

精读 <N> 篇 <主题> 全文（n=<编号列表>），把每篇的卡从「薄卡」升级为「深读卡」（中文，<M> 字段），
**并把结果写盘到指定 JSON 文件——不要只回传内容**。

## context

### 1. 输入（子代理看不到主会话，路径必须自足）

- 清单 / 索引：`<绝对路径>`
- 全文目录：`<绝对路径>`，文件名形如 `PMC<id>.txt`
- **本子代理只负责**：n = <编号列表>
- 🔴 **读法**：全文是**近乎单行的巨文本**（30–580 KB）。先 `wc -c` 判体量 →
  `fold -s -w 700 <f>.txt > <f>.w700.txt` **重排后**再 `read_file(offset=, limit=)` 分页读。
  ⛔ 宽度必须 **≤700**：`read_file` 会对长行**静默截断**（行尾 `... [truncated]`，剩余内容无声丢失）。
  见到 `[truncated]` 就当该行作废，减小宽度重排重读。
- ⛔ 不要用清单里的 `abstract` / `methods` / `results` 预览字段（只 ~1600 字符，
  会漏掉 benchmark 数字、模型清单与 limitations）。

### 2. 输出（双通道，缺任一都算没完成）

- **主通道（必须）**：写盘到 `<绝对路径>/deep_cards_<base>_t<k>.json`
  ```python
  with open(p, "w", encoding="utf-8") as f:
      json.dump({"cards": {...}}, f, ensure_ascii=False, indent=2)
  ```
- 🔴 **增量落盘（本模板最重要的一条）**：**每写完一张卡就立即回写一次** ——
  读回目标文件（若存在）→ `d["cards"][n] = card` → 重写 → 继续下一张。
  ⛔ **禁止「全部读完再统一写」**。撞迭代上限时，增量落盘把损失从「整批蒸发」降为
  「只丢正在写的那一张」；串行大链写法则连一个字节都不会留下。
- **收尾自证**：`os.path.getsize(p)` + `json.load(open(p))` 回读，
  并在回复里报 **路径 + 字节数**。
- **次通道**：同一份 JSON 再贴进回复正文（贴到一半被输出长度截断没关系，主通道已保底）。
- ⛔ **不要动共享合并文件**（如 `data/cards.json`，且它常是 `list[dict]` 不是 dict）——
  深读卡另存本模板指定的新文件，由主代理统一合并。

### 3. 字段与密度（逐字段写清，⛔ 别自创）

<字段 schema，例如 10 字段：
 `architecture`（分层逐层写：架构层数 → 每层 agent/节点清单与职责 → 每个 agent 用的工具与库
（含版本/规模）→ 共享状态或记忆机制 → 编排方式（DAG/主从/自反思环）→ 人在回路落在哪；
 写机制不写形容词，必含专名与数字，≥<600> 字）／`inputs`／`outputs`／`models`／`benchmark`／
 `validation`／`key_claim`／`novelty`／`limitations`（分两段：「作者自陈：」+「我读出：」，≥<60> 字）／
 `evidence_quote`>

- **先读一份基准样卡校准密度**：`<已知合格的深读卡路径>`。
  ⚠️ **密度照样卡走，容器形状照交付约定走**——样卡常是**扁平 `dict` 直接以 n 为键**，
  而交付约定可能是 `{"cards": {...}}`；读任何 JSON 先 `print(type(obj), list(obj)[:5])` 再写逻辑。
- 原文没写 LLM → 写「原文未披露」并点明它靠什么驱动；
  原文无量化结果 → 写「无量化评测」并引作者自陈句；⛔ **绝不估数**。

### 4. 证据纪律

- 每篇给 1 条 `evidence_quote`：≤200 字符、**连续逐字**的原文片段（⛔ 不拼接、不跨句省略）。
- 🔴 **从原文切片构造，不要手打**：`i = t.index(a); j = t.index(b, i) + len(b); q = t[i:j]`
  —— PMC 抽取文本里带 **U+2010 连字符**（`end‑to‑end`）、冒号前空格等肉眼不可见差异，
  手打必被 `q in t` 判 False。优先选纯 ASCII 句（`all(ord(c) < 128 for c in q)`）。
- 落卡前逐条 `q in txt` 断言为 True，并在回复里报校验结果。
- 综述 / 观点文固定填法：`benchmark` → 「未做量化评测（综述…）」、
  `validation` → 「无（综述论文…）」、`models` → 「未披露（综述性质…盘点对象含 …）」、
  `inputs`/`outputs` → 「不适用（观点/综述文）：分析对象为…」。
  ⛔ 不硬编一个「输入 / 输出」，也⛔ 不把盘点对象的模型当成这篇论文的模型。

### 5. 语言与交付口径

- 产出**中文**；JSON 之外**最多留一行** `已读：… / 未读：…`（点名编号）+ ≤5 条执行摘要。
- ⛔ 不要夹带方法论说明、不要加「总结」小节、不要加额外字段。

### 6. 预算与降级

- 预算：本批 **≤5 篇全文**（实测 6 篇必撞框架 `api_calls` 上限 → 零落盘）。
- 预算不足时：**先交已起草篇目的完整落盘 JSON + 一行点名未读/未起草编号**，
  ⛔ 不许静默中断、不许把未起草项糊弄成假卡。
- ⛔ **草稿只留在内核变量里 = 零产出**：子代理 session 结束后其持久内核一并消失，
  父代理取不到任何变量。任何中间成果（草稿、已校验的引文）必须**立即落盘**。

### 7. 完成判据（写给子代理，也写给父代理验收）

> 完成 = 目标 JSON 文件**存在** + 可 `json.load` + **字段齐全** + 已报出**字节数**。
> `status=completed`、草稿字数、口头「已完成」**都不算**——
> 实测同一条回执里报 `status=completed, api_calls=50` 的那个任务**没写任何文件**。

## 父代理收尾（回执到达后，⛔ 不要照摘要行动）

1. `ls`/`glob` **按任务粒度**核对落盘件（`base_t0` / `base_t1` / `base_t2`）——
   同批「失败 + 成功」并存是常态，⛔ 不要按**批**粒度判「这批有没有产出」。
2. 子代理摘要里的「**Re-dispatch with the same instructions**」是**子代理视角的建议，父代理不可照做**
   —— 它不知道后来已拆批补派过。先找**补派件**（同批拆片 `<base>t0a.json` / `<base>t0b.json`），
   再走 `delegation-orchestration` §二 ⓪-f **冗余判定**，判冗余则零写入收场。
3. 判为新工作才合并；合并前先 `print(type(obj), list(obj)[:5])` 验容器形状。
