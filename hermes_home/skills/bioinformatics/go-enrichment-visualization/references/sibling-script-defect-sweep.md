# 同族脚本的缺陷波及面：修好手上这张 ≠ 全族都好了

> 触发：在一张图上定位并修掉一个**机制性**缺陷（如绘制顺序裁掉色块、标签锚底边偏半格、
> `for (d in OUTS)` 循环变量遮蔽矩阵、`par(xaxs)` 外扩压色块）之后。
> 这类缺陷由**共享的代码骨架**带来 ⇒ 同一脚本家族的其它脚本**极可能同病**。

## 一、扫波及面（一行 grep，必须有实证）

```bash
# 典型三坑的联合扫描
search_files "group_stripes|draw_cbar|axis\(2|xaxs" scripts/fig_*.R
```

2026-09-25 实测（骨骼肌 MF 项目）：在 `fig_A2_5effects_v3.R` / `fig_A3_transposed_v3.R`
上修好「绘制顺序裁色块 + 标签锚底边」两坑后，一扫发现**母脚本 `scripts/fig_split_v10.R`
两坑齐全**（L179/L272/L317 标签为底边约定；L239/L248/L290/L299 的 `draw_group_stripes()`
调在 L184/L279/L324 的 `draw_cbar()` 之后），且**仍持旧分组 / 旧成员**（旧 5 组、18 程序、
含已被用户判死的 Stress 项）⇒ 它产出的 **FigA1/B1/B2/B3 四张基础图**同样带病。

## 二、正确动作：报告，不擅自批量重画

| 动作 | 做不做 | 理由 |
|---|---|---|
| 修好当前这张 + 出图 + 核验 | ✅ | 用户当轮要的就是这张 |
| 把「还有哪几张带旧口径/旧坑」列成**显式清单**交用户 | ✅ | 用户下次必撞上，早晚要问 |
| 末尾加一句「**要修就说一声**」 | ✅ | 把决定权交回用户，不替他排期 |
| 顺手把全族四张一次性重画 | ❌ | 未经确认的批量返工 = 打扰；用户明确偏好**连续性**（记忆：「不需要重跑，就按之前那样」） |
| 默默留着不说 | ❌ | 下个会话会以旧版为基准继续改，坑越滚越深 |

**判据：任何"同类缺陷不止一处"的发现，交付时未同步清单必须显式列出。**

## 三、清单怎么写（一行/张，带证据）

```
⚠️ 母脚本 scripts/fig_split_v10.R 未同步修正 —— 仍持旧 5 组/18 程序（含 Stress），
   且 L179/L272/L317 标签为底边约定、draw_group_stripes() 调在 draw_cbar() 之后
   ⇒ 其产出的 FigA1/B1/B2/B3 四张图同样带病。要修就说一声。
```

要点：**给出脚本行号或常量名**（让用户能自己核），不要只写"那几张图可能有问题"。

## 四、验收：新脚本从哪一版起复制

同族里**已修好的那一版**才是正确的复制起点。实测记录：
`fig_A2_5effects_v3.R`（两坑已修）> `fig_A2_5effects_v2.R`（两坑都在）；
**不要从母脚本 `fig_split_v10.R` 起**。复制起点写进 SKILL.md 的 Proven Scripts 说明列，
下次直接照抄，不用重新考古。
