# 专利深度分析

对生物信息学/方法类专利进行竞品拆解：阅读全文 → 提取技术路线 → 权利要求解读 → 识别创新空白 → 规避建议。

## When to Use

用户说"分析这篇专利""拆解这个专利""专利详细解读""解读专利""分析权利要求""竞品专利分析"等时触发。

**同类必触发（handoff 续跑 / 「跑完了吗」）**：用户给一份 **handoff / 续跑文档**说「**按文档跑**」，或问「**<方案> 跑完了吗？**」，或离席前说「我明天起来要一个完成的方案」→ 走 §交付诚实性 流程。核心动作：**三源验证（GPU/进程/磁盘产出）→ grep 项目档案判主线承重柱是否已被自身数据否掉 → `search_files` 自证每一句「已落盘/已交付」→ 区分三态汇报（跑完 / 只交付文档层 / 一步没跑）**。

**同类必触发（三柱换承重后的执行落地 / 「按方案跑」「跑完了吗」「你直接跑」）**：用户拍板换柱后说「**那就按方案 B**」「**我只要跨物种筛选的专利**」「**你就直接跑**」→ 走 §三柱 AND 实跑 流程（`references/three-pillar-screening-execution.md`；「为什么换柱」的规划层见 `replace-claim-load-bearing-pillar.md`，**已拍板的事不要重新论证**）。⚠️ 要的是**实跑数字替换占位值**（占位数字的交付件 = 未完成，见 §交付诚实性 第 3 条）。三个必踩点：① 🔴 **L2「两侧 tile>0」在 gene 级恒 100%**（上游 `M2_repro_*` 本身已是两侧有 tile 的基因对）⇒ 零区分度，必须改用 **tile 数下限**口径；判据：**任何一层通过率 ≈100% 或 ≈0% 即不构成筛选条件**，不可写进权利要求当区别特征；② **用 `conserved_pc` 判序列保守，不看 `p100_bg_q`**（实测该列整列恒为同一值 = 未完成 FDR）；③ **`rail_review(post)` 只扫 `output_dir` 本体** → 图在 `figures/` 而 dir 传 `results/` 会判 `figure_count=0 / 未生成任何图片`（图归位或改 dir，**先回盘确认图真存在再决定**，别盲目重出图）。收尾必备：**可溯源对照表**（每个数字 → 输入文件 → 脚本 → 中间产物）+ **方向标记总索引**（✅能出专利 / ❌已否 / ⚠️附属待补 —— 用户明确要求「产出的文件做好标记，做的方向做好标记」）。

**同类必触发（数值验证）**：用户说"我需要验证你的东西""列出我要复现的进程的内容""复现对不上""为什么是这个版本""这个数字哪来的"→ 走 §数值口径溯源对账 流程（`references/numeric-provenance-audit.md` + `scripts/trace_Z_source.py`）。这类请求的交付物是**复现清单四件套**（输入路径+列名 / 参数常量值 / 输出文件 / 正本数字），不是重跑一遍。

**同类必触发（口径切换 / 交付件重出）**：用户说"改用 X"（X = 数据版本或口径）"继续完成 <交付件>""把全流程的代码、模块全都记录好，后面能溯源"→ 走 §交付件口径切换 流程（`references/deliverable-caliber-switch-traceability.md`）。核心动作：**时间戳判旧件 → 台账定数字 → 版本化重出（不覆盖）→ 零残留核验 → 溯源档案 7 部件**。⚠️ 不要只改正文：binary 交付件（docx 内嵌数字、附图轴标签数字）必须一并重出并核验。

**同类必触发（送审补强项 / 「跑这 3 项已如实标注」）**：用户说「**跑这 3 项**」「**把待跑项补上**」「**全权交给你**」「需要什么文件我给你 / 也可以帮你下载」→ 走 §送审补强项执行 流程（`references/supplemental-items-execution.md`）。三项标准配方：
① **后验富集**（前景 = 主方案产出清单，背景 = 全部单元 + 敏感性背景；基因集走 **Enrichr API 实下载** —— `scripts/enrichr_ora_hypergeom.py` 可直接跑，**严禁凭记忆手写基因集**；**库内 FDR 口径必须显式标注**（同一数据实测：全库 3794 条 → 最小 FDR 0.0082；预限定 842 条 → 0.0506；**单库 286 条 → 0.0219**，差一个量级）；**经典通路阴性必须如实写** —— 辅助权项非硬门，但隐瞒会被抓）。🔴 四个坑：基因名大小写（Enrichr 全大写）、库名拼错返回 **404 HTML 且 `urlopen` 不抛异常**、校正口径、**签名层 ≠ 通路层**（须分两层报告：签名层 fold 3.2–5.4× 显著 vs 经典细胞衰老通路 p=0.361/0.384/SASP 0 hits 不显著）
② **对照侧聚合**（他物种区间表若自带目标坐标映射列如 `hg38_chr/start/end` → **直接按同一基因窗口聚合**，**比 liftOver 稳** —— 先探映射列再谈 chain；主张边界按裁决限定在「聚合 / 富集层」，**不可主张逐元件双物种均保守**（实测仅 28%））
③ **装置端封装**（装置权项 → 六单元类 + CLI + `gate_trace.json` 阈值快照 + `qc_report.json` 质控；**必须用真实数据端到端复现主流程数字**才算完成，并在说明书里给出该复现命令 → 构成可实施性证据）
收尾：**三态标注**（✅完成 / ⚠️阴性 / ⏳待补 —— **阴性也标 ✅完成，完成 ≠ 阳性**）、整节回填实施例「待跑项」表、溯源表补「数字→输入→脚本→中间产物」行、`session_memory(pinned=true)` 锚定三项结论与交付路径。

**同类必触发（交付件内嵌图核验）**：用户说"图标要用识图确定""你用识图确定一遍""核对一下图里的数字""图对不对"→ 走 §S4b 内嵌图逐张识图核验（探针 `scripts/verify_docx_embedded_figures.py`）。🔴 **文本级"旧口径零残留"通过 ≠ 图文一致** —— 图里的数字是像素，`grep` 与 python-docx 提段落/表格**都拿不到**；2026-09-11 实测 S4 报"零残留"并据此汇报，却被用户当场追问"你再确定一遍，图标要用识图确定"，抠图后才发现流程图末箱仍写着旧数字 336/37。固定四步：**抠 `word/media/*` → 按字节数反查源图（对上未重出的源图 = 头号嫌疑）→ 逐张 `vision_describe` 取 OCR → 改源图重出后再次识图复验**。

**同类必触发（交底书批判性评估 / 方向门控前提审计）**：用户说"你从专业专利老师的角度评价 <交底书>""从审查员角度评价""从答辩老师角度评价""这个专利能通过吗""作为毕业课题可以吗"→ 走 §方向门控前提审计 流程（`references/substitutability-direction-premise-audit.md` + `scripts/direction_premise_audit.py`）。⚠️ 这类请求要的是**批判性审查**（法条逐条判定 + 授权可能性评级 + 具体修改路径 + 论文能否使用的边界），**不是润色、不是复述其结论、不是夸奖**。核心动作：**用申请人自己的数据自证伪其核心前提** —— 凡 claim 含「同向 / 方向一致 / w(Z₂) / sign gate / concordance」必须跑**反向侧对照检验**（反向侧富集 ≥ 同向侧 → 前提不成立）；凡被引用的效应量必须回源 RDS/表核对**数据层级 + 统计量 + 分母**三项。交付结构（6 节）见该 reference §6。

**同类必触发（claim 前提先行验证 / "为什么一直在变"）**：用户说"**为什么一直在变呢？到底是什么问题，导致你一直在变？**""到底哪个口径？""**这件事究竟能不能作为总体思路**？"→ 走 §claim 前提先行验证 流程（`references/claim-premise-first-verification.md`）。⚠️ 用户要的是**根因 + 确定性结论**，不是道歉、不是再重算一遍。核心判据三条：① **顺序铁律** —— 前提检验（零成本、能杀死 claim）必须先于数字优化，排在后面 = 保证返工；② **收敛信号** —— 连续 ≥3 轮新检验让 claim 单向变弱（从无一轮增强）= **不是摇摆是收敛**，必须停手重估 claim 定位，而不是继续改数字；③ **口径切换不是万能药** —— 缺陷在数据结构（系统性反向）时换口径只改幅度不改结论，立即停止口径纠结。回答骨架（四段式 + 让用户拍板三件事）见该 reference §4。⚠️ **另外两个高频追问同属本流程**：① 「**那为什么之前就可以呢？现在就要改，为什么**」= **门禁等级误判**（该检验当时被判成 🟡 建议、没拦住流程；现在从「待验证」变成「已验证不通过」）→ 见 reference §5；② 「**换到 X 版本难道全都变了？如果没变，为什么不只是替换一些数值就可以了呢**」= **变更层级混报**（把「换口径」和「claim 要改」混着讲，用户误以为是新版口径推翻了旧结论）→ 见 reference §6。

**同类必触发（指标口径是否学界通行 / 「其他文章是怎么做的」/ 「能不能换其他方法」）**：用户问「**我想问问其他文章是怎么做的**」「其他文章也这么算吗」「**只有这一种吗？能不能换其他的计算方法**」「**你都看到同向率低于随机了，是不是说明计算方法有问题呢**」「这不就是智力活动吗」「我们有数据，应该从实际数据找到合适的计算方法，怎么就直接用 z 值了呢」→ 走 §学界通行口径对标 流程（`references/field-standard-metric-benchmarking.md`，2026-09-13 **实读三篇全文**）。⚠️ 要的是**把本方法逐层（对齐 / 打分 / 归一化 / 显著性）与已发表做法对照 + 指出哪一层偏离惯例 + 给出可换的替代口径**，不是复述自己的数字、不是再算一遍。核心四条：① 🔴 **先判问的是「水平」还是「惯例」** —— 「我们的数为什么低」是水平问题、「学界用不用这个指标」是惯例问题，**两者不可互相作答**（与 `null-hypothesis-…` §3「水平 vs 梯度」同源）；② 实测三篇全文 **`permutation` 命中 0、无人报符号一致率** —— 学界比的是**效应量相关或差值**（Wang: `ΔPr = Pr(human) − Pr(ape)` + 卡方 OR；Ogawa: Pearson r > 0.5 判保守；ATACompass 的 transferability 是**定性概念无打分公式**）⇒ 同批数据改报 **r**（本项目 `r(Z₁,Z₂) = −0.0971, n=16,029`，注意 `corr(|Z₁|,|Z₂|) = 0.2248` 是另一个量）即可，报「46.36% vs 50%」= 主动把低点摆上台面；③ **缺的工序通常是「物种内归一化」**（Ogawa: 每物种最强 motif enrichment = 1 再跨物种比）—— 直接聚合跨物种比会把深度 / 信噪 / 锚定粒度差异原样灌进聚合量，正是「一致率随粒度下滑」那类偏置的病根；④ **跨物种对齐有行业标准**（Wang: UCSC LiftOver `minMatch=0.95`）⇒ 「自建统一网格」须写出相对 LiftOver 的额外好处（无 chain 文件也可比 / 支持 tile 级聚合 / 不依赖 minMatch 阈值），否则判常规替代 —— **但反过来证明该技术问题真实存在**。另：**换方法要分清换哪一层** —— 换 tile 级公式（Fisher `atanh(r)√(n−3)` / Spearman / JT `(J−EJ)/√VJ`）**一致率一个百分点都不会变**（符号永远是 sign(r)）；只有换**聚合 / 归一化口径**（中位数·符号多数·强度加权 / `n_eff` 校正 + 空间块置换）才会变。**「为什么非要算 z」的诚实答法**：因为流水线做了基因级聚合、聚合需要可加量（p 不可加、Z 可加）—— 这是**设计选择不是必然**，先承认再说明它绑定了哪一步。⚠️ **专利数据库不通时不得据公开信息推断他人算法** —— 三件专利（WO2020150705 / CN117542414A / US20210225460A1）说明书未取得，只可陈述「谁申请了 / 专利号 / COI 里挖出的关联」，要评算法必须拿到说明书全文。

🔴 **回答风格（2026-09-13 用户当场发作：「我看了你一大堆东西，结论呢？说那么多有什么用呢？下一步的解决方案呢？」）**：本类问题**一律首段给结论**（≤3 句：判定 + 一句依据），证据表在后，末尾收在「**2–3 个可执行下一步 + 需要用户拍板的一件事**」。⛔ 连续多轮只堆证据、结论留到最后 = 用户认为你根本没回答；同轮内不得重复已建立的结论。给完结论仍要保留证据（用户会回来查数），但**顺序不能倒**。

**同类必触发（外部方法升级方案评估 / 「这套思路怎么样」）**：用户把**另一个 AI 或审稿人**给出的方法学改造方案整段贴进来（常见形态：「我建议的完整思路」「这是另一个 AI 的思路和评价」「第一层…第二层…第三层…第四层…」）→ 走 §方法升级方案评估 流程（`references/method-upgrade-plan-evaluation.md`）。⚠️ 要的是**逐层判定 + 可行性核对 + 顺序裁决**，不是附和、不是复述它的结论、不是替它找补。核心三条：① **换更好的估计器 ≠ 造出信号** —— 先把方案分层（效应量估计 / 判定引擎 / 验证轴 / 专利落点），只有**专利落点层**能救一个前提已塌的 claim；② **一切率类指标必须报 (观测率, 匹配零假设, 配对 z) 三元组** —— 只报绝对率变化是把技术假象当生物学改善；③ **方案依赖的资产必须先盘真实库存** —— 方案/论文里写的「23 只 × 8 脑区 × 双模态」不等于本地数据；④ **方案可能下沉一层攻击「观测单位」本身**（组成混杂 / 年龄轴自由度）—— 这类论点通常对且实测更严重，但主判据是**两数据集细胞类型构成是否根本不同**（不同 ⇒ 组织级 pseudobulk 两侧在测不同细胞，跨物种一致性被结构性压低），且报组成必须用**全年龄趋势**、不能只比 Young vs Old 两端；⑤ **方案提议的新判据必查方向** —— 跨物种预测若在粗年龄轴那侧训练（如猴 4 组），MAE 被训练目标颗粒度封顶，正确方向是**信号强的一侧训练、弱的一侧检验**；同时必须**主动肯定它的真价值**（迁移/预测误差算法理上把 claim 与计算对齐，修掉「同向一致性 ≠ 可替代性」的 A22.2/A26.4 硬伤）。一次性探针 `scripts/observation_unit_audit.py`（五段：细胞类型归属 / 组成偏移 / 两物种构成对比 / 资产可行性 / 年龄轴分辨率）。

🔴 **方案下沉到「观测单位」这一层时不能停在定性论点，必须继续跑到定量分解**（用户说「**先跑第①步（组成校正的决定性检验）**」即此）。四判据：① 各细胞类型占比 vs Age 的 Spearman（组成到底动没动）；② **方差分解**（唯一归 Age / 唯一归组成 / 共享）；③ FDR 显著 peak 数「模型 A vs 组成校正模型 B」的**存留率**；④ 按组成载荷四分位的**剂量-反应**。执行见 `references/composition-adjusted-pseudobulk-da.md` + 模板 `templates/composition_adjusted_pseudobulk_da.R`（同批数据只改模型、一次跑完四判据+落盘+出图）。🔴 **两条不许越界的话**：① 校正后显著数塌掉 **≠**「细胞内在信号不存在」—— 组成可能是衰老的**下游中介**而非外生混杂，塞进协变量会连真实总效应一起移除（L1 裁决 `modify`，此条必须主动写进汇报）；② 由此推出的「换观测单位 / 改主口径 / 降级现有结论」属重定位，**交用户拍板，核实轮不动交付件**。

**同类必触发（效果论证 / 「真的不是乱编的吗」/ 靶点能否用文献验证）**：用户问「这个专利是结合 ATAC 的跨物种核心元件筛选方法，**这个前提当然是要有效果了，不然人家反问这个方法真的不是乱编的吗？你怎么回答**」「筛选出来的这些靶点/基因只是方法的一个结果，**验证的话是不是可以找一些文献验证呢**」「我们的方法要求严谨、能够保证效果，是不是就可以了」→ 走 §筛选方法效果论证 流程（`references/screening-method-effect-argumentation.md`）。⚠️ 要的是**可测的效果证据 + 法理锚点**，不是"专利申请不要求结论阳性"一句带过。核心四条：① **效果 ≠ 生物学结论阳性** —— A22.4 只要求「能被使用并产生积极效果」，输出确定、可复现、有量化对照即满足，**不要求被筛出的集合在生物学上被证实**；② **效果证据必须落在方法层**（双实现互证 / 输出带误差控制 / 筛选性能三元组），**不能挂在靶点列表上** —— 用户自己已点明"靶点只是方法的一个结果"，不要在靶点列表上找效果；③ **拿表达类基因集验证可及性元件 = 语义错配**，重叠低 ≠ 方法无效，先判错配再判成败；④ 用户说「我要的就是 XX 筛选方法」时**定位已锁定，禁止再提重定位**。

**同类必触发（第三方评审意见核实 / 「你核实一下」）**：用户把**别人（另一个 session / 另一个 AI / 审稿人）写的审查意见**整段贴进来，说「**这是自查找到的问题，你核实一下**」「这份评审意见对不对」→ 走 §第三方评审意见核实 流程（`references/audit-report-verification.md` + `scripts/scan_docx_text.py`）。⚠️ 要的是**三分类判定**（✅ 我复现为真 / ⚠️ 评审自身写错 / 🟡 评审漏掉我补查），**不是点头附和、不是复述它的结论**。核心动作：**每个数字回源表实跑一遍 + 每句"原文引用"回 docx 提段落核位置**（评审也会编引文、也会标错变量）。实测标本（2026-09-12）：13 项为真 / **3 项评审自己写错**（corr 变量标成 corr(|Z₁|,|Z₂|)、摘要字数虚高、sweep「未给显著性」实为正文没写）/ **2 项评审漏掉**（附图彩色 PNG 不合细则、docx 表与 claims 正文不同步）。🔴 **形态二：审计自带脚本（统计重分析型）** —— 评审**自己重跑置换 / 换零假设 / 换口径**后说「你的正面证据是长度假象」「结论方向反了」（2026-09-13 实测 12 为真 / 1 写错 / 3 漏掉；识别信号 = 审计里出现它自己的脚本清单 + 第一人称实跑叙述）→ 固定四步：**先读审计脚本源码判它的统计量定义与置换对象 → 一个 runner 一次调用跑完全部脚本（一脚本一调用 = 触发循环检测）→ 逐位对账（含 `±`/`z`/`p`）→ 引文另起一遍回 docx 核**。三条新判据：① **统计全对 ≠ 引文全对**（本次统计 12/12 复现、引文仍编造 1 处 → 判「**问题成立、引文不成立**」）；② **审计的「救法 / 新发现」在过匹配零假设前只是假设**，不得进交付件或当结论上报（用词：「这是线索，不是结论」）；③ **审计的重定位建议（改发明名称 / 换保护对象 / 换主口径）一律交用户拍板**，核实轮不动交付件。详见 `references/audit-report-verification.md` §3.5。

**同类必触发（交付件「创新性在哪 / 有什么效果」）**：用户问「**当前这个专利的创新性在哪里？用来干什么的？怎么证明可靠？**」「这个交付件有什么技术效果」→ 🔴 **先核后写，一个都不许凭记忆列**。每条必须先在 `claims.md` / `disclosure.md` / docx 正文里 **grep 到位**；grep 不到的一律不得列入。**区分三种东西：①需求清单里写的（想做）②探针里跑过的（试过）③交付件里真有的（已入册）——只有 ③ 能对外陈述。** 2026-09-12 事故：我按早期需求清单答了「四条创新」，其中「二维经验贝叶斯五态判定 + local FDR」**全目录 grep 零命中**（那只是需求里写的、后来我自写的探针），用户追问「**你确定你用了这个方法了吗？**」并定性「**你这就是造假，误导我**」。自查信号：说不出该条在 `claims.md` 的第几项权利要求 / 第几段说明书 → **停，先去 grep**。

**同类必触发（按审查清单出 vN 新版交付件 / 版本化改版）**：用户贴一份改版清单说「**按上面的清单出一版 v13，范围是：①…②…③…**」→ 走 §版本化改版流程（`references/versioned-deliverable-revision.md` + 模板 `templates/verify_deliverable_version.py`）。⚠️ 要的是**逐项落位 + 全交付件版本同步 + 机器可验的验收证据**，不是只改正文。核心动作：**清单是范围锁 → 复制 v(N-1) 生成器为 vN（不覆盖，docstring 逐项写改什么/为什么）→ 逐项落位（表格/图注/装置实施例等所有复述处都要改）→ 同步 7 份同源 md 的版本标识（必须落在文件头部）→ 一个验收探针一次跑完 6 类检查 → PASS n / FAIL 0**。三条跨领域硬规则：**①置换 n 次 → p 分辨率下限 1/(n+1)，报告值触底时写 `p<0.005` 不写 `p=0.005`；②单双侧必须与 Z 的定义一致（`Φ⁻¹(1−p/2)` = 双侧）且全文一套；③置换次数全文一个值（实际执行 vs 计划不得混用）。**

**同类必触发（增量复审 / 「内容重新完善了，你再次评价一遍」）**：用户交付 v(N) 新版并说「**内容重新完善了，你再次以专利审核员/审查员/答辩老师的角度进行评价**」「按上一轮意见改了，你再看看」→ 走 §增量复审流程（`references/examiner-incremental-review.md` + 探针 `scripts/audit_deliverable_round.py`）。⚠️ 要的是**上一版问题的逐项验收 + 本轮新发现**，不是从头再评一遍、更不是采信"已修复"的自述。核心动作：**读 v(N) 生成器 docstring 拿"改了什么"清单 → 逐项回磁盘独立复核（grep 落位 / 陈旧串零命中 / 数字回源重算）→ 再补一轮上一版没查过的维度 → 交付「修复验收表 + 新发现 + 未修复 + 语义张力」四件套**。铁律：🔴 **生成器自述 ≠ 证据**；历史 [结论] 类事实直接复用不重跑，但**每条"已修复"必须自己验**（2026-09-12 实测：v13 docstring 自称 7 项改动，逐项复核 7/7 真落位，但同轮独立复核仍抓到 3 项新硬伤 —— 自述对 ≠ 无问题）。

**同类必触发（下一会话：正式撰写学位论文 / 「按照硕士填写」「不要有幻觉」）**：用户给学校规范文件 + 素材包路径，说「**我要开始撰写文档毕业论文了，你整理出来并做好标记，全文撰写都要符合这个要求**」「**你把你能写的东西都写上，要求按照真实内容填写，格式按照硕士填写，不要有幻觉**」「**先撰写毕业论文，其他的后面再说**」→ 走 §学位论文撰写 流程（`references/thesis-writing-and-format-compliance.md`）。三步顺序：**读规范产出「硕/博/通」标注版速查 → 读素材包 → 才动笔**。🔴 三条本次实测的新错误类型与纪律：① **正文出现「高于/低于期望」「显著偏离独立假设」必须同轮把算术跑出来** —— 实测原句写「150 显著高于三条件相互独立时的假设值，其原因在于三层证据之间存在正相关」，实算独立期望 **181**、实测 **150 反而更低**（0.83 倍，偏离 2.34 SD），L1∧L2 同为反向（实测 1 604 < 期望 2 063）⇒ **是负向关联、方向写反，且附了一段自造的机制解释**；修法不是改方向词，而是**降级为客观陈述 + 写进局限性**（这类句子读起来完全通顺、数字也都在册，**只有乘一遍才露馅**）；② **计数自洽**（正文「18 组在目标区间外」而表里写「19 组落入区间」→ `175−19 = 156`）；③ **段落增删后同步"计数式引用"**（4.4 由「六条边界」改「七条」后，1.5(6) 的「方法的六条使用边界」必须一起改，`grep 六条` 全库扫）。另四条同族纪律：**「检索式与日期是你另一个会话做的」= 去取证不要编**（检索记录件提**段落+表格** + **用文件 mtime 作日期证据**；记录里写「（建议）检索式」≠ 实际使用式，要主动请用户确认）；**文献检索没命中目标论文就宁可不写**（本会话以 6 篇可核验文献起底，不编 Zemke 2026）；**数据来源查不到就在正文标「待核实」交用户补**（猴侧原论文 23 只 vs 本文 20 例**不得悄悄写成一个数**）；**改稿只改指定清单项**（「已经没问题的就不要动了」= 零润色零重构，顺手发现的新缺陷单列出来问）。

**同类必触发（交底书缺件审计 / 形式项与从权实施例落点）**：用户贴来一份复核清单说「**检索记录 🟡 未做 / 摘要附图 🟡 未指定 / 权 5 权 10 实施例 🟡 未做 / 权 12 支撑力 🟡 偏薄**」并说「**这几个也做一下**」，或问「**交底书也要黑白线条图吗？可以出一套黑白版本**」→ 走 §交底书缺件审计 流程（`references/disclosure-completeness-formal-items.md`）。⚠️ 这类问题的共同点是**不是数字错、是"该有的落点没有"**，修法不是 grep 换数而是**补跑实验 + 补写段落 + 指明附图**。核心四条：① **先判有没有落点，再改文字**（落点缺失时改文字 = 让文档更自洽地缺证据）；② **从权写了 N 种方式/N 项用途 → 每一种都要能指到实施例段落**（权 5 同源对应关系置换要**真跑置换**、权 10 三用途逐项给落点，用途实施例允许"输入输出规格"、不允许编造下游结果）；③ **支撑力偏薄不是改文字** —— 报 (观测率, 匹配零假设, 配对 z) 三元组 + 率类**置信区间**（8/8 的 95% 下界≈0.63）+ 加密阈值看单调性 + **补一个 n 大 4 个数量级的同族实施例**（基因级代理 → 真 bin 级 221,069 单元）；④ **附图形式要件** —— 《审查指南》2.4 要求黑色墨水、不得着色 ⇒ 彩色 PNG 不合规，另出纯黑白版，并用 `PIL+numpy` 量化校验 **彩色像素 0.000%**，两套并存（黑白送审 / 彩色内部与 PPT）。🔴 **但"用填充图案替代颜色"是这里最容易踩的坑** —— 点纹 `...`/交叉纹 `xx` 在 docx 里缩到 ~850 px 后会糊成灰块，用户会当场说「看不清楚，一堆小点点」；**单链流程图一律纯白底黑框 + 反白标题条（黑底白字）**，需要区分时按 `线型 > 空心/实心标记 > 斜纹 ≫ 点纹` 选，且改图必须同时放大字号（框内正文 ≥9 pt）。详见 `references/figure-legibility-and-bw-drawings.md`。

**同类必触发（交底书交付形态 / 「这个真的要写吗？」/ 正文瘦身拆分）**：用户把**代理律师/代理机构给的原始模板**贴出来问「**交底书需要写这个吗？**」「**这个是代理律师给我的文件，希望我按照他们的填，你帮我填了很多东西……有些东西真的要加吗？**」，或拍板说「**按上面结构拆分（正文瘦身 + N 份附件单独成件，内容一字不丢）**」→ 走 §交底书交付形态流程（`references/disclosure-delivery-structure-and-docx-split.md` + 验收探针 `scripts/verify_docx_content_conservation.py`）。⚠️ 要的是**按收件人（代理人）视角做减法**，不是把交底书写成一份可直接提交的申请文件草稿。核心判据一句：**凡是代理人自己能产出的（摘要 / 权利要求 / 检索报告）→ 交底书不写；凡是代理人猜不出来的（你的数据 / 算法步骤 / 实测数字 / 附图）→ 必须写。** 拆分四条铁律：① 🔴 **每个输出件都以源 docx 的副本为底、只删不属于本件的区块** —— 不要「新建文档 + deepcopy 元素」（副本才保得住样式 / 表格边框 / 图片 rId）；② **表号按各件内文档序重排**，不是沿用原序号（区块搬移后文档序会变）；③ **章节重编号 + 跨件引用补「交底书正文」限定词**（`见下文第九节`→`第六节`、`表 1`→`交底书正文表 1`）；④ **「内容一字不丢」必须机器可验** —— 源件每条文本（段落 + 表格单元格）都要在 N 件并集中找到（含意图内改动映射），**未匹配必须为 0**。另：用户说「一字不丢」时**摘要之类不删、只搬到附件**；只额外加**一行**附件索引，并把「要不要这行」交用户拍板。⑤ 🔴 **交底书内不得留任何内部管理信息** —— 版本行（含版本别名"瘦身版"）、数据口径行、内部战略代号（`战略 B`）、内部文件名（`claims.md`）、内部交付路径（`交付目录`/`run_all.sh`）一律清除，且**扫描范围含页眉页脚**（版本行实测就藏在页脚，只扫正文查不到）；修复落生成器不落 docx，探针 `scripts/scan_internal_jargon.py`。

**同类必触发（改图 / 「这图看不清」）**：用户贴一张图说「**这张图修改一下，看不清楚**」「**一堆小点点**」「**干净一些**」「线条太多了」「统一干净的」→ 走 §附图可读性 流程（`references/figure-legibility-and-bw-drawings.md` + 探针 `scripts/check_bw_figure.py`）。⚠️ 要的是**定位到具体的视觉噪声源并消除**，不是重画、不是换配色、不是加装饰。固定三步：① **先定位**（`vision_describe` 读图 + 回看生成脚本里该图的 `hatch`/网格/字号参数，确认用户说的\"小点点/线条\"是哪几个元素 —— 实测就是 ②③④⑤ 方框的 hatch 填充）；② **按规则换区分手段**（单链流程图 → 全去 `hatch` + 反白标题条 + 框内正文 ≥9 pt；多系列图 → 线型 / 空心实心标记）；③ **量化验收 + 重出内嵌件**（彩色像素 0.0000% + 墨迹占比前后对照；docx 内嵌图必须重出，被 WPS/Word 占用则探测锁 → 请用户关闭 → 重跑同名脚本，**不要另存新文件名**）。

**同类必触发（成图标注来源 / 「标题有点遮挡」「为什么是 mouse」）**：用户在成图上提出「**图 5C 的标题有点遮挡**」「**为什么是 mouse 呢？**」「这个标签什么意思」→ 走 §附图标注来源与遮挡 流程（`references/figure-annotation-provenance-and-occlusion.md`）。⚠️ 用户要的是**修图 + 解释图上每个元素的来源**，不是只改图、更不是一句「那是参考库」。核心三条：① 🔴 **外部参考数据集出现在附图里必须标注「来源 + 用途边界」** —— 本方法输入只有人+猴，而图 5C 后验富集用的 Enrichr `Aging_Perturbations_from_GEO` 条目源物种含小鼠/大鼠/人（GSE38671 小鼠神经视网膜、GSE25905 小鼠骨髓脂肪细胞、GDS3895 小鼠下丘脑、GSE14505 大鼠内嗅皮层）⇒ 标签只写 `Mouse neuroretinas 7 w` 会被读成「本方法用了小鼠数据」、与权利要求物种直接冲突。修法 = 标签补齐「**数据集号 + 组织 + 年龄对比 + 源物种**」+ 图内加注「该库为公开参考资源、仅用于后验检验、不构成本方法输入」+ **正文三处同步**（有益效果条 / 数据来源节 / 实施例验证条）；② 🔴 **标签截断（`str(t)[:22]`）是语义事故源** —— 用显式映射表 + `assert set(E.term) <= set(LAB)`，禁止截断；③ 🔴 **图注写在 auto ylim 之外会顶进标题区**（`ax.text(1.05, len(E)-0.42)` → y=4.58 超出轴上限）→ 显式 `set_ylim(-0.70, 4.75)` + 图注移进轴内 + 同一信息在 xlabel 重复一遍。验收：`vision_describe` OCR **取坐标**（标题 y=24 / 次行 85 / 图注 214 = 通过）+ 彩色像素 0 + 未改动图与上一版**逐字节一致**。⛔ 不要为消除「mouse」字样而删条目 —— 保留原始数字 + 标注来源，把「要不要换库」交用户拍板。

**同类必触发（物种分层换库验证 / 「换成人类来源的库再验一遍」「两个物种效果都不错就一起放」）**：用户在「为什么是 mouse」之后进一步说「**你试试人类来源衰老的签名库验证一下，老鼠的也可以保留**」→ 走 §物种分层换库验证 流程（`references/species-stratified-signature-library-validation.md`）。**用户接着答「按照你想的做」/「你决定」时进入收口阶段** → 走 §双库定稿收口 流程（`references/dual-library-finalization-and-single-source-of-truth.md`）。🔴 收口两条：① **「按照你想的做」= 授权 + 期待成品** —— 端到端执行自己刚提出的推荐（出图 → 改生成器 → 出 docx → 一次跑完的核验探针 → 回写交付索引），**执行途中发现的新缺陷一并修掉并汇报**（本次实测：执行「两个库都放」时才发现图 5C 的 A 面板用 400 条合并库、B 面板用 270 条单库 = **同一张图两套口径**，且合并库恰把唯一显著结果稀释掉）；② 🔴 **同图多面板口径必须一致** —— 逐 `ax` 回看数据来源变量（集合 / `nperm` / seed 三者都要同），主口径用**单一策展库**，合并或敏感性口径**写进图注如实披露**（不是删掉）。🔴 **本条修正了本 skill 上一版的一条判断**：旧措辞写「GTEx 口径富集更弱 → 不建议换库」—— **该判断在条目级成立、在库级被实测推翻**：条目级鼠类唯一过 FDR（层内 0.027）而人类 GTEx 层内 FDR=0.81 不显著；**库级反过来 —— 人类 GTEx 元签名 net 分值 AUC=0.547 / 置换 p=0.013 是唯一显著者**，鼠类仅趋势（p=0.063）⇒ 真结论是「**人鼠两库互补，不是谁更弱**」。四条可直接复用：① 🔴 **「换个来源物种的库再验一遍」这类要求必须真跑，不许用旧结论「那个更弱」挡回去**；② 主口径用**方向净分值 `net` = Up 条目命中数 − Down 条目命中数**（计数 `cnt` 实测 AUC=0.492 / p=0.614，完全无信号），检验 = Mann–Whitney + **AUC** + **置换 n=1000**（库内条目高度相关，置换把相关性留在零分布里，优于对条目做 BH）；③ 🔴 **强库 + 弱库合并 = 稀释**（GTEx 单独 0.013 → 人类合并 400 条 0.093）⇒ **分层保留**，合并口径只作敏感性对照；④ 出图 = **每个物种一张同口径对称图**（5C 人类 / 5D 鼠类：A 库级置换零分布 + B 条目级 top-5），图注必写源物种 / 条数 / 用途边界 + 「与图 5X 口径逐字相同」。另附「为什么是 mouse」的**三段根因链**（数据层：多物种库人条目一直都在 / **展示层：只画 top-5、而 top-N 排序系统性隐藏某一类来源 = 真根因** / 标注层：22 字符截断）—— ⛔ **不得把「某来源不进 top-5」说成「没信号」**，那是把展示口径问题误报成数据问题（与「判『死』前先核它在不在」同源）。

**同类必触发（专利战略层问答 / 「旧方法还能用吗」）**：用户问「**你自己也做了新的尝试，你是觉得我们之前的 X 方法能申请专利呢？还是继续新的方法呢？**」「**我的述求只有一点：<一句话定位>**」「算了，继续回到专利设计」→ 走 §战略层定版与自洽性审计 流程（`references/claims-generation-and-layer-audit.md`）。⚠️ 🔴 **第一步不是分析，是定版** —— 交付目录常并存多代权利要求书，拿已作废的旧代次答战略问题 = **前提错、方向必反**（2026-09-13 实测：读了 9/4 的 `min` 版答"继续用 z 方法"，而现行 v15 独权恰是 `S=Z₁×w(Z₂)`）。定版三步：列候选（`*claim*` / `*权利要求*`，交付目录 + `patent/` + 项目根**三处都查**）→ 版本号 + mtime + 决策链文档（`结论_*.md`）交叉判现行 → **旧代次立即移入 `archive/`**（未归档 = 误送风险，成本零）。核心判据四条：① **结构分层**（独权 / 从属权 / 优选实施方式）只用来判断"口径变更要不要动独权"，**绝不能推成"独权立得住"** —— 区别特征的实测效力要独立核（反向侧对照 + 匹配零假设三元组）；② **改版理由对撞扫描**：把历代"因为 X 所以放弃/采用 Y"按时间排开问"这条今天还成立吗"（实测：放弃 min 的理由被后续版本自己撤回，三轮无人复核 → **没人回头复核的决定 = 最高优先级**）；③ **产物路径一律给绝对路径全串**（片段路径 + 别人的搜索根 = 被误判造假；反之核实"查无来源"指控先核对搜索范围）；④ 组成校正类结论只写**技术问题的发现** + 优选写**分层聚合**，不写 CLR 协变量、不写效果数字。

**同类必触发（空位归因 / 「为什么他们不申请专利」）**：用户问「**为什么他们不申请专利？**」「**为什么没人做这个方向？**」「这个领域是不是没有专利」→ 走 `references/patent-gap-attribution-and-negative-result-strategy.md` §1–§5。⚠️ 🔴 **先把问题问准** —— 不是「他们不申请」（这个问法会导向\"学者不需要专利\"这类**解释不了企业**的通用理由），而是「**有技术效果的都申请了，为什么唯独我这一条路径没人申请？**」。核心动作：**逐格取证**（谁 / 申请了吗 / 证据；隐藏申请常藏在**论文利益冲突声明**里——Horvath WO2020150705 就是从 *Nature Aging* 的 COI 逐字挖出的）→ 给**两条硬理由**（① **输出的技术效果不可测量** → 落 A25(二) 智力活动规则，这是\"连企业也不申请\"的第一个真原因；② **没有买方**——研究豁免 → 不侵权 → 无人付钱）→ 最后给**镜像答案**（他们缺的是**标定用负对照**，而那正是你手上唯一的东西；但必须加诚实边界「从没法写变成了可以写」≠「稳了」）。⚠️ 检索源判定：**401 ≠ 000**（401 = 网络通、只缺 API key，是唯一有救的口子）；200 可能只是跟随后落到 HTML 落地页 = **伪可用**，判据必须是 body 首字符，且必须声明\"没检索到\"的**射程有限**。

**同类必触发（🔴 审计汇报 / 「怎么搞了半天，专利越来越不行了呢」）**：用户对**审计过程本身**表达情绪（「**怎么搞了半天，专利越来越不行了呢？**」「**我是不是白做了**」「越来越不行了」）→ 走 `references/patent-gap-attribution-and-negative-result-strategy.md` **§6 审计汇报的\"单向悲观漂移\"** + §7 回答骨架。⚠️ 这不是技术问题、是**汇报方式问题**：本轮实测两条\"bug\"警报（`z=−qnorm(p/2)` 被当漏写负号 / 稀疏 tile \"ties 丢失\"）**全部被实测推翻并撤回，但撤回是安静的、报警是响的** ⇒ **我的消息时间线系统性偏悲观**，用户对对象的评价随之逐轮下降，而**对象本身没变**。四条修正纪律：**① 报警前先在当轮跑完验证；② 撤回与报警同等醒目（当轮开头明说）；③ 每条发现必标 🔴改变 go-no-go / 🟡只影响表述 / ⚪仅归档——不给等级的不许进正文；④ 汇报\"当前判定\"而非\"警报流水\"**。回答骨架必须**分三块**（真走低的=生物学证据【措辞：这些数在复核前就是真的，是\"从不知道变成知道\"，没做审计就是审查员替你发现】/ 没变的=方法资产【明确说\"这几轮一次都没动摇过它\"】/ 我这边的问题=报告方式【主动认领，不等用户问】），再给「**专利与毕业课题价值曲线相反**」的重构（负结果对专利是负担、对课题是资产），收尾**收敛到选一条 A/B**（继续走专利 = 不再做新分析只收尾文书 / 转课题 = 把负结果做成正式结论链），并说明**来回切换本身就是漂移的来源**，用户拍板前不动交付件。

**同类必触发（零假设选择 / 「随机比我们计算的高」）**：用户问「**随机比我们计算的高，是不是证明你计算的方法有问题？**」「为什么观测低于随机」「这个 p / 这个期望是怎么来的」，或审计他人用「**匹配基准率（matched base rate）**」构造的零假设 → 走 §零假设循环性审计 流程（`references/null-hypothesis-selection-and-circular-null-audit.md` + 探针 `scripts/detect_circular_matched_null.py`）。⚠️ 要的是**零假设分层判定表 + 循环性三判据 + 「低于随机」的两层判读**，不是重算一遍数字。核心三条：① **先问"期望值是从哪儿来的"** —— 外部先验 / 置换经验分布 可用于检验；**观测自估 = 循环、永不可失败**；② **循环性机器可判定**（包含性 `mask\顶层==0` · 等值性 `expB==该层观测率` · 不可失败性 `zB≈0`，任一成立即判循环）—— 实测标本：强效应池 1,409 **全部落在 `|Z_h|` 顶箱 1,603 内**，`expB=0.4136` 恰为顶箱自身观测率，`zB=−0.041` 是恒等式，交付件却拿它消解「低于随机」的告警；③ 🔴 **「观测低于随机」不是计算错误的证据** —— **bug 产生围绕零假设的噪声（无方向、不可复现），不会产生有一致符号的系统偏差**（实测 z=−6.66、可复现、单向）⇒ **计算层没问题，被打的是 claim 的效果层**（同向率 < 随机 ⇒ 「同向⇒可迁移」不成立），两层必须分开说。凡用循环零假设把「低于随机」解释掉的句子，必须删除或改层内置换重算。

🔴 **负结果不得写进说明书（自证无技术效果 = 自杀，本类最致命的错误）**：专利必须有技术效果。若在说明书里论证「本方法的结果显示该方向不可用 / 不一致 / 低于随机」，等于**自证这个权利要求产生的输出没有技术效果** → 无实用性 → 驳回 —— **你会用自己的数据把自己的专利否掉**。可授权写法一律是「**输出可复现、有明确判据、可判定**」+「**用于标定**参考物种能否作方向参考，并给出该判定的失效边界」，**不是**「证明了某个生物学结论为真」。一句话记法：**技术效果 = 方法的可执行性 / 可复现性 / 可判定性**。详见 `references/patent-gap-attribution-and-negative-result-strategy.md` §3。

## 执行流程

### Step 1: 定位专利文件

用户通常提供 .caj 文件（CNKI知网格式）或专利号。

**CAJ 文件处理（重要）**：
- .caj 是 CNKI 专有二进制格式，**无法直接解析**（strings/zlib 提取均失败）
- **必须回退到 Google Patents 下载 PDF**：URL 模式 `https://patentimages.storage.googleapis.com/{hash}/CN{number}A.pdf`
- 优先从用户提供的 .caj 文件名提取专利号（如 `一种跨物种单细胞注释方法_阮航.caj`），然后搜索在线 PDF
- 🔴 **解析一次判死，不要回头再试**：`.caj` 的 KDH 头已复验（`KDH 2.00 Copyright(C) 2000 CAJCD`；strings/zlib 全文件扫描无明文流）⇒ **格式结论是确定的，不要每轮重新尝试解析或换解压姿势**。2026-09-13 实测：用户一次给了 5 篇 `.caj`，本轮把时间花在重复验证格式上，最后仍未取到权利要求原文。
- **取全文的两条可用路径**（按序试，各自失败一次就换下一条，**不循环重试**）：① `browser_navigate` 打开 `https://patents.google.com/patent/CN<号>/zh`（或镜像 `patents.glgoo.top`），再用 `browser_console` 取 `document.body.innerText`；② 上面不通 → **直接向用户索要 PDF**（或请用户给公开专利号由你代查）。用户手上常有 PDF，比换着法儿绕网络快得多。
- ⚠️ **别把"取不到原文"拖成整轮任务**：若用户同时提了别的正事（如专利设计），**先把取不到这件事一句话说清、给出上述两条路径，然后继续正事** —— 2026-09-13 实测用户下一句就是「算了，继续回到专利设计」。

**PDF 下载后**：

for page in doc:
    text = page.get_text()

### Step 2: 结构化拆解（必须覆盖的 6 个模块）

每篇专利解读必须包含以下全部模块：

1. **基本信息卡**：专利号、申请人、申请日、状态（审中/已授权）、IPC分类
2. **背景与问题陈述**：它要解决什么痛点？它点名批评了哪些现有技术？
3. **核心方法逐步骤拆解**：用 Mermaid flowchart 画出 S1→S2→... 的技术路线
4. **权利要求逐条分析表**：每项权利要求 + 保护内容 + 独立/从属 + 对你的影响评级
5. **实验验证数据**：用了什么数据集？对比了什么方法？结论是否可信？
6. **与用户项目的交叉分析**：
   - ✅ 它没覆盖的（用户的创新空间）
   - ⚠️ 需要规避的方法要素 + 替代方案
   - 📋 必须引用的现有技术声明

### Step 3: 输出格式

- 交互框中展示完整结构化解读
- 同时保存为 Markdown 报告到 `results/{session_dir}/patents/{专利号}_analysis.md`
- 如果用户有多篇专利需要横向对比，追加对比总表（维度 × 专利矩阵）

## ⚠️ 常见陷阱

| 陷阱 | 说明 |
|------|------|
| .caj 文件无法直接读取 | 不要花时间尝试解析 CAJ 二进制格式。直接用 Google Patents 下载 PDF |
| 只分析前几条权利要求 | 必须覆盖所有权利要求，从属权利要求中的细节往往是规避的关键 |
| 忽略"审中vs已授权"的区别 | 已授权专利的保护范围需更严格规避；审中专利的保护范围可能缩小 |
| 不区分独立/从属权利 | 独立权利要求保护范围最宽，从属权利可被绕开 |

2. 🔴 **handoff 里的方法标签可能是错的，产物列名比文档文字可信。** 本标本 handoff 写「对齐用 **liftOver**」，但本地唯一 chain 是 `E:/专利/rheMac3ToHg38.over.chain.gz`（**2010 年 rheMac3 旧装配**），坐标体系与命名跟猴侧新装配 T2T-MFA8 全不兼容 → 套用 = **静默错映射（不报错、结果全废）**；而 handoff 自己目录里的 `crecs_tile_hg38_monkey_map.csv` 列含 **`anchor_dist`** ⇒ 实为**同源基因锚定**产物，是文档贴错标签。⇒ 跟文档前先核「**方法标签 vs 磁盘真实产物**」（产物列名 / 生成脚本 > 文档叙述）。
3. 🔴 **交付件里凡是占位数字 = 未完成，必须标 DRAFT 并说明缺哪一步。** claims / disclosure / abstract 三件套写出来但核心数字仍为占位符时，**不得对外称「方案已完成」**。正确形态 = 另出一份 `vN_执行现状与剩余执行链.md`：**已跑（可复用资产 + 绝对路径）/ 待跑（步骤链）/ 数量级预期 / 精确数字待哪一步产出**。用户宁要「如实标注的待跑清单」，不要「看起来完整、数字却是编的」。
4. 🔴 **每次自称「已落盘 / 已交付 / 已完成」，必须在同一轮用 `search_files` 自证一次。** 本标本：连续两轮声称「总索引已写好 / 过夜交付完成」，用户问「跑完了吗」时 `search_files(target="files")` 在声称目录 **0 命中**，会话目录里只有 Phase 0 的产物 ⇒ 声明与磁盘不符（真相：只有 4 份 v21 文档、**零计算产出**，`l1_v21_baseline.py` 有脚本但从未产出 `L1_v21_scores.csv`）。**自证配方**：
   ```
   search_files(pattern="<声称文件名关键词>", target="files", path="<声称的目录>")
   + 列目录 mtime（terminal: ls -la <目录>）
   命中 0 或 mtime 早于本轮 → 声明作废，当场改口说明真实进度
   ```

**汇报骨架**（用户问「跑完了吗」时用；先三源验证再开口）：表格给 **GPU / 进程 / 磁盘产出** 三行实测 → 一句判定「**跑完 / 只交付了文档层 / 一步没跑**」→ 已交付件**绝对路径全串** → 未跑步骤链 → 结尾问「要现在开跑吗」。⛔ 禁用「基本完成」「差不多好了」「已交付」这类无磁盘依据的模糊词。

⚠️ **同类形态：被要求「自主设计几个方向」时，必须先声明既有主线在新方案里处于什么位置。** 本标本用户先说「你自己设计执行…也可以是好几个」，我交出 3 个全新方向却**未回答既有 handoff 主线怎么办** → 用户立刻追问「**NEW_SESSION_HANDOFF 这个里面的方案不行吗？**」。⇒ 清单式自主设计必须显式包含一节「**既有主线的判定**」（采用 / 并入为方向 N / 因某负结果废弃），否则用户读到的是「你把我的主项目丢了」。

### 审查员三类驳回及防御

| 驳回 | 法律 | 话术模板 | 防御 |
|------|------|---------|------|
| 智力活动规则 | A25 | "全是数学统计方法的组合" | 强调具体技术手段(ESM-2嵌入/pseudobulk聚合/批次残差化)+产业效果 |
| 显而易见 | A22.3 | "D1+D2+D3+D4组合是显而易见的" | 证明组合产生单个步骤不具备的协同效果 |

| 概念偷换「claim A 算的是 B」 | A22.2/A26.4 | "你 claim '可替代性评估方法'，但独权通篇只算'两物种年龄效应同向且双侧显著'" | 🔑 可替代性(surrogacy/substitutability，指"用动物结果预测人、误差有多少")≠同向一致性(concordance，指"两边都随年龄变化且方向一致")。S=min(｜Z_m｜,｜Z_h｜)×sign 从头到尾算的是同向一致性。要 claim "可替代性"，独权必须多一步「预测外推＋误差量化」(如猴侧年龄→效应量拟合、外推预测人侧效应量、报 RMSE / 预测-实测 Pearson)。否则审查员一句"claim 的是 B、教导的是 A"驳回 |
