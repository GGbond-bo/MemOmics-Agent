## §0 定位：收件人是「学生自己的论文」，不是代理人 / 律师 / 审查员

与本 skill 其他交付形态的区别一句话：

| 交付形态 | 收件人 | 优化目标 |
|---|---|---|
| 送代理人 | 专利代理师 | 做减法（他自己能产出的不写） |
| 送律师/导师 | 律师、答辩老师 | 单文件完整版 + 形式要件齐全 |
| **论文素材包（本文件）** | **学生自己 / 学校格式要求** | **可溯源 + 零虚构 + 方法可复现，供后续按格式编写** |

⇒ 🔴 **不要复用送审版交底书的判断标准**：论文素材包里**权项框架、检索记录、对比专利著录项全部要保留并前移**（论文的「创新点 / 讨论 / 参考文献」章正好吃这些），而**形式要件（黑白附图纯色校验、300 字摘要上限、申请人栏位）退居次要**。

## §2 🔴 三条硬纪律

### 2.1 零虚构 = 搬运，不重算

用户原话「**确定不要虚构内容，专利用到什么就用什么**」。含义是**不要为了补全包而新算数字**：

- ✅ 从已有产物 `grep` / `read_file` 取数 → 写进速查表并**带上出处文件列**
- ✅ 资产（CSV/JSON/PNG/脚本/专利原文）**原样拷贝**，不重算、不重绘
- ❌ 不要「顺手把缺的那几个数补算一下」—— 补算出来的数字**不在交底书里**，写进速查表就制造了「交付件里真有的」与「我新算的」混淆（同族事故见 SKILL.md「凭需求清单列举创新点 = 造假」条）

**速查表的标准列**：`数字 | 值 | 出处文件 |（可选）生成脚本`。凡是填不出出处文件的数字 = 不许进表。

### 2.2 🔴 方法章必须读**代码**，不能读交底书的叙述

**实测差例（本次真实抓到）**：

| 来源 | 表述 |
|---|---|
| 交底书正文 | 「在基因体 ±2 kb 窗口内的每个可及元件单元上，**逐碱基提取**系统发育保守性轨迹的保守分值，并以该单元内保守分值的**均值**聚合」 |
| 实际代码 `v21_step1_gene_table_L1.py` L45–98 | 读 `l1_full_human.csv`（**peak 级** 524,256 行），用 `searchsorted` 取与窗口重叠的 peak 子集，对该子集的 `p100_mean` 列取 **`nanmean`** |

差别不是修辞：前者描述的是"逐碱基聚合"（单元内所有碱基的均值），后者是"**peak 级先聚合再取均值**"（两级聚合，跳过未落在 peak 内的碱基）。**论文写后者，否则是方法学陈述不实。**

⇒ 配方：`read_file` 读 `04_脚本复现/` 里的 step1/step2 正本代码 → 逐步骤抄它的**实际函数与列名** → 与交底书叙述逐句对照 → 不一致处以**代码为准**并在总索引里单列一节说明差异（不要偷改交底书，那是送审件）。

### 2.3 🔴 包内必须显式列出「⛔ 不得引用的旧口径清单」

**这是本类任务最危险的坑**：交付目录里**旧代次档案与现行件并存**（本次实测：`_archive_旧口径/`、`A级核心元件_357_all.csv`、`双侧铁证核心元件_16_all.csv`、`反向分歧元件_19_all.csv`、`A22.3_对比实验与答辩论据.md` 与现行 v21/v28 件同盘）。论文作者（学生自己）翻到哪个用哪个 → 写串口径 → 数字自相矛盾。

⇒ 处理：在 `00_总索引` 与 `07_结果数字速查表` **各写一节**「不得引用的旧口径」，逐条给 **旧值 + 为什么不能用**：

| 旧口径数字 | 为什么不能用 |
|---|---|
| 357 元件 / 16 双侧铁证 / 19 反向分歧 | 属旧方案（非对称评分 + 方向一致性） |
| 召回 25.3% vs 1.1% | 旧方案上的对比实验，已从交付件删除 |
| 同向率 46.36% | **负结果**（< 随机 50.2%），是「旧方案被否的证据」，不是本方法的成绩 |
| FDR = 0.0219（286 条子库） | 已被现行双库口径取代 |

并声明 **`03_数据结果/` 内 CSV 全部为现行口径、可放心用**（用位置保证法降低误用概率）。

## §3 主张边界表 = 论文「局限性」节的现成素材

论文必须比专利**更诚实**（专利可以把阴性藏进从属权，论文藏不住）。把交底书里三态标注（✅完成 / ⚠️阴性 / ⏳待补）中的**⚠️阴性全部转成边界条目**，一次列全：

| # | 边界 | 依据数字 |
|---|---|---|
| 1 | **不主张「筛出的元件是经典衰老标志物」** | 经典细胞衰老通路**不富集**：Reactome Cellular Senescence 2 hits p=0.361；KEGG hsa04218 2 hits p=0.384；SASP 0 hits |
| 2 | 方法筛的是「随年龄发生调控变化的保守元件」，非「衰老基因」 | L3 定义为物种内年龄效应统计量 |
| 3 | **某侧保守性只能在聚合层/富集层主张**，不能主张逐元件双物种均保守 | 双物种均保守仅 42/150 = 28% |
| 4 | 人类库**条目级未过 FDR**（0.811），其显著性是**库级** | 条目统计 CSV |
| 5 | 鼠类库**库级只是趋势**（p=0.058），强度在**条目级 FDR** | 权威 stats JSON |
| 6 | 输出规模依赖阈值口径，须报告敏感性 | 175 组扫描中仅 19 组落目标区间 |

## §4 🔴 新发现的数据错误类型：`min_*` / `max_*` 汇总字段跨行混引

**本次实测标本**：交底书正文写

> 「最强条目富集 **4.5 倍**（**10 个**核心元件命中、p = **7.7×10⁻⁵**、库内 **FDR = 0.027**）」

回源表 `v28_fig5d_mouse_entry_stats.csv` 逐行核 → 这 4 个数字**分属两个不同条目**：

| 条目 | hits | fold | p | 库内 FDR |
|---|---|---|---|---|
| Mouse neuroretinas 7w vs 64w GSE38671 | **10** | **4.53** | **7.65×10⁻⁵** | 0.0338 |
| Mouse bone marrow adipocyte 6m vs 14m GSE25905 | 8 | 5.41 | 1.20×10⁻⁴ | **0.0266** |

**根因**：权威 stats JSON 里同时存了 `min_entry_p` 与 `min_entry_fdr` —— 这两个是**独立求 min 的汇总字段，天然可能来自不同行**。写句子时把它们当成"同一个条目"的并列属性 → 跨条目混引。**这类错误 `grep` 抓不到、stale 串表也抓不到**（每个数字单独看都对、都在册），只有回原表逐行核才发现。

⇒ 两条可泛化规则：

1. 🔴 **凡引用 `min_*` / `max_*` / `argmin` 类汇总字段写句子，必须回原表逐行找出这些极值各自属于哪一行；不同行就不能拼成一件事**（要拼就明确写「p 最小者 ……；FDR 最小者 ……」两条分列）。
2. 🔴 **JSON 里同时存 `min_X` 与 `min_Y` 就是一个陷阱** —— 生成器要么改存**单条记录**（`best_entry: {...}`），要么在字段名里写明它是最小谁（`min_p_entry_term` / `min_fdr_entry_term`）。发现后**先向用户报，不要擅改送审件**（本次即原样归档 + 在总索引 §八 与速查表 §五 双处标注待用户拍板）。

## §5 数据可用性节的诚实边界

- **查不到来源一律不编编号**。本次猴侧 20 例交底书写「申请人在本实施例中取得的对应组织测序数据」→ 素材包补一节「待你补充」（若是公开数据集给编号、若是机构提供给名称），并说明**论文的数据可用性声明需要它**。
- 人侧写全：**GSE278576**（人类海马单核多组学图谱，2026 年公开释放）+ 明确「本方法对该公开数据仅施加统一网格映射与三层证据统计处理，未改变其原始内容」。
- **外部参考库必须带「用途边界」句**：签名库「仅用于后验富集检验，**不构成本方法的任何筛选步骤输入**」；并写明条目**基因符号已统一为人类同源符号**（这是能拿它检验人/猴锚定基因的正当性依据）。
- **试过但不可用的资源要单列一节**（⛔ 不得引用为已用）：本次为 SenMayo / CellAge（下载得到 683 B 的 404 残页，从未真正取到）、HAGR 站点不可达。

## §6 执行顺序（一次跑完，避免循环检测）

```
① 侦察：ls 交付目录 + find 现行件/溯源档案 + 定位 v<N> docx
② 读正文：read_file 读 docx（平台 read_file 会自动抽 .docx 文本）→ 通读全文取章节结构
③ 读代码：read_file 读 step1/step2 等核心脚本（§2.2 —— 方法章必须据此写）
④ 取数：read_file 读关键产物表头 + 统计 JSON（数据字典与速查表的原料）
⑤ 拷贝资产：一次 terminal 收完（`cp` 到 7 个目录 + `du -sh` 报总量）
⑥ 写文档：8 份 md 用并行 write_file 分批落盘（每批 4 份）
⑦ 汇报：包树 + 各文档职责 + 三件我专门做了的事 + 发现的数字问题 + 待用户补充项
```

🔴 **不要「想到一项检查就再写一个探针脚本」** —— 与 SKILL.md「一产物一探针」同源；本类任务最终交付物是**文档包**，核验靠写文档时逐条回源读，不靠额外探针脚本（顶多收尾一次 `ls -R` 确认件数）。

## §7 汇报骨架

1. **包位置 + 体量 + 文件树**（每个目录标注「N 个」）
2. **三件我专门做了的事**（对应用户的三条要求）：
   - 零虚构、可溯源 —— 举 **2 个具体例子**（如「L1 通过 3,180」追到 `v21_step2_summary.json`；「ρ=0.764」追到 `v21_monkey_L1_stats.json`）
   - 写明「怎么做的、各步骤是什么」—— 指出 `S1-S5_方法与步骤全解.md` 与**真实代码逐行对得上**
   - 标出不能用的东西 —— 指出「⛔ 不得引用清单」落在哪两处
3. **顺带发现的数字问题**（§4 那类）—— 明确「我原样归档、未擅改送审件」，并问要不要同步改专利
4. **等用户提供什么** —— 学校格式要求；以及不用再给任何数据文件（已自足）

⛔ 不要在这一轮就写论文正文 —— 用户明说「**我会给你我们学校的论文要求，然后需要你在新会话编写**」。素材包 ≠ 论文。
