# 物种分层的衰老签名库验证 —— 「换个来源物种的库再验一遍」

> 触发场景（2026-09-15 实测）：用户在成图上发现「**为什么是 mouse 呢？**」之后，
> 进一步说「**你试试人类来源衰老的签名库验证一下，老鼠的也可以保留，如果两个物种
> 效果都不错，可以一起放，你觉得呢？**」
>
> 上一版回答（见 `figure-annotation-provenance-and-occlusion.md` §1）只做了「标注来源」，
> 并把「换 GTEx 库」列为「**更弱的库，不建议换**」。**本文件是对该判断的实测修正。**

---

## 1. 🔴 先纠正一条被写进 skill 的错误判断

上一轮沉淀的措辞是：

> ⛔ 不要为消除「mouse」字样而删条目或换更弱的库（GTEx 口径富集更弱）—— 保留原始数字 + 标注来源。

**这句在「条目级」成立、在「库级」被实测推翻。** 实测（150 核心元件 / 16,029 背景）两套口径结论相反：

| 口径 | 人类 GTEx（270 条） | 鼠类 GEO（442 条） |
|------|--------------------|-------------------|
| **条目级**（超几何 + 层内 BH） | 最小 p=0.0072、**层内 FDR=0.81（不显著）** | 最小 p=7.7e-05、**层内 FDR=0.027（唯一显著）** |
| **库级**（元签名 net 分值 AUC + 置换） | **AUC=0.547、置换 p=0.013（唯一显著）** | AUC=0.535、置换 p=0.063（趋势） |

⇒ **正确结论不是「GTEx 更弱」，而是「人鼠两库互补」**：鼠类条目级强，人类库级强。
**收到「换个来源物种的库再验一遍」这类要求时，必须真跑，不许用旧结论「那个更弱」挡回去。**

---

## 2. 「为什么是 mouse」的完整根因链（回答用户时要讲清）

三层，缺一层用户就不满意：

1. **数据层**：`Aging_Perturbations_from_GEO_up/down` 是**多物种**库（286+286 条，含人/鼠/大鼠）。
   人条目一直都在，从未缺席。
2. **展示层**（真正的根因）：旧 5C 只画**条目级 top-5**，而 top-5 恰好被小鼠/大鼠占据
   （它们 p 最小：GSE38671 神经视网膜 4.53×、GSE25905 骨髓脂肪细胞 5.41×）⇒ 人类条目排名靠后、**从没被画出来**。
   🔴 **这不是数据问题，是展示口径问题** —— 「top-N 排序」会自动过滤掉某一类来源。
3. **标注层**：y 轴标签截断到 22 字符，只剩 `Mouse neuroretinas 7 w`，源物种信息被截掉。

⇒ 修法 = **按来源物种分层重算 + 每个物种各出一张图**，而不是只改标签。

## 3. 执行配方（可直接照做）

### 3.1 分层

```python
GU = parse_enrichr('.../Aging_Perturbations_from_GEO_up.txt',  'up')   # 方向按文件传，别按名字猜
GD = parse_enrichr('.../Aging_Perturbations_from_GEO_down.txt','dn')
GT = parse_enrichr('.../GTEx_Aging_Signatures_2021.txt', None)          # 该库条目名带 Up/Down，可从名字读

HUM = GT + GEO 中含 'human' 的条目        # 270 + 130 = 400
MUS = GEO 中含 'mouse' / 以 'rat' 开头的条目   # 442
```

🔴 **两个必踩的坑**（详见 `functional-enrichment` 的库级元签名文档；此处只列判据）：
- up/down 用 `{**up, **dn}` 会因**条目名相同**而静默吞掉一半（实测 130→65、442→221）→ 用复合键 `f'{tag}||{term}'`
- 从条目名判 `'down' in term` 会**全判成 up**（方向写在文件名上）→ 指纹是 `net(g) ≡ cnt(g)`（两者 AUC 完全相等）

### 3.2 两个统计量都要跑

| 统计量 | 定义 | 实测结论 |
|--------|------|---------|
| `cnt(g)` | g 出现在多少个条目里 | **主口径禁用**（人类 GTEx AUC=0.492、p=0.614，完全无信号） |
| **`net(g)`** | Up 命中数 − Down 命中数 | ✅ **主口径** —— 信号全在这里 |

检验 = `mannwhitneyu(core, bg, alternative='greater')` → `AUC = U/(n_core×n_bg)` + **置换 n=1000** 求经验 p。
**置换优于对条目做 BH**：库内条目高度相关，置换会把这份相关性原样留在零分布里。

🔴 **置换次数与随机种子必须全文唯一**（2026-09-15 v28 实测踩到）：
`n=1000` 且 seed 未固定时，同一数据两次运行给出 **p=0.059 / p=0.063** ——
图上标一个、统计 JSON 存另一个，复核者问一句「哪个是对的」就穿。
定稿配方：**`nperm=5000` + `seed=42` 固定 + 一次运行写出权威 `vN_*_stats.json`，
图与正文数字全部从该 JSON 取**（图必须是同一次 run 的产物，**禁止分两次跑**）。
置换 p 的分辨率下限是 `1/(nperm+1)`，`n=5000` 时最小可报 **p<0.0002**。

### 3.3 🔴 分层保留，不要合并口径

实测：GTEx 单独 p=0.013 → 「人类合并库（GTEx+GEO-human，400 条）」p=**0.093**。
**强库 + 弱库合并 = 稀释。** 报告时按来源物种分开列；合并口径只能作敏感性对照。

### 3.4 出图：两个物种 → 两张对称图

🔴 **2026-09-15 v28 修正（本节早期版本是错的，且它的错误被实际执行了一轮）**：
早期版本把图 5C 的库定义写成「GTEx 270 + **GEO 人类 130**」= 400 条合并库，
于是生成器里 `HUM = {**GT, **GEO-human}` 画 A 面板、`GTEX_ONLY` 画 B 面板
⇒ **同一张图两个口径**，且合并库把强信号稀释（AUC 0.532 / p=0.081 画在图上，
而真正显著的 0.547 / p=0.008 只存在于统计 JSON 里）。
**现行写法 = 单库做主口径 + 合并口径只进图注。**

```
图 5C　人类来源库 = GTEx 270（人源单一策展资源，**A、B 两面板同库**）
  A 库级元签名检验（置换零分布 + 观测 AUC 竖线 + 标注 AUC/p）
  B 条目级前 5 位富集倍数（**必须与 A 同一个集合变量**）
图 5D　鼠类来源库（GEO 小鼠/大鼠 442）  ← 与 5C 统计量 / 置换次数 / 随机种子逐字相同
```

⚠️ 图注必须**如实披露**合并口径（「并入 GEO 人类扰动 130 条后 AUC 0.532、p = 0.081」）
—— 主口径选单库、合并值写进图注，是「**不藏**」，不是「不用」。
  A 库级元签名检验（置换零分布 + 观测 AUC 竖线 + 标注 AUC/p）
  B 条目级前 5 位富集倍数
图 5D　鼠类来源库（GEO 小鼠/大鼠 442）  ← 与 5C 口径逐字相同
```

- 图注写清：**源物种 / 条数 / 用途边界**（「仅用于后验检验，不构成本方法输入」）
  + 「本图与图 5X 采用完全相同的统计口径」（这句是「可对照」的合法性来源）。
- 黑白：`color='white', edgecolor='black'` + hatch 轮换；中文标签用 ASCII 数字防豆腐块。
- 验收：新目录 vs 上一版目录**逐张 md5 对账**，未改动的必须逐字节一致（严格范围修复的机器证明）。

## 4. 交付时的汇报骨架

1. **首段给结论**：「可以一起放，人类库反而是更强的那个」+ 一句依据。
2. **四行对照表**（库 / 条目数 / AUC / 置换 p / 判定）—— 人鼠同表，一眼可比。
3. **一句话说清互补性**：鼠类条目级强（唯一过 FDR 的条目）、人类库级强（唯一显著的 AUC），
   且两库方向一致（AUC 全 >0.5，全部偏向随龄**上调**基因）⇒ 专利要的正是「两个独立物种同向证据」。
4. **主动解释上轮的疑问**（为什么是 mouse）—— 三段根因链，不要只说「那是参考库」。
5. **收在一个待用户拍板的选项**上（例：5C 用 GTEx 单库 p=0.013 作主口径 vs 用合并库 p=0.093），
   并给出自己的建议 + 一句「你说一句我就改图并滚进 v(N+1)」。

⛔ 不要把「人类库不进 top-5」说成「人类库没有信号」——
**这是把展示口径问题误报成数据问题**，与「判『死』前先核它在不在」同源。

---

## 5. 一句话记法

> **top-N 排序会系统性隐藏某一类来源；要求「换个来源物种再验一遍」时，先分层、再换库级统计量、
> 然后每个物种出一张同口径的图，最后把「合并 vs 保留分层」交给用户拍板。**
