# claim 前提先行验证 与 claim 塌了之后的重新定位

**触发场景**：用户问「**为什么一直在变？到底是什么问题导致你一直在变？**」「到底哪个口径？」「**这件事究竟能不能作为总体思路**？」——即 Agent 已连续多轮重算数字、用户开始怀疑方向本身。也用于：任一 claim（专利/论文/结论）的核心效果句被自己的数据否掉之后。

---

## 一、为什么"一直在变" —— 根因不是数据反复，是任务定义错了

**表层（用户看得见的）**：口径连续切换，每切一次全套数字重算、结论表换脸。用户看到的是"数字在飘"。

**深层（真根因）**：**把"替换数字"当成了任务，没把"验证 claim 是否成立"当成任务。**

判别证据（本项目 Phase 1–5 实测）：五轮返工全部发生在"优化数字"（重算 v5 四级 / v6 / v7 / 核心元件 / 替换交付件文案 / 修图文不一致），**没有一步在问"这个前提本身成立吗"**。用户一提"先跑前提检验 C/B"，claim 当场就塌 —— 如果一开始就跑 C/B，这五轮返工大半不会发生。

### 顺序铁律

```
收到 claim 类任务
  ↓
① 前提检验（几乎零成本，先做）    ← 分母是否循环论证 / 前提是否可被自己的数据反驳
  ↓ 前提不成立 → 立即停手、报告、重估 claim 定位（不要进入 ②）
  ↓ 前提成立
② 数字优化 / 口径切换 / 交付件重出  ← 已有 skill 覆盖
```

**"先跑便宜的、能杀死 claim 的检验"是唯一能避免 churn 的顺序。** 把前提检验排在数字优化之后 = 保证返工。

### 收敛信号判据（识别"我该停手了"）

统计每轮新检验对 claim 的净影响：

| 信号 | 判读 |
|---|---|
| 净方向**单向变弱**（每轮新检验都让 claim 更弱，从无一轮增强） | **不是摇摆，是收敛** —— 收敛到"claim 不成立"。停手重估 claim，不要再改数字 |
| 净方向左右交替（一轮强一轮弱） | 真摇摆 —— 是口径/参数不稳，继续查 |
| 连续 ≥3 轮单向变弱 | 强制触发本节流程（本项目即 5 轮：v6 失效 → C 方向不稳 → B-1 反向富集 → B-2 全 ns → 582 循环论证） |

**向用户汇报这种"变"时，必须点明这是收敛而非摇摆** —— 否则用户只看到数字在换，会持续不信任；讲清"五条独立证据全部指向同一方向"，用户才能判断这是结论而非噪声。

## 二、口径切换不是万能药（实测对照，用来终结"到底哪个口径"的纠结）

**判据：缺陷在数据结构（系统性反向）时，换口径只改幅度、不改结论 → 立即停止口径纠结。**

本项目 all / continuous 两口径最终对照（同一 human 输入，只换猴侧输入）：

| 指标 | all 口径 | continuous 口径 |
|---|---|---|
| 人侧强效应 \|Z₁\|≥12 | 1,404 | 1,404（**完全相同**） |
| 其中猴侧 p<0.05 | 890（63.4%） | 940（67.0%） |
| 其中同向 | 357 | 336 |
| 其中反向 | 533 | 604 |
| **同向率** | **40.1%**（二项 p=3.99e-9） | **35.7%**（二项 p=1.82e-18） |
| A 级元件数 | 2,335 | 1,905 |

**两个口径都远低于随机的 50%，都在 3×10⁻⁹ 量级显著。** 换口径让同向率从 40.1% 变 35.7% —— 幅度变了，结论（前提不成立）一模一样。

⇒ **口径之争在此类缺陷下是无效挣扎**：问题不在口径，在数据本身"不是无信号，而是有信号的反向"（符号置换 z=−6.27，反向 1.21× 富集 / 同向 0.79× 亏损）。**这比"无信号"更糟** —— 用它当代理会主动误导，而非仅仅无效。

## 三、claim 塌了怎么办 —— 三层判定 + 重新定位

### 3.1 分两层判：方法层 vs 效果层（结论相反，不要一起否）

| 层次 | 声称内容 | 判定 | 依据 |
|---|---|---|---|
| **方法层**（怎么判） | 能**逐个元件判定**方向是否一致 | ✅ **成立** | 逐个给出方向、357 同向 / 533 反向，可复现、双实现互证 |
| **效果层**（判出来干啥） | 判为一致的元件 = **同向保守、可外推** | ❌ **不成立** | 同向率 40.1% < 随机 50%，"一致"是**少数例外**而非默认结果 |

**关键认知**：方法可以是好方法，但筛出来的东西**不叫"保守集"**——保守集本该是多数或至少过半，而实测一致性仅 40.1%。**把"筛出保守元件"当技术效果写，数据会当场反驳。**

### 3.2 三条可保留的技术效果（全部有实测支撑）

| # | 技术效果 | 支撑 |
|---|---|---|
| 1 | 元件级方向一致性判定**可执行** | 全部猴侧显著元件逐个给出方向，同向/反向分流 |
| 2 | **外推风险诊断** | 识别"人侧强效应 + 参考侧反向"的元件；符号置换 z=−6.27；反向 **富集** 1.21× / 同向 0.79× 亏损 |
| 3 | 标定替代假设的**失效边界** | 同向率定量下限（40.1% / 35.7%），二项 p≈4e-9 / 2e-18 → 低于随机即否定 |

### 3.3 必须一起改掉的三处（不改 = 把已被否掉的话继续写在专利里）

| 位置 | 问题 | 处理 |
|---|---|---|
| 富集倍数（如 12.3×） | 分母 = 「主侧强效应 **且同向**」，方向条件在分子分母同现 → **循环论证**；且其"零假设"假设参考侧 p<0.05=5%，实测 63.4% 不符 | **删除或重算**（换独立分母 / 改报同向率） |
| 权要效果句「筛选跨物种同向保守核心元件」 | 同向率 < 50%，"保守"不成立 | 改为「**输出可外推 / 需独立验证的分层清单**」 |
| 摘要/说明书「动物模型可作为人研究的替代模型」 | 整体替代声称被否 | 降级为「**元件级可外推性判定方法**」 |

### 3.4 必须向用户点明的降级（不可含糊）

> 若该专利的核心卖点是"**某物种能替代另一物种**"，这个卖点**已被数据否掉**。能留下的是**方法学价值**（判定流程 + 风险诊断 + 失效边界），不是**生物学结论**（替代成立）。**这是硬性降级，不是措辞问题。**

⚠️ 不要替用户决定降级。把判定 + 依据 + 三条可选路径摆出来，**让用户拍板**：
1. 接不接受这个降级（不接受 → 得换 claim 或换数据，改文案救不了）；
2. 循环论证类数字（富集倍数）全删还是重算一版独立分母；
3. 要不要**现在就动手**改写 claims / abstract / disclosure，并列出需删除的表述清单。

## 四、汇报组织（用户问"为什么一直在变"时的回答骨架）

用户要的不是道歉，是**根因 + 确定性结论**。四段式：

1. **为什么会变** —— 表象（口径切换）× 根因（把替换数字当任务）× 收敛信号（五条证据单向）
2. **两个口径到底差多少** —— 实测对照表 + "换口径救不了"的判据
3. **能不能作为总体思路** —— 方法层/效果层两层判定 + 三条可保留效果 + 三处必须改
4. **需要你拍板的三件事** —— 编号列表（用户偏好 3–5 条编号，不要长篇）

**不要**在回答里只给"我错了 + 我会改正"——用户会继续追问同一个问题。

---

## 五、门禁等级误判 —— 回答「之前可以，为什么现在要改」

**用户原话**：「那为什么之前就可以呢？现在就要改，为什么」

### 5.1 真相：变的是**门禁等级**，不是数据、不是结论

本项目实测时间线（同一缺陷，三种判级）：

| 时间 | 我说了什么 | 当时定级 | 后果 |
|---|---|---|---|
| 08-25 | 「一审核会死在第 3 条」：可替代性 ≠ 同向性 / 置换靶子错位 / `min×sign` 平凡 | 毒辣评价，**未阻塞流程** | 流程照跑 |
| 09-10 | 「风险 2（**强烈建议**）：参考侧方向门控 p<0.05 本身的质量没有验证……**改法：打乱参考侧年龄标签重算方向一致率，给出 +1 方向的错误率**」 | 🟡 **建议** | **流程不被拦住**，五轮数字优化照跑 |
| 09-12 | 前提检验实测跑完，前提被五项检验否定 | 🔴 **阻断** | claim 结论层当场塌 |

**关键自省**：缺陷早就被精确指出、药方早就开好了（09-10 那段原文就是后来才跑的 B-2 检验）。**唯一的差别是它被排在"优先级清单的 🟡 建议行"，而不是 🔴 必改行。** 所以在 09-10～09-12 之间，我把它当成了"可以以后再补的加分项"，实际上它是 **claim 的前提** —— 前提没验证，后面所有数字都垒在未验证的假设上。

### 5.2 铁律

> **成本极低、且能杀死 claim 的前提检验，默认列 🔴 阻断级，不得降级为「建议」。**

- 判级依据只有一条：**它失效会不会让 claim 不成立？** 会 → 🔴。与"实施成本高低"无关。
- 审阅历史评审时必做**反向扫描**：凡历史 🟡 项中涉及「claim 前提 / 核心效果句是否成立」的，**一律升级为 🔴 并立即执行**。
- 汇报里出现「强烈建议」字样时要自问：这是建议，还是被我用建议语气包起来的前提？

### 5.3 回答骨架：三级归因表（不要辩解，要定位）

| 项 | 08月/9月初 | 现在 | 变了吗 |
|---|---|---|---|
| 新颖性（检索空白） | ✅ | ✅ | **没变** |
| A25（技术方案非纯数学） | ✅ | ✅ | **没变** |
| 方法可实施、可复现 | ✅ | ✅ | **没变** |
| **参考侧方向门控能否使用** | 🟡 **"建议补验证"** | 🔴 **"已验证不通过"** | ← **只有这一个变了** |
| 由此带出的 A22.3 技术效果 | "风险低" | 不成立 | 连带 |
| 由此带出的 A26.3 实施例充分性 | "风险低" | 高风险 | 连带 |

**结论句模板**：「不是之前"可以"、现在"要改"。是之前我把一条致命问题判成了"建议"、所以它没拦住流程；前提检验一跑，它就从"建议"变成了"已证实不通过"。**责任在判级，不在数据。**」

### 5.4 顺带核查：缺陷是不是"新版引入的"

用户会顺势怀疑"是不是换版本换坏了"。必须**同时**核查该缺陷在每个版本的存在情况 —— 本项目实测：**循环论证的富集倍数旧版就有**（continuous 12.5×，分母 536；all 12.3×，分母 581），**两版分母都含"同向"条件** ⇒ **不是新版引入，第一版就写进去了**。汇报时必须点明这一点，否则用户会继续在版本上找原因。

## 六、变更层级分离汇报 —— 回答「换版本是不是全都变了 / 是不是只替换数值就行」

**用户原话**：「`…_v8.docx` 是 continuous 出来的专利结论，难道换到 all 版本全都变了？如果没变，为什么不只是替换一些数值就可以了呢？」

### 6.1 根因：我把三层的变更混在一条回复里讲

- **数值层**：换了输入口径 → 数字必然动；
- **口径/版本层**：只换参考侧输入（人侧输入不变，|Z₁|≥12 恒为 1,404）；
- **claim/结论层**：效果句是否成立 —— **与口径无关**。

我在同一条回复里既汇报"数字已替换"、又汇报"claim 效果句要改"，且当时整体在 all 口径下讲话 → 用户自然归因成「**all 版推翻了 continuous**」。**这是我的汇报结构问题，不是数据问题**，必须承认。

### 6.2 标准答法（三步）

1. **先答数值层**：贴两版实测对照表，明确「数值全变了」。
2. **再答结论层**：明确「**结论一个字没变**」，并给两版共有的不变项 —— 判据：**换口径后结论没变 ⇒ 缺陷在 claim，与口径无关。**
3. **最后答"是不是只替换数值就行"**：**是，而且已经做了** —— v9 本身就是"把 v8 的数字成批替换"的产物，做成了。**不成立的是 claim 层，替换数值救不了**（因为它不是数字错，是效果句被自己的数据反驳）。

### 6.3 本项目两版对照（实算，可复用为模板）

| 指标 | v8 / continuous | v9 / all | 性质 |
|---|---|---|---|
| 基因数 | 16,012 | 16,010 | 微变 |
| 整体 r(Z₁,Z₂) | −0.0624 | −0.0960 | 变 · **同为负** |
| 整体同向率 | 41.62% | 46.40% | 变 · **均 <50%** |
| A 级元件 | 1,905 | 2,335 | 变 |
| B 级反向 | 3,474 | 3,070 | 变 |
| 主侧 \|Z₁\|≥12 | 1,404 | 1,404 | **完全相同** |
| 参考侧显著 | 940 (67.0%) | 890 (63.4%) | 变 |
| 同向 / 反向 | 336 / 604 | 357 / 533 | 变 |
| 显著内同向率 | **35.74%** | **40.11%** | 变 · **均 <50%** |
| 富集倍数 | 12.54× | 12.29× | 变 |
| 分母含「同向」条件 | 是（536） | 是（581） | 🔴 **都没变 · 都错（循环论证）** |

**三条结论两版完全一致**：① r 都为负 ② 同向率都 < 50% ③ 12.x× 的分母都含"同向"条件（循环论证）。
**且旧版更差**（35.74% < 40.11%）⇒ **「留在旧版就没事」是错觉**，必须主动告知用户，否则用户会把"回退版本"当成出路。

### 6.4 汇报禁用句式

- ❌ 「改用 X 后数字都更新了，claim 也需要跟着改」—— 把两层绑在一句里，用户必然归因错误。
- ✅ 「数值层：全变（表）；结论层：没变；要改的是 claim 效果句，**这两件事互相独立**。」

## 七、用户问「claim 到底是什么 / 会怎样」—— 定义框架 + 风险分级定位

**触发**：Agent 说了"claim 的效果层塌了"之后，用户必然要弄清两件事：① **claim 到底是什么**（法律地位）② **后果是什么等级**（会不会直接驳回）。两个都不答透，用户会持续追问（本项目实测用户直接追问"claim 到底是什么？"）。

### 7.1 定义框架（三段：先地位 → 再结构 → 后映射到他自己的权要）

| 段 | 要点 |
|---|---|
| ① **地位** | claim = **权利要求**，是专利文件里**唯一有法律效力**的部分；说明书（description）用于解释 claim、证明其可实现，**本身不划定边界**。**审查员审的、无效宣告攻的、侵权诉讼比的，都是 claim。** |
| ② **结构** | 方法专利的 claim 大多是**方法步骤**（S1 取数 → S2 计算 → S3 评分 → S4 定阈值 → S5 输出）；真正的"断言"往往只藏在**少数几条**里（定性词 + 实施例数字 + 用途 + 有益效果）。 |
| ③ **映射** | 把用户的 claim **逐条列成表**「权要 → 内容 → 状态」，让"哪几条是活的、哪几条是塌的"一眼可见。**不要只给教科书定义，必须锚到他自己的权要编号。** |

本项目实例表（可直接套用为模板）：

| 权要 | 内容 | 状态 |
|---|---|---|
| 1（独权·方法） | S1 取数 → S2 逐元件算 Z₁/Z₂ → S3 S=Z₁×w(Z₂) → S4 置换定 τ → S5 分级输出 | ✅ 可实施 |
| 2/3/5/6/9（从权·算法） | Z 定义 / 主-参考非对称 / 置换检验 / τ=1.96 | ✅ 未塌 |
| **4（定性断言）** | A 级元件 = \\|Z₁\\|≥τ_A 且 w(Z₂)=+1，**定性为「跨物种同向保守」** | ❌ 实测同向率 40.1% < 50% |
| **10 + 有益效果（用途）** | 可替代性评估 / 靶点筛选 / 富集 12.3× | ❌ 分母循环论证 |
| 11（实施例） | τ_A=12 → 357 核心 + 16 最高置信 | ⚠️ 口径敏感（名单换血 47%） |
| 12（独权·装置） | 处理器 + 存储器实现权要 1–11 | ✅ 未塌 |

一句话版（用户要的就是这句）：**"claim = 你要求法律排他的范围。这份专利要求的是'一套逐元件计算方向一致性并分级输出清单的方法'——方法步骤这层是活的，写死的是它的'产品说明'。"**

### 7.2 风险分级定位（决定用户该多紧张，**必须主动讲**）

⚠️ 两种常见误导：把"效果句被自己的数据否掉"直接说成"会被驳回" → 用户过度反应；轻描淡写成"改个措辞就行" → 用户以为无碍。正确做法 = **给等级 + 给法条对应**：

| 等级 | 情形 | 本项目实例 |
|---|---|---|
| 形式缺陷（可补正） | 名称/标题/格式不齐 | — |
| **答辩风险（← 本例在这一档）** | 审查员一般**不会重复实验**验证生物学真假；风险出现在审查/无效/质证被引用时 | ① **A26.3 公开不充分**——声称的技术效果无法实现；② **A26.4 权利要求得不到说明书支持**——效果断言超出可支持范围；③ **创造性论证失锚**——problem-solution 中"对比文件 + 技术效果 = 非显而易见"的**效果端被自家数据反驳**，答辩时对方一查即中 |
| 必然驳回 | 客体不适格（A25 / 实用新型受理方法类）、门类错误 | — |

**必讲清的一句**：这是**答辩风险**，不是**形式缺陷**，也不是"必然驳回"——所以正确处置**不是删几个字**，而是修效果句（定性词）+ 删/重算循环论证类数字（富集倍数），或按 §3.4 的三条路径让用户拍板。

**自查**：汇报"claim 某层塌了"时，是否同时给了 ① 它是什么（地位＋结构＋逐条映射）② 塌的是哪几条 ③ 后果等级 + 法条。**三者缺一，用户会继续追问。**
