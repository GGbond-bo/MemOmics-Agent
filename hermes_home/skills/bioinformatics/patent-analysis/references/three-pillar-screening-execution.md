## 1. 单元口径：先建「同源基因单元表」

**单元 = 同源基因对**（独权 S1.5 的「统一编号的同源调控元件单元」），人侧取 hg38 坐标 ±2 kb（`WINDOW=2000`），窗口内 500bp tile 为细分单元。

建表三源合并（缺一不可）：

| 源 | 文件 | 作用 |
|---|---|---|
| 同源映射 | `monkey_human_orthologs_full.csv`（`macaque_gene_id, human_gene_id, human_symbol`） | symbol ↔ human_gene_id 桥 |
| 人侧坐标 | `human_ortholog_hg38_full.csv`（`human_gene_id, chr, start, end`，**chr 无前缀**） | 取 ±2kb 窗口 |
| 物种内年龄效应 | `M2_repro_gene_conservation_all.csv`（`symbol, Z_m/Z_h, p, n_tiles`） | L3 主门 + L2 tile 数 |

🔴 **chr 前缀必须统一**：坐标表是 `19`，peak 表是 `chr19` → `'chr' + str.replace('^chr','')`。不统一则 L1 overlap 静默 0 命中（不报错）。
🔴 **三源 inner join 后收敛到 16,029 单元**（26,501 同源 → ∩ 16,160 坐标 → ∩ 16,029 有年龄效应）。这个数字要在交付件里写明来源链，不能只写结果。

## 2. L1 序列保守聚合（用现成 peak 级分数，**不重跑 bigWig**）

已跑好的 `P3_L1_data/v4/l1_full_human.csv`（524,256 行）列：
`chr,start,end,p100_mean,p100_bg_pct,p100_bg_pval,p100_bg_q,p30_mean,pc_mean,pc_elem_frac,conserved_pc`

⚠️ **`p100_bg_q` 整列恒为同一个值（0.627764）= 占位/未完成的 FDR** → **不要用 q 值判保守**，用 `conserved_pc`（phastCons 元件判定，实测 `Y` 占 **5.24%** = 27,494/524,256）或连续 `p100_mean` 分位。

聚合方法（每基因窗口内）→ `n_peaks_win, p100_mean, p30_mean, pc_mean, frac_conserved, p100_max`：
按 chr 分组 → `np.searchsorted(start, hi)` 定位候选 → 过滤 `end > lo`。**不要两两全比**（524K × 16K 会爆）。实测 15,865/16,029 基因窗口内有 peak，`frac_conserved>0` 者 6,769。

**L1 实测分布**（有 peak 的基因）：`p100_mean` 中位 0.197 / q75 0.426 / q90 0.714；`p100_max` 中位 1.387。

## 3. 🔴 L2 退化陷阱：`n_tiles > 0` 在 gene 级恒为 100%

**本类任务最容易白跑一轮的地方。** `M2_repro_gene_conservation_all.csv` **本身就是「两侧都有 tile」的基因对集合** ⇒ 若把 L2 定义成「人侧 tile > 0 且 猴侧 tile > 0」，实测通过率 **16,029/16,029 = 100%**，零区分度。

⇒ **L2 必须用强度口径（tile 数下限）**，实测分布：人侧中位 **66**（IQR 28–159），猴侧中位 **51**（IQR 23–112）。

判据：**任何一层若通过率 ≈100% 或 ≈0%，该层不构成筛选条件** → 换口径或换层，不要把它写进权利要求当区别特征（审查员一眼看出该限定无作用）。

## 4. 阈值扫描 + 黄金区间反推（本方法的核心动作）

**黄金区间 = [30, 500]**：输出 <10 个 → 实用性被质疑；几千个 → 「核心元件」名不副实。

**175 组扫描**（L1 5 档 × L2 5 档 × L3 7 档），实测 **19 组**落在黄金区间。L3 档位建议 `[1.96, 2.58, 3.29, 4.0, 6.0, 8.0, 12.0]`；L1 档位用 `frac_conserved>0 / ≥5% / ≥10%` + `p100_mean≥0.25 / ≥0.50`；L2 档位 `>0(退化,仅作对照) / ≥5 / ≥中位 / ≥15 / ≥30`。

**实测主口径与逐层基数**（可作交付件表 1 模板）：

| 层 | 判定条件 | 通过基数 | 收缩率 |
|---|---|---|---|
| 全部同源单元 | — | 16,029 | — |
| L1 序列保守 | phyloP100 窗口均值 ≥ 0.50 | 3,180 | 19.8% |
| L2 跨物种可及 | 人侧 tile ≥ 30 **且** 猴侧 tile ≥ 30 | 10,401 | 64.9% |
| L3 年龄效应 | `\|Z_human\|` ≥ 12（≈q91 分位） | 1,409 | 8.8% |
| **三柱 AND** | L1 ∧ L2 ∧ L3 | **150** | 0.94% |

**L3 实测分布**：`|Z_h|` 中位 3.37 / q75 6.69 / q90 11.32 / q99 24.69 —— 阈值 12 落在 q91，属「强效应」而非「极值」。

**校准逻辑一句话**：先用零依赖 L3 的 L1∧L2 基数摸底 → 再据基数反推 L3 阈值 → 让 AND 后落黄金区间。这是「**标定**」而非「三个现成过滤器叠一下」，是副锚 2 的落点（写说明书时用得上）。

## 7. 🔴 rail_review(post) 的图片扫描范围（本次连挂两轮）

**症状**：`passed=false, issues=["未生成任何图片"]`，但图确实生成了（`figures/v21_*.png`，127–195 KB 健康）。

**根因**：审查器只扫你传的 `output_dir` 目录**本体**，图放在 `figures/` 而 `output_dir` 传 `results/` → `figure_count=0`。

**修法（按序）**：① 把图**归位到 `output_dir` 内**（`shutil.copy2` 到 `results/figures/`）→ 重跑 post；② 或直接传**含图的那层目录**（传项目根，同时含 `results/` 与 `figures/`）。
与已知近亲合并记：**传 `.docx` 文件路径也会 `figure_count=0`** ⇒ 一句话：**`output_dir` 必须是「目录」，且图要真在它下面。**

⚠️ 收到「未生成任何图片」时**先回盘列目录里到底有没有 PNG、多大**，再决定重跑还是改 `output_dir` —— 不要盲目重跑出图（与 SKILL.md「见到空白图告警先回盘核对」同源）。
