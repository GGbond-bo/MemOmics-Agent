# 交付目录治理 —— 多代次交付件的收敛与防误读

> 触发：用户说「**清理一下目录**」「把当前的文件和资产**全都保留在一个干净可靠的目录**下」
> 「**查证这些目录是最新的、可靠的**」「**然后记录这个目录，不要读错了**」
> 也用于：任何交付目录里同时躺着 ≥2 代同名/近名文件的场合（docx 多版本、claims 多代、附件改名）。

⚠️ 用户提这个要求，说明**已经发生过或接近发生误读/误送**。这不是整理癖 ——
本类目录的典型事故是「**拿已作废的旧代次答战略问题**」（见 `claims-generation-and-layer-audit.md` §1），
或「**同名不同代的附件并排躺着，送错一份就是送错一代发明**」。
本流程的交付物是**一个权威目录 + 两级索引 + 归档隔离 + 跨会话锚点**，不是「看起来整齐的文件树」。

---

## 0. 铁律四条（动手前先记住）

1. **零删除**：全程只用**移动**（`shutil.move`）。删除动作会触发平台删除保护，
   且用户明确说过「全都保留」。要"清掉"的东西一律**移入 archive**，不删。
2. **不搬大资产**：数据文件（CSV/RDS/bigWig/Arrow/fragments）被脚本按**绝对路径**引用，
   移动即破坏复现。留在原位、**在索引里写清路径**。
3. **不信文件名、不信版本标签**：实测 README 自称 `v15` 而其内容已含 v17 的数据。
   现行代次只能靠 **mtime + 内容标记**交叉判。
4. **一个目录只认一个入口**：治理后必须有两个索引文件（根目录导航 + 权威目录总索引），
   否则下次照样读错。

---

## 1. 扫：递归 mtime 建代次谱系

先用一次脚本拿到全树的「目录 + 修改时间 + 文件数 + 体积」，**按 mtime 倒序**看：

```python
import os, time
def walk(root, maxdepth=2):
    root = os.path.normpath(root); base = root.count(os.sep)
    for dp, dns, fns in os.walk(root):
        if dp.count(os.sep) - base > maxdepth: dns[:] = []; continue
        tot = sum(os.path.getsize(os.path.join(dp,f)) for f in fns if os.path.isfile(os.path.join(dp,f)))
        print(time.strftime('%m-%d %H:%M', time.localtime(os.path.getmtime(dp))),
              f"{len(fns):>5}", f"{tot/1e6:>10.1f}MB", os.path.relpath(dp, root))
```

判据：**mtime 最新 ≠ 一定是现行代次**（生成脚本可能刚把旧内容重新打包），
必须配合 §2 的内容核对。

## 2. 判：哪一代是现行（三步交叉）

| 步 | 动作 | 标本 |
|---|---|---|
| ① **列候选** | 交付目录 + `patent/` + 项目根 **三处都查**；按 `*claim*`/`*权利要求*`/`*v[0-9]*` 列全 | 三代同盘：9/4 `min` 版（在 `patent/`）、9/5 切换说明（在根）、9/12 v15（在交付目录） |
| ② **内容标记核对** | 现行件里有**只有它才有**的数字/段落。grep 一批「晚期标记词」看哪些文件命中 | 晚期标记 `0.23`/`p=0.815`/`0.94`/`失效边界（十二）` → 判出**交付目录的 md 已含 v17 内容**，尽管 README 仍写 v15 |
| ③ **查生成链** | 找 `gen_*vN*` / `verify_*vN*` 脚本，看它**读什么、写哪里** | `23_gen_v17_delivery.py` 从交付目录 md 生成 v17 docx → 确认 md 是源、docx 是产物 |

🔴 **最省事的判据**：交付件 docx 与源 md **时间戳谁新**。
若 docx 更新 → 它以 md 为源重新打包过 → **md 内容即现行**，只是版本标签没同步。

## 3. 并：纯移动收敛（无删除）

推荐布局（保持原目录名不改，只加子目录，最小破坏）：

```
<权威目录>/
├── 00_目录索引.md          ← 新建：权威声明 + 全部清单 + 数据源 + 未决事项
├── 01_送审_vN/             ← 新建：只放现行送审件
├── [原有 md / results / figures / scripts —— 一律不动]
└── _archive_旧口径/        ← 原有
<项目根>/
├── 00_先读我_目录说明.md    ← 新建：根目录导航 + 禁读清单
├── _archive_交底书旧版/     ← 旧 docx 全部移入
├── _archive_旧代次_md/      ← 旧 md + 9月N日_<路线>版/ 子目录
└── [数据资产原位不动]
```

移动脚本模板（**只用 move，任何 `os.remove`/`os.rmdir`/`shutil.rmtree` 都会触发删除保护、
整段脚本被拦下**）：

```python
import os, shutil
log = []
def mv(src, dst_dir, tag):
    if not os.path.exists(src):
        log.append(("跳过·不存在", os.path.basename(src), "")); return
    os.makedirs(dst_dir, exist_ok=True)
    dst = os.path.join(dst_dir, os.path.basename(src))
    if os.path.exists(dst):                       # 同名冲突 → 加后缀，绝不覆盖
        b, e = os.path.splitext(os.path.basename(src))
        dst = os.path.join(dst_dir, f"{b}__dup{e}")
    try:
        shutil.move(src, dst); log.append((tag, os.path.basename(src), dst_dir))
    except Exception as ex:
        log.append((f"❌{type(ex).__name__}", src, str(ex)[:70]))
```

**空目录不要 `rmdir` —— 让它留着**，或把整个目录一次 `mv` 走（目录整体移动是移动不是删除，放行）。

## 4. 移动前必做：文件占用探测

先测目标文件是否被 Word/WPS 占用，再决定能否直接移：

```python
try:
    open(p, "r+b").close(); print("可移动 ✅", p)
except Exception as e:
    print("被占用 ❌", type(e).__name__, p)
```

⚠️ **锁是逐文件的**：目录里躺着 `~$xxx.docx` 不代表目标文件被占用
（旧版遗留的 `~$` 不会自动消失）。**只测目标文件自己那一个**。
`~$` 临时锁文件本身也要移出送审目录（保持送审件纯净），移进 `_archive_*/临时文件/`。

## 5. 写索引：两级，缺一不可

### 5.1 权威目录里的 `00_目录索引.md`（给"要交付/要复现"的人）

必含九节：现行代次声明（含**生成脚本与校验脚本名**）→ 送审件表 → 正文源文件表 →
元件/口径锁 → 结果/图/脚本 → **输入数据源（绝对路径 + 体积）** → **已归档代次（明写"不要读"）**
→ 未决事项（按优先级）→ 一键复现命令。

### 5.2 项目根的 `00_先读我_目录说明.md`（给"下次打开这个目录"的人）

必含：唯一权威目录 + 现行送审件路径 → **根目录速查表（每项：是什么 / 能不能动）**
→ **⛔「不要读这些」清单**（逐条写清为什么 + 曾造成什么误读）→ 口径锁 → 当前未决。

🔴 禁读清单是本流程最有价值的一节，**必须点名具体文件与原因**，例如：
「`_archive_旧代次_md/9月4日_min版/权利要求书_….md` —— 9/4 对称 min 版，
已被两代取代；**曾导致误读并据此得出相反结论**」。

## 6. 记：跨会话锚点 + 持久记忆

治理完立刻写，否则下次照旧读错：

- `session_memory(action="add", kind="path", pinned=True, importance=1.0, content="【权威目录·<日期>核实】<绝对路径> 是唯一权威交付目录……现行送审件 = …/01_送审_vN/；正文源 = …；输入数据 = …；旧代次隔离在 …（含 …，勿读）。入口文件 = …/00_目录索引.md 与 …/00_先读我_目录说明.md")`
- `memory(action="add", target="memory", content="<项目> 目录已于 <日期> 治理完毕：唯一权威目录 = …（入口 00_目录索引.md）……输入数据在 …，不可移动（脚本按绝对路径引用）")`

## 7. 实测坑表

| 坑 | 现象 | 处置 |
|---|---|---|
| 🔴 `os.rmdir` / 任何删除动作 | 整段脚本被拦：`[⚠️ 操作需确认] 你刚才尝试执行删除操作`，**25 项移动全部没执行** | 纯移动重跑；要清的空目录留着，或整目录 `mv` 走 |
| 🔴 文件内版本标签滞后于内容 | README 头部写 `版本 v15`，内容已含 v17 的失效边界段 | **以内容标记判现行，不以标签判**；在索引里如实标注「内页版本号仍标 vX，内容已含 vY 数据」 |
| 🔴 生成脚本把输出路径写死在项目根 | 下次重跑 docx 又落回根目录 → 又形成两份 | 在索引里**显式写明**「重生成后请手动移回 `01_送审_vN/`」；不要擅自改别人的生成器 |
| 🔴 大资产被"顺手整理" | 移动 `*_ageDA_all.csv` / `.rds` / bigWig | 一律不动：脚本按绝对路径引用；在索引里写清路径与体积 |
| 🟡 过期清单混在里面 | 根目录一份 `提交前核查清单.md` 自称"以 v10 交付件为准" | 连同旧代次一起移入 `_archive_旧代次_md/`，索引里注明它已过期 |
| 🟡 别人/自己的临时脚本混放 | `_审核agent/` 里外部审计者的 `audit*.py` 与本人的 `audit13b.py` 同目录 | **不要当交付件**；在索引"相关但不属于本目录"一节写明作者归属与用途 |
| 🟡 只移动不写索引 | 目录整齐了，但下次仍从旧路径找 | §5 两级索引是流程的一部分，不是可选项 |
