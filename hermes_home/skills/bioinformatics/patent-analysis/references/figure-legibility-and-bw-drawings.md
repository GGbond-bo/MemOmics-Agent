# 附图可读性铁律：黑白线条图 + 缩印检验（2026-09-12 用户当场纠正）

## 触发

- 用户说「**这张图修改一下，看不清楚**」「**一堆小点点**」「**干净一些**」「**线条太多了**」「**统一干净的**」
- 要给专利交底书出**黑白线条版附图**（《审查指南》2.4：黑色墨水绘制、不得着色）
- 任何图要**内嵌进 docx**（图会被压到 ~800–900 px 宽，等效缩印 30–40%）

## 🔴 规则 1：单链流程图/示意图 —— 禁用任何填充图案

**技术链示意图、流程图、框图一律纯白底黑框**。这些图的方框本来就有 ①–⑤ 序号和标题，图案是纯噪声，且在 docx 里缩到 ~850 px 宽后**点纹 `...` 与交叉纹 `xx` 会糊成灰块**，用户第一反应就是「一堆小点点，看不清楚」。

```python
# ✅ 正确：纯白底黑框 + 反白标题条（黑底白字）
ax.add_patch(FancyBboxPatch((x, y), w, h, boxstyle='round,pad=0.6,rounding_size=1.2',
                            fc='white', ec='black', lw=1.4, zorder=2))   # 无 hatch
ax.add_patch(Rectangle((x+0.6, y+h-5.4), w-1.2, 5.4, fc='black', ec='black', zorder=3))
ax.text(cx, cy, title, color='white', fontweight='bold', zorder=4)

# ❌ 错误：用 hatch 给每个框"区分"
steps = [('①', None), ('②', '///'), ('③', '\\\\\\'), ('④', 'xxx'), ('⑤', '...')]  # 用户会投诉
```

**实测标本（2026-09-12，本专利 fig1_pipeline_bw.png）**：我给 ②③④⑤ 各配一种纹样 + 输出框 `'..'`，用户原话
「**看不清楚，一堆小点点，干净一些**」→ 追问确认「**就是 2，3，4，5 这几个方框，线条太多了，统一干净的**」。
修法 = 5 框全部 `fc='white'`、**去掉 `hatch` 参数**、字号一并放大（标题 10.5→11.5 pt，正文 8.4→9.4 pt）。
结果：彩色像素 0.0000%、墨迹占比 **18.6% → 15.54%**、文件 **273,564 → 245,274 B**（墨少=更干净）。

**唯一例外**：多系列对比图（如 9 方法横评）必须有区分手段 → 见规则 2。

## 🔴 规则 2：必须区分时，优先级 线型 > 空心/实心标记 > 斜纹 >> 点纹

| 手段 | 缩印后 | 建议 |
|---|---|---|
| 线型（实线/虚线/点划线 `o-` / `s--`） | 最稳 | ✅ 第一优先 |
| 空心/实心标记（`mfc='white'` / `mfc='black'`） | 稳 | ✅ 第二优先 |
| 斜纹 `//`、反斜纹 `\\` | 尚可 | 🟡 可用 |
| 交叉纹 `xx` | 易糊 | 🟠 少用 |
| **点纹 `..` / `...`** | **最糊**（缩小后成灰块） | 🔴 **避免**（实测惹用户投诉的就是它） |
| 反白标题条（黑底白字） | 最干净 | ✅ 零墨迹代价的黑白区分手段 |

本专利 fig2/fig4/fig5 仍保留影线（多系列区分需要）——**这是刻意的**，汇报时主动说明；用户若抱怨再换线型。

## 🔴 规则 3：字号下限（缩印可读性）

入 docx 后图宽常被压到 ~850 px。**框内正文 < 9 pt 在两栏 A4 下不可读**。改图时把"去图案"和"放大字号"当一件事做（只去图案不放大字号，用户仍会说看不清）。

## 🔴 规则 4：改图必须重出 binary 交付件（内嵌图不会自动更新）

```
改源图 → 跑出图脚本（注意脚本常双写 patent/figures_bw + 交付目录/figures_bw）
       → 重跑 docx 生成器（内嵌 word/media 仍是旧图！）
       → 验收探针里"内嵌图字节 == 源图"那一项会 FAIL（正是它在报警）
```

**docx 被 Word/WPS 占用时（`PermissionError: [Errno 13]`）**：
1. 权威判据只有一条 —— `open(path, 'r+b').close()` 抛 PermissionError = 确认占用（目录里躺着别的 `~$` 不算数）；`tasklist | grep -i -E "winword|wps"` 可佐证
2. 🔴 **不要为了绕锁另存新文件名**（新版本文件 = 破坏"单一产物"原则，用户明确禁止多版本并存）
3. 正确处置：**报告占用 + 请用户关闭该文档 → 关闭后重跑同名生成器 → 重跑验收探针**。关掉之前不要反复重试（触发系统循环检测）

## 🔴 规则 5：量化验收（一个脚本一次跑完）

- **彩色像素占比必须 0.0000%**（黑白合规硬指标）：`((a.max(2)-a.min(2)) > 6).mean()`
- **墨迹占比（非白像素比例）作前后对照**：去图案后应下降（实测 18.6% → 15.54%）
- **`vision_describe` 读 ASCII 亮度图确认框内无图案**：正确状态是框内除文字外基本为空字符；若框内呈现密集成片的花纹字符 = 图案还在
- 探针：`scripts/check_bw_figure.py`

## 汇报纪律

改图后汇报要带**前/后对照表**（图案状态 / 墨迹占比 / 彩色像素 / 尺寸）+ 改好的图**绝对路径**，并说明哪些图**刻意保留**了区分手段（否则用户看别的图再投诉一轮）。
