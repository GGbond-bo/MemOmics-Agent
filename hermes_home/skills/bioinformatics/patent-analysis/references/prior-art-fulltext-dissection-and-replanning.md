## 1. 固定四步（不要一上来读说明书）

1. **先读权利要求书**——权利要求才是保护范围；说明书只在需要核「技术问题段怎么写的」时读。
   `.txt` 格式通常把「权利要求书 N 页」压成一段，`read_file` 前 110–140 行即可拿到全部权项。
2. **每件提炼三字段**：`命题（在问什么）` / `核心手段（独权层的技术动作）` / `可借的招`。
3. **与本案 `claims.md` 做逐环对照**：对齐 → 打分 → 归一化 → 显著性 → 输出（五环）。找出**公共的、而本案缺的那一环**。
4. **输出四件**：五件解剖表 + 发现（含"别人怎么写技术问题"）+ 重新规划骨架 + **与最接近对比文件（D1）的差异表**。

---

## 2. 关键判据

### 2.1 先按「问什么」给对比文件分命题

相似性 / 保守性 / 迁移性 / 同构性 / **可替代性**（模型有效性）。

若只有本案问「能否替代」⇒ **新颖性空间大，但无同类先例 = A25（智力活动规则）风险最高**（「评估能否替代」听起来像判断）⇒ 必须复核独权动词链全部落在数据处理上。

### 2.2 「找缺的那道工序」= 重新规划的主抓手

把五件的工序列成表，看哪一道是**公共的、而本案没有的**。

### 2.3 负面结果可重构

实测低于随机的指标，在「比较两物种」定位下是**方法失败**；在「校正粒度偏置」定位下是**技术问题的实测证据**。同一组数字，定位决定生死（与 `patent-gap-attribution-and-negative-result-strategy.md` §3 同源）。

### 2.4 ⚠️ 五件的共性（值得警觉）

每件都有一段明确的「技术问题」——**没有一件把自己的负面结果写进说明书**。

### 3.1 本案的发现（五件 × 本案）

| 发现 | 内容 |
|---|---|
| **1. 命题独一份** | 五件全在问「两物种有多像」，只有本案问「能否替代」⇒ 新颖性空间大 + **A25 风险最高** |
| **2. 缺背景校正** | D2 王欢用中性进化模型做局部背景校正；Ogawa 2025 Sci Adv 用「每物种最强 motif=1」做物种内归一化。**本案 S1.5 的分层（测序深度/GC/可比对性）+ 层内匹配基准率其实就是背景校正雏形，但它藏在从属权 11 里、没被写成发明点** ⇒ 提为独权核心 |
| **3. z 写法比 D4 弱** | 本案从权 2 写 `Z = sign(r)·Φ⁻¹(1−p/2)`（**p 值反推**）；D4 用 `atanh(r)·√(n−3)`（**效应量变换**，p 机器零时不饱和、不混入样本量）⇒ 从权增 Fisher-Z 变体 |
| **4. 可量化的技术问题没写进说明书** | 实测：方向一致率随锚定单元数 **−4.74 pp/log₁₀(n)，t=−6.41**；强效应池 vs 非强效应池锚定数均值 **522.9 vs 116.3（4.49 倍）**；`corr(\|Z_h\|, log n_h) = +0.557`；√n 聚合的独立性前提**实测不成立** |

## 4. 重新规划产出骨架（四件套）

1. **五件解剖表**（上文 §3）
2. **发现**（§3.1 四条）
3. **新定位 + 新技术问题 + 新独权骨架**：
   - 新定位：`旧 = 比较两物种衰老可及性 → 新 = 校正跨物种比较中的粒度依赖偏置`
   - 新技术问题段（可直接写说明书）：锚定单元数 1–4952 变化 → `ΣZᵢ/√n` 在自相关下方差被低估、|Z| 被放大 → ① 阈值实际在筛大元件（4.49 倍）② 方向判定随粒度漂移（−4.74pp/log₁₀(n)）
   - 新骨架：`S1 数据获取（不变）→ S1.5 统一网格+单元内分层（提为核心）→ S2' 分层背景校正 + n_eff（新增）→ S3 方向门控（保留）→ S4 置换校准（保留，加分层零假设）→ S5 分级输出（不变）`
4. **与 D1 差异表**（§3.2）

### 4.1 收尾铁律

- **必须先做那件决定新定位成不成立的事**：把 `ΣZᵢ/√n` 换成 n_eff 校正版（或符号多数聚合）重算方向一致率 —— 回到 ~50% ⇒ 新定位三条全成立；仍 <50% ⇒ 回到诚实披露路线、不改定位。**素材常已齐，不需要新数据。**
- 规划文档落**交付目录根**、**不改动现行送审件**（`01_送审_vNN/` 保持原样），文末写明这句。
- 收尾给用户 2–3 个可执行下一步 + 一件待拍板的事（与 `patent-analysis` SKILL.md 的「回答风格」条一致）。

## 5. 工具坑（本次实测）

| 坑 | 现象 | 处置 |
|---|---|---|
| `read_file` 去重不回传内容 | 对**已读过、但其内容已被上下文压缩**的文件返回 `{"status":"unchanged", "content_returned": false}`，**拿不到正文** | 用 `terminal`：`sed -n '1,80p' <path>` 直读；**不要反复 `read_file` 硬碰** |
| 中文路径下 content 搜索 | `search_files` content 模式在 `E:/专利/...` 下曾返回 `total_count: 0`，而同一文件里该串确实存在（`n_out` 在脚本 L53） | **先 `read_file` / `sed` 直读确认**，再考虑 grep；0 命中不得直接当"不存在" |

⚠️ 这两条都会导致**误判「文件/内容不存在」**，进而污染结论（本次自犯过一次：据此误报"生成脚本不在交付 scripts/ 里"，事后收回）。
