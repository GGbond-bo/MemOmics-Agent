# 附图标注来源与遮挡 —— 外部参考数据集出现在成图上时怎么标

**触发**：用户在成图上指出「**图 5C 的标题有点遮挡**」「**为什么是 mouse 呢？**」「这个标签是什么意思？」；或你正要把**外部公共数据集**的条目画进专利附图 / 交付件附图。
**用户预期**：①把遮挡修掉；②**解释清楚图上每个元素的来源**（用户会追问图上任何一个物种/编号从哪来）。只修图不解释 = 没答完。

---

## §1 🔴 外部参考数据集出现在附图里 → 必须标注「来源 + 用途边界」

**标本（2026-09-15，跨物种衰老专利 v26）**：本方法的输入数据只有 **人 40 例 + 食蟹猴 20 例**；图 5C 是把 150 个核心元件的锚定基因拿去做**后验富集**，用的库是 Enrichr `Aging_Perturbations_from_GEO_up/down` —— 该库条目源自 GEO 芯片数据集，**源物种混杂**：

| 代表性条目 | 源物种 | 组织 |
|---|---|---|
| `Mouse neuroretinas 7 weeks vs 64 weeks GSE38671` | 小鼠 | 神经视网膜 |
| `Mouse bone marrow adipocyte 6 months vs 14 months GSE25905` | 小鼠 | 骨髓脂肪细胞 |
| `Mouse hypothalamus 42 days vs 182 days GDS3895` | 小鼠 | 下丘脑 |
| `Rat entorhinal cortex 5 months vs 24 months GSE14505` | 大鼠 | 内嗅皮层 |
| `Human brain (frontal cortex) 55 vs 82 years GSE53890` | 人 | 额叶皮层 |

**后果**：y 轴只显示 `Mouse neuroretinas 7 w` 时，读者（律师 / 审查员）会读成「**本方法用了小鼠数据**」→ 与权利要求「第一物种（人）/ 第二物种（猴）」**直接冲突**，是形式上看不出来的实质风险。

**铁律三条（缺一即不合格）**：
1. **标签必须含四项**：数据集号 + 组织 + 年龄对比 + **源物种**（如 `GSE38671 神经视网膜 / 7 周 vs 64 周 · 小鼠`）；
2. **图内加注一句话**：该库为**公共**参考资源、**仅用于后验检验**、**不构成本方法的输入数据**（并点明本方法输入是谁）；
3. **正文三处同步**（否则图文口径不一致）：有益效果条 / 数据来源与公开信息节 / 实施例验证条 —— 每处都补「该库来源 + 基因符号已统一为人类同源符号 + 不参与筛选步骤」。

**可直接引的正当性事实**：Enrichr 该衰老库的**基因符号已统一为人类同源符号**（实测 `Rat liver … GSE11097` 条目里的基因名就是 `GAMT`/`RPS6` 这类人类符号）—— 这就是「跨物种公共参考库可用于人/猴锚定基因的后验检验」的依据，**务必写出来**，否则「为什么能拿鼠库检验人猴基因」本身会被追问。

**不要做**：为了消除「mouse」字样而删条目 / 换更弱的库。实测替代口径（GTEx 组织衰老签名）富集强度更弱（FDR 边缘）→ **宁可保留原始数字 + 标注清楚来源**（诚实边界 > 好看），并把「是否换库」作为选项交用户拍板。

## §2 🔴 标签字符串截断 = 语义事故源

默认写法 `ax.set_yticklabels(['{} (n={})'.format(str(t)[:22], h) for t, h in zip(E.term, E.hits)])` —— 截到 22 字符会**砍掉数据集号或年龄跨度**，只留「物种 + 组织」，正好制造 §1 的误读。

**修法**：显式映射表 + 断言，禁止截断：
```python
LAB = { 'Mouse neuroretinas 7 weeks vs 64 weeks GSE38671 aging:211':
          'GSE38671 神经视网膜\n7 周 vs 64 周 · 小鼠',  # …5 条逐条映射
        'Mouse neuroretina 7 weeks vs 64 weeks GSE38671 aging:210':
          'GSE38671 神经视网膜\n7 周 vs 64 周 · 小鼠（另套签名）', }
assert set(E.term) <= set(LAB), '存在未映射的术语: %s' % (set(E.term) - set(LAB))
ax.set_yticklabels([LAB[t] for t in E.term], fontsize=8.5)   # 两行标签，字号同步下调
```
**同源坑**：同一研究可能贡献**多条**签名集（`GSE38671 aging:210 / :211`，仅集合基数不同）→ 两条标签会完全相同，需加「（另套签名）」区分，否则图上出现两行一模一样的 y 标签。

## §3 🔴 图注写在 auto ylim 之外 → 被顶进标题区（「标题有点遮挡」）

**现状**：`ax.text(1.05, len(E) - 0.42, 'fold = 1（无富集）')`，`len(E)=5` → y=4.58，而 5 根 bar 的自动上限通常只到 4.5 → 文本落在轴外、被顶到**标题第二行**上（用户看到的就是「标题被遮」）。

**修法三步**：
1. **显式设 ylim 留头**：`ax.set_ylim(-0.70, 4.75)`；
2. **图注移到轴内**：`ax.text(1.06, 4.42, '虚线 = fold 1（无富集）', va='center')`；
3. **同一信息在 xlabel 里重复一遍**（`富集倍数（fold，虚线 = 1 即无富集）`）→ 不依赖单一位置，缩印后仍读得到。

**通用判据**：任何 `ax.text` 的 y 都必须落在显式 ylim 之内；凡图上有 2 行标题 + 轴内注释，先算「最上元素 y + 一行高」是否 ≤ ylim 上限。

## §4 验收（**一个探针一次跑完**，防循环检测）

1. **遮挡**：`vision_describe` 取 OCR 文本 + **坐标** → 检查标题两行与最近元素的 y 间距。实测通过值：标题 `图5C…` @y=24、第二行 `（核心元件…）` @y=85、图注 `虚线 = fold 1` @y=214（间距 ≥ 40 px 即安全）；修复前图注与标题第二行**同处 y≈73** = 重叠铁证。
2. **纯黑白**：`PIL+numpy` 彩色像素 = 0；非白占比 5–40%。
3. **只改该改的**：新目录与上一版目录逐张 **md5/sha256 对账** —— 未改动的图必须**逐字节一致**（本次 8 张中 7 张 ✔ 一致、仅 5C 新增），这是「严格范围修复」的机器证据。
4. 新图标签**逐条与源 CSV 对账**（术语 → 映射标签），防映射错位。

## §5 生成器源码批量替换的安全模式（本次新增）

改 v(N−1) 生成器出 v(N) 时，多处文本替换用**一个脚本 + 逐处断言**：
```python
for i, (old, new) in enumerate(reps, 1):
    assert s.count(old) == 1, '第 %d 处命中 %d 次（应为 1）' % (i, s.count(old))
    s = s.replace(old, new)
io.open(P, 'w', encoding='utf-8').write(s)
compile(s, P, 'exec')        # 🔴 写完立刻语法自检
```
- **实测事故**：拼中文串时多写一个 `"`（`…富集倍数，"虚线为…`）→ 生成器 `SyntaxError: invalid character '（'`，且**报错在运行期**（terminal 跑到才炸，白等一轮）。`compile()` 是零成本前置检查。
- 写盘后**不要**只靠「我在脑子里检查过」；`compile` + 逐处 `count==1` 两道断言即可。
