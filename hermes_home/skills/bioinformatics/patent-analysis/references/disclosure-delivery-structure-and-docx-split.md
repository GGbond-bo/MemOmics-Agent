# 交底书交付形态：正文瘦身 + 附件单独成件（docx 区块拆分）

> 触发：用户贴来**代理律师给的原始模板**问「交底书需要写这个吗？」「这个是代理律师给我的文件，希望我按照他们的填……有些东西真的要加吗？」；
> 或用户拍板「按上面结构拆分（正文瘦身 + N 份附件单独成件，**内容一字不丢**）」。
> 本文回答的是**交付形态**问题（东西放哪个容器），不是内容正确性 —— 内容正确性走 `examiner-incremental-review.md` / `audit-report-verification.md`。

---

## §0 唯一判据（一句话，先答这个）

> **凡是代理人自己能产出的（说明书摘要 / 权利要求 / 检索报告）→ 交底书别写；凡是代理人猜不出来的（你的数据 / 算法步骤 / 实测数字 / 附图）→ 必须写。**

交底书是**给代理人的输入件**，不是申请文件。判断顺序：先问「这一段是代理人本职产出吗？」是 → 移出或降级为附件；不是 → 保留。

⚠️ **"该删" ≠ "删掉"**：用户说过「一字不丢」时一律**搬移**（正文 → 附件），不删除内容。删不删这件事本身要单独问用户。

## §2 拆分技术：**以源 docx 副本为底，只删不属于本件的区块**

🔴 **不要「新建 Document + deepcopy 元素」**。deepcopy 段落会把 `a:blip` 的 `r:embed` 关系一起带过去，但目标文档的 `word/_rels/document.xml.rels` 与 `word/media/*` 没有对应条目 → 图片静默变空框；表格样式（`w:tblStyle` 指向 `Table Grid`）也可能在目标 styles.xml 缺失 → 表格掉边框。

正确做法：**每个输出件 = `shutil.copy2(源件, 输出)` 然后删掉不属于它的元素**。副本天然保住样式、编号、表格边框、图片 rId、页脚。

### 代码骨架

```python
import docx, shutil
from docx.table import Table
from docx.text.paragraph import Paragraph
from docx.oxml.ns import qn

def load_items(path):
    """[(kind, obj, element)] 按 body 文档序；表格与段落混排必须按 iterchildren 走。"""
    d = docx.Document(path)
    out = []
    for child in d.element.body.iterchildren():
        if child.tag == qn('w:p'):
            out.append(('P', Paragraph(child, d), child))
        elif child.tag == qn('w:tbl'):
            out.append(('T', Table(child, d), child))
    return d, out

def is_h1(it):                       # 分区靠 Heading 1
    return it[0] == 'P' and it[1].style.name == 'Heading 1'

def blocks(items):
    heads = [i for i, it in enumerate(items) if is_h1(it)]
    return [(items[h][1].text.strip(), h,
             heads[n+1] if n+1 < len(heads) else len(items))
            for n, h in enumerate(heads)]

def repl_para(p, old, new):
    """🔴 优先 run 级替换 —— 保住字体/字号/加粗。段落级 .text 赋值会把多 run 压成一个 run。"""
    for r in p.runs:
        if old in r.text:
            r.text = r.text.replace(old, new); return True
    full = ''.join(r.text for r in p.runs)      # 跨 run 兜底
    if old in full and p.runs:
        p.runs[0].text = full.replace(old, new)
        for r in p.runs[1:]: r.text = ''
        return True
    return False
```

## §3 五条实测坑（全部 2026-09-12 真踩）

| 坑 | 症状 | 处置 |
|---|---|---|
| 🔴 **标题字符串记错一字** | 断言 `未命中 '表 8\u3000待比对文件清单与对照'` —— 真文本是 `表 8　待比对文件清单与**区别**对照` | 断言式替换（`assert n>=1`）是**对的**，它替你拦住了。修法：先 `print(repr(p.text))` 回读**真实字符串**（含全角空格 U+3000），不要凭肉眼抄 |
| 🔴 **表号沿用原序号 → 不连续** | 正文表号序列 `[1, 2, 4, 3]`（申请人被挪到最后，序号却没跟着调） | 表号**按各件内文档序重排**：先 `grep '^表 N　'` 列出**出现顺序**，再逐条改。标本：装置表 原"表 6"→**表 3**、申请人表**保持表 4**（因为申请人挪尾后它才排第 4）——不是简单 -3 |
| 🔴 **要素合法但顺序错** | 附件 1 首章变成"摘要草稿" | 见 §2 第三段：附件保留区块必须显式重排 |
| 🟡 **跨件引用悬空** | 附件里写"表 1（9 方法）/ 图 4 / 图 5"——那几个表图已不在本件 | 附件内指向正文的对象一律补限定词：`交底书正文表 1`、`正文图 4`、`交底书正文 §四（补充）表 2` |

## §7 🔴 内部管理信息清除（本类任务的最后一道门禁）

**为什么单列一节**：2026-09-12 v16 拆分完成后，用户当场指着**页脚**追问「**这个不需要吧，而且还添加这些正文瘦身版，这些都是不必要的信息**」——被指的正是我"正文瘦身"时**顺手搬进页脚**的那行版本行。它同时含 4 类内部信息：版本号及其内部别名（`v16（正文瘦身版）`）、数据口径（`口径：all 输入版`）、内部战略代号（`战略 B`）、内部文档索引（`权项框架 14 项见附件 1`）。

**根因（一句话）**：我把交付件当成了**项目组的管理台账**，而不是给代理人的**输入件**。拆分任务做减法时，只在删"章节"，忘了删"页眉页脚/表格里的项目元信息"。

### §7.3 修复必须落在生成器（可复现铁律）

用户要求「产物必须由脚本直接生成」⇒ 内部信息清除只能改**生成器**：删 `FOOTER_TEXT` 常量 → 删整段页脚写入代码 → 附件补 `extra_edits` 映射（`(旧串, 新串)` + `assert n>=1`）。**禁止直接手改 docx**（改了 docx 下次重跑生成器又会长回来）。重跑后必跑 §7.2 探针复检。

### §7.4 汇报格式

① 命中表（原文 → 改为，标注所在件）；② 复检结论「N 件 × M 关键词 × 4 处 = 0 命中」；③ 修复落在哪个生成器的哪一段；④ **主动列出同类边界项**（法条援引 / 附件索引行 / 结构括注）并说明为什么留着，交用户拍板 —— 不要因为改完主问题就沉默，用户上一轮已经问过一次「有些东西真的要加吗」。

## §8 🔴 辩论裁决驱动的边界清理（第二轮：从「搬移」到「删改」）

> 触发：用户拍板「**四处全按辩论改**」；或把决定权交回来 ——「**B 会删掉权项草稿和摘要草稿这一项，你看着要不要删除，你来决定**」。
> 前置：§7 解决的是「**别把内部管理信息留在交付件里**」；§8 解决的是「**边界项到底该留还是该清、清到什么程度**」——由 L1 辩论裁决给出，不由 Agent 自行拍板。

### §8.1 ⚠️ 先解除「一字不丢」

「内容一字不丢」是**拆分轮（§0–§6）的约束**，它保证搬移不丢内容。到**裁决轮**，用户已明确授权删减（本案原话「四处全按辩论改」+ 把 B 项删不删交回来决定）⇒ **约束从「只搬移」切换为「按裁决删改」**。
🔴 切换动作要显式确认一次：本会话是用户一句「A｜出 v16：按上面结构拆分（…内容一字不丢）」定下前一轮约束，一句「四处全按辩论改」解除它。**不要沿用上一轮的约束去拒绝本轮该做的删除**，也不要在没拿到这句授权前自行删。

### §8.3 B 项的决断法：**删形式，留内容**（用户把决定权交回时照此办）

用户说「你看着要不要删除，你来决定」= 要的是**一个带理由的决定**，不是把问题再抛回去。判据用**风险不对称**，不用个人偏好：

| 候选 | 删掉损失什么 | 留住损失什么 | 决定 |
|---|---|---|---|
| **摘要草稿** | 几乎没有 —— 内容与正文 §三（简介）重复；边际信息 ≈ 0 | 摘要是**申请文件的法定组成部分**（法定由代理师撰写），出现在交底书里即越位；且格式约束（≤300 字）是申请文件规格 | 🔴 **删** —— 零损失 + 正风险 ⇒ 删 |
| **14 项成文权项** | **代理师猜不出来的独家信息**（"发明人希望保护什么"）—— 删了不可恢复 | ① 成文权项是**法律撰写**，越位；② 本案草稿**自身有 A26.4 支持风险**（独权写"由置换检验确定 τ_A"、说明书写"τ_A 取观测高分位、该检验不用于标定"）⇒ 代理师照抄 = 硬伤直接进申请文件、答辩难改 | 🔴 **不删内容，换形式**：降级为「**技术特征要点清单（非约束性，供代理师参考）**」 |

**降级的具体动作**（去掉法律形式 + 保留技术特征）：
- 标题 `附件 1　权利要求框架建议（供参考）` → `技术特征要点清单（非约束性，供代理师参考）`
- 导语去 `A25` 与「独权/从权框架建议」→ 改为「所列各项仅为**发明人视角的技术特征说明**……具体保护范围与技术特征取舍由代理师独立判断」
- 表标题 `权利要求搭建建议框架` → `技术特征要点清单`
- 表首列 `权项` / `独立权利要求 N` / `从属权利要求 N` → **`要点` / `要点 N`**（14 行）

### §8.4 E 项：术语统一（本案 Agent 自查发现，可复用规则）

`代理人` → **`代理师`**（中国现行法定称谓）。**触发场景**：一旦按 §8.2 改了某件标题里的称谓，**同一套交付件里其它件的旧称谓就变成不一致** —— 本案 D 项把附件3 标题改成「供代理师参考」，而正文/附件3 正文仍写「供代理人……」→ 同一套件两种称谓。**改称谓要整套扫**（本案 4 件共 5 处）。
判据：**凡改动了某类称谓/术语的一处，立刻全文扫该类术语的全部出现处**，不要只改被裁决点到的那一处。

### §8.5 🔴 `id()` 去重 → 表格单元格被静默跳过（本案真踩，已单列进 SKILL.md 陷阱表）

写「遍历正文段落 + 表格单元格」的收集函数时本能会写 `seen.add(id(p._element))` 去重合并单元格。**会静默丢数据**：lxml 元素代理在第一轮正文遍历结束后 **被 GC**，地址被第二轮新对象**复用** → `id()` 撞车 → 单元格误判「已访问」而跳过；脚本**不报错**，只是少改了若干处。
- 症状：断言式替换报「**未命中**」，而逐位比码点**完全相同**（本案先怀疑短横线 `–` vs `-`、全角空格，全部排除）。
- 修法：**持强引用 + `is` 比较**
```python
seen = []
def first_visit(el):
    for x in seen:
        if x is el: return False
    seen.append(el); return True
```
- 判据：**凡「多层级遍历元素并去重」一律禁用 `id()`** —— 与是否 lxml 无关，对象生命周期不确定就有撞车风险。

| 检查 | 做法 | 本案实测 |
|---|---|---|
| **A 越位信息清零** | `BANNED` 关键词表（19 词：`A22.4`/`A25`/`权利要求`/`权项`/`独权`/`从权`/`交付目录`/`run_all.sh`/`scripts/`/`results/`/`patent/`/`bash`/`版本 v`/`战略 B`/`正文瘦身版`/`口径：all`/`代理人`…）× 全部件 × 段落+表格 | 4 件全 **0 命中** |

🔴 **ALLOWED 登记表是这类验收的关键**：没有它，「有意改动」与「意外丢失」无法区分，验收会到处假 FAIL（本案就先后漏登记了 `scripts/`、`results/`、`代理人` 三次，每次都报假丢失）。**每加一条替换规则，同步在 ALLOWED 里登记其原文前缀。**

### §8.7 汇报纪律（本案用户接受的形态）

① **先给决定 + 理由**（B 项为什么删摘要、为什么不删权项 —— 用风险不对称表，不要只说"我删了"）；
② **四处裁决的落地表**（裁决 → 落地做法 → 命中数）；
③ **主动交代超出裁决的自加项**（本案 E 术语统一：「**外加一项 E（我自加的，你可否决）**」）—— 自加项必须显式标记可撤销，不能混在裁决项里；
④ 交付件表（路径 + 字节数 + 章节/表/图计数）+ 验收证据（N PASS / 0 FAIL）；
⑤ **过程中修掉的真 bug 要报告**（本案 `id()` 坑）—— 用户视 Agent 为需调试的系统，主动报根因比藏起来强；
⑥ 结尾给「还剩哪几件等你定」（本案：申请人信息、图 2/4/5 影线、旧版是否归档）。
