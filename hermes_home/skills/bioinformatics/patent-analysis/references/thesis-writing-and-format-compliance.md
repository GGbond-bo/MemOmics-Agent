## §0 三步顺序（先读规范 → 再读素材 → 才动笔）

1. **读学校规范文件**（.doc / .docx / 扫描 PDF 混合）→ 产出「**整理标注版**」速查 md 落盘
2. **读素材包**（`00_总索引` → 方法步骤 → 结果数字速查表 → 图件对照 → 文献来源）
3. **动笔**：分部写 md → 一个生成器合并出 docx → 回读产物验证

⛔ 不要跳过第 1 步开始写正文；⛔ 不要在读完素材包前就开始写（会写出与素材不符的句子）。

## §3 DOCX 生成管线（可复制的工程做法）

- 🔴 **平台 `execute_python` 持久内核没有 python-docx** → 用**系统 Python**：
  `C:/Users/<user>/AppData/Local/Programs/Python/Python312/python.exe`（本机已装 python-docx 1.2.0）。
  **不要为它重复 `pip install`** —— 先查系统 Python 装没装（素材包/历史记录里常已写明）。
- **分部写 md，单一生成器合并**：`part1_front` / `part2a_ch1` / `part2b_ch2` / `part3_ch3_ch4_ch5` / `part4_refs_appendix`
  → `scripts/gen_thesis_docx.py` 合并 + 插图 + 出 docx。
  好处：**改一节不用重写全文**，且目录/清单/交叉引用可脚本化同步。
- **页眉逐节**是实现难点（规范要求每节页眉 = 该章编号及标题）：用 python-docx 逐节 `section.header` 写入，

- **产物验证必须回读**（不许只看脚本打印"OK"）：

- 图片随 docx 一起交付（`figures/` 9 张）+ 保留 md 母本 + 生成脚本，三者同目录。

## §4 🔴 新增错误类型：正文里的「独立性 / 显著性」断言与算术相反

**这是本次文本核对抓出的最严重错误，也是最容易复发的一类。**

**标本（3.3 节原句）**：
> 「三层逻辑与后的输出规模（150）**显著高于**三条件相互独立时的假设值，其原因在于三层证据之间存在**正相关**——保守元件更可能可及……」

**实算（零成本，一行乘除）**：
```
N=16 029；L1 19.8%（3 180）、L2 64.9%（10 401）、L3 8.8%（1 409）
独立期望（三层）= N × 0.198 × 0.649 × 0.088 = 181
实测 = 150  →  150 < 181（0.83 倍，偏离 2.34 SD）
独立期望（L1∧L2）= 3 180 × 10 401 / 16 029 = 2 063
实测 = 1 604 → 1 604 < 2 063（0.78 倍）
```
⇒ **两项实测交集都低于独立期望 = 负向关联，原句把方向写反了**，且给出的是机制性因果解释（"保守更可能可及"），属于**用一段自造的机制去圆一个不成立的观察**。

**铁律**：
1. 🔴 **凡正文出现「高于/低于期望」「显著偏离独立假设」「显著富集于…期望」的句子，必须在同一轮把算术跑出来**
   （交集实测数 vs 独立期望乘积）。**这类句子不能只做语言检查** —— 读起来完全通顺、数字也都在册，只有乘一遍才露馅。
2. **方向不符时不许只改方向词**。正确处置 = **降级为客观陈述**，本会话采纳的写法：
   > 三层证据并非相互独立——L1 ∧ L2 实测 1 604 **低于**独立期望 2 063（0.78 倍）；三层实测 150 **低于**独立期望 181（0.83 倍，偏离 2.3 倍 SD），提示三层证据之间存在负向关联。因此本研究**不对输出规模作独立性假设下的显著性主张**，输出规模的意义仅在于其落在预设目标区间 [30, 500] 内。
3. **修法二选一**（用户拍板）：
   - **A（零成本，推荐）**：删断言 + 改客观陈述 → 同时写进「局限性」一节
   - **B（需补算）**：复用已有置换框架对三层交集做**经验零分布**（`nperm=5000, seed=42`），有 p 值再谈"偏离期望"
4. **同族错误：计数自洽** —— 正文写「**18 组**（175 组中的大多数）落在目标区间之外」，而表中写着「19 组落入区间」。
   正确 = `175 − 19 = 156`。⇒ **凡出现「N 组中的大多数 / 其余 / 少数」类表述，回原始总数做一次减法**。
5. **段落增删后必须同步"计数式引用"**：4.4 由「六条边界」改为「七条」后，1.5(6) 的「方法的**六条**使用边界」必须一起改
   —— `grep -n 六条` 全库扫一遍（本方测试涉及 3 处命中，其中 2 处在分部 md、1 处在合并后的 md）。

## §6 「检索式与日期」的取证法（另一个会话的产物怎么拿）

用户说「**新颖性检索的检索式与日期：CNIPA 那几件的检索是你另一个会话做的**」——
含义是**去取证，不要编**。三条动作：

1. **定位检索记录件**（通常叫《检索记录与对比文件》）：本例 `E:/专利/交付_…/01_送审_v17/检索记录与对比文件_v17.docx`
   → python-docx 提**段落 + 表格**（检索式在段落里、IPC 表在 tables 里）。
2. 🔴 **用文件 mtime 作为日期证据**（唯一可核验的日期来源）：
   ```
   ls -l --time-style='+%Y-%m-%d %H:%M' <公开文本目录>/*.txt <逐件比对.md>
   ```
   本例实测：5 件公开文本落盘 **2026-09-13 22:37–22:39**、逐件比对文件 **2026-09-14 01:51**。
3. ⚠️ **注意记录里写的是「（二）检索式（建议）」** —— 建议式 ≠ 实际使用式。
   写入论文时按记录如实写，**并主动向用户确认"如果你那次实际用的是别的式子请告知，我替换成实际那版"**。

**写入位置**：现有技术小节首段 = 检索平台（CNIPA / CNKI / Espacenet / PATENTSCOPE / Google Patents）
+ 中文检索式 + 英文检索式 + 分类号组配 + 检索与比对日期。

## §10 论文文献准备：下载受阻时的回退链

> ⚠️ 这类知识的规范归属是 `paper-download` 技能，但该技能为**手工编写**（不可由 agent 修改）→ 暂记于此。
> 若后续 `paper-download` 可由 agent 维护，应迁入。

论文绪论/背景章需要一批文献时，`download_pdf` 在 Elsevier / Wiley / MDPI / Science 常被 **403 硬拦**；
本机 `curl` 另有 TLS 后端问题（Windows schannel `CRYPT_E_REVOCATION_OFFLINE` = 证书吊销检查离线）。
**不要在这一条路上反复重试**，换「Python + 元数据 API」两条腿：

1. **先判是"反爬"还是"链路"**：Python `urllib.request.urlopen('https://eutils.ncbi.nlm.nih.gov')` 能通
   ⇒ 网络正常，问题在目标站或 curl 后端 → 改用 Python 请求。
2. **Unpaywall 取合法开放版**：`https://api.unpaywall.org/v2/<DOI>?email=<email>` → `best_oa_location.url_for_pdf`
3. **Europe PMC REST 取全文**（实测 200 可用）：
   - 定位 PMCID：`https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=DOI:"<DOI>"&format=json`
   - 全文 XML：`https://www.ebi.ac.uk/europepmc/webservices/rest/<PMCID>/fullTextXML`
   - ⚠️ **PDF 渲染端点常 403，但 `fullTextXML` 可用** → 拿不到 PDF 就用 XML
     （XML 足够支撑「引用不编造」+ 参数/方法提取）
4. **验收**：`http_code` + 字节数 + **内容首字符**（`%PDF` / `<?xml`）。
   ⛔ `200` + 0 字节 / HTML 落地页 = **伪成功**，不算下载成功。
5. **汇报要分类**：哪些是 PDF、哪些只有 XML、哪些没拿到 —— **不要把 XML 说成 PDF**。
   实测一批 20 篇：出版商直链全 403，走 API 后得 **3 篇 PDF + 13 篇全文 XML**。
