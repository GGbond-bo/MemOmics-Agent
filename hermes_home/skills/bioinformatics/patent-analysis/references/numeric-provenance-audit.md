# 数值口径溯源对账（列级 provenance audit）

> 触发：用户说「我需要验证你的东西」「对不上」「为什么是这个版本」「你复现给我看」
> 或你重跑出来的数字与交底书/正文/已交付表**不一致**时。
> 适用类别：任何「已成文的数字 vs 重跑数字」冲突的定位（专利正文、论文 Figure、报告交付表、benchmark 对账）。

---

## 0. 铁律：禁止用「口径差异属预期」结案

重跑数字与正文不一致时，**只允许两种收尾**：
1. 定位到**具体是哪个输入文件/哪一步**产生的差异（逐基因比对证明），并说清哪个才是对的；
2. 明确列出「要定论还缺什么」——缺哪个脚本、哪个参数、哪份原始日志。

⛔ 不允许写「两版坐标网格同一套（差 +1bp），r 值体系不同，数字差异属预期，非 bug」这类含糊结论就交付。
那个说法 2026-09-11 被实测推翻：两版猴文件**不是 ±1bp 偏移**（见 §3）。

---

## 1. 核心方法：列级溯源（column-level provenance trace）

不确定「正文数字用的是哪份输入」时，不要猜、不要全量重跑。按下面顺序做：

```
步骤 A  读正本表 + 重跑表，按 symbol（或任何稳定主键）merge
步骤 B  逐列算「round(value,4) 精确相等比例」
        → 哪一列 100% 相等 = 该侧输入同源
        → 哪一列 0% 相等   = 该侧输入是另一个文件
步骤 C  对候选输入文件，各跑一遍 → 与正本那一列逐基因比
        → 100% 相等者 = 正文数字的真来源（决定性证据）
```

**实测样例（2026-09-11，跨物种衰老可替代性专利）**

| 比较 | 结果 | 结论 |
|---|---|---|
| 正本 `v5_substitutability_all.csv` vs 重跑表，**Z_human** | 15963 共享 symbol，**100%** round4 精确相等 | 人侧输入同源（都用 `M2/human_ageDA_all.csv`） |
| 同上，**Z_monkey** | **0%** 相等，中位绝对差 1.81；正本均值 −1.934 vs 重跑 +0.092 | 猴侧输入不是同一个文件 |
| 正本 Zm vs 猴 **continuous** 版管道输出 | chr1 取 1664 基因逐基因比，**100%** 相等，中位差 **0.0000** | ✅ 找到真来源 |
| 正本 Zm vs 猴 **all** 版管道输出 | 0% 相等，中位差 1.6349 | ✗ 不是它 |

→ 结论：**正文全部数字 = 「人 all 版 + 猴 continuous 版」的混合输入产物**。这是单一最强结论，
远比「差异属预期」有用——它直接告诉用户要改哪份文件、要重算哪些表。

## 2. 廉价探针：单染色体子集，1–2 分钟出定论

全量重跑要几十分钟（456MB + 433MB 流式锚定），**溯源不需要全量**：

```python
def scan_chrom(path, target, cap=3_000_000):
    """只收集 target 染色体的行；首次遇到 target 开始，chrom 一变立刻 break。
       坐标一律 int(float(x)) 解析（见 §3 陷阱）。"""
    rows, started = [], False
    with open(path, encoding='utf-8') as f:
        rd = csv.reader(f); next(rd)          # 跳表头
        for i, p in enumerate(rd):
            if i > cap: break
            if p[0] == target:
                started = True
                rows.append((int(float(p[1])), int(float(p[2])), float(p[3]), float(p[4])))
            elif started:
                break
    return rows
```

配合 `searchsorted` 锚定（tile 中点 ±2kb）+ Stouffer 合并，取第一条染色体的 ~1600–1700 个基因
就足以判定 0% vs 100%（无需全基因组）。

> 现成可跑脚本：`scripts/trace_Z_source.py`（本 skill 内，纯 numpy/零 scipy，argparse 直接指定
> 正本表 + 若干候选输入）。**优先跑它，不要现场手写。**

## 3. 必须避开的陷阱

| 陷阱 | 说明 |
|---|---|
| 🔴 **文件名 ≠ 口径** | `M2_repro_gene_conservation_continuous.csv` 名字带 continuous，生成脚本 `repro_m3_from_M2.py` 里读的却是 `M2/*_all.csv`。判口径**只能看生成脚本的输入常量 + 逐基因比对**，文件名和注释都不可信 |
| 🔴 **中间产物 == 正文，只证明自洽不证明正确** | `v4b_gene_substitutability_table.csv` 与 `v5` 的 Zm/Zh 100% 相等，只说明 v5 是从 v4b 算出来的；v4b 的 Zm 来自哪份输入仍需继续往上追 |
| 🔴 **混合输入：两侧可能来自不同版本** | 本例人侧用 all 版、猴侧用 continuous 版。做「版本一致性」核查时必须**分侧分别溯源**，不能查一侧就下结论 |
| 🔴 **0-based vs 1-based 不能轻描淡写成「±1bp」** | 实测差异远不止 1bp：起点 19500/20000（0-based）vs 20001/20501（1-based）；chr1 tile 数 445,722 vs 427,213（全基因组 ≈567 万 vs 530 万）；**r 均值 −0.028 vs +0.027、r>0 比例 42.5% vs 55.4%**。r 分布形态都变了 = 不是同一口径，必须由用户/生成脚本定哪个为准 |
| 坐标列可能是科学计数法 | continuous 版坐标写成 `1e+05`，`int(p[1])` 直接 ValueError。一律 `int(float(p[1]))` |
| 置换 p 从 0.0 变 0.285 | 这是**方向性差异**（该口径下置换不显著），不是精度问题，必须在对账表里单列出来 |
| 只看总数字不看分布 | 除了 A/B/C/D 计数，务必比 `mean/sd/min/max` 和 `|Z|` 阈值外的计数——正本 Zm 均值 −1.934（整体负偏）vs 重跑 +0.092（居中）是定位「换了输入」的关键指纹 |

## 4. 交付格式：复现清单四件套

用户（本专利项目）明确要求「列出我要复现的进程的内容」。交付必须**逐步骤**给四件套，缺一不可：

| 步骤名 | 输入（绝对路径 + 列名） | 参数（常量名 + 值） | 输出文件 | 正本数字 |
|---|---|---|---|---|

- 输入要写**列名**（`chr,start,end,r,p,q`；`macaque_gene_id,human_gene_id,human_symbol`），
  否则用户无法核对自己手上的文件
- 参数写**常量名 + 值**（`WINDOW=2000` / `TAU=1.96` / `N_PERM=10000` / `SEED=42`），
  并注明上游口径细节（如「猴用 strand 精确 TSS，人用 start 近似」）
- 配一张 Mermaid flowchart 画管道骨架（先图后表）
- 最后单列一节「**本条你要核对什么 / 怎么核**」，每条给一条可执行判据
  （例：「`df[(df.Z_human.abs()>=12) & (df.p_monkey<0.05) & df.same_direction]` → 应得 336」）

### 出图与门禁
纯溯源/只读比对步骤没有图，`rail_review(post)` 会报「未生成任何图片」——**这是误报，不拦截执行工具**。
正确做法不是忽略，而是补一张**对账图**（正文 vs 重跑 的 Z 散点 / 两版候选输入的 Zm 对比），
它同时满足审查门禁、又是用户要的直观证据。

## 5. 定论缺口（2026-09-11 L1 辩论裁决 = need_more_info / 置信度 low）

裁决给出还缺的东西，照此向用户索要即可定论：

1. 两版猴 ageDA（all / continuous）的**生成脚本与 ArchR 参数**：genome、tileStart/tileSize、
   黑名单、染色体/性染色体过滤、标准化（divideN）、样本纳入；
2. 证明 1-based all 版是**修复**了 0-based continuous 版的缺陷，还是只是**换了过滤/窗口覆盖**；
3. 用同一 ArchR 版本与 QC 重跑人、猴两版，解释「人侧两版无差异、猴侧 r 均值却由 −0.028 翻到 +0.027」；
4. 独立验证：年龄分层重采样、已知海马衰老 marker、阴性对照 tile/gene 支持哪一版；
5. 确认专利/毕业课题是否允许**混合口径**。若不允许 → 需版本化重算
   `1904/3487/7562/3078`、`ρ`、`336/37` 核心元件表、`v6 402`、`v7` 公式。
