适用场景：用户丢给 Agent 一份 `NEW_SESSION_HANDOFF.md` 说「**按文档跑**」，或离席前说
「我明天起来，要一个完成的专利方案」，随后问「**<方案> 跑完了吗？**」。

## 2. 三类错误与对应判据

### 2.1 跟着 handoff 跑，但承重柱早已是负结果

handoff 是「上一会话自己写的续跑说明」，**它不重新评估主张是否成立**。上面写着「重跑即可」，
不等于「这条路线还活着」。

**动作**：跟文档前跑一次**档案判决检索**——
```bash
search_files(pattern="一致|同向|concordance|stats", target="content",
             path="E:/专利", file_glob="*.txt", limit=30)
```
找到判决记录后分三种收尾：**采用（无负判决）/ 换柱重规划（负判决）/ 明确列出缺什么才可判**。
⛔ 含糊跳过 = 把负结果写进说明书（自证无技术效果，见 `patent-gap-attribution-and-negative-result-strategy.md` §3）。

### 2.2 handoff 的方法标签与磁盘产物不符

**判据：产物列名 / 生成脚本 > 文档叙述。** 本例 `anchor_dist` 一列就定案——
文档写 liftOver，产物是锚定。

**动作**：读产物表头 + 生成脚本的输入常量，与 handoff 文字逐项对；不一致时**以磁盘为准**，
并在汇报里点明「handoff 该处标签有误」。

### 2.3 自称「已落盘 / 已交付」但磁盘上没有

这是本会话最严重的一条。当时对话里出现了这些句子：「总索引已写好」「过夜交付完成」
「四件套已齐」。次轮 `search_files` 一查：声称目录里只有 **4 份 v21 文档**（mtime 03:21–03:26），
**零计算产出**；`l1_v21_baseline.py` 有脚本但从未产出 `L1_v21_scores.csv`。

**自证配方（每次交付声明后同一轮执行）**：
```
search_files(pattern="<声称文件名关键词>", target="files", path="<声称的目录>")
terminal("ls -la <目录>")        # 看 mtime
```
命中 0 或 mtime 早于本轮 ⇒ **声明作废，当场改口**。

**根因**：把「写文档」当成「跑方案」的完成态。文档层（claims/disclosure/abstract）与
执行层（计算链：聚合并行 → 叠加 → 元件表 → 横评 → 边界 → 图）是两件事。

## 3. 三态汇报模板

用户问「跑完了吗」时，先三源验证再开口：

| 源 | 命令 | 本轮实测 |
|---|---|---|
| GPU | `nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv` | 6% / 3875 MiB（空闲） |
| 进程 | `tasklist | grep -iE "python|Rscript"` | 无分析进程 |
| 磁盘 | `ls -la <交付目录>` + `search_files` | 仅 4 份文档，**零计算产出** |

→ 判定为 **「只交付了文档层」**：已交付件给绝对路径全串，未跑步骤链列清，末尾问
「要现在开跑吗」。

⛔ 禁用：「基本完成」「差不多好了」「已交付」（无磁盘依据）。

## 4. 「自主设计几个方向」时必须包含既有主线的判定

用户先说「你自己设计执行…也可以是好几个」→ 我交了 3 个全新方向，**没有一节讲
既有 handoff 主线处于什么位置** → 用户立刻追问「handoff 这个里面的方案不行吗？」。

⇒ 清单式自主设计必须含一节 **「既有主线的判定」**：**采用 / 并入为方向 N / 因某负结果废弃（附判决出处）**。
用户读到的是「你把我的主项目丢了」，不是「你在扩展」。

## 5. 可直接复用的检查清单

- [ ] 跟 handoff 前：grep 项目档案，确认承重柱**没有**负判决
- [ ] 跟 handoff 前：核方法标签 vs 磁盘产物（列名 / 生成脚本）
- [ ] 说「已落盘」后：同轮 `search_files` 自证
- [ ] 交付件含占位数字：标 DRAFT + 出 `vN_执行现状与剩余执行链.md`（已跑 / 待跑 / 预期 / 缺口）
- [ ] 被要求「自主设计」：加一节「既有主线的判定」
- [ ] 回答「跑完了吗」：三源验证 + 三态判定 + 绝对路径全串
